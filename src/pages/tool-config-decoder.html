Two decoders for the two register spaces every NVMe-over-PCIe engineer reads: the PCIe configuration space of the function (from lspci -xxx or -xxxx), and the NVM Express (NVMe) controller registers at the start of BAR0 (from nvme show-regs or a raw dump). Both come with a synthetic sample from the course's lab system.

What these decoders do

Configuration space tells you what the PCIe function is and how the link and the transaction layer were set up: identity, BARs, enables, interrupts, Max Payload Size (MPS), Max Read Request Size (MRRS), link speed and width, and error status. The NVMe registers tell you what the controller is doing: its capabilities, the host's configuration, its readiness and the admin queue location. Most bring-up and performance failures are visible in one of these two pages before you ever open a trace.

  • The config space decoder decodes the Type 0 header (and the bus numbers of a Type 1 header), walks the capability list from offset 34h and the extended capability list from 100h with loop detection, names common capability IDs, and decodes in detail the Power Management, MSI, MSI-X, PCI Express and Advanced Error Reporting (AER) capabilities, including the link fields.
  • The NVMe register decoder decodes CAP, VS, INTMS, CC, CSTS, AQA, ASQ and ACQ field by field, checks consistency between them, and computes the doorbell offsets from CAP.DSTRD.

Read Chapter 18 — Configuration Space and Chapter 19 — BARs and MMIO for the first decoder, Chapter 24 — NVMe Registers for the second. Linux commands to collect both dumps are in Chapter 69 and Chapter 70.

Safe lab Collecting the inputs only reads registers: sudo lspci -xxxx -s 01:00.0 and sudo nvme show-regs /dev/nvme0. Never use setpci to write values you have decoded here on a system you care about.

Config space decoder

Paste lspci -xxx (256 bytes) or lspci -xxxx (4,096 bytes) output, header line included or not. A plain list of bytes also works. The sample is the lab SSD at 01:00.0; it is synthetic, and its Vendor ID ABCDh is invented for teaching.

  1. Little-endian. Configuration registers are little-endian: bytes cd ab at 00h are the Vendor ID ABCDh, 01 10 the Device ID 1001h.
  2. Command and Status at 04h: 06 04 = 0406h → Memory Space (bit 1), Bus Master (bit 2), Interrupt Disable (bit 10, because MSI-X is used). Status 10 00 = 0010h → bit 4, a capability list exists.
  3. Class code at 09h–0Bh: 02 08 01 read upward as base class 01h (mass storage), subclass 08h (non-volatile memory), programming interface 02h (NVM Express). This triple is how the operating system knows to bind the NVMe driver.
  4. BAR0 at 10h: 04 00 60 fe = FE600004h. Bit 0 = 0 → memory; bits 2:1 = 10b → 64-bit, so BAR1 (14h) holds the upper half (0); bit 3 = 0 → non-prefetchable. Address FE60_0000h — where the NVMe registers live.
  5. Capability pointer at 34h: 40h. Each capability starts with an ID byte and a next-pointer byte: 40h (01h, PM) → 50h (05h, MSI) → 70h (10h, PCI Express) → B0h (11h, MSI-X) → 00h, end.
  6. PCI Express capability at 70h: Device Capabilities (74h) 22 80 00 10 → bits 2:0 = 010b, 512-byte MPS supported. Device Control (78h) 3f 29 = 293Fh → bits 7:5 = 001b (MPS 256), bits 14:12 = 010b (MRRS 512). Link Capabilities (7Ch) 44 08 00 00 → speed 4 (16 GT/s), width 4. Link Status (82h) 44 10 = 1044h → running at 16 GT/s x4.
  7. MSI-X at B0h: Message Control 20 80 = 8020h → enabled, table size 20h + 1 = 33 vectors; table in BAR0 at 2000h, Pending Bit Array at 3000h.

Reading the link fields

Three numbers decide most PCIe performance questions: what the link can do (Link Capabilities, and the Supported Link Speeds vector in Link Capabilities 2), what it was asked to do (Target Link Speed in Link Control 2), and what it is doing (Link Status). The decoder warns when Link Status is below Link Capabilities. Try it: in the sample, change the byte at 82h from 44 to 43 (or 24). The link now reports 8 GT/s x4 (or 16 GT/s x2), half the bandwidth (see the bandwidth calculator).

Strictly, the speed fields are indexes into the Supported Link Speeds vector (value n means "the speed in vector bit n−1"). On every device that sets the vector contiguously from 2.5 GT/s, that gives the mapping above. See PCI Express Base Specification, Revision 6.x — PCI Express Capability Structure.

A link that trained down is a property of both ends and the channel between them. Before blaming the SSD, decode the root port's (or switch port's) configuration space too: if its Link Capabilities say 8 GT/s, the SSD is fine.

NVMe register decoder

Paste lines in the form name : value or name = value (cap, vs, intms, intmc, cc, csts, nssr, aqa, asq, acq), as printed by nvme show-regs without -H, or a hexdump of BAR0 from offset 0 (little-endian, like a config-space dump). The sample is the lab controller after a successful enable.

What the sample says

  • CAP = 0x0040_0830_1401_0FFF: up to 4,096 entries per I/O queue (MQES FFFh, 0-based); queues must be contiguous (CQR); only the mandatory round robin arbitration (AMS 0); up to 10 s to become ready (TO = 20 × 500 ms); doorbell stride 4 bytes (DSTRD 0); NVM Subsystem Reset supported; NVM and other I/O command sets; memory page size 4 KiB to 64 KiB.
  • VS = 0x0002_0000: the controller reports NVMe 2.0. The version a controller reports is its own claim; it says nothing about which optional features it implements. Version-dependent
  • CC = 0x0046_0061: enabled, all supported I/O command sets (CSS 110b), 4 KiB pages, round robin, 64-byte SQEs (IOSQES 6), 16-byte CQEs (IOCQES 4).
  • CSTS = 1: ready, no fatal status, no shutdown in progress.
  • AQA = 0x001F_001F: 32-entry admin SQ and CQ, at ASQ = 0x1_0000_0000 and ACQ = 0x1_0000_1000, both 4 KiB aligned.

Enable sequence, as the registers show it

  1. read CAP, VS
  2. CC.EN = 0; wait CSTS.RDY = 0
  3. write AQA, ASQ, ACQ
  4. write CC (MPS, CSS, IOSQES, IOCQES, EN = 1)
  5. within CAP.TO × 500 ms
  6. CSTS.RDY = 1

Limitations

  • Only the capabilities listed above are decoded in detail; others are named (if known) and their position in the chain is shown.
  • BAR sizes cannot be derived from a dump; Linux prints them in lspci -vv and in /sys/bus/pci/devices/…/resource.
  • Device Capabilities 2, Device Control 2 and Link Status 2 are not decoded field by field. Completion timeout ranges and 10-bit tag settings live there; consult the PCI Express capability structure in the specification.
  • CAP fields added in recent NVMe revisions beyond those shown (for example controller ready modes and power-scope fields) are not decoded. Version-dependent
  • Registers read through a hypervisor or a VFIO-assigned device may be emulated: the decoder trusts whatever you paste.

Practice

  1. Bytes at 09h–0Bh are 01 06 01. What is the device?

    Answer

    Base 01h mass storage, subclass 06h SATA, interface 01h AHCI: a SATA controller, not NVMe.

  2. BAR0 reads 0c 00 00 e0. Decode it.

    Answer

    E000000Ch: memory BAR, type 10b (64-bit), prefetchable (bit 3), address E000_0000h with the upper half in BAR1.

  3. Device Control reads 503Fh. What are MPS and MRRS?

    • 256 B / 512 B
    • 128 B / 2048 B
    • 256 B / 4096 B
    Answer and reasoning

    Bits 7:5 of 503Fh = 001b → 256 B; bits 14:12 = 101b → 4,096 B.

  4. CAP.DSTRD = 2. Where is the SQ1 Tail doorbell?

    Answer

    Stride = 4 << 2 = 16 bytes; SQ1 tail = 1000h + 2 × 16 = 1020h.

  5. CC.MPS = 1 and CAP.MPSMAX = 0. What happens when the host sets CC.EN?

    Answer

    The host configured an unsupported page size; the controller may fail to become ready or set CFS. The decoder flags it as an error before you try.

  6. The capability chain goes 40h → 50h → 40h. What does the decoder do, and what does it mean?

    Answer

    It stops and reports a loop. In a real dump this means corrupted config space, a broken emulation, or a misread dump; software that walks lists without a loop guard can hang.

  7. Why does lspci -xxx never show AER?

    Answer

    AER is an extended capability at 100h or above; -xxx shows only the first 256 bytes. Use -xxxx as root.
