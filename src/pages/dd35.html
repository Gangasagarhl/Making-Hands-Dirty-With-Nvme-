A Scatter Gather List (SGL) is a small program the controller executes: read a descriptor, move or skip some bytes, maybe jump to another segment. Like any program it can be malformed, slow or ambiguous. This module goes into the SGL engine: how it walks chains, what Bit Buckets really cost, why one controller is quick with SGLs and another is not, and how to prove whether host or controller broke a rule.

Kid story

A different treasure hunt. This time every note says exactly how far to go: "pick up 12 shells starting at the big rock". Some notes say "walk past 4 shells without picking any up". The last line of a note may say "the next note is in the red mailbox and has 3 lines", or "the next note is in the blue mailbox, has 2 lines, and is the final note".

You can describe a messy beach with very few notes, or a beach in one note if all the shells are in a single row. But you must read the notes in order to know where shell number 100 is, and if the mailbox is far away, every trip to fetch a note is a long walk. And if the final note itself says "go to another mailbox", the hunter stops: the instructions broke their own promise.

Analogy boundary

What it represents. Notes are SGL segments; "pick up 12 shells at the rock" is a Data Block (address and byte length); "walk past 4" is a Bit Bucket; the mailbox line is a Segment or Last Segment descriptor; the promise "this is the final note" is the Last Segment type; the walk to a mailbox is a PCIe Memory Read round trip.

What it hides. The hunter cannot see the total until the end; the controller compares the sum with the transfer length it computed from the command, and lengths, alignment and types are each checked against capabilities the controller advertises. The beach is I/O virtual address space behind an IOMMU, which can make a scattered beach look like one row.

Where it becomes misleading. A real hunter collects shells in note order; a controller can expand the whole list into a table and move bytes in any order. "Walk past" costs the hunter time; a Bit Bucket costs no link traffic at all — but the drive still reads those bytes from media.

Mechanism

A 16 KiB Read (CID 0x1100) on namespace 1 whose 16 KiB is gathered into four fragments with a 4 KiB hole discarded by a Bit Bucket. SGL1 is a Segment descriptor; the chain has two segments.

  1. Check capabilities. Who: driver at initialisation. What: SGLS bits 1:0 = 01b (byte granular), bit 16 = 1 (Bit Bucket supported). Where: Identify Controller. Evidence: nvme id-ctrl -H.
  2. Build segments. Who: driver. What: segment A at 0x1_5000_1000, 64 bytes: Data Block 0x2_0040_0000/4096, Bit Bucket 4096, Data Block 0x2_0041_0200/2048, Last Segment → 0x1_5000_2000 length 32. Segment B: Data Block 0x2_0042_0000/4096, Data Block 0x2_0043_0000/2048. Where: segment pool. Evidence: memory dump.
  3. Build the SQE. Who: driver. What: opcode 02h, PSDT = 01b, SGL1 = Segment (byte 15 = 0x20) → 0x1_5000_1000, length 0x40; NLB = 31. Where: SQ1 slot 0xB0 (0x1_2340_2C00). Evidence: SQE bytes.
  4. Doorbell and SQE fetch. Who: driver, then controller. What: tail 0xB1; 64-byte Memory Read (MRd). Evidence: two Transaction Layer Packets (TLPs).
  5. Fetch segment A. Who: SGL walker. What: MRd of exactly 64 bytes at 0x1_5000_1000. Evidence: MRd Len = 16 DW.
  6. Parse A. Who: walker. What: three data-carrying descriptors (sum 10,240 B), then a Last Segment descriptor in the final slot — legal. Evidence: next MRd target.
  7. Fetch segment B. Who: walker. What: MRd of 32 bytes at 0x1_5000_2000; marks "last". Evidence: dependent MRd.
  8. Validate. Who: walker. What: no chain descriptors in B; sum = 16,384 = 32 × 512. Evidence: absence of an error CQE.
  9. Read media and move data. Who: controller. What: reads all 32 LBAs from media; sends Memory Writes (MWr) for 12 KiB to four fragments; discards bytes 4096–8191. Evidence: 48 MWrs of 256 B, none for the hole.
  10. Complete. Who: controller then driver. What: CQE; driver frees both segments. Evidence: CQE MWr, interrupt.

The central concept on the ladder: an SGL is a program whose result is checked against the command

Notes tell you how far to walk and where the next note is; at the end you must have exactly as many shells as the order asked for.

The SGL is executed in order; the sum of Data Block and Bit Bucket lengths must match the transfer length; chain descriptors appear only at segment ends and never in the last segment.

The command's length (NLB and LBA format) and the SGL's length come from different code; the controller is the only place where both meet, and it reports mismatches with the SGL status family.

NVM Express Base Specification, Revision 2.4 — Scatter Gather List; SGL descriptor formats; Identify Controller SGLS; Generic Command Status values; NVMe over PCIe Transport Specification, Revision 1.4 for PCIe-specific data pointer rules.

Each segment fetch must equal the pointing descriptor's address and length; data TLPs must partition the Data Blocks; holes have no TLPs.

Decode SGL1 from byte 15 of DPTR, predict the first fetch, then walk descriptor by descriptor, comparing predicted and observed requests.

When the walk fails, decide whether the SGL broke a rule (host bug, controller should reject) or the controller mis-executed a valid SGL (controller bug) — the reference walker is the arbiter.

The specification does not say a controller must validate the whole SGL before moving data, does not limit segment sizes to pages, does not require segments to be aligned to more than the stated descriptor alignment (confirm the exact rule for segment addresses), and does not say SGLs perform better than PRPs. Check in the specification: the SGL status values (0Dh–11h in revisions the author has read), the exact SGLS bit positions beyond bits 1:0, 2 and 16, the restriction on metadata SGLs with PSDT 10b, and the treatment of zero-length Data Blocks.

Never mark SGL1 as Last Segment before you know chaining is unnecessary; never put a Bit Bucket in a write; never use byte-aligned fragments without SGLS 01b; never rely on "longer SGL" acceptance without the capability bit; never infer SGL support from the presence of a fabrics transport on the same system.

Hardware view

Internal, unobservableDescriptor cache size, validation order, expansion table, firmware versus hardware walk

A PRP engine computes addresses with shifts and masks. An SGL engine must sum variable lengths and handle byte-granular edges, so many designs walk SGLs in firmware or expand them into a page table before data moves. That costs latency per descriptor, not per byte: harmless for one large Data Block, noticeable for hundreds of small fragments. Whether a given controller does this is invisible except through measurement — which is why Linux uses a threshold rather than "SGL whenever supported".

Ordering, completion and errors

  • Causal order. Segment n + 1 can be fetched only after the chain descriptor at the end of segment n is read. Within a segment, a cached descriptor can be used in any order.
  • Data order. Not prescribed; a controller that expands the SGL may move fragments as media completes.
  • Error timing. A walker that streams (validates as it goes) can move data for early descriptors before discovering a later error; one that validates first moves nothing. Both end with an error CQE; the host must treat buffer contents as undefined.
  • Fabrics. The same descriptors appear in command capsules; data moves as RDMA operations or TCP data units, not TLPs (see Chapter 66 and Chapter 67).

Analysis. Legal and correct, but each 16-descriptor window costs a host round trip, so the command is bound by descriptor latency, not by the link. The advanced lab counts it: 4,096 bytes of descriptors in 8 MRds eagerly (one dependent round) versus 16 dependent rounds with a 256-byte window. Owner of the slowness: controller design (window too small for realistic round trips); report it with this evidence.

Analysis. The SGL broke its own promise: a Last Segment descriptor declares that the target contains no chain descriptors. The status is the symptom; the descriptor content in row 5 is the first abnormal event. The host's builder allocated segments from a 256-byte pool (16 descriptors) and chained correctly when a command needed more — but it chose SGL1's type with a "≤ 256 descriptors fits one page" test written for an older 4 KiB pool. The 32-fragment command fitted the old test and not the new pool. This controller validated the segment before moving data; a streaming walker might have pulled 60 KiB first and then failed — either way the command fails. Fix: choose each pointing descriptor's type only after the target segment's contents are known (Last Segment if and only if the target has no chain). sgl_walk.py in the Labs reproduces this case.

Analysis. Two readings are possible. (1) The controller advertises the SGLS capability "SGL longer than the data transfer" and the host deliberately reuses a 12 KiB SGL — legal, and the extra descriptor is simply unused. (2) The controller does not advertise it and does not check sums; the host has a length bug (as in Chapter 37's short-SGL trace, but in the other direction) that this controller masks and a stricter one will reject with Data SGL Length Invalid. Note the risk of reading (2): on a Write, a non-checking controller would quietly ignore host data, and the host would believe 12 KiB was written.

# sgl_walk.py - walk an NVMe SGL the way a careful PCIe controller would.
# Memory is a dict {address: bytes}. Status names follow the Base
# Specification's Generic Command Status table (confirm values there).
import struct

DATA, BITBUCKET, SEGMENT, LAST = 0x0, 0x1, 0x2, 0x3
NAMES = {0x0: "Data Block", 0x1: "Bit Bucket", 0x2: "Segment",
         0x3: "Last Segment"}

def desc(kind, addr=0, length=0, sub=0):
    """Encode one 16-byte descriptor (little-endian)."""
    return struct.pack("<QI3xB", addr, length, (kind << 4) | sub)

def parse(raw):
    addr, length, ident = struct.unpack("<QI3xB", raw)
    return ident >> 4, ident & 0xF, addr, length

def walk(sgl1, mem, xfer_len, is_read, sgls_mode=1, bit_bucket=True,
         max_desc=256):
    """Return (status, chunks, fetches). chunks: (addr or None, length)."""
    chunks, fetches = [], []
    kind, sub, addr, length = parse(sgl1)
    if kind in (DATA, BITBUCKET):          # whole SGL is in the SQE
        todo = [(kind, sub, addr, length)]
        last = True
    elif kind in (SEGMENT, LAST):
        todo, last = None, kind == LAST
        seg_addr, seg_len = addr, length
    else:
        return "SGL Descriptor Type Invalid", chunks, fetches
    while True:
        if todo is None:                    # fetch the next segment
            if seg_len == 0 or seg_len % 16:
                return "Invalid SGL Segment Descriptor", chunks, fetches
            if seg_len // 16 > max_desc:
                return "Invalid Number of SGL Descriptors", chunks, fetches
            raw = mem.get(seg_addr)
            fetches.append((seg_addr, seg_len))
            if raw is None or len(raw) < seg_len:
                return "Data Transfer Error (segment unreadable)", chunks, fetches
            todo = [parse(raw[i:i + 16]) for i in range(0, seg_len, 16)]
        nxt = None
        for i, (k, s, a, n) in enumerate(todo):
            if k in (SEGMENT, LAST):
                if last or i != len(todo) - 1:
                    return "Invalid SGL Segment Descriptor", chunks, fetches
                nxt = (k, a, n)
            elif k == DATA:
                if s != 0:
                    return "SGL Descriptor Type Invalid", chunks, fetches
                if sgls_mode == 2 and (a % 4 or n % 4):
                    return "rejected: dword rule (status: confirm)", chunks, fetches
                chunks.append((a, n))
            elif k == BITBUCKET:
                if not bit_bucket or not is_read:
                    return "SGL Descriptor Type Invalid", chunks, fetches
                chunks.append((None, n))
            else:
                return "SGL Descriptor Type Invalid", chunks, fetches
        if nxt is None:
            break
        last = nxt[0] == LAST
        seg_addr, seg_len, todo = nxt[1], nxt[2], None
    total = sum(n for _, n in chunks)
    if total != xfer_len:
        return "Data SGL Length Invalid (%d != %d)" % (total, xfer_len), chunks, fetches
    return "Success", chunks, fetches

def show(title, sgl1, mem, xfer_len, is_read=True, **kw):
    status, chunks, fetches = walk(sgl1, mem, xfer_len, is_read, **kw)
    print("--- " + title)
    for a, n in fetches:
        print("    fetch segment 0x%X, %d bytes" % (a, n))
    off = 0
    for a, n in chunks:
        where = "discard" if a is None else "0x%X" % a
        print("    cmd bytes %5d..%5d -> %s" % (off, off + n - 1, where))
        off += n
    print("    status: " + status)

# Trace M35-N: Read of 16 KiB, two chained segments with a Bit Bucket

Advanced lab — PRP versus SGL descriptor traffic

Safe lab Python 3, standard library.

Objective
Count descriptor bytes, fetch requests, dependent rounds and data requests for four buffer shapes.
Prerequisites
Deep dive: PRP advanced lab.
Setup
Save as sgl_cost.py.
# sgl_cost.py - descriptor traffic for PRPs versus SGLs, per buffer shape.
# Lab system: 4 KiB controller pages, MRRS 512 B. Fragments are IOVA ranges.
PS, MRRS = 4096, 512

def prp_possible(frags):
    """PRPs need every fragment boundary inside the buffer to be a page edge."""
    for i, (a, n) in enumerate(frags):
        if i > 0 and a % PS:
            return False
        if i < len(frags) - 1 and (a + n) % PS:
            return False
    return True

def reads(addr, length):
    """Memory Read requests to fetch [addr, addr+length): MRRS and 4 KiB cuts."""
    count, end = 0, addr + length
    while addr < end:
        step = min(MRRS - addr % MRRS if addr % MRRS else MRRS,
                   PS - addr % PS, end - addr)
        addr += step
        count += 1
    return count

def prp_cost(frags):
    pages = sum(-(-((a % PS) + n) // PS) for a, n in frags)
    entries = max(pages - 1, 0) if pages > 2 else 0
    list_bytes = 8 * entries
    # list at a page-aligned pool address: one segment per 511 entries
    rounds = -(-entries // 511) if entries else 0
    return pages, list_bytes, reads(0, list_bytes) if list_bytes else 0, rounds

def sgl_cost(frags, window=None):
    d = len(frags)
    if d == 1:
        return d, 0, 0, 0            # one Data Block, inside the SQE
    seg_bytes = 16 * d                # chained: 255 data + 1 chain per 4 KiB
    segs = -(-d // 255) if d > 256 else 1
    seg_bytes += 16 * (segs - 1)
    fetch_reqs = reads(0, seg_bytes)
    rounds = segs if window is None else -(-seg_bytes // window)
    return d, seg_bytes, fetch_reqs, rounds

def data_cost(frags):
    edges = sum((a % 4 != 0) + ((a + n) % 4 != 0) for a, n in frags)
    return sum(reads(a, n) for a, n in frags), edges

SHAPES = {
    "128 KiB, one IOVA range": [(0x200800000, 131072)],
    "128 KiB, 32 scattered pages": [(0x200800000 + i * 0x10000, 4096)
                                    for i in range(32)],
    "128 KiB, 256 x 512 B pieces": [(0x200800000 + i * 0x1000, 512)
                                    for i in range(256)],
    "8 KiB, 3 byte-aligned pieces": [(0x200900003, 1021), (0x200910000, 3000),
                                     (0x200920101, 4171)],
}

print("%-30s %-28s %-36s %s" % ("shape", "PRP: pages/list B/reqs/dep",
                                "SGL: descs/seg B/reqs/dep (lazy 256)",
                                "data MRds, odd edges"))
for name, frags in SHAPES.items():
    if prp_possible(frags):
        p = "%d / %d / %d / %d" % prp_cost(frags)
    else:
        p = "not describable"
    d, sb, fr, rd = sgl_cost(frags)
    lazy = sgl_cost(frags, window=256)[3]
    s = "%d / %d / %d / %d (%d)" % (d, sb, fr, rd, lazy)
    mrd, odd = data_cost(frags)
    print("%-30s %-28s %-36s %d, %d" % (name, p, s, mrd, odd))
Procedure
(1) Run it. (2) Change the 256 × 512 B shape to 600 × 512 B (beyond one MDTS on the lab system, but useful for chaining) and read the chain count. (3) Add a shape of 32 pages where the IOMMU merged pairs (16 × 8 KiB).
Observations
Where do SGLs win, lose, or offer the only option?
Questions
(a) Why does the one-range shape still need a 248-byte PRP list? (b) Why does the scattered-pages shape cost more descriptor bytes as an SGL? (c) What do "odd edges" mean on the link?
Expected reasoning
PRPs scale with pages; SGLs scale with fragments.
Solution

Output: one range — PRP 32 pages, 248 B list, one fetch; SGL one Data Block in the SQE, no fetch. Scattered pages — PRP 248 B; SGL 32 descriptors, 512 B (two rounds with a 256 B window). 256 × 512 B — PRP impossible; SGL 4,096 B in 8 MRds, one round eagerly or 16 with a 256 B window (Trace M35-S). Three byte-aligned pieces — PRP impossible; SGL 48 B; 17 data MRds and 2 unaligned edges. (a) PRPs cannot express contiguity beyond a page. (b) 16 bytes per fragment versus 8 per page. (c) Requests whose first or last dword uses partial byte enables. For (2) the model chains every 255 data descriptors: 3 segments, 3 dependent rounds. For (3) 16 descriptors, 256 B, one window.

Senior forensic lab — latency regression after an IOMMU change

Safe lab Evidence analysis.

Objective
Attribute a performance regression across host policy, IOMMU and controller.
Prerequisites
This module.
Setup (evidence pack, synthetic)
  • A fleet switched its servers from IOMMU passthrough to translated mode for security. On SSD model Q only, 128 KiB direct-I/O read latency rose from 180 µs to 260 µs at queue depth 1; 4 KiB reads did not change. Another SSD model improved slightly.
  • Model Q reports SGLS 01b. sgl_threshold is 32768.
  • Captures: before the change, 128 KiB reads had PSDT 00b with a 248-byte PRP list. After, PSDT 01b with SGL1 = a single Data Block of 131,072 B. After the SQE fetch, the controller takes 78 µs longer before the first data MWr; the media read time reported by vendor telemetry is unchanged.
  • Setting sgl_threshold=0 on a test machine restores 180 µs.
Procedure
Explain the chain of causes, the first abnormal event, owner, fix and test.
Observations
What changed in the requests, and what did not change in the media?
Questions
(1) Why did enabling translation make the driver choose SGLs? (2) Why are 4 KiB reads unaffected? (3) Who should fix what?
Expected reasoning
Host policy changed the descriptor type; the controller's SGL path is the slow element.
Solution

(1) In translated mode, the DMA mapping merged 32 scattered pages into one contiguous IOVA range, so the request had one segment of 128 KiB; average segment size crossed the threshold and the driver chose SGLs. (2) A 4 KiB request is a single segment of 4 KiB, below the threshold: still PRPs. First abnormal event: the 78 µs gap between SQE fetch and first data on SGL commands with unchanged media time — the controller's SGL path is slow even for one descriptor (for example a firmware walk or expansion into page entries). Owner: controller vendor (performance defect, not a protocol violation); immediate host workaround: per-controller policy (sgl_threshold=0 or a quirk entry) for model Q. Test: latency matrix PSDT 00b versus 01b per size, under both IOMMU modes, added to qualification. Confidence: high for attribution; the internal cause in the controller is an inference.

Extension. The security team asks to keep translated mode. Write the fleet change: which knob, scoped how, with what monitoring.

Debugging

Six patterns, complementing Cases 7–8 of Chapter 38 and the short-SGL trace in Chapter 37.

Invalid SGL Segment Descriptor only on large I/O

Symptom
Writes above a certain fragment count fail; smaller ones succeed (Trace M35-F).
Possible causes
SGL1 typed as Last Segment while the target chains; chain descriptor not in the last slot; segment length not a multiple of 16.
Evidence
SGL1 byte 15; segment contents; position of chain descriptors.
First check
Does any segment reached through a Last Segment descriptor contain a chain descriptor?
Second check
Are chain descriptors only in final slots?
Disambiguating experiment
Sweep fragment counts across segment-pool sizes (15, 16, 17, 255, 256, 257).
Likely conclusion
Builder type selection.
Confidence
High.

Data SGL Length Invalid after enabling protection information

Symptom
After formatting with 8 bytes of metadata per block in extended-LBA format, every SGL I/O fails with Data SGL Length Invalid; PRP I/O seems fine.
Possible causes
Interleaved metadata adds to the transfer length; the builder sums only data bytes. PRP I/O "works" because PRPs have no length to compare — the controller may be writing past the buffer.
Evidence
Format (LBA size, metadata size, extended or separate), SGL sum, expected (NLB + 1) × (data + metadata).
First check
Compute the expected length including metadata.
Second check
For PRP I/O, does data extend beyond the buffer (IOMMU faults, guard pages)?
Disambiguating experiment
Repeat with separate metadata buffers (MPTR); SGL errors should vanish.
Likely conclusion
Host length computation ignores interleaved metadata; the PRP path hides a real overrun.
Confidence
High.

Invalid Number of SGL Descriptors with vectored I/O

Symptom
An application using many small buffers fails with Invalid Number of SGL Descriptors (0Eh, confirm) on one controller.
Possible causes
Controller limit on descriptors per segment or per command (implementation-dependent); empty segment.
Evidence
Descriptor counts per segment; vendor documentation; any Identify limit (confirm which fields apply on PCIe).
First check
Largest segment size in failing commands.
Second check
Any zero-length segment?
Disambiguating experiment
Split segments into smaller chained segments with the same total; if success, it is a per-segment limit.
Likely conclusion
Controller limit; host should cap segment size or merge fragments.
Confidence
Medium.

SGL Descriptor Type Invalid from a read-ahead feature

Symptom
A new driver feature that skips unwanted blocks with Bit Buckets fails on some drives and on writes generally.
Possible causes
SGLS bit 16 clear; Bit Bucket used in a Write; a type from a fabrics transport used on PCIe.
Evidence
SGLS; command direction; descriptor types used.
First check
SGLS bit 16.
Second check
Direction of failing commands.
Disambiguating experiment
Replace the Bit Bucket by a Data Block into a scratch buffer.
Likely conclusion
Unadvertised or misused descriptor type.
Confidence
High.

Corruption at the edges of byte-aligned fragments

Symptom
On a controller reporting SGLS 01b, reads into odd-aligned network buffers occasionally have wrong bytes at fragment edges; the middle is correct.
Possible causes
Controller partial-byte-enable bug on MWr edges; host fragment length off by one; root-complex handling of partial writes (rare).
Evidence
Captured MWr byte enables and lengths at edges; descriptor addresses and lengths; which bytes differ.
First check
Do the MWrs' First/Last DW Byte Enables match the fragment edges exactly?
Second check
Do fragment lengths in the SGL sum correctly and match the application's buffers?
Disambiguating experiment
Sweep start offsets 0–7 and lengths n, n ± 1..3 with a pattern oracle; capture any failing offset.
Likely conclusion
The capture assigns it: wrong byte enables → controller; correct TLPs but wrong lengths → host.
Confidence
High once captured.

Metadata SGL Length Invalid with PSDT 10b

Symptom
A driver moving to separate metadata buffers described by SGL gets Metadata SGL Length Invalid (10h, confirm).
Possible causes
Metadata length computed with the wrong per-block size; MPTR points to a segment with several descriptors where one is expected; PSDT 01b used with an MPTR that is an SGL.
Evidence
PSDT, MPTR target contents, format's metadata size.
First check
Metadata descriptor length versus (NLB + 1) × metadata size.
Second check
PSDT value and the number of descriptors at MPTR.
Disambiguating experiment
Use PSDT 01b with a contiguous metadata buffer.
Likely conclusion
Metadata length or structure error.
Confidence
Medium to high.

Interview

Beginner

  1. Which byte identifies an SGL descriptor's type?

    Model answer

    Byte 15, bits 7:4 (type) and 3:0 (sub type).

  2. Where is the first descriptor?

    Model answer

    In the SQE's DPTR (SGL1), with PSDT 01b or 10b.

  3. What does a Bit Bucket do?

    Model answer

    Counts toward the transfer length but discards those read bytes; no data TLPs.

  4. Can admin commands on PCIe use SGLs?

    Model answer

    No; they use PRPs.

  5. How does a host know SGLs are supported?

    Model answer

    SGLS bits 1:0 in Identify Controller: 00b none, 01b byte, 10b dword granular.

Intermediate

  1. Why have both Segment and Last Segment types?

    Model answer

    The controller knows when to stop chaining, can size the fetch, and can detect chains in the last segment as errors.

  2. Must segments be page aligned?

    Model answer

    No page requirement; length is a multiple of 16; check the specification's exact alignment rule for segment addresses.

  3. What does SGL1 = Data Block mean?

    Model answer

    The whole transfer is one contiguous range; no segment fetch.

  4. Why can a buffer with a 4 KiB hole be read with an SGL but not with PRPs?

    Model answer

    A Bit Bucket covers the hole, and Data Blocks may start at any (allowed) offset.

  5. Does a Bit Bucket save media reads?

    Model answer

    No; it saves link and host-memory bandwidth.

Advanced

  1. How can a correct SGL be slow?

    Model answer

    Many small fragments with a small descriptor window cause dependent round trips; firmware walks add per-descriptor cost.

  2. Why does SGL validation order matter?

    Model answer

    Streaming walkers may move data before detecting a later error; buffer contents become undefined.

  3. How do you predict segment fetches from a trace?

    Model answer

    Each fetch equals the pointing descriptor's address and length (split by strategy).

  4. What does an SGL longer than the transfer imply?

    Model answer

    Legal only with the SGLS capability; otherwise a host bug, possibly masked by a non-checking controller.

  5. How does the IOMMU affect SGL use?

    Model answer

    Merging pages into contiguous IOVAs turns many fragments into one Data Block and can change the driver's PRP/SGL choice.

Senior

  1. Design an SGL validation matrix.

    Model answer

    Every descriptor type and sub type; chain positions; Last Segment promises; segment lengths 0, 16, non-multiples; descriptor counts at pool and controller limits; sums equal, short and long (with and without the capability); Bit Buckets in reads and writes; byte offsets 0–7 under 01b and 10b; metadata SGLs; validation timing; latency per fragment count.

  2. How should a driver choose PRPs or SGLs?

    Model answer

    By measured per-controller cost, capability and buffer shape; default threshold plus quirks for slow SGL paths.

  3. Who owns a slow but legal SGL path?

    Model answer

    The vendor as a performance defect; the host mitigates with policy until fixed.

  4. What should a strict controller check, and in what order?

    Model answer

    PSDT and support, SGL1 type, each segment's length and fetch result, descriptor positions and types, alignment mode, Bit Bucket direction, total length — before data moves if latency allows.

  5. Why is fabrics experience relevant to PCIe SGL debugging?

    Model answer

    Fabrics carry SGLs in every command; the descriptor reading skill and the length rules are the same.

Quiz

  1. Byte 15 of SGL1 is 0x20. SGL1 is a

    • Data Block
    • Bit Bucket
    • Segment
    • Last Segment
    Answer and reasoning

    Type 2h.

  2. A segment reached through a Last Segment descriptor may contain

    • A Segment descriptor in its last slot
    • Data Blocks and Bit Buckets only
    • A Last Segment descriptor in its last slot
    • Any descriptor type
    Answer and reasoning

    The last segment contains no chain descriptors.

  3. A 16 KiB Read with a 4 KiB Bit Bucket produces how many 256 B data MWrs?

    • 64
    • 16
    • 48
    • 32
    Answer and reasoning

    12 KiB of host data ÷ 256 B.

  4. A segment descriptor has length 40. The controller should

    • Fetch 48 bytes
    • Fetch 32 bytes
    • Ignore the last 8
    • Reject the SGL
    Answer and reasoning

    Segment lengths are multiples of 16; an invalid segment descriptor.

  5. Which buffer gains most from an SGL over PRPs?

    • 128 KiB in one contiguous IOVA range
    • 32 scattered page-aligned 4 KiB pages
    • One 4 KiB page
    • An admin Identify buffer
    Answer and reasoning

    One Data Block in the SQE replaces a 31-entry list.

  6. SGLS bits 1:0 = 10b. Which Data Block is acceptable?

    • 0x2_0000_0002 / 512
    • 0x2_0000_0004 / 508
    • 0x2_0000_0004 / 511
    • 0x2_0000_0001 / 4
    Answer and reasoning

    Address and length must be dword multiples.

  7. Why is the first abnormal event in Trace M35-F row 5 rather than the CQE?

    Model answer

    The segment contents already violate the Last Segment promise; the CQE is the consequence.

  8. Name two explanations for Trace M35-A and the evidence that separates them.

    Model answer

    Permitted longer SGL (SGLS capability set, intentional host design) versus host length bug masked by a non-checking controller (capability clear).

  9. Why did 4 KiB reads not change in the senior lab?

    Model answer

    Their average segment size stayed below the threshold, so they kept using PRPs.

Teach-back

  1. To a child: how notes with "walk past" and "final note" help the treasure hunter.

    Model explanation

    Notes say how many shells to pick up or skip, and where the next note is. "Final note" tells her she can stop looking for more mailboxes. If the final note points to another mailbox, the instructions are broken and she refuses.

  2. To a junior engineer: how to check an SGL from a capture.

    Model explanation

    Check PSDT and SGLS; decode SGL1 from byte 15; predict each segment fetch from its pointing descriptor; parse descriptors in order, checking chain positions and the last-segment rule; sum Data Blocks and Bit Buckets against (NLB + 1) × block size including interleaved metadata; partition Data Blocks into expected TLPs, with no TLPs for holes. The first divergence is the first abnormal event.

  3. To a senior engineer: how to decide between PRPs and SGLs for a product.

    Model explanation

    SGLs describe fragments, PRPs describe pages: SGLs win for contiguous IOVA ranges and byte-granular or holey buffers, PRPs for scattered pages on controllers with fast PRP paths. Measure per controller (latency per fragment count, per PSDT, under both IOMMU modes), use a threshold with per-device overrides, keep one length source for both builders, and validate with a strict reference walker so that host bugs are not masked by lenient controllers.
