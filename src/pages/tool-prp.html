Give it a buffer address, a length and a memory page size; the visualizer builds the Physical Region Page (PRP) entries an NVM Express (NVMe) driver would put in the command, draws the pages and any PRP list pages with their chain pointers, and predicts how many PCIe Transaction Layer Packets (TLPs) the controller will send to move the data.

What the visualizer does

The Submission Queue Entry has sixteen bytes for the data pointer: PRP Entry 1 (PRP1) and PRP Entry 2 (PRP2). Chapter 36 — Physical Region Pages teaches how any buffer is squeezed into those two entries. This tool does the same arithmetic for any input and shows the result three ways:

  • The numbers: page count, PRP1, PRP2 and what PRP2 means (unused, second data page, or list pointer).
  • A diagram: the SQE's two entries on the left, list pages in the middle (with chain pointers in orange), data pages on the right with a green bar showing which bytes of each page the transfer actually uses.
  • A TLP budget: SQE fetch, list fetches, data TLPs and completions, for the Max Payload Size (MPS), Max Read Request Size (MRRS) and Read Completion Boundary (RCB) you choose.

You need Chapter 36 for the rules and Chapter 10 for MWr, MRd and CplD. The lab system's defaults are used throughout: 4 KiB memory pages (CC.MPS = 0), MPS 256 bytes, MRRS 512 bytes, RCB 64 bytes, data at 0x2_0000_0000, PRP list pages at 0x1_5000_0000.

The visualizer

Addresses accept hexadecimal with 0x and optional underscores. Lengths accept bytes (8192), hexadecimal (0x2000) or K/M suffixes (128K, 4M, meaning KiB and MiB).

Assumptions, stated plainly

Master-prompt section 38 asks for the assumptions to be explicit. Here they are.

  • One transfer, one PRP set. The length is the command's data length (for Read/Write: (NLB + 1) × LBA size). Metadata in a separate buffer (MPTR) is ignored.
  • The page count formula N = ⌈(offset + length) / page size⌉ decides everything, as in Chapter 36. Derived
  • List layout. The list starts at the address you give. Slots that fit before the end of that page are S = (page size − list offset) / 8. If more entries remain than slots, the last slot is a chain pointer to the next list page. The tool places chained list pages at the next page up (or three pages up in "scattered" mode); a real driver allocates them anywhere. Implementation-dependent
  • Scattered mode invents distinct, page-aligned addresses in the 0x2_xxxx_x000 range so you can see that data pages need not be adjacent. They are not from any real allocator.
  • TLP cutting. The controller cuts data requests at naturally aligned MPS (writes to host) or MRRS (reads from host) boundaries, which never crosses a 4 KB boundary. Real DMA engines may cut differently but may never exceed the limits. Implementation-dependent
  • Completions are counted as a range: from MPS-sized pieces (fewest) to RCB-sized pieces (most). Which one you get is a property of the root complex. Implementation-dependent
  • List fetch. The controller reads exactly the list entries it needs, once. Some controllers prefetch whole list pages or re-read entries. Implementation-dependent
  • Addresses are I/O virtual addresses (IOVAs) as the device sees them through the IOMMU, not CPU physical addresses.

How to read the result

The verdict line

It states N and the meaning of PRP2. Learn to predict it before you press the button: offset + length, divided by the page size, rounded up. If the answer is 1, PRP2 is unused; 2, PRP2 is the second data page; 3 or more, PRP2 is a list pointer.

The diagram

Solid arrows come from the SQE, dashed arrows from list entries. Each data page box shows its page address and how many bytes of the transfer fall into it; the green bar's position shows where. Only page D0 can start part-way in; only the last page can end part-way. Orange curves are chain pointers. Long lists are abbreviated with ⋮; open "All PRP list entries" for the full list.

The TLP budget

The table adds the per-command overhead (SQE fetch, CQE, MSI-X) to the data TLPs and the list fetches. Compare the list-fetch line with and without a list to see why the first page boundary is "free" and the second costs an extra dependent round trip: the controller cannot send data for page D2 until the list read has completed.

The offset that changes everything

Compare rows 1 and 2: the same 4 KiB, but moving the buffer 2 KiB into a page makes it straddle a boundary, so PRP2 becomes mandatory. Rows 2 and 3 show the classic bug of Chapter 38: a driver that computes pages as length / page size gets 2 for an 8 KiB buffer and builds PRP2 as a data page, while the controller (correctly) counts 3 pages and reads PRP2 as a list. Load the "8 KiB at offset 0x800" preset, then decode the matching abnormal SQE in the NVMe Command Decoder.

Chaining

The 4 MiB preset needs 1,023 list entries. A page-aligned 4 KiB list page has 512 slots, so the first page holds 511 data entries plus a chain pointer in slot 511, and the second page holds the remaining 512. Now set the PRP list address to 0x1_5000_0F00: only 32 slots fit before the page ends, so the first "page" of the list is 31 entries plus a chain, and the list spans three pages. A real controller would refuse most of these transfers because of MDTS (set MDTS to 5 to see the warning); chained lists show up mainly with large MDTS values or large memory page sizes.

Bigger pages

Switch the page size to 64 KiB with the 128 KiB preset: N drops to 2 and PRP2 becomes a plain data page. The TLP count does not change at all, because TLPs are cut by MPS and the 4 KB rule, not by the NVMe page size. Larger pages shrink the descriptor work, not the link work.

Limitations

  • PRPs only. Scatter Gather Lists are taught in Chapter 37; the tool does not build SGLs.
  • The TLP counts ignore link-level traffic (DLLPs, flow control, retries) and the data on the wire per TLP; use the bandwidth calculator for throughput.
  • Non-contiguous I/O queue creation (Physically Contiguous = 0) also uses PRP lists; the tool's arithmetic applies, but it labels everything as data.
  • Data for an NVMe Read can also be written to a Controller Memory Buffer or a peer device; the tool assumes host memory.

Practice

  1. A 12 KiB transfer starts at offset 0xC00 in a 4 KiB page. How many pages, and what is PRP2?

    Answer

    ⌈(3072 + 12288)/4096⌉ = ⌈3.75⌉ = 4 pages; PRP2 is a list pointer with 3 entries.

  2. With 4 KiB pages and a page-aligned list, what is the largest transfer from an aligned buffer that needs no chain pointer?

    Answer

    PRP1 covers one page and a single list page holds 512 entries: 513 pages = 2,052 KiB (2 MiB + 4 KiB).

  3. Moving from 4 KiB to 64 KiB memory pages, does a 1 MiB NVMe Read generate fewer MWr TLPs?

    • Yes, 16 times fewer
    • No, the same number
    • Yes, about half
    Answer and reasoning

    Data TLPs are limited by MPS (and the 4 KB rule), not by the NVMe page size. Only the list shrinks.

  4. Why can a list pointer have an offset when list entries cannot?

    Answer

    Entries describe data pages, which must be whole except the first; the list itself is just an array that may start anywhere 8-byte aligned. Linux uses this to allocate short lists from a small pool.

  5. An NVMe Write of 64 KiB, MRRS 512, MPS 256, RCB 64. What range of CplD counts should you expect for the data?

    Answer

    128 MRd; 256 CplD with 256-byte completions up to 1,024 with 64-byte completions.

  6. PRP2 = 0x2_0004_1000 for an 8 KiB transfer at 0x2_0004_0800. What will the controller do?

    Answer

    Treat PRP2 as a list (three pages), read 16 bytes of the data page as two list entries, and send data to whatever addresses those bytes contain — the Chapter 38 bug.
