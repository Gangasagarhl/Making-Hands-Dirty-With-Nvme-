Paste a 64-byte NVM Express (NVMe) Submission Queue Entry (SQE) and this tool names the command, interprets every field, works out what the data pointer means, and predicts the PCIe traffic the command will cause. A second decoder reads the 16-byte Completion Queue Entry (CQE) that comes back.

What this tool does

An NVMe command is a fixed 64-byte record that the host driver writes into a Submission Queue in host memory. The controller fetches it with a PCIe Memory Read (MRd) and gets it back in a Completion with Data (CplD). Whether you see those 64 bytes in a protocol analyzer, in a kernel trace event, in an nvme-cli passthrough dump or in your own driver's debug log, the decoding is the same. Chapter 29 — NVMe Command Structure teaches the layout; this page lets you apply it to any command.

Following master-prompt section 37, the SQE decoder:

  1. identifies the command set — you choose whether the entry came from the Admin Submission Queue or an I/O Submission Queue, because the same opcode means different commands in each (02h is Get Log Page on the admin queue and Read on an I/O queue);
  2. builds a field table for Command Dword 0 (CDW0: opcode, FUSE, PSDT, Command Identifier), the Namespace Identifier (NSID), the Metadata Pointer (MPTR), the data pointer (PRP1/PRP2 or an SGL descriptor) and Command Dwords 10–15 interpreted for Identify, Create/Delete I/O SQ/CQ, Get Log Page, Set/Get Features, Abort, Read, Write, Compare, Flush and Dataset Management;
  3. analyses the data pointer — transfer length, pages touched, and whether PRP2 must be unused, a second data page or a PRP list pointer — and flags inconsistent combinations;
  4. predicts protocol events on the course's lab system: doorbell write, SQE fetch, list fetch, data TLPs, CQE write, MSI-X interrupt and CQ head doorbell.

Know the queue model from Chapter 25–Chapter 28 and the command layout from Chapter 29. Admin commands are covered in Chapter 30, I/O commands in Chapter 31–Chapter 35, PRPs in Chapter 36.

SQE decoder

Paste 16 DWORDs as a driver would print them (00110002 00000001 …), or 64 bytes in memory order (02 00 11 00 01 00 00 00 …). Byte input is read little-endian: the first byte is the low byte of CDW0, which is the opcode. Hexdump offsets such as 0010: are ignored.

CQE decoder

Paste the four DWORDs of a completion entry (DW0 first) or 16 bytes in memory order.

Zero-based counts

Many NVMe count fields are 0-based: Number of Logical Blocks (NLB), queue size (QSIZE), Number of Dwords (NUMD) in Get Log Page, Number of Ranges (NR) in Dataset Management, the Number of Queues feature. The tool always shows both the raw value and the real count ("NLB 0x0007 → 8 blocks"). Forgetting the +1 is the single most common cause of off-by-one-page PRP bugs.

The data-pointer analysis

For commands with a data buffer the tool computes the transfer length (NLB+1 blocks × LBA size for Read/Write/Compare, 4096 bytes for Identify, (NUMD+1) × 4 for Get Log Page, (NR+1) × 16 for Dataset Management), then the number of memory pages the buffer touches from PRP1's offset. That page count — not the transfer size — decides PRP2's meaning, exactly as in Chapter 36. If PRP2 does not fit that meaning, you get an error or a warning.

Expected protocol events

The event list uses the lab system: BAR0 at 0xFE60_0000, doorbell stride 4 bytes, Admin SQ at 0x1_0000_0000, SQ1 at 0x1_2340_0000, CQ1 at 0x1_2341_0000, Max Payload Size 256 bytes, Max Read Request Size 512 bytes. Set the SQ slot to get the exact SQE address and doorbell value. The list is the trace you should expect; compare it with a real capture event by event, and the first mismatch is where to look.

Read a CQE in this order: Phase Tag (is this entry new?), SQID + CID (which command?), SCT + SC (did it work?), DNR/More/CRD (what should the host do next?), SQHD (which SQ slots can be reused?), then DW0 for command-specific results such as the queue counts granted by Set Features Number of Queues.

Status Code Types: 0 Generic Command Status, 1 Command Specific Status, 2 Media and Data Integrity Errors, 3 Path Related Status, 7 Vendor Specific. Generic codes 00h–7Fh apply to every command; 80h–BFh are I/O command set specific (for the NVM Command Set: LBA Out of Range 80h, Capacity Exceeded 81h, Namespace Not Ready 82h, Reservation Conflict 83h, Format In Progress 84h). The tool's tables were cross-checked against the open-source libnvme headers; confirm any code you rely on in the NVM Express Base Specification 2.4 — Status Field definition and the I/O command set specifications.

Worked examples

1. A 4 KiB Read

Load "NVM Read 4 KiB". CDW0 = 0x00110002: opcode 02h (Read on an I/O queue), FUSE 00b, PSDT 00b (PRPs), CID 0x0011. NSID = 1. PRP1 = 0x2_0000_0000 (offset 0). SLBA = 0x100000, NLB = 7, so 8 × 512 = 4096 bytes. One page is touched, so PRP2 is unused. Predicted traffic: one doorbell MWr32, one 64-byte SQE fetch, sixteen 256-byte MWr data TLPs (controller to host, because a Read writes host memory), one CQE MWr, one MSI-X MWr, one CQ head doorbell. Switch "Queue the entry came from" to Admin and watch the same bytes become Get Log Page — that is why the queue context matters.

2. Building a queue pair

Load "Create I/O CQ 1" and then "Create I/O SQ 1". The CQ command: CDW10 = 0x03FF0001 → QID 1, QSIZE 0x3FF → 1024 entries × 16 bytes = 16 KiB; CDW11 = 0x00010003 → PC 1 (contiguous), IEN 1, IV 1. PRP1 = 0x1_2341_0000 is the queue base. The SQ command: CDW10 the same, CDW11 = 0x00010001 → PC 1, QPRIO Urgent (ignored under round robin), CQID 1. The order matters: the CQ must exist before an SQ that points at it; deletion runs the other way.

  1. Create I/O CQ (QID 1, IV 1)
  2. CQE: success
  3. Create I/O SQ (QID 1, CQID 1)
  4. CQE: success
  5. SQ1/CQ1 ready for I/O

3. A 128 KiB Write with a PRP list

"NVM Write 128 KiB": NLB 0xFF → 256 × 512 = 131,072 bytes, 32 pages. PRP2 = 0x1_5000_0000 is therefore a list pointer to 31 entries (248 bytes). Predicted events now include an extra MRd for the list before any data moves, and the data moves as MRd requests from the controller (a Write reads host memory) answered by CplDs. Pair this with the PRP Visualizer to see the list laid out.

4. The abnormal PRP

"Abnormal: Read 8 KiB at offset 0x800": PRP1 = 0x2_0004_0800, NLB 0x0F → 8,192 bytes. With a 2 KiB offset the buffer touches three pages (2 KiB + 4 KiB + 2 KiB), so PRP2 must be a list pointer. But PRP2 = 0x2_0004_1000 — exactly PRP1's page plus one page. The tool warns that the host built PRP2 as a second data page. The controller will read the first 16 bytes of that data page as if they were list entries. This is the case dissected in Chapter 36 and Chapter 38.

Paste the CQE into the CQE decoder: SCT 2 (Media and Data Integrity Errors), SC 80h (Write Fault), DNR = 0. Every PCIe transaction before it was normal: the data reached the controller, and the failure happened behind it, in the media. The long gap before the CQE is the controller's internal retry. The PCIe trace cannot show you the cause; the SMART / Health log and the Error Information log can.

How long a controller retries a failing program operation, and whether it relocates the data and reports success instead of Write Fault, is implementation-dependent. The trace shows one plausible behaviour, not a required one.

Limitations and truth labels

  • Opcode, CNS, Log Identifier, Feature Identifier and status-code names come from tables in the tool that cover the common, long-established values. They were cross-checked against libnvme's headers, not against the specification text. Values outside the tables are shown as "not in this tool's table", never guessed. Derived
  • Command Dwords for commands outside the decoded list (Format NVM, Sanitize, Firmware commands, Namespace Management, Directives, Zoned Namespace, Key Value, Copy …) are shown raw.
  • Read/Write CDW12–15 bit fields are decoded for the long-standing fields (NLB, LR, FUA, PRINFO, DTYPE, DSM, application tag). Newer protection-information formats and storage tags reuse CDW2, CDW3 and CDW14 in ways the tool does not decode. Version-dependent
  • Command-specific status codes depend on the command; the tool names the most common meaning and says which command it belongs to.
  • Predicted events are an idealised trace for the lab system. Real controllers prefetch SQEs in batches, coalesce interrupts and split transfers differently. Implementation-dependent
  • NVMe over Fabrics capsules, SGLs with multiple segments and the Controller Memory Buffer are out of scope.

Practice

  1. CDW0 = 0x002A0006 on the Admin queue. What is the command and its CID?

    Answer

    Opcode 06h = Identify; CID = 0x002A. FUSE and PSDT are 0.

  2. A Read has NLB = 0x001F with 512-byte LBAs and PRP1 = 0x2_0000_0200. What does PRP2 hold?

    • Nothing, it is unused
    • The second data page
    • A PRP list pointer
    Answer and reasoning

    32 × 512 = 16 KiB starting 512 bytes into a page: ⌈(512 + 16384)/4096⌉ = 5 pages, so PRP2 points to a 4-entry list. Check it in the tool by editing the "Read 4 KiB" preset.

  3. What QSIZE value creates a 64-entry queue?

    Answer

    63 (0x3F), because QSIZE is 0-based.

  4. A CQE has DW3 = 0x00010007. Is it a success?

    Answer

    Yes: status bits 31:17 are zero, Phase Tag 1, CID 0x0007.

  5. Set Features Number of Queues was sent with CDW11 = 0x003F003F; the CQE DW0 is 0x001F001F. What happened?

    Answer

    The host asked for 64 SQs and 64 CQs (0-based); the controller granted 32 of each. The host must not create more than it was granted.

  6. Why does the SQE decoder need to know which queue the entry came from, while the CQE decoder does not need the opcode?

    Answer

    The SQE's opcode is only unique within a command set. The CQE layout is the same for every command; only command-specific status codes and DW0 need the command, and the host knows it from the CID.

  7. A CQE shows SCT 0, SC 13h. Where do you look next?

    Answer

    PRP Offset Invalid: decode the SQE's PRP1/PRP2 and the PRP list. A data entry after PRP1 had a non-zero offset, or PRP1 was not dword aligned.

  8. Two outstanding commands on SQ1 have CID 0x0010. What can go wrong?

    Answer

    The host cannot tell which command a CQE completes. A controller may detect it (Command ID Conflict) but is not obliged to; usually the result is a completion matched to the wrong request and data corruption or a timeout.
