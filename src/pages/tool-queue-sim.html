A step-by-step simulator of one NVM Express (NVMe) I/O queue pair. You play both sides: the host driver that writes commands and rings doorbells, and the controller that fetches, executes and completes them. Every step updates the rings, the head and tail pointers, the Phase Tag, and a trace table showing what would cross the PCIe link. Then you break it on purpose.

What this simulator does

NVMe queues are circular buffers in host memory shared by two agents that never lock anything. The Submission Queue (SQ) is written by the host and read by the controller; the Completion Queue (CQ) is written by the controller and read by the host. Each side owns one pointer of each ring and tells the other side about it through a different channel: the host tells the controller with doorbell writes (PCIe Memory Writes into BAR0), and the controller tells the host with the SQ Head Pointer field and the Phase Tag inside each Completion Queue Entry (CQE).

That arrangement is fast and subtle. The simulator makes the subtlety visible. Following master-prompt section 35, it simulates queue creation, command insertion, tail update, doorbell, controller consumption, CQ insertion, head update, phase transitions and interrupt generation, and lets you inject: a doorbell beyond the queue size, a wrong tail, a doorbell to the wrong queue ID, a duplicate Command Identifier (CID), CQ overflow, a stale phase, a missed interrupt and a missing completion.

Read Chapter 25 — Queue Architecture (head, tail, phase), Chapter 27 — I/O Queues (creation and sizing) and Chapter 28 — Doorbells (what a doorbell write really is) first. The simulator assumes them.

How to read the display

The SQ ring

Each cell is one 64-byte slot. Its state is empty (never written), written (host wrote an SQE; controller has not fetched it), fetched (controller has read it; the host may not reuse it until a CQE's SQ Head Pointer says so) or free (released by SQHD). Four markers matter:

The controller has work when H ≠ DB. The host may write a new SQE only while (T + 1) mod N ≠ hH — one slot always stays empty, because a ring with head = tail must mean "empty", so "full" has to be one short of that.

The CQ ring and the Phase Tag

Each CQ cell shows the CID and Phase Tag (P) of the entry in memory. CQ memory starts zeroed, so every slot reads P = 0, and the host starts by expecting P = 1. The controller writes P = 1 on its first lap, P = 0 on its second, and so on, flipping every time its tail wraps to slot 0. The host flips its expectation every time its head wraps. A slot is new exactly when its P equals the host's expectation; the simulator colours those cells green (success) or red (error).

The CQ is full, from the controller's view, when (tail + 1) mod N = the head it last read from the CQ head doorbell. The controller must then stop posting completions. It cannot see what the host has consumed but not yet reported, which is why ringing the CQ head doorbell is not optional.

The trace table

The "PCIe / bus effect" column shows what a protocol analyzer would see: doorbells are 32-bit Memory Writes (MWr32) to 0xFE60_1008 (SQ1 tail) and 0xFE60_100C (CQ1 head); SQE fetches are 64-byte Memory Reads (MRd64) from 0x1_2340_0000 + 64 × slot; CQEs are 16-byte MWr64 to 0x1_2341_0000 + 16 × slot; interrupts are MWr32 to the MSI-X address. Host reads of the CQ are CPU loads from cached memory: they produce no PCIe traffic, which is why an analyzer cannot tell you when the host noticed a completion.

Guided scenarios

Reset the simulator before each scenario. Each one says what to click and what you should see. Write down your prediction before you click.

1. A normal command, slowly

Click 1, 2, 3, 4, 5, 6. After step 1 the SQ slot is written but nothing has happened on the link. After step 2 the doorbell (DB) moves: this is the only moment the controller learns anything. Step 3 moves H. Step 4 writes a CQE with P = 1 and SQHD = 1. Step 5 is invisible to PCIe and moves hH. Step 6 tells the controller the CQ slot is free.

2. Wrap-around and phase flips

Set both queues to 4 entries and click "Run one normal command" five times. Watch the controller's phase flip to 0 when its CQ tail wraps, then the host's expected phase flip when its head wraps. On the second lap the old entries still say P = 1 but the host now expects 0, so they are correctly ignored. The Phase Tag is what lets the host detect new entries without the controller ever clearing memory.

3. Out-of-order completion

Click "Run 3 commands, complete out of order". The third command completes first. CQ entries are in completion order, not submission order; the host matches each by CID, never by position. SQHD is the same in all three CQEs, because it reports how far the controller has fetched, not which commands finished.

4. SQ full

With 4 SQ entries, click "1. Host writes SQE" four times. The fourth attempt is refused: three entries fill a 4-entry ring. The host must wait for a CQE whose SQHD moves hH forward.

5. CQ overflow

Set SQ = 8, CQ = 4. Submit five commands, ring the doorbell, fetch five times, then complete five times without consuming. The fourth completion stalls: the CQ is full and the controller may not overwrite an entry the host has not released. The host caused this by allowing more commands in flight than its CQ can hold. Real drivers size the CQ at least as large as the commands they let into flight.

What a controller does when a CQ stays full is not something the host can rely on: the NVMe Base Specification makes avoiding it the host's job. Some controllers stall that queue indefinitely; behaviour across the rest of the controller is Implementation-dependent.

What the simulator simplifies

  • One SQ feeding one CQ. Real drivers often have one SQ per CPU and may map several SQs to one CQ. The Admin queue pair works the same way but is created by registers (AQA, ASQ, ACQ), not commands.
  • The controller fetches one SQE at a time. Real controllers fetch several in one larger MRd and arbitrate between SQs. Implementation-dependent
  • Commands carry no data, so there are no data TLPs; see the NVMe Command Decoder and the PRP Visualizer for those.
  • Every completion triggers its own interrupt. Interrupt coalescing (Set Features, Interrupt Coalescing) and polled queues change that.
  • Time is counted in steps, and the timeout is 12 steps. Real timeouts are seconds (the Linux driver's default I/O timeout is 30 s). Implementation-dependent
  • The asynchronous-event behaviour for invalid doorbell writes is summarised, not simulated. Check the Asynchronous Event Request command and the doorbell register descriptions in the NVM Express Base Specification 2.4 — Controller Registers; Asynchronous Event Request command.
  • Shadow doorbells (Doorbell Buffer Config) and Controller Memory Buffer queues are not modelled.

Practice

  1. An 8-entry SQ has host tail 5 and host-view head 6. How many more SQEs can the host write?

    • 0
    • 1
    • 2
    • 7
    Answer and reasoning

    (5 + 1) mod 8 = 6 = head, so the ring is already full. Verify it with an 8-entry SQ: write 7 SQEs without completing any.

  2. CQ of 4 entries, controller has wrapped once. What Phase Tag does it write into slot 2 on this lap?

    Answer

    0. First lap writes 1; after the first wrap it writes 0.

  3. Why does SQHD appear in every CQE instead of the controller writing a "head doorbell" to the host?

    Answer

    The controller already writes the CQE; piggy-backing SQHD on it costs nothing and needs no extra PCIe transaction or host register.

  4. The analyzer shows CQE writes but never a CQ head doorbell. What will eventually happen?

    Answer

    The CQ fills from the controller's view; completions stall (scenario 5), then every command on queues using that CQ times out.

  5. A driver ignores the doorbell beyond the queue size check and writes tail = N. Why is that a bug even though N mod N = 0?

    Answer

    The doorbell must hold a valid index 0…N−1; the controller does not reduce it modulo N. The host must wrap the tail itself.

  6. Two completions arrive with CIDs in the order 0x0003, 0x0001. Is the controller broken?

    Answer

    No. Completion order is not submission order. Only CID matching matters.

  7. Which fault produces no abnormal PCIe packet at all?

    Answer

    Missing completion and the stale-phase host bug: both are visible only as absence (no CQE) or as host behaviour (no CQ head doorbell), never as a malformed packet.

  8. Why must CQ memory be zeroed (or otherwise have P = 0) when the queue is created?

    Answer

    The host starts expecting P = 1. Garbage with P = 1 in a slot would be read as a valid completion before the controller ever wrote it.
