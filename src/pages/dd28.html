Chapter 29 taught you to read the 64-byte command and the 16-byte completion field by field. This module treats them as a contract with rules about ordering of checks, pairing, identity and retry — and teaches you to settle "was it the driver or the firmware?" arguments using the bytes themselves as witnesses.

Orientation

Knowing where every field lives is the entry ticket. Senior work starts with questions the layout alone does not answer. In what order does a controller validate the fields, and why does that make the returned status implementation-dependent when several fields are wrong? What exactly are the rules for fused commands? How do Command Identifiers (CIDs) behave over time, across aborts and timeouts? What do Do Not Retry (DNR), More (M) and Command Retry Delay (CRD) oblige the host to do? And how does a Submission Queue Entry (SQE) look when a PCI Express (PCIe) completer splits it across several completions? This module answers those, using the reference lab system and four new traces.

You need the SQE and Completion Queue Entry (CQE) layouts, the Status Field sub-fields and the (SQID, CID) key from Chapter 29 — NVMe Command Structure. Doorbells are in Chapter 28; completion splitting at the Read Completion Boundary in Chapter 13 and Module 12 — PCIe Completions.

Where it goes next: Module 29 — NVM Command Set fills in CDW10–15 for every I/O command, and Module 39 — NVMe Errors takes the Status Field into full error handling.

Kid story

Every train ticket is printed on the same size of card with the same boxes in the same places. The gate machine reads the first box — what kind of ticket it is — and that tells it how to read all the other boxes. Next to it is a number you write yourself, so you can match the receipt that comes out later.

The gate is strict. If you scribble in the box marked "office use only", it may refuse your ticket, even if everything else is right. Some tickets are for two travellers who must go through together: the first ticket says "I am the first of a pair", the second says "I am the second of a pair", and they must be put in one right after the other. If the first one is refused, the second one is refused too.

The receipt that comes out is tiny: your number, a colour dot that tells you the receipt is new, and a short code saying "OK" or what was wrong. Sometimes the code says "don't bother trying again", sometimes "try again in a little while", and sometimes "ask at the office for the long story".

Analogy boundary

What it represents. The fixed card is the 64-byte SQE; the first box is the opcode; your number is the CID; "office use only" boxes are reserved fields; the pair of tickets is a fused operation; the receipt is the 16-byte CQE with its Phase Tag, Status Code, DNR ("don't bother"), CRD ("try again in a while") and More ("ask at the office" — the Error Information log).

What it hides. The gate (controller) does not receive the ticket from your hand: it reads it out of host memory with a PCIe Memory Read when it chooses, and the bytes may arrive in several pieces. The ticket's number is unique only among tickets in flight on the same Submission Queue, not across the station. The gate may check boxes in any order it likes, so when several boxes are wrong, which complaint you get is up to the gate.

Where it misleads. A gate rejecting scribbles is guaranteed in the story; in NVMe, controllers may reject or ignore non-zero reserved fields — never rely on either. And "try again in a little while" is only honoured if the host told the controller it understands retry delays (Advanced Command Retry Enable); otherwise the delay field should be zero.

Mechanism

A fused Compare-and-Write on SQ1, the most demanding use of the common format. Reference lab system, synthetic example for teaching.

  1. Allocate two CIDs. Who: driver. What: 0x0010 for Compare, 0x0011 for Write; both unused among SQ1's outstanding commands. Where: host tag table. Evidence: later, in both SQE payloads.
  2. Build both SQEs in adjacent slots. Who: driver. What: slot 32: CDW0 0x0010_0105 (opcode 05h Compare, FUSE 01b). Slot 33: CDW0 0x0011_0201 (opcode 01h Write, FUSE 10b). Same NSID and same LBA range. Where: SQ1 memory. Evidence: payloads in the CplDs.
  3. Publish both with one doorbell. Who: driver. What: SQ1 tail 32 → 34. A doorbell that published only slot 32 would leave the pair split across doorbells, which a careful driver avoids. Evidence: MWr32 0xFE60_1008 = 0x22.
  4. Fetch and reassemble. Who: controller and root complex. What: one MRd of 32 Dwords; the root complex may answer with two CplDs split at the 64-byte Read Completion Boundary. Evidence: CplDs with the same Tag, decreasing Byte Count (128 then 64) and Lower Address 0x00 then 0x40.
  5. Validate the pair. Who: controller. What: first is Compare with FUSE 01b; next slot is a Write with FUSE 10b; ranges match. Where: controller parser. Evidence: none unless rejected.
  6. Execute atomically. Who: controller. What: fetch Compare data, compare with media; if equal, fetch Write data and write; no other command may modify the range in between. Evidence: MRd/CplD for both buffers.
  7. Complete both. Who: controller. What: two CQEs (CIDs 0x0010 and 0x0011), each with status. If the compare fails: Compare completes with Compare Failure and the Write with Command Aborted due to Failed Fused Command. Evidence: two CQE MWrs.
  8. Apply the host policy. Who: driver. What: success → done; Compare Failure → report "condition not met" to the caller, no retry; any status with DNR = 0 and CRD ≠ 0 under Advanced Command Retry → delayed retry. Evidence: tracepoints.

The central concept on the ladder: the command contract

Same-size tickets with fixed boxes; the first box says how to read the rest; pairs go through together; the receipt says OK, never retry, retry later, or ask for details.

The SQE's common fields (opcode, FUSE, PSDT, CID, NSID, MPTR, DPTR) are fixed; CDW10–15 depend on the opcode. The CQE returns SQID, SQHD, CID, Phase Tag and a Status Field whose DNR, CRD and M bits direct the host's next step.

The controller fetches 64 bytes, reassembles them from completions, parses CDW0 in hardware or firmware, runs checks in its own order, then either dispatches or builds an error CQE without any data transfer.

NVMe Base 2.4 defines the common command format, fused operations, the CQE, the Status Field, Command Retry Delay, the Error Information and Commands Supported and Effects logs; the NVM Command Set 1.3 defines Compare and Write fields.

SQE: MRd from the device and CplD(s) from the root complex. CQE: posted MWr from the device. No status crosses the link except inside the CQE payload.

Reassemble by Tag, Byte Count and Lower Address; decode little-endian; pair CQE to SQE by SQID, CID and the most recent fetch before the CQE.

Fast rejection (CQE microseconds after fetch, no data) means a validation failure: decode every field, then read the Error Information log's Parameter Error Location.

The specification does not define the order in which a controller validates fields, how a host allocates CIDs, how many times a host should retry, or how long to wait when CRD is zero. It does not say what a host should do with a completion whose CID matches nothing (that is host policy; Linux logs and ignores it). The exact unit of the Command Retry Delay Times and the precise conditions for the fused-abort statuses must be confirmed in the Base 2.4 text Check details; this module gives the names but not the numeric codes of the fused statuses and of Command ID Conflict.

Because the parser and validator are designed independently by each vendor, two compliant controllers can return different statuses for the same doubly-invalid command — one Invalid Command Opcode, another Invalid Field in Command. Validation suites must accept any status the specification allows for each invalid field, and tests should break one field at a time.

Two decoding hazards follow. First, split completions: an MRd for two SQEs (128 bytes) may come back as one CplD (Byte Count 128) or two (Byte Count 128 then 64, Lower Address 0x00 then 0x40). Byte Count in each CplD is the number of bytes remaining including this one; reassemble in order before decoding. Second, packed CQEs: one MWr of 8 or 16 Dwords carries two or four CQEs; a tool that decodes only the first 16 bytes misses completions and later reports phantom timeouts.

Status never travels as a PCIe completion status. A command rejected for an invalid field produces a perfectly successful PCIe exchange: MRd, CplD with Successful Completion, MWr of a CQE. The only error is inside the CQE payload.

If it points at byte 50 (CDW12 bits 23:16), story (a) or (b) is confirmed; if the controller filled the location with the "not applicable" value, the ambiguity remains and you bisect by clearing one field at a time. Linux prints NVMe status values as the CQE status word shifted right by one (dropping the Phase Tag), so SCT appears in bits 10:8 and SC in bits 7:0 — "0x281" is SCT 2h, SC 81h. Labs

Beginner lab — Encode a fused pair and its two outcomes

Safe lab Paper or a hex editor.

Objective

Produce the 128 bytes of a fused Compare-and-Write and the CQEs for success and for compare failure.

Prerequisites

Chapter 29 field tables; Compare in Chapter 31.

Setup

SQ1 slots 40–41, CIDs 0x0100 and 0x0101, NSID 1, SLBA 0x7000, 1 block (512 B), compare buffer 0x2_0000_A000, write buffer 0x2_0000_B000.

Procedure

  1. Write CDW0, NSID, PRP1, CDW10, CDW12 for both SQEs.
  2. Write the first 16 bytes of each as they sit in memory.
  3. Write both CQEs (DW2, DW3) for success, assuming SQHD 42 and phase 1.
  4. Describe both CQEs for a compare mismatch, by status name.

Observations

Your byte layouts and decoded fields.

Questions

  1. What is NLB?
  2. Which doorbell value publishes the pair?
  3. Why must the pair not straddle two doorbells?

Expected reasoning

Little-endian bytes; FUSE in bits 9:8; NLB 0's based.

Solution

Compare: CDW0 = 0x0100_0105 → bytes 05 01 00 01; NSID 01 00 00 00; PRP1 = 0x2_0000_A000 → bytes 00 A0 00 00 02 00 00 00; CDW10 = 0x0000_7000; CDW12 = 0 (NLB 0 = one block). Write: CDW0 = 0x0101_0201 → 01 02 01 01; PRP1 0x2_0000_B000; same CDW10/12. Success CQEs: DW2 = 0x0001_002A (SQID 1, SQHD 42) for both; DW3 = 0x0001_0100 and 0x0001_0101. Mismatch: Compare completes with Compare Failure (a media and data integrity status), the Write with Command Aborted due to Failed Fused Command. Doorbell: SQ1 tail = 42 (0x2A). A split publish lets the controller see the first half alone; well-behaved hosts publish both together so no time window exists where a lone first command is visible.

Extension

Write the same pair with PSDT = 01b and explain why it fails on the reference controller (no SGL support).

Intermediate lab — An SQE linter

Safe lab Pure software.

Objective

Catch host-side command construction errors before the doorbell — or from captured payloads after the fact.

Prerequisites

This module's Protocol and Trace views.

Setup

    rsvd, psdt, cid = (dw[0] >> 10) & 0xF, (dw[0] >> 14) & 3, dw[0] >> 16
    nsid = dw[1]
    out = []
    if opc not in (ADMIN_OPS if admin else IO_OPS):
        out.append(f"opcode {opc:02X}h not supported on this queue type -> Invalid Command Opcode")
    if rsvd:
        out.append("CDW0 bits 13:10 reserved but non-zero -> Invalid Field in Command (if checked)")
    if fuse == 3:
        out.append("FUSE = 11b is reserved")
    if fuse == 2 and (prev is None or ((prev[0] >> 8) & 3) != 1):
        out.append("second fused command without a first one in the previous slot")
    if fuse == 1 and opc != 0x05:
        out.append("first fused command is not Compare")
    if psdt == 3:
        out.append("PSDT = 11b is reserved")
    if psdt in (1, 2) and (admin or not CTRL["sgl_supported"]):
        out.append("SGL requested but not allowed/supported -> Invalid Field in Command")
    if not admin and opc in LBA_RANGE_OPS | {0x08}:
        if nsid not in CTRL["active_nsids"]:
            out.append(f"NSID {nsid} not active -> Invalid Namespace or Format")
        else:
            nbytes = ((dw[12] & 0xFFFF) + 1) * CTRL["lba_bytes"][nsid]
            if opc in LBA_RANGE_OPS and nbytes > CTRL["mdts_bytes"]:
                out.append(f"transfer {nbytes} B exceeds MDTS {CTRL['mdts_bytes']} B -> Invalid Field in Command")
        prp1 = dw[6] | dw[7] << 32
        if opc in LBA_RANGE_OPS and psdt == 0 and (prp1 == 0 or prp1 & 0x3):
            out.append("PRP1 zero or not Dword aligned")
    return cid, out

def sqe(cdw0, nsid=0, prp1=0, prp2=0, cdw10=0, cdw11=0, cdw12=0):
    return struct.pack("<16I", cdw0, nsid, 0, 0, 0, 0, prp1 & 0xFFFFFFFF, prp1 >> 32,
                       prp2 & 0xFFFFFFFF, prp2 >> 32, cdw10, cdw11, cdw12, 0, 0, 0)

Advanced lab — A completion policy engine

Safe lab Pure software.

Objective

Turn CQE Dword 3 into a host action that honours DNR, CRD, M and path-related status.

Prerequisites

Status Field sub-fields (Chapter 29).

Setup

#!/usr/bin/env python3
"""Decide what a host does with a completion, from CQE Dword 3 alone.
Synthetic teaching model of a host policy (not a specification algorithm).
CRDT values are the three Command Retry Delay Times from Identify Controller,
here already converted to milliseconds; acre is whether the host enabled
Advanced Command Retry (through the Host Behavior Support feature).
"""
SCT_NAMES = {0: "Generic", 1: "Command Specific", 2: "Media/Data Integrity",
             3: "Path Related", 7: "Vendor Specific"}

def split(dw3):
    return {"cid": dw3 & 0xFFFF, "p": (dw3 >> 16) & 1, "sc": (dw3 >> 17) & 0xFF,
            "sct": (dw3 >> 25) & 7, "crd": (dw3 >> 28) & 3, "m": (dw3 >> 30) & 1,
            "dnr": dw3 >> 31}

def decide(dw3, retries, acre=True, crdt_ms=(100, 500, 2000), max_retries=5):
    f = split(dw3)
    actions = []
    if f["m"]:
        actions.append("read Error Information log (LID 01h)")
    if f["sc"] == 0 and f["sct"] == 0:
        return f, ["complete OK"] + actions
    if f["dnr"]:
        return f, ["fail now (DNR=1)"] + actions
    if retries >= max_retries:
        return f, ["fail: retry budget exhausted"] + actions
    if f["sct"] == 3:
        actions.insert(0, "retry, preferably on another path")
    elif acre and f["crd"]:
        actions.insert(0, f"retry after {crdt_ms[f['crd'] - 1]} ms (CRD={f['crd']})")
    else:
        actions.insert(0, "retry now")
    return f, actions

if __name__ == "__main__":
    tests = [0x0001_0007, 0x8005_000C, 0x9105_0031, 0x1105_0031, 0x6105_0040,
             0x0607_0050, 0x8503_0009]
    for dw3 in tests:
        f, act = decide(dw3, retries=0)
        print(f"DW3={dw3:08X} CID={f['cid']:04X} SCT={f['sct']}({SCT_NAMES.get(f['sct'], 'rsvd')}) "
              f"SC={f['sc']:02X} CRD={f['crd']} M={f['m']} DNR={f['dnr']} -> {'; '.join(act)}")
    print("same CRD=1 status with ACRE disabled:", decide(0x1105_0031, 0, acre=False)[1])

Procedure

  1. Run it and check every decision by hand.
  2. Add exponential back-off for CRD = 0 retries.
  3. Add a rule: a media status with DNR = 0 is retried at most once, with Limited Retry cleared.

Questions

  1. Why does 0x9105_0031 fail immediately although CRD = 1?
  2. What is the risk of "retry now" when Advanced Command Retry is disabled?
  3. Why prefer another path for SCT 3h?

Expected reasoning

DNR dominates; CRD is a delay selector; path-related statuses concern the route to the namespace, not the media.

Solution

(1) DNR = 1 overrides everything: the controller says retrying the same command will fail. (2) A tight retry loop against a controller that is temporarily not ready: thousands of commands per second that all fail, consuming queue slots and log entries — a retry storm. Hosts that do not enable Advanced Command Retry need their own back-off. (3) Path-related statuses (for example asymmetric-access states in multipath configurations) mean this controller path cannot serve the namespace now; another controller in the subsystem may.

Extension

Senior forensic lab — "The firmware corrupts our commands"

Safe lab Reasoning over supplied synthetic evidence.

Objective

Decide, from evidence only, whether the host or the controller altered a command.

Prerequisites

This module; Chapter 41 — Command-to-TLP Correlation.

Setup — evidence (synthetic)

  • Customer claim: about 1 in 10⁷ Writes lands at the wrong LBA; "the firmware corrupts the SLBA".
  • Driver tracepoint for a bad case: Write CID 0x1a2c SLBA 0x0000_0001_0000_0000 (above 2 TiB on 512-byte LBAs), 8 blocks.
  • Analyzer CplD payload for the matching fetch: CDW10 = 0x0000_0000, CDW11 = 0x0000_0000.
  • Controller Error Information log: nothing for that CID. Data later found at LBA 0.
  • The driver's command-building code was recently changed to build the SQE on the stack and copy it into the SQ slot with a 32-byte copy routine "for speed".

Procedure

  1. Identify the first abnormal event.
  2. Decide whose bytes are wrong and why.
  3. Propose a confirming experiment and a regression test.

Observations

Separate the driver's intent, the bytes on the wire and the controller's action.

Questions

  1. Where are CDW10–11 in the SQE, by byte offset?
  2. Why would a 32-byte copy lose them?

Expected reasoning

Three witnesses: tracepoint (intent), CplD (fetched bytes), media effect (action). The first place two of them disagree is the fault boundary.

Solution

CDW10–11 occupy bytes 40–47. A 32-byte copy writes only bytes 0–31 (CDW0–CDW7); bytes 32–63 keep whatever the slot held before — for this slot, a previous command whose CDW10–11 were zero. The tracepoint shows intent (SLBA 2³²); the fetched payload shows SLBA 0; the controller wrote exactly what it fetched. First abnormal event: the CplD payload's CDW10/CDW11 disagreeing with the driver's intent — host side. It is rare because most previous slot contents happen to match or the bug only matters when the new SLBA differs in the upper bytes. Confirming experiment: poison every SQ slot with a pattern (for example 0xA5) after completion; the next fetched SQEs will show the pattern in bytes 32–63. Regression test: decode-after-copy assertion in debug builds, plus a randomised test that compares every fetched SQE (from an emulated controller's trace) with the driver's intent.

Extension

Write the two-paragraph incident summary for the firmware team that clears them and thanks them for the error-log evidence.

Debugging

Pattern 1 — "Completion for unknown command ID"

Symptom
Host logs a CQE whose CID matches no outstanding request; often followed by a timeout.
Possible causes
Byte-order or copy bug in CDW0; duplicate or stale CQE from the controller; CID generation bits mismatched after a reset; CQ shared but host demultiplexes by CID only.
Evidence
Fetched SQE payload for the slot; SQID in the CQE; driver CID allocation trace.
First check
Does any fetched SQE carry that CID?
Second check
Was it already completed once (duplicate CQE)?
Disambiguating experiment
Poison SQ slots after use; if the unknown CIDs carry the poison pattern, the controller fetched stale or partial SQEs.
Likely conclusion
Usually host construction or ordering; controller duplicates are rarer but real.
Confidence
High once the fetched payload is decoded.

Pattern 2 — Fast rejections with Invalid Field in Command

Symptom
CQE within a few microseconds of the fetch, no data, SC 02h.
Possible causes
Reserved bits set; PSDT not supported; MDTS exceeded; revision skew in CDW2–3/13; directive or protection fields without the feature enabled.
Evidence
Decoded SQE; Identify Controller; Error Information log.
First check
M bit: if set, read the Error Information log for the Parameter Error Location.
Second check
Compare non-zero fields against the revision the controller reports in VS.
Disambiguating experiment
Clear one non-zero optional field at a time.
Likely conclusion
Host field usage.
Confidence
High.

Pattern 3 — Fused Writes "randomly" aborted

Symptom
Some fused Writes complete with an abort status; Compares complete with failure or success.
Possible causes
Genuine compare mismatches (concurrency in the application); pair split by a wrap where a doorbell published only the first half; second command not adjacent because of a concurrent submitter on the same SQ.
Evidence
Compare's status; slot numbers of both halves; doorbell values between them.
First check
Compare status: failure means the application condition simply was not met.
Second check
Adjacency and same-doorbell publication.
Disambiguating experiment
Serialise submissions on that SQ; if aborts with successful compares disappear, it was a pairing race.
Likely conclusion
Application semantics or host pairing.
Confidence
Medium–high.

Pattern 4 — Retry storm after a transient condition

Symptom
Thousands of identical failing commands per second during a firmware activation or namespace change.
Possible causes
Host ignores CRD (Advanced Command Retry not enabled, or policy bug); host ignores DNR = 0 versus 1 distinction.
Evidence
Status sub-fields of the failures; time between retries.
First check
Decode CRD and DNR on the failing CQEs.
Second check
Whether Host Behavior Support enabled Advanced Command Retry.
Disambiguating experiment
Enable it (or add host back-off) and rerun the activation.
Likely conclusion
Host policy.
Confidence
High.

Pattern 5 — Decoder shows "missing" completions

Symptom
An analysis tool reports commands without completions, yet the host saw no timeouts.
Possible causes
Packed CQEs (several per MWr) decoded as one; SQE fetches split across CplDs not reassembled; capture filter dropping part of the CQ range.
Evidence
MWr lengths to the CQ range (4, 8, 16 Dwords); CplD Byte Counts.
First check
Count CQEs as Length / 4 per MWr.
Second check
Reassemble CplDs by Tag before decoding.
Disambiguating experiment
Compare tool counts with driver tracepoint counts for the same interval.
Likely conclusion
Tool bug, not device bug.
Confidence
High.

Interview

Beginner

  1. Which byte of an SQE in memory is the opcode?

    Model answer

    Byte 0, the least significant byte of CDW0.

  2. Who chooses the CID?

    Model answer

    The host; the controller copies it into the CQE.

  3. What does DNR mean?

    Model answer

    Do Not Retry: resubmitting the same command is expected to fail again.

  4. What are CDW10–15?

    Model answer

    Command-specific Dwords whose meaning depends on the opcode.

  5. Can two SQs use the same CID at the same time?

    Model answer

    Yes; uniqueness is per SQ among outstanding commands.

Intermediate

  1. State the rules for a fused Compare-and-Write.

    Model answer

    Adjacent slots in the same SQ; Compare with FUSE 01b first, Write with 10b second; same namespace and range; executed atomically; if the Compare fails the Write is aborted with the failed-fused status; controller support must be advertised.

  2. Why can an SQE fetch produce two CplDs?

    Model answer

    The completer may split a read completion at Read Completion Boundaries; a 128-byte read can return as 64 + 64 bytes.

  3. How does the CRD field get turned into a delay?

    Model answer

    CRD 1–3 selects Command Retry Delay Time 1–3 from Identify Controller; it applies when the host has enabled Advanced Command Retry.

  4. Why can a doubly-invalid command return different statuses on different controllers?

    Model answer

    Validation order is implementation-dependent; the first check that fails determines the status.

  5. What does M = 1 tell you to do?

    Model answer

    Read the Error Information log (Get Log Page 01h) for the entry matching the SQID and CID.

Advanced

  1. How would you detect a big-endian SQE in a trace?

    Model answer

    Decode the CplD bytes little-endian: unusual opcodes, reserved FUSE values, CIDs with byte-swapped patterns (0x0700 for 7), NSIDs like 0x0100_0000. The CQE's CID will not match any host CID.

  2. Why is SQHD not a completion indicator?

    Model answer

    It reports how far the controller has consumed (fetched) the SQ; completion of a command is its own CQE, in any order.

  3. What makes a CQE the "commit point" for read data, and when does that fail?

    Model answer

    Posted-write ordering puts data before the CQE on the same path; Relaxed Ordering on the CQE or non-compliant fabrics can break it.

  4. How does the Commands Supported and Effects log help a driver?

    Model answer

    It lists implemented opcodes and their effects (for example, whether a command changes namespace capability or requires quiescing), so the host need not probe with failing commands.

  5. What host bug produces Command ID Conflict?

    Model answer

    Reusing a CID on the same SQ while the earlier command is still outstanding — often in timeout or abort paths that free a tag too early.

Senior

  1. Design a negative-test matrix for the common command format.

    Model answer

    One invalid field per test: each reserved bit range, every reserved FUSE/PSDT value, opcode on wrong queue type, unsupported opcodes from the effects log, NSID 0/inactive/broadcast where not allowed, MDTS ± 1 block, misaligned PRP1, CID reuse while outstanding, fused pair split across doorbells, non-adjacent fused halves. Accept any status the specification permits; record which one each controller returns.

  2. How do you settle a host-versus-firmware dispute about a command?

    Model answer

    Collect three witnesses: host intent (tracepoint/log), bytes on the wire (CplD payload), controller action (data TLPs, error log). The first disagreement locates the fault.

  3. What would you change in a driver's CID scheme for debuggability?

    Model answer

    Encode a small generation counter in upper bits so stale or duplicate CQEs are detectable; log CID allocation and free events; never free a CID until its CQE is consumed or the queue is deleted.

  4. A controller fills Parameter Error Location with "not applicable" for all errors. Is that compliant, and what do you ask the vendor?

    Model answer

    Possibly compliant, since meaningful location reporting depends on the error, but it costs host debuggability; ask for location reporting on field-validation failures and document their validation order.

  5. How do revision differences show up in command structure?

    Model answer

    Fields that were reserved gain meaning (CDW2–3, CDW12/13 directive and protection fields, CQE DW1, CRD). A host built for a newer revision can trigger Invalid Field on an older controller; the reverse can make new fields silently zero. Check VS and Identify before using new fields.

Quiz

  1. CDW0 = 0x0011_0201 means:

    • Read, CID 0x0011, first fused
    • Write, CID 0x0011, second fused
    • Write, CID 0x0201
    • Compare, CID 0x0011
    Answer and reasoning

    Opcode 01h (Write on an I/O queue), bits 9:8 = 10b (second fused), CID in bits 31:16.

  2. A CplD has Byte Count 64 and Lower Address 0x40 for a 128-byte SQE fetch. It is:

    • An error
    • The first half
    • The second (final) part
    • A different request
    Answer and reasoning

    Byte Count counts remaining bytes; 64 remaining at offset 0x40 is the last piece.

  3. Status word 0x1105 contains:

    • SC 82h, CRD 1, DNR 0
    • SC 05h, CRD 1
    • SC 82h, DNR 1
    • SC 11h
    Answer and reasoning

    (0x1105 >> 1) & 0xFF = 0x82; bits 13:12 = 01b; bit 15 = 0.

  4. Which statement about reserved fields is true?

    • Controllers must ignore them
    • Controllers must reject them
    • Hosts may use them freely
    • Hosts must write zero; controller behaviour may vary
    Answer and reasoning

    The host obligation is normative; whether a controller checks is implementation-dependent.

  5. A Write exceeding MDTS should complete with:

    • LBA Out of Range
    • Invalid Field in Command
    • Data Transfer Error
    • Capacity Exceeded
    Answer and reasoning

    Exceeding the maximum data transfer size is an invalid field, not a range error.

  6. One CQ MWr has Length 16 DW. How many CQEs?

    • 1
    • 2
    • 4
    • 16
    Answer and reasoning

    16 bytes per CQE: 64 bytes / 16 = 4.

  7. Why must a fused pair be published by one doorbell?

    Model answer

    So the controller never sees the first half without the second in the next slot; a split publish creates a window where the pairing rules cannot be satisfied and the pair may be aborted.

  8. Name the three witnesses for a disputed command and what each proves.

    Model answer

    Host trace (what the driver intended), the fetched CplD payload (what the controller received), and the controller's action and logs (what it did). Their first disagreement locates the fault.

Teach-back

  1. To a child: the ticket gate, the "office use only" box and the pair tickets.

    Model explanation

    "Every ticket is the same shape so the gate knows where to look. The first box tells it what kind of ticket it is. Don't write in the office box. Pair tickets go in one after the other; if the first is refused, so is the second. The receipt has your number and tells you if it worked, if you should try again later, or if you shouldn't bother."

  2. To a junior engineer: how to read a CQE and decide what to do.

    Model explanation

    "Check the phase first. Then SQID and CID to find the request. Status zero: done. Otherwise split the status: SCT and SC say what; DNR says whether retrying can work; CRD says how long to wait if we enabled retry delays; M says read the error log. Never retry DNR = 1."

  3. To a senior engineer: why the status alone is weak evidence and what you add.

    Model explanation

    "Status reflects the first check that failed in the controller's own order and says nothing about who built the bad field. I add the fetched bytes (reassembled from CplDs), the host's intent from tracepoints, and the Error Information log's Parameter Error Location. With those three, a command dispute usually resolves in minutes."
