A hands-on forensic lab. You get NVMe commands, the host memory their data pointers reference, and synthetic PCIe traces. For each one you decide whether the command is valid, where the data really is, which Direct Memory Access (DMA) transactions should occur, and what failure results — then you prove it with a Physical Region Page (PRP) walker you can run.

Why this chapter exists

Chapters 36 and 37 taught the rules of PRPs and Scatter Gather Lists (SGLs). Rules are easy to recite and hard to apply under pressure: when a customer reports "one in a million writes has the wrong last 4 KiB", nobody hands you a labeled diagram. You get a trace with half a million Transaction Layer Packets (TLPs), an Input/Output Memory Management Unit (IOMMU) fault buried in a kernel log, and a driver that "works on every other SSD".

This chapter turns rules into a repeatable procedure. Each case gives you the same four questions the master prompt demands:

  1. Is the command valid? Structurally (alignment, list shape, descriptor types) and semantically (does the data pointer describe exactly the bytes the command transfers?).
  2. Where is the data? The exact host address ranges the controller will touch.
  3. What DMA transactions should occur? Descriptor fetches, data Memory Read (MRd) or Memory Write (MWr) TLPs, the Completion Queue Entry (CQE), the interrupt.
  4. What failure might result? Error status, silent corruption, IOMMU fault, timeout — and which layer reports it.

Data-pointer bugs are among the most expensive storage bugs because so many of them are silent. A malformed pointer that the controller follows without complaint moves real bytes to or from the wrong place. Learning to see them in a trace is a core senior skill.

Learning objectives

  • Apply a fixed validation procedure to any PRP or SGL data pointer.
  • Recompute the transfer length from the controller's point of view and detect length disagreements.
  • Predict descriptor fetches and data TLPs, and find the first event that deviates.
  • Distinguish structural pointer bugs from mapping (IOMMU) and lifetime (use-after-free) bugs, which a structure check cannot see.
  • Write root-cause statements with evidence, fix and regression test.
  • Use and extend an executable PRP walker.

The story

You are the checker at a moving company. Every morning, before the trucks leave, you get a stack of job sheets. Each sheet says how many boxes to move and lists the rooms they are in. Your job is to catch mistakes before a truck drives off: a sheet that says "12 boxes" but only lists rooms for 10; a room number that is half-way through a wall; a "see the next page" note on a sheet that has no next page; a room that belonged to this customer last week but has since been rented to someone else.

If you miss a mistake, the movers do not stop and ask. They carry boxes out of a stranger's room, or they put boxes into a room that isn't yours, and nobody finds out until the stranger comes home.

An aviation load-sheet audit is close: the load controller cross-checks the passenger count, the baggage weights per hold and the fuel figure, because each is computed by a different person from different sources. A plane is loaded according to the sheet, not according to reality. When two numbers that should agree do not — 180 passengers on the manifest, 179 boarding passes scanned — the auditor does not guess which is right. They find the first point where the two records diverge.

  • There is no checker before the truck leaves. Nothing validates a data pointer between the driver writing it and the controller following it. Some controllers check some rules; none can check intent.
  • "Last week's room" is literal. A freed buffer page is reused by unrelated code within microseconds; the analogy's week is far too slow.
  • The movers can't see the street signs you see. The controller only knows bus addresses (IOVAs on our lab system); the driver may think in kernel virtual or physical addresses.
  • The audit happens after the flight. In practice you audit traces and logs after the failure; the load-sheet auditor works before departure.

Beginner explanation

Every NVMe command that moves data has two descriptions of the same bytes:

  • The command's length: for a Read or Write, (NLB + 1) × the logical block size of the namespace's current format, plus metadata if the format interleaves it.
  • The data pointer's length: the bytes described by PRP1, PRP2 and any PRP list, or by the SGL's Data Block and Bit Bucket descriptors.

A valid command has these two lengths equal and a well-formed data pointer whose addresses are mapped for this device for the whole life of the command. Almost every data-pointer bug breaks one of three things:

The teaching ladder for data-pointer forensics

Check the job sheet against the box count and the room list before the movers act; afterwards, find the first room they entered that wasn't on your list.

Recompute the transfer length, walk the PRP/SGL structure, list every address the controller will touch, and compare with the intended buffer.

The controller's data-pointer engine follows whatever is in host memory at fetch time; the IOMMU is the only hardware that can refuse an access, and only if the IOVA is unmapped.

The NVMe Base Specification defines the structure rules and the statuses (PRP Offset Invalid, SGL family); it leaves detection of many malformed cases to the implementation.

Every data-pointer decision becomes visible as an MRd (descriptor or data) or MWr (data) with a specific address and length.

The first TLP whose address or length you did not predict is the first abnormal event.

Classify: structure, length, or mapping/lifetime; then fix the builder or the lifecycle, not the symptom, and add a regression test that would have caught it.

The sixteen questions, for a malformed data pointer

1–3. What is it, why does it exist, what problem does it cause?
A data pointer that does not describe exactly the command's bytes in memory the device may use; it exists because the host computes pointer and length separately and nothing checks them against each other; it causes misdirected DMA.
4–5. What existed before; why is the current design better?
Bounce buffers and vendor scatter lists; PRP/SGL let devices DMA directly into application buffers, at the cost of trusting the host's pointer.
6–7. Who creates it; who consumes it?
The driver (kernel, SPDK, test tool, firmware); the controller.
8–9. Where does it live; what is involved?
SQE Dwords 6–9, list/segment pages, data pages, IOMMU tables, CC.MPS, SGLS, namespace format.
10–11. Before and after?
Before: buffer mapping, list building, length computation. After: DMA, CQE, unmapping and freeing.
12. What if it is wrong?
Status error if detected; otherwise silent corruption, IOMMU faults, timeouts or crashes far from the cause.
13. Analyzer?
Descriptor fetches to unexpected addresses or of unexpected lengths; data TLPs outside the buffer; missing data TLPs.
14. Linux?
IOMMU fault messages, NVMe error messages with status, DMA-API debug warnings, data-verification failures.
15. Validation?
Boundary sweeps of offsets and lengths; negative tests; IOMMU-strict runs; pattern verification of neighboring memory.
16. Senior suspicion?
Two code paths computing one length; resource release on timeout paths; format changes; assumptions about controller checking.

Valid reference examples

Before the broken cases, three valid ones, answered with the four questions. Use them as your baseline. All are synthetic examples for teaching on the lab system: memory page size 4 KiB, Max Payload Size (MPS) 256 B, Max Read Request Size (MRRS) 512 B, Read Completion Boundary (RCB) 64 B, Namespace 1 with 512-byte blocks, SSD Requester ID 0x0100, IOMMU enabled.

V1 — 4 KiB Read into an offset buffer

SQE: opcode 02h, PSDT 00b, PRP1 = 0x2_0000_0800, PRP2 = 0x2_0000_1000, NLB = 0x0007.

  • Valid? L = 8 × 512 = 4,096. N = ⌈(2048 + 4096)/4096⌉ = 2 → PRP2 is a data page, offset 0. Valid.
  • Where? 0x2_0000_0800–0x2_0000_0FFF and 0x2_0000_1000–0x2_0000_17FF.
  • DMA: SQE MRd; 16 MWr of 256 B (8 per page); CQE MWr; MSI-X MWr. No list fetch.
  • Failure: none.

V2 — 1 MiB Write with a chained list

SQE: opcode 01h, PSDT 00b, PRP1 = 0x2_0000_0000, PRP2 = 0x1_5000_0C00, NLB = 0x07FF. List page 0x1_5000_0C00: 127 data entries and slot 127 = 0x1_5000_1000; list page 0x1_5000_1000: 128 data entries.

  • Valid? L = 1 MiB, N = 256, 255 entries. Slots at 0xC00: 128 → chain after 127. Second list page holds 128 ≤ 512. Valid (MDTS permitting).
  • Where? 256 pages: PRP1's page plus the 255 listed pages.
  • DMA: list MRds of 1,024 B and then 1,024 B (2 × 512 B each, the second pair only after the chain pointer is read); 2,048 data MRd of 512 B; ≥ 4,096 CplD; CQE; MSI-X.
  • Failure: none.

V3 — SGL Read keeping only the second half

SQE: opcode 02h, PSDT 01b, SGL1 = Last Segment 0x1_5000_1000 length 32, NLB = 0x000F. Segment: [Bit Bucket length 4096], [Data Block 0x2_0000_0000 length 4096]. Controller SGLS bits 1:0 = 01b with Bit Bucket support.

  • Valid? L = 8,192; sum = 4,096 + 4,096 = 8,192; Bit Bucket in a Read; supported. Valid.
  • Where? blocks 0–7 discarded; blocks 8–15 to 0x2_0000_0000–0x2_0000_0FFF.
  • DMA: SQE MRd; 1 MRd of 32 B (segment); 16 MWr of 256 B; CQE; MSI-X.
  • Failure: none.

  • Valid? No. L = 8,192, PRP1 offset 0 → N = 2 → PRP2 must be a page-aligned data pointer. 0x2_0004_1200 has offset 0x200 (invariant P3).
  • Where? If the controller uses it as given, the second 4 KiB goes to 0x2_0004_1200–0x2_0004_21FF: 3,584 B in page 0x2_0004_1000 and 512 B in page 0x2_0004_2000.   • Regression test: a builder unit test asserting P3 for every two-page command, plus an integration test with a guard pattern in the neighboring page.

Analysis: symptom, first abnormal event, root cause, fix
  • Valid? No: L = (8 + 1) × 512 = 4,608 B needs two pages, and PRP2 = 0 (invariant P2/P3). The walker reports PRP2 is 0 but the command needs a second page.
  • Where? 4,096 B into the buffer and 512 B to IOVA 0x0.
  • DMA: 18 MWr instead of the intended 16.
  • Symptom: IOMMU fault at address 0 (blocked); without an IOMMU, a write to physical address 0 — real memory on many platforms (low memory used by firmware structures), hence hangs.
  • First abnormal event: row 20. The SQE already reveals it if you compute L instead of trusting the script's comment.
  • Root cause: NLB is zero-based; the script passed a block count. The variant "same NLB after the namespace was reformatted from 512 B to 4 KiB blocks" moves 36 KiB into a 4 KiB buffer.
  • Fix: one helper that takes a byte length, derives NLB = bytes / LBA size − 1 from the current format, and builds the PRPs from the same byte length.
  • Regression test: assertion that the pointer length equals (NLB + 1) × LBA size for every command; tests for 1, 8, 9 blocks and after a format change.

Case 7 — SGL sent to a controller without SGL support

Scenario

A test framework enables SGLs globally "for coverage". On one SSD model every I/O fails immediately.

Command and memory

Write, PSDT = 01b, SGL1 = Data Block 0x2_0020_0000 length 4096, NLB = 0x0007. The controller's Identify Controller SGLS bits 1:0 = 00b.

#DirTime (ns)TypeFieldsMeaning
3Host→Dev1,430CplDByteCount=64SQE: opc=01h CDW0 bits 15:14 = 01b, DPTR byte 15 = 0x00
4Dev→Host2,050MWr64CQ1CQE: Status Code Type 0h, Invalid Field in Command, DNR=1
Analysis
  • Valid? No (invariant S1). Structurally the SGL is fine; the controller does not support SGLs.
  • Where? Nowhere; no data moves.
  • DMA: SQE fetch and CQE only. The absence of any data TLP between them is itself evidence of an early rejection.
  • Symptom / first abnormal event: the CQE status (row 4). The expected status for this case should be confirmed in the specification; Invalid Field in Command is what controllers commonly return.
  • Root cause: the framework did not consult SGLS.
  • Fix: gate PSDT on SGLS per controller; report "not supported" as a skipped test rather than a failure.
  • Regression test: run the suite on one SGL-capable and one PRP-only controller.

Case 8 — Byte-aligned SGL Data Block on a dword-granular controller

Scenario

A network-storage gateway forwards payloads with odd lengths. On a controller reporting SGLS bits 1:0 = 10b, some Writes fail.

Command and memory

Write, PSDT = 01b, SGL1 = Last Segment 0x1_5000_5000 length 32 → [Data Block 0x2_0024_0002 length 510], [Data Block 0x2_0025_0000 length 3586]. NLB = 0x0007 (4,096 B).

Code / pseudocode

The PRP walker. Given a buffer address, length and memory page size, it prints PRP1, PRP2, every list page with its entries and chain pointers, the list fetches, and the data TLPs a controller would plausibly issue. With --lab it walks the broken PRP sets of this chapter as a controller would and reports what is wrong. Standard library only.

#!/usr/bin/env python3
"""prp_walk.py - build, print and check NVMe PRP data pointers (teaching tool).

Synthetic example for teaching. Standard library only.

  python3 prp_walk.py                         # run the built-in worked examples
  python3 prp_walk.py 0x200000800 4096        # one buffer: address, length
  python3 prp_walk.py 0x200000000 1048576 --page-size 4096 \\
          --list-base 0x150000c00 --dir write --mps 256 --mrrs 512
  python3 prp_walk.py --lab                   # check the broken PRP sets of the debugging lab

The TLP split it prints is ONE plausible device behavior (requests cut at
MPS/MRRS-aligned boundaries, completions cut at RCB boundaries). Real
controllers and root complexes choose their own split: implementation-dependent.
"""
import argparse


def align_down(x, a):
    return x - (x % a)


def build_prps(addr, length, ps, list_base):
    """Return (prp1, prp2, list_pages, data_pages) following the PRP rules.

    list_pages: list of (list_page_address, [(slot_address, value, kind), ...])
    kind is 'data' for a data-page entry and 'chain' for a next-list pointer.
    """
    if addr % 4:
        raise ValueError("PRP1 must be dword aligned (bits 1:0 = 00b)")
    if length <= 0:
        raise ValueError("length must be positive")
    first_off = addr % ps
    npages = (first_off + length + ps - 1) // ps
    data_pages = [addr] + [align_down(addr, ps) + i * ps for i in range(1, npages)]
    prp1 = addr
    if npages == 1:
        return prp1, 0, [], data_pages          # PRP2 not used
    if npages == 2:
        return prp1, data_pages[1], [], data_pages   # PRP2 = second page
    if list_base % 8:
        raise ValueError("PRP list pointer must be qword aligned")
    remaining = data_pages[1:]
    list_pages, cur, next_page = [], list_base, align_down(list_base, ps) + ps
    while remaining:
        slots = (ps - cur % ps) // 8            # entries that fit before page end
        entries = []
        if len(remaining) > slots:              # must chain: last slot -> next list
            for i in range(slots - 1):
                entries.append((cur + 8 * i, remaining[i], "data"))
            entries.append((cur + 8 * (slots - 1), next_page, "chain"))
            remaining = remaining[slots - 1:]
            list_pages.append((cur, entries))
            cur, next_page = next_page, next_page + ps
        else:
            for i, v in enumerate(remaining):
                entries.append((cur + 8 * i, v, "data"))
            list_pages.append((cur, entries))
            remaining = []
    return prp1, list_base, list_pages, data_pages


def segments(addr, length, ps):
    """Split a virtually contiguous buffer into (address, bytes) per memory page."""
    out, a, left = [], addr, length
    while left:
        n = min(left, ps - a % ps)
        out.append((a, n))
        a, left = a + n, left - n
    return out


def split_requests(segs, limit):
    """Cut each segment at limit-aligned boundaries (limit = MPS or MRRS)."""
    out = []
    for a, n in segs:
        while n:
            k = min(n, limit - a % limit)
            out.append((a, k))
            a, n = a + k, n - k
    return out


def completions_for(addr, n, mps, rcb):
    """One plausible completer: CplDs of at most MPS bytes ending on RCB boundaries."""
    out = []
    while n:
        if n <= mps:
            k = n
        else:
            k = mps - ((addr + mps) % rcb)
        out.append((addr, k))
        addr, n = addr + k, n - k
    return out


def report(addr, length, ps, list_base, direction, mps, mrrs, rcb, show_tlps=8):
    prp1, prp2, lists, pages = build_prps(addr, length, ps, list_base)
    print(f"Buffer 0x{addr:x}, {length} bytes, memory page size {ps}")
    print(f"  pages touched : {len(pages)}  (first-page offset 0x{addr % ps:x})")
    print(f"  PRP1          : 0x{prp1:016x}")
    if not prp2:
        print("  PRP2          : not used (transfer fits in PRP1's page)")
    elif not lists:
        print(f"  PRP2          : 0x{prp2:016x}  (second data page)")
    else:
        print(f"  PRP2          : 0x{prp2:016x}  (PRP list pointer)")
    for n, (base, entries) in enumerate(lists):
        ndata = sum(1 for e in entries if e[2] == "data")
        print(f"  PRP list page {n} at 0x{base:x}: {len(entries)} entries "
              f"({ndata} data, {len(entries) - ndata} chain), {8 * len(entries)} bytes")
        shown = entries if len(entries) <= 6 else entries[:3] + [None] + entries[-2:]
        for e in shown:
            if e is None:
                print("      ...")
            else:
                tag = "-> next PRP list" if e[2] == "chain" else "data page"
                print(f"      [0x{e[0]:x}] = 0x{e[1]:016x}  {tag}")
    segs = segments(addr, length, ps)
    list_reads = []
    for base, entries in lists:
        list_reads += split_requests([(base, 8 * len(entries))], mrrs)
    if direction == "read":   # NVMe Read: controller WRITES host memory
        tlps = split_requests(segs, mps)
        print(f"  Data TLPs (NVMe Read -> device MWr): {len(tlps)} MWr of <= {mps} B")
        for a, n in tlps[:show_tlps]:
            print(f"      MWr 0x{a:x} {n} B")
        if len(tlps) > show_tlps:
            print(f"      ... {len(tlps) - show_tlps} more")
    else:                     # NVMe Write: controller READS host memory
        reqs = split_requests(segs, mrrs)
        cpls = sum(len(completions_for(a, n, mps, rcb)) for a, n in reqs)
        print(f"  Data TLPs (NVMe Write -> device MRd): {len(reqs)} MRd of <= {mrrs} B,"
              f" about {cpls} CplD (completer-dependent)")
        for a, n in reqs[:show_tlps]:
            print(f"      MRd 0x{a:x} {n} B")
        if len(reqs) > show_tlps:
            print(f"      ... {len(reqs) - show_tlps} more")
    if list_reads:
        print(f"  PRP list fetches: {len(list_reads)} MRd (" +
              ", ".join(f"0x{a:x}/{n} B" for a, n in list_reads) + ")")
    print()


def check(prp1, prp2, length, ps, memory, intended=None):
    """Walk a PRP set the way a controller would and return a list of findings.

    length:   bytes the COMMAND asks for ((NLB + 1) x LBA size), not what the host allocated.
    memory:   dict {address: 64-bit value} holding whatever is in the PRP list slots,
              including stale values the host did not mean to be there.
    intended: optional set of page addresses the host meant to use; any data page the
              controller would touch outside this set is reported.
    """
    problems, touched = [], [align_down(prp1, ps)]
    data_lo = align_down(prp1, ps)
    data_hi = data_lo + ((prp1 % ps + length + ps - 1) // ps) * ps
    if prp1 % 4:
        problems.append(f"PRP1 0x{prp1:x} is not dword aligned")
    left = length - min(length, ps - prp1 % ps)
    if 0 < left <= ps:                      # exactly two pages: PRP2 is data
        if prp2 == 0:
            problems.append("PRP2 is 0 but the command needs a second page: "
                            "the controller will DMA to/from address 0")
        elif prp2 % ps:
            problems.append(f"PRP2 0x{prp2:x} used as data pointer but has offset "
                            f"0x{prp2 % ps:x} (must be page aligned)")
        touched.append(align_down(prp2, ps))
        left = 0
    elif left > ps and prp2 % 8:
        problems.append(f"PRP2 0x{prp2:x} used as list pointer but not qword aligned")
        left = 0
    slot = prp2
    lists = 1 if left else 0
    while left > 0:
        if slot not in memory:
            problems.append(f"list slot 0x{slot:x} was never written by the host "
                            f"({left} bytes still to place) - list too short")
            break
        val = memory[slot]
        if (slot + 8) % ps == 0 and left > ps:      # last slot, more than a page to go
            if data_lo <= val < data_hi or (intended and val in intended):
                problems.append(f"last slot of list page (0x{slot:x}) holds 0x{val:x}, a DATA "
                                "page: the controller treats it as the next PRP list and "
                                "reads data bytes as PRP entries")
                break
            if val % ps:
                problems.append(f"chain pointer at 0x{slot:x} = 0x{val:x} not page aligned")
                break
            slot, lists = val, lists + 1
            continue
        if val % ps:
            problems.append(f"entry at 0x{slot:x} = 0x{val:x} has offset 0x{val % ps:x}")
        touched.append(align_down(val, ps))
        left -= min(ps, left)
        slot += 8
    if intended:
        alien = [t for t in touched if t not in intended]
        for t in alien:
            problems.append(f"controller would access page 0x{t:x}, which is not part "
                            "of the host buffer (stale or wrong entry)")
    if not problems:
        if lists:
            return [f"valid: {len(touched)} data pages, {lists} list page(s) walked"]
        return [f"valid: {len(touched)} data page(s), no list"]
    return problems


def lab_cases(ps=4096):
    """The structural cases of the PRP/SGL debugging lab (same numbers as the chapter)."""
    lst = 0x1_5000_0000

    def pages(base, n):
        return {base + i * ps for i in range(n)}

    cases = []
    # Case 1: 8 KiB Read, PRP2 has offset 0x200
    b = 0x2_0004_0000
    cases.append(("1 misaligned PRP2", b, b + 0x1200, 8192, {}, pages(b, 2)))
    # Case 2: 128 KiB Write, host wrote 30 entries; slot 30 holds a stale value
    b = 0x2_0008_0000
    m = {lst + 8 * i: b + (i + 1) * ps for i in range(30)}
    m[lst + 8 * 30] = 0x2_0033_7000
    cases.append(("2 off-by-one list length", b, lst, 128 * 1024, m, pages(b, 32)))
    # Case 3: 128 KiB Read, list starts at 0xF80 of its page and runs on without a chain
    b, lp = 0x2_000C_0000, lst + 0x1F80
    m = {lp + 8 * i: b + (i + 1) * ps for i in range(31)}
    cases.append(("3 list crosses page, no chain", b, lp, 128 * 1024, m, pages(b, 32)))
    # Case 3 fixed: 15 data entries, chain in slot 15, 16 entries in a new list page
    m = {lp + 8 * i: b + (i + 1) * ps for i in range(15)}
    m[lp + 8 * 15] = lst + 0x3000
    m.update({lst + 0x3000 + 8 * i: b + (i + 16) * ps for i in range(16)})
    cases.append(("3 fixed with chain", b, lp, 128 * 1024, m, pages(b, 32)))
    # Case 6: NLB = 8 (nine 512-byte blocks = 4,608 B) into a 4 KiB buffer, PRP2 = 0
    b = 0x2_0010_0000
    cases.append(("6 NLB one too large", b, 0, 9 * 512, {}, pages(b, 1)))
    # Case 4 and 5 are structurally valid: the walker cannot see mapping or lifetime bugs
    b = 0x2_0014_0000
    cases.append(("4/5 structurally valid 16 KiB", b, lst + 0x4000, 16384,
                  {lst + 0x4000 + 8 * i: b + (i + 1) * ps for i in range(3)}, pages(b, 4)))
    for name, p1, p2, n, mem, want in cases:
        print(f"{name:32s} -> " + "; ".join(check(p1, p2, n, ps, mem, want)))


def main():
    ap = argparse.ArgumentParser(description=__doc__,
                                 formatter_class=argparse.RawDescriptionHelpFormatter)
    ap.add_argument("addr", nargs="?", help="buffer IOVA, e.g. 0x200000800")
    ap.add_argument("length", nargs="?", help="bytes, e.g. 4096 or 0x20000")
    ap.add_argument("--page-size", type=lambda s: int(s, 0), default=4096,
                    help="memory page size = 2^(12+CC.MPS); default 4096")
    ap.add_argument("--list-base", type=lambda s: int(s, 0), default=0x1_5000_0000,
                    help="address of the first PRP list (qword aligned)")
    ap.add_argument("--dir", choices=["read", "write"], default="read",
                    help="NVMe command direction: read = device writes host memory")
    ap.add_argument("--mps", type=int, default=256, help="PCIe Max Payload Size")
    ap.add_argument("--mrrs", type=int, default=512, help="PCIe Max Read Request Size")
    ap.add_argument("--rcb", type=int, default=64, help="Read Completion Boundary")
    ap.add_argument("--lab", action="store_true", help="check the debugging-lab PRP sets")
    a = ap.parse_args()
    if a.lab:
        lab_cases(a.page_size)
        return
    common = dict(ps=a.page_size, list_base=a.list_base, direction=a.dir,
                  mps=a.mps, mrrs=a.mrrs, rcb=a.rcb)
    if a.addr is not None and a.length is not None:
        report(int(a.addr, 0), int(a.length, 0), **common)
        return
    for addr, n in [(0x2_0000_0000, 4096), (0x2_0000_0000, 8192),
                    (0x2_0000_0800, 4096), (0x2_0000_0000, 128 * 1024)]:
        report(addr, n, **common)
    common["list_base"] = 0x1_5000_0C00     # 1 MiB with an offset list: chains
    report(0x2_0000_0000, 1024 * 1024, **common)


if __name__ == "__main__":
    main()

With --lab the walker prints one verdict per case: Case 1 reports the PRP2 offset 0x200; Case 2 reports access to page 0x200337000 outside the buffer; Case 3 reports that the last slot of the list page holds a data page; the fixed Case 3 walks two list pages; Case 6 reports PRP2 = 0 with a second page needed; and the Case 4/5 command is reported valid — the point being that mapping and lifetime bugs are invisible to a structure check.

The walker's check() takes the length the command implies, not the buffer the host allocated. That single design choice is what lets it catch Case 6. Tools that take the length from the host's allocation repeat the host's mistake.

Worked example

Work Case 3 from raw evidence, the way you would at a customer site.

  1. Decode the SQE (from the analyzer's CplD at row 3): opcode 02h, PSDT 00b, PRP1 = 0x2_000C_0000, PRP2 = 0x1_5000_1F80, NLB = 0x00FF.
  2. Get the format: nvme id-ns -H says the LBA format in use has 512-byte data and no metadata. L = 256 × 512 = 131,072.
  3. Walk: offset 0 → N = 32 → PRP2 is a list pointer; 31 entries needed. List pointer offset 0xF80 → S = (4096 − 3968)/8 = 16 slots. 31 > 16 → slots 0–14 data, slot 15 must be a chain pointer.
  4. Predict: list MRd of 128 B at 0x1_5000_1F80; then a list MRd at whatever slot 15 holds, which must be a page in list memory (0x1_5000_xxxx region on this system).
  5. Compare: row 6 reads 0x2_000D_0000 — the data region. Prediction violated. First abnormal event found.
  6. Confirm with the walker: run python3 prp_walk.py --lab; Case 3 reports "last slot of list page (0x150001ff8) holds 0x2000d0000, a DATA page".
  7. Explain the downstream symptoms: the controller reads "This is " as a PRP entry → MWr to 0x2073692073696000 → IOMMU fault with an ASCII-looking address.
  8. Write the root cause: "The PRP list builder places lists at 128-byte granularity and fills them linearly without checking remaining slots; lists longer than the remaining slots run into the next page and the controller interprets the last in-page slot as a chain pointer."
  9. Fix and test: chain or reallocate; add the walker check to the builder's debug path; add the analyzer rule.

Common mistakes

  • Starting from the symptom. Chasing the IOMMU fault address in Case 3 leads nowhere: it is data, not a pointer anyone built. Start from the command.
  • Trusting the host's length. Every length bug in this chapter is invisible if you take the length from the host code.
  • Treating Success as proof. Cases 2, 4, 5 and 6 can all complete with Success.
  • Blaming the SSD because another SSD works. Different validation and prefetch behavior exposes the same host bug differently.
  • Disabling the IOMMU "to make it work". That converts detectable faults into silent corruption.
  • Reading byte 15 of DPTR as an SGL identifier without checking PSDT. With PRPs, it is the top byte of PRP2.

Senior engineer insight

  • Ask "who computed the length, and how many times?" If the answer is more than once, you have probably found the bug.
  • Lifetime bugs hide behind timeouts. Every timeout path in a driver or test tool deserves a review for "who owns the buffer now?".
  • Make the IOMMU your ally. Strict translation in all test environments turns silent corruption into a fault with an address and a device.
  • Poison what you recycle. List pages, segments and buffers filled with a recognizable pattern on free make stale-entry bugs scream instead of whisper.
  • Encode the invariants in the builder. A debug-build assertion that walks every pointer you build costs microseconds and saves months.
  • Separate observation from inference in reports. "MRd at 0x2_000D_0000 with list-fetch length" is an observation; "the list ran off the page" is the inference; the walker output is the corroboration.

For each: valid or not, data ranges, predicted TLPs, failure, first abnormal event, root cause, fix.

Use the invariant tables; recompute L from the format given.

Step 1

Compute L and the pointer length for each input.

Step 2

Walk each pointer by hand, then with check() from the walker (write a few lines calling it with the input values).

Predict the TLPs and say which one would be the first abnormal event.

Questions

  1. Which input is valid?
  2. Which input is a format-change bug?
  3. Why can input D complete with Success despite the fault?

Challenge

Extend check() to take the LBA size and NLB instead of a byte length, and to flag a format mismatch when given the size the host assumed.

Hint

For A, compute where 1,024 bytes starting at offset 0xF00 end. For D, think about what an MRd blocked by the IOMMU returns and what a controller might do with it.

Solution
  1. L = 2 × 512 = 1,024; offset 0xF00 leaves 256 B in page 0 → N = 2 → PRP2 needed but 0. Invalid. 256 B to 0x2_0040_0F00, 768 B to address 0. First abnormal: MWr to 0x0. Root cause: page count computed from length only. Fix: include the offset.
  2. L = 64 × 4,096 = 256 KiB → N = 64 → 63 entries needed; the list has 7 (built for 64 × 512 = 32 KiB). Invalid. The controller reads 56 stale slots (or zeros) → MRd from stale addresses / address 0. First abnormal: list fetch of 504 B where the host built 56 B, then data MRd outside the buffer. Root cause: the host assumed 512-byte blocks after the namespace was reformatted to 4 KiB. Fix: read the current format before building commands.
  3. L = 64 × 512 = 32 KiB, N = 8, 7 entries. Valid. One 56-byte list MRd, 128 data MWr of 256 B.
  4. Structure valid and sum correct. The IOMMU blocked reads of the second page; the root complex completed those MRd with an error status (UR or CA), but if the analyzer view shown filters completions, you see only the requests. A controller that correctly handles poisoned or failed completions should report an error; one that ignores completion status writes garbage to media and reports Success — a controller bug on top of a host mapping bug (the buffer's second page was not mapped, e.g. mapped with length 0x1000 instead of 0x2000). Fix the mapping length; report the controller's error handling separately.

Challenge sketch: check_cmd(prp1, prp2, nlb, lba_size, ps, memory, assumed_lba=None) computes length = (nlb + 1) * lba_size, calls check(), and if assumed_lba differs, adds "host built for (nlb+1) × assumed_lba bytes".

What a senior engineer notices

Input D has two bugs from two parties. The report must separate them: the host mapping bug causes the fault; the controller's handling of failed completions determines whether the failure was loud or silent.

  • Input B with the list page zeroed: MRd to address 0 instead of stale pages.

Exercises

  1. For each of Cases 1–8, state whether a controller could detect it from the command and descriptors alone.

  3. Why does Case 3 produce addresses that look like ASCII?
    Answer

    The controller reads 8-byte values from a data page holding text and uses them as page addresses.

  4. In Case 5, list three host actions that would have made the late DMA harmless.
    Answer

    Waiting for the CQE; resetting the controller before freeing; strict IOMMU invalidation on unmap (turns corruption into a fault); quarantining the buffer.

  5. Design an analyzer trigger that catches Case 3 in production captures.
    Answer

    Track, per command, the data ranges derived from PRP1 and fetched list entries; trigger on any MRd whose address lies inside a data range of the same command and whose length is a multiple of 8 consistent with a list fetch, immediately after a list fetch that ended at a page boundary.

Quiz

  1. A Read completes with Success. Which statement is justified?

    • The data pointer was valid
    • All data reached the buffer
    • The controller believes it completed the command
    • No IOMMU fault occurred
    Answer and reasoning

    Posted writes give the controller no feedback; Success only reflects the controller's view.

  2. NLB = 0x0008 with 512-byte blocks moves how many bytes?

    • 4,096
    • 4,608
    • 4,104
    • 8
    Answer and reasoning

    (8 + 1) × 512 = 4,608; NLB is zero-based.

  3. A list pointer at offset 0xF80 in a 4 KiB page has how many slots before the page ends?

    • 16
    • 31
    • 128
    • 512
    Answer and reasoning

    (4096 − 3968) / 8 = 16.

  4. Which bug cannot be detected by any structure check?

    • Misaligned PRP2
    • List crossing a page
    • SGL segment descriptor in the last segment
    • Buffer freed while the command is outstanding
    Answer and reasoning

    Lifetime bugs involve a well-formed pointer whose memory changed owner.

  5. For an NVMe Write, an IOMMU-blocked data read most likely causes:

    • No visible effect anywhere
    • An error completion to the controller's MRd, and usually an error status in the CQE
    • A CQE with PRP Offset Invalid
    • A link retrain
    Answer and reasoning

    MRd is non-posted; the root complex returns a completion with an error status; how the controller reports it is implementation-dependent.

  6. What is the first abnormal event in Case 3?

    Model answer

    The list-fetch MRd to 0x2_000D_0000, an address inside the command's own data buffer.

  7. Why does the walker take the command's length rather than the buffer size?

    Model answer

    Because the controller does; using the host's allocation would reproduce the host's error and hide length bugs such as Case 6.

  8. Give two reasons the same host bug might pass on SSD A and fail on SSD B.

    Model answer

    Different validation (A rejects bad offsets, B follows them); different list prefetch (A fetches only needed entries, B reads whole pages); different data ordering and timing exposing races.

  9. In the ambiguous trace, what must you rule out before blaming the controller?

    Model answer

    A valid Bit Bucket in the segment, capture filtering of other addresses, and capture loss.

Interview questions

  1. Beginner: What four questions do you ask of a command's data pointer?
    Model answer

    Is it valid; where is the data; what DMA transactions should occur; what failure would result if it is wrong.

  2. Intermediate: A 4 KiB read writes to address 0. What do you check?
    Model answer

    Whether the transfer actually needs two pages — an offset in PRP1 or NLB off by one — with PRP2 left zero.

  3. Intermediate: How do posted and non-posted semantics change what an IOMMU fault looks like for Reads versus Writes?
    Model answer

    NVMe Read → device MWr (posted) → blocked silently from the device's view → Success; NVMe Write → device MRd (non-posted) → error completion → controller sees the failure.

  4. Advanced: Walk me through diagnosing heap corruption suspected to come from DMA.
    Model answer

    Enable strict IOMMU and DMA-API debug on a test system; correlate corruption addresses with IOVA mappings; look for late completions after timeouts; check buffer lifetime on abort/reset paths; capture with an analyzer and compare data TLP addresses to live mappings.

  5. Senior: How would you design a driver so these eight cases cannot happen?
    Model answer

    One byte-length source of truth; builders that derive NLB and pointers from it; debug-build walkers; page-aligned list allocation that cannot straddle; SGLS-gated SGL use with alignment handling; strict ownership: buffers owned until CQE or reset; poisoning on free; IOMMU-strict CI.

  6. Senior: A customer insists the SSD corrupted data. Your trace shows the controller read from a page outside the buffer. How do you communicate this?
    Model answer

    Present observations (SQE fields, list content, data TLP addresses), the walker's independent verdict, the invariant violated, and the host code path responsible; acknowledge any controller-side improvement (e.g. stricter checking) separately; propose the fix and a regression test.

Chapter summary

  • Every data command has two lengths — the command's and the pointer's — that must agree.
  • Bugs fall into structure, length, and mapping/lifetime families; only the first two are visible in the command.
  • The validation procedure: decode, recompute L, walk, check rules, compare lengths, check addresses, predict TLPs, compare with the trace.
  • The first abnormal event is the first deviation from your prediction, often the command or descriptor content itself.
  • Success status, a working second SSD and a disabled IOMMU are not evidence of correctness.
