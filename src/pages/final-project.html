The final project is to design, and build a working core of, an "NVM Express (NVMe) PCI Express (PCIe) Forensic Investigation Platform". It takes in PCIe traces, NVMe logs, Advanced Error Reporting (AER) logs, Linux logs, configuration-space dumps, Identify data and Self-Monitoring, Analysis and Reporting Technology (SMART) data. It normalizes, decodes and correlates them, builds one timeline, finds the first abnormal event, proposes hypotheses with evidence, and writes an HTML root-cause report. This page gives the requirements, architecture, schemas, parser design, state machines, correlation algorithm, a runnable miniature, milestones and acceptance criteria.

Why this project

Every investigation in this course followed the same steps: collect, decode, line up, find what went wrong first, reason about why, write it down. Senior engineers do these steps in their heads and in spreadsheets. A platform that does the mechanical parts (decoding, correlation, timelines, rule checks) frees the engineer for the parts that need judgement (hypotheses, experiments, communication) and makes investigations reproducible.

Learning objectives

  • Turn the course's investigation method into a software architecture with clear stages and data contracts.
  • Design a normalized event model that keeps provenance for every fact.
  • Write a correlation algorithm that links doorbells, Submission Queue Entry (SQE) fetches, data movement, Completion Queue Entries (CQEs), interrupts, kernel log lines and AER records to commands.
  • Encode protocol expectations as state machines and rules, and use them to find the first abnormal event.
  • Produce reports that show their evidence and state their confidence.

Prerequisites

Command-to-TLP correlation (Chapter 41, Module 38); error correlation (Chapter 47); Automated Trace Analysis and Module 57; AI + NVMe Protocol Analysis; synthetic versus real traces and golden traces (Synthetic vs Real Traces, Diffing and Golden Traces); report structure (Engineering Bug Report Training); and the worked investigation in the Final Capstone, which is this platform's first acceptance test.

Imagine a detective's office that sorts every clue as it arrives: it writes the time on each one, puts them in order on a long wall, draws strings between clues about the same suspect, and puts a red pin on the first thing that looks wrong. The detective still has to think, but no clue gets lost and nobody argues about what happened when.

A real office can't tell which clocks were wrong, which witness misremembered, or which clue was planted. A forensic platform faces the same problems: unsynchronised clocks, analyzers that miss packets, logs that are paraphrased or rate-limited. The platform must show its uncertainty instead of hiding it behind a neat timeline.

Non-functional requirements

  • NFR-1 Provenance: every derived fact can be traced to raw input records and decoder versions.
  • NFR-2 Determinism: the same inputs and configuration always produce the same report.
  • NFR-3 Truthfulness: decoders never invent fields; unknown fields are shown raw and marked unknown; specification-dependent interpretations name the revision.
  • NFR-4 Explainability: every anomaly names the rule it violated; every conclusion lists its evidence; confidence is explicit.
  • NFR-5 Scale: process a 10-million-event trace in under ten minutes on a workstation (streaming, not all in memory).
  • NFR-6 Privacy: payload data is dropped by default; host names and serial numbers can be redacted.
  • NFR-7 Extensibility: new sources, decoders and rules are plug-ins.
  • NFR-8 Offline: no network access needed to analyse or to view the report.

Clock alignment

Each source has its own clock. Alignment uses anchor events visible in two sources: a register write the driver logs and the analyzer captures (as in the capstone's Controller Configuration (CC) write), a kernel message about a link event and the analyzer's LTSSM record, a harness I/O start and its doorbell. The aligner fits an offset (and drift, for long captures) per source and records the residual as uncertainty. If two events are closer than the combined uncertainty, the timeline must not claim an order between them.

taligned = tnative × (1 + d) + o
taligned
time on the reference timeline (seconds)
tnative
time in the source's own clock (seconds)
d
relative drift of the source clock (dimensionless; fitted from two or more anchors, 0 with one anchor)
o
offset between the clocks (seconds), fitted from anchors

State machines

Expectations are written as state machines per entity. An anomaly is a transition the machine does not allow, or a state held longer than its timeout.

NVMe command lifecycle (per command on PCIe)

FETCHEDMRd of the slot + CplD with the SQE
DATAPhysical Region Page (PRP)/Scatter Gather List (SGL) fetches, data MRd/CplD or MWr

Correlation algorithm

Correlation turns a flat stream of packets and messages into commands and causes. On NVMe over PCIe, the keys are addresses (queue memory, buffers, Base Address Register (BAR) offsets), identifiers (Requester ID, tag, CID, SQ ID) and the queue configuration learned from admin commands.

  1. Learn the configuration. From configuration events and admin commands: BAR0 base and doorbell stride; admin queue bases; for each Create I/O CQ: base, size, interrupt vector; for each Create I/O SQ: base, size, CQ ID; MSI-X table entries (address, data, mask) from BAR writes.
  2. Classify host-to-device writes. An MWr into BAR0 at 0x1000 + k × stride is a doorbell: even k = SQ tail of queue k/2, odd k = CQ head of queue (k−1)/2. MSI-X table writes update the vector map.
  3. Pair requests and completions. Key (Requester ID, tag) while outstanding; close on Byte Count satisfied; flag reuse and orphans.
  4. Identify SQE fetches. A device MRd whose address lies in an SQ's range gives (SQ ID, slot); its completion data is the SQE; decode the CID → create the command entity with a generation number.
  5. Attach data movement. Decode PRP1/PRP2 (and PRP lists when fetched) or SGLs into address ranges; attach device MRds/MWrs that fall in those ranges to the command (time window: after fetch, before CQE).
  6. Attach completions. A device MWr into a CQ range gives (CQ ID, slot); decode SQ ID and CID → command; check the phase against the expected phase for that pass.
  7. Attach interrupts. A device MWr matching an MSI-X entry's address and data gives the vector → CQ(s) → the oldest posted-but-unsignalled commands on those CQs.
  8. Attach host-side records. Kernel messages mentioning QID and tag/CID; IOMMU faults by requester and address; AER records by function and time window; harness I/O records by time and size.
  9. Score every link as exact (unique key), inferred (key plus time window) or heuristic (time only), and keep alternatives when ambiguous.
  • CIDs and tags are reused; always use (key, generation).
  • Several SQs can share one CQ; use the SQ ID in the CQE.
  • Capture gaps: a missing CQE may be a capture artefact. Check analyzer gap markers before declaring an anomaly.
  • IOMMU: device addresses are I/O virtual addresses; match against the host's mappings, not physical addresses.
  • Controller Memory Buffer queues: SQEs written by the host into device memory do not appear as device MRds.

Anomalies, the first abnormal event and hypotheses

Choosing the first abnormal event

The earliest anomaly is not automatically the first abnormal event. The selector:

  1. finds the reported failure on the timeline (for example the first I/O timeout);
  2. walks back along the entity graph from the failing command(s) collecting anomalies on the same entities, then on shared entities (the queue, the vector, the function, the link);
  3. down-weights anomalies that also occur in baseline windows without a failure (the capstone's Receiver Errors occurred at many harmless L1.2 exits);
  4. selects the earliest remaining anomaly and records why each earlier one was excluded;
  5. reports the result with a confidence that drops if alignment uncertainty overlaps neighbouring events.

Pipeline pseudocode

def investigate(inputs, config):
    raw = RawStore()
    events = []
    for path in inputs:
        parser = select_parser(path)            # fails loudly if none matches
        for ev in parser.parse(path):
            raw.keep(ev.raw_ref)
            events.append(ev)

    events = [decode(ev, decoders_for(ev, config.spec_revisions)) for ev in events]
    clocks = align(events, find_anchors(events))           # offsets, drift, uncertainty
    timeline = sorted(apply_alignment(events, clocks), key=lambda e: e.t_aligned.t)

    graph = Correlator(config).build(timeline)              # entities + scored links
    anomalies = RuleEngine(load_rules(config.rules)).run(graph, timeline)
    baseline = Baseline(config.golden_traces, passing_windows(timeline))
    for a in anomalies:
        a.also_in_baseline = baseline.contains(a)

    failure = locate_failure(timeline, config.symptom)      # e.g. first timeout
    fae, excluded = select_first_abnormal(anomalies, graph, failure, clocks)
    hyps = HypothesisEngine(config.library).propose(fae, anomalies, graph)
    for h in hyps:
        h.supports, h.contradicts = gather_evidence(h, graph, timeline)
        h.confidence = score(h)

    report = fill_template(timeline, graph, fae, excluded, hyps, config)
    write_html(report, raw)                                 # self-contained, linked evidence
    write_json(report)                                      # machine-readable bundle
    return report

A runnable miniature

The program below is a teaching-sized core of the platform: it reads a small synthetic, already-decoded event list, learns the queue configuration, classifies doorbells, pairs SQE fetches with their completions, attaches CQEs and MSI-X writes, applies rule CMD-04, chooses the first abnormal event and writes an HTML report. It uses only the Python standard library and runs as written. The sample input is a cut-down version of the Final Capstone.

"""forensic_mini.py - a teaching-sized core of the NVMe/PCIe forensic platform.
Standard library only. Input: a synthetic, already-decoded event list (CSV).
Output: correlated command timeline, anomalies, first abnormal event, HTML report."""
import csv, io, html

BAR0 = 0xFE600000
DSTRD = 0
SAMPLE = """t_us,src,dir,kind,addr,len,tag,data,note

45009200.0,pcie,up,MRd,0x123400040,16,0x11,,

def kv(s):
    return dict(p.split("=", 1) for p in s.split(";") if "=" in p) if s else {}

def load(text):
    rows = list(csv.DictReader(io.StringIO(text)))
    for r in rows:
        r["t"] = float(r["t_us"])
        r["a"] = int(r["addr"], 16) if r["addr"] else None
        r["kv"] = kv(r["data"])
    return sorted(rows, key=lambda r: r["t"])

def doorbell(addr):
    """Return ('SQ'|'CQ', qid) for a doorbell write, or None."""
    off = addr - BAR0 - 0x1000
    stride = 4 << DSTRD
    if off < 0 or off % stride:
        return None
    idx = off // stride
    return ("SQ" if idx % 2 == 0 else "CQ", idx // 2)

def correlate(rows):
    sq_base, cq_base, cq_of_sq, vec_of_cq, msix = {}, {}, {}, {}, {}
    cmds, pending_tag, anomalies = {}, {}, []
    for r in rows:
        k = r["kind"]
        if k == "create_cq":
            q = int(r["kv"]["qid"]); cq_base[q] = r["a"]; vec_of_cq[q] = int(r["kv"]["iv"])
            r["meaning"] = f"CQ{q} at {r['addr']}, vector {vec_of_cq[q]}"
        elif k == "create_sq":
            q = int(r["kv"]["qid"]); sq_base[q] = r["a"]; cq_of_sq[q] = int(r["kv"]["cqid"])
            r["meaning"] = f"SQ{q} at {r['addr']}, completes to CQ{cq_of_sq[q]}"
        elif k == "msix":
            msix[int(r["kv"]["vec"])] = (r["a"], int(r["kv"]["data"], 16))
            r["meaning"] = f"MSI-X vector {r['kv']['vec']}: {r['addr']} / {r['kv']['data']}"
        elif k == "MWr" and r["dir"] == "down" and doorbell(r["a"]):
            which, q = doorbell(r["a"])
            r["meaning"] = f"{which}{q} {'tail' if which == 'SQ' else 'head'} = {int(r['data'], 16)}"
        elif k == "MRd" and r["dir"] == "up":
            for q, b in sq_base.items():
                if b <= r["a"] < b + 64 * 1024:
                    pending_tag[r["tag"]] = (q, (r["a"] - b) // 64, r["t"])
                    r["meaning"] = f"SQE fetch SQ{q} slot {(r['a'] - b) // 64}"
        elif k == "CplD" and r["tag"] in pending_tag:
            q, slot, t0 = pending_tag.pop(r["tag"])
            cid = int(r["kv"]["cid"], 16)
            cmds[(q, cid)] = {"sq": q, "cid": cid, "opc": r["kv"]["opc"], "fetch": t0,
                              "cqe": None, "irq": None, "consumed": None}
            r["meaning"] = f"SQE for CID 0x{cid:04X}"
        elif k == "MWr" and r["dir"] == "up" and r["note"] == "CQE":
            cid, sq = int(r["kv"]["cid"], 16), int(r["kv"]["sqid"])
            c = cmds.get((sq, cid))
            if c:
                c["cqe"] = r["t"]
                c["cq"] = cq_of_sq[sq]
                r["meaning"] = f"CQE for SQ{sq} CID 0x{cid:04X}"
        elif k == "MWr" and r["dir"] == "up" and r["a"] is not None and (r["a"] >> 20) == 0xFEE:
            for v, (addr, data) in msix.items():
                if addr == r["a"] and data == int(r["data"], 16):
                    r["meaning"] = f"MSI-X vector {v}"
                    for c in cmds.values():
                        if (c["cqe"] is not None and c["irq"] is None and vec_of_cq.get(c.get("cq")) == v
                                and r["t"] - c["cqe"] <= 50.0):
                            c["irq"] = r["t"]
        elif k == "timeout":
            r["meaning"] = f"Linux timeout QID {r['kv']['qid']} CID {r['kv']['cid']} ({r['note']})"
    # rule: every CQE must be followed by its interrupt within 50 us
    for c in cmds.values():
        if c["cqe"] is not None and c["irq"] is None:
            anomalies.append((c["cqe"], "missing-msix",
                              f"CQE for SQ{c['sq']} CID 0x{c['cid']:04X} at {c['cqe']:.1f} us "
                              f"not followed by MSI-X vector {vec_of_cq[c['cq']]}"))
        if c["cqe"] is None:
            anomalies.append((c["fetch"], "missing-cqe", f"SQ{c['sq']} CID 0x{c['cid']:04X} never completed"))
    return cmds, sorted(anomalies)

def report(rows, cmds, anomalies):
    first = anomalies[0] if anomalies else None
    out = ["<!doctype html><meta charset='utf-8'><title>Forensic report</title>",
           "<h1>Forensic report (synthetic input)</h1>"]
    if first:
        out.append(f"<p><b>First abnormal event:</b> {html.escape(first[2])} [{first[1]}]</p>")
    out.append("<table border=1><tr><th>t (us)</th><th>event</th><th>meaning</th></tr>")
    for r in rows:
        bad = first and abs(r["t"] - first[0]) < 1e-9 and r["note"] == "CQE"
        style = " style='background:#fdd'" if bad else ""
        out.append(f"<tr{style}><td>{r['t']:.1f}</td><td>{html.escape(r['src'] + ' ' + r['kind'])}</td>"
                   f"<td>{html.escape(r.get('meaning', r['note']))}</td></tr>")
    out.append("</table>")
    return "\n".join(out)

if __name__ == "__main__":
    rows = load(SAMPLE)
    cmds, anomalies = correlate(rows)
    for (q, cid), c in sorted(cmds.items()):
        print(f"SQ{q} CID 0x{cid:04X} opc {c['opc']} fetch={c['fetch']:.1f} "
              f"cqe={c['cqe']} irq={c['irq']}")
    for a in anomalies:
        print("ANOMALY", a[1], "-", a[2])
    with open("forensic_report.html", "w", encoding="utf-8") as f:
        f.write(report(rows, cmds, anomalies))
    print("wrote forensic_report.html")

Test strategy

  • Unit tests for every decoder with the worked examples from the course (for example the header and command values in the final exam Parts C and D).
  • Golden traces: synthetic captures with known expected output, version-controlled (see Synthetic vs Real Traces, Diffing and Golden Traces).
  • Mutation tests (AC-4) to measure detection, and clean runs to measure false positives.
  • Property tests: random valid command streams must never raise anomalies; queue invariants must hold.
  • Review of rules and hypotheses by a second engineer, like code review.

Risks and limits

  • Proprietary formats. Analyzer capture files are vendor formats; rely on the vendor's export tools and documented export formats. Do not reverse-engineer formats you are not licensed to.
  • Specification access. Decoders for PCIe structures must be written from the PCI Express Base Specification, which is a PCI-SIG members' document; keep decoder tables reviewable and cite section names.
  • False confidence. A clean timeline can hide capture gaps and clock uncertainty. The report must show both.
  • Automation bias. Engineers may accept the tool's first abnormal event without checking. Make the evidence links the main interface, not an appendix.
  • Privacy. Traces contain user data; default to dropping payloads.
