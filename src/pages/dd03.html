Chapter 4 named the parts of a PCI Express (PCIe) tree. This module makes the tree do work: how each port decides where a Transaction Layer Packet (TLP) goes, how hierarchy domains bound what can reach what, how peer-to-peer traffic flows (or fails to), how Access Control Services (ACS) bend those paths for isolation, and how topology alone can cap NVM Express (NVMe) performance.

Orientation

Topology questions arrive disguised: "why can't I give this SSD alone to a virtual machine?", "why is SSD-to-GPU copy slower than going through memory?", "why do four drives behind this switch never exceed 14 GB/s?", "why does peer-to-peer work on one server and return Unsupported Request on another?". All four are answered by the routing rules of Root Ports, switches and bridges. This module turns the static tree of Chapter 4 into a routing machine you can simulate by hand.

Review Chapter 4 — PCIe Mental Model (Root Complex, Root Port, Switch, Endpoint, bridge) and Chapter 5 — PCIe Physical Architecture (links, width, speed). Bus numbers and Type 1 headers are introduced in Chapter 17; TLP routing fields in Chapter 11; I/O memory-management unit (IOMMU) groups in Module 02.

Next: Module 04 shows how software assigns the bus numbers and windows this module routes with; Module 05 decodes the Type 1 and ACS registers byte by byte.

Kid story

Picture a big river with streams branching off it, and streams branching off those. The city (the Root Complex) sits at the mouth. Every fork has a lock-keeper with a sign: "boats for the harbors numbered 3 to 6 go left; boats for docks with addresses between 1000 and 1999 go left; everything else goes downstream toward the city." Lock-keepers never look at the cargo — only at the label on the boat.

Two villages on neighboring streams can send boats directly to each other through their shared fork, without going down to the city. But some forks have a stern rule: "every boat must go to the city customs house first, even if its destination is next door." That is slower, but the customs officer can check every boat.

Analogy boundary

Represents. Forks are switches and Root Ports; signs are base/limit windows and secondary/subordinate bus ranges; boat labels are TLP addresses and IDs; going to the city is upstream routing; the customs rule is ACS P2P Request Redirect; the customs officer is the Root Complex with its I/O memory-management unit (IOMMU).

Hides. Every stream is a pair of one-way channels (each link is full-duplex). Boats are flow-controlled by credits per fork. Two boats crossing the same fork in opposite directions do not interfere, but two boats going the same way share bandwidth. Rivers have one city; a PCIe system may have several Root Complexes and segments.

Misleads. A real city does not always accept boats from one river branch bound for another branch (P2P between Root Ports is Optional). And lock-keepers are not quite cargo-blind: a port uses the TLP's Type field to pick the routing method, and ACS may check the sender's ID.

The ladder for "routing a TLP through the tree"

Lock-keepers read the boat's label and choose a stream; some forks send every boat to customs first.

Every port compares a TLP's address or ID with its own ranges and forwards it down, up or across.

Root Ports and switch ports are Type 1 bridges with bus ranges and windows; the switch has an internal fabric; the Root Complex has its own internal routing between Root Ports.

The PCI Express Base Specification defines routing by TLP type, Type 1 header semantics, and ACS. P2P between Root Ports is permitted but not required.

Memory TLPs use address routing; completions use ID routing; messages use implicit routing. ACS can redirect P2P requests and completions upstream.

Whether a TLP appears on a link depends on topology: a switch-local P2P write never appears on the upstream link; a redirected one appears there twice.

"Device unreachable" → check windows and bus ranges along the path; "slow P2P" → check ACS redirect; "UR on P2P" → check Root Complex P2P support.

Oversubscription

O = (Σi Bdown,i) / Bup
O
oversubscription ratio of a switch (1 means no oversubscription)
Bdown,i
usable bandwidth of downstream link i in one direction
Bup
usable bandwidth of the upstream link in the same direction

Example: eight Gen4 x4 SSDs (about 7.9 GB/s raw each, per direction) behind a Gen4 x16 upstream link (about 31.5 GB/s raw) give O ≈ 2. Aggregate read throughput to host memory cannot exceed the upstream link's usable rate, no matter how fast each drive is. Switch-local P2P traffic does not consume upstream bandwidth — unless ACS redirects it.

Well established: memory requests are address-routed; completions and configuration requests are ID-routed; messages use the routing indicated in their Type field; the non-prefetchable memory window of a Type 1 bridge is 32-bit with 1 MiB granularity; a switch is modeled as Type 1 bridges on an internal bus.

Derived: if a switch downstream port has P2P Request Redirect set, no P2P request from its link can reach a sibling without passing the Root Complex — so the IOMMU sees it, which is why Linux treats such functions as separately isolatable.

Implementation-dependent: whether the Root Complex routes P2P between Root Ports (and at what performance); whether it returns redirected P2P back down the same Root Port; switch internal latency and buffering; which ACS features a switch implements.

Version-dependent: newer revisions added ACS controls (for example enhanced capability variants) and Flit Mode changes header layout but not routing principles. Confirm the ACS bit list for your revision before decoding.

The specification does not say how fast P2P must be, that a Root Complex supports it at all, or how an operating system should form IOMMU groups. Those are platform and OS policy.

Never assume a TLP crossed a link because it crossed the tree; never assume ACS is enabled by default; never assume lspci -tv shows physical slots or retimers.

Capture point is a topology decision. An interposer between Root Port 00:02.0 and the switch sees everything SSD B exchanges with host memory but none of SSD B's switch-local P2P traffic. To prove P2P happened, capture on the target's link (05) or the source's link (04).

Ordering: PCIe ordering guarantees hold per path. A requester that writes data to a peer and then signals the host (for example with a Message Signalled Interrupts, extended (MSI-X) message or a Completion Queue Entry (CQE) write to host memory) uses two different paths; the signal can arrive before the data has reached the peer. Software that consumes peer data on such a signal must allow for it — one reason P2P designs read back from the target or rely on target-side completion.

#!/usr/bin/env python3
"""Route TLPs through the module's synthetic topology (simulation)."""

PORTS = {   # name: (parent, sec, sub, windows [(base, limit)], acs_redirect)
    "RP 00:01.1":  ("RC", 0x01, 0x01, [(0xFE60_0000, 0xFE6F_FFFF)], False),
    "RP 00:02.0":  ("RC", 0x02, 0x06, [(0xFE40_0000, 0xFE5F_FFFF), (0x60_0000_0000, 0x60_0FFF_FFFF)], False),
    "USP 02:00.0": ("RP 00:02.0", 0x03, 0x06, [(0xFE40_0000, 0xFE5F_FFFF), (0x60_0000_0000, 0x60_0FFF_FFFF)], False),
    "DSP 03:00.0": ("USP 02:00.0", 0x04, 0x04, [(0xFE40_0000, 0xFE4F_FFFF)], False),
    "DSP 03:01.0": ("USP 02:00.0", 0x05, 0x05, [(0x60_0000_0000, 0x60_0FFF_FFFF)], False),
    "DSP 03:02.0": ("USP 02:00.0", 0x06, 0x06, [(0xFE50_0000, 0xFE5F_FFFF)], False),
}
RC_P2P = False   # does the Root Complex route between Root Ports?

def children(name):
    return [p for p, v in PORTS.items() if v[0] == name]

def claims(port, addr=None, bus=None):
    _, sec, sub, wins, _ = PORTS[port]
    if bus is not None:
        return sec <= bus <= sub
    return any(b <= addr <= l for b, l in wins)

def port_above(bus):
    """The deepest port whose secondary bus equals the device's bus."""
    return next(p for p, v in PORTS.items() if v[1] == bus)

def route(src_bus, addr=None, dst_bus=None):
    hops, port = [f"device on bus {src_bus:02x}"], port_above(src_bus)
    while True:
        parent = PORTS[port][0]
        siblings = children(parent)
        hops.append(port)
        target = next((s for s in siblings if s != port and claims(s, addr, dst_bus)), None)
        if target and not PORTS[port][4] and parent != "RC":
            return descend(hops + [f"internal bus of {parent}"], target, addr, dst_bus)
        if parent == "RC":
            hops.append("Root Complex")
            dest = next((s for s in children("RC") if claims(s, addr, dst_bus)), None)
            if dest is None:
                return hops + ["UR: no port claims it (host memory or unsupported)"]
            if dest != port and not RC_P2P:
                return hops + [f"UR: Root Complex does not route {port} -> {dest}"]
            return descend(hops, dest, addr, dst_bus)
        port = parent

def descend(hops, port, addr, dst_bus):
    while True:
        hops.append(port)
        kids = [c for c in children(port) if claims(c, addr, dst_bus)]
        if not kids and children(port):
            return hops + ["UR: no downstream port claims it"]
        if not kids:
            return hops + [f"delivered on bus {PORTS[port][1]:02x}"]
        port = kids[0]

def show(title, **kw):
    print(title)
    print("   " + "\n   -> ".join(route(**kw)))

show("P2P write SSD B -> accelerator BAR", src_bus=0x04, addr=0x60_0000_1000)
show("Completion accelerator -> SSD B", src_bus=0x05, dst_bus=0x04)
show("SSD B -> Lab SSD CMB", src_bus=0x04, addr=0xFE68_0000)
for p in ("DSP 03:00.0",):
    PORTS[p] = PORTS[p][:4] + (True,)
show("Same P2P write with ACS redirect on 03:00.0", src_bus=0x04, addr=0x60_0000_1000)
Procedure
Run it; then set RC_P2P = True and rerun.
Observations
Local P2P stays inside the switch; the completion is ID-routed across the internal bus; cross-Root-Port P2P ends in UR unless RC_P2P is true; with redirect, the write climbs to the Root Complex and descends again.
Questions
(1) Which hop count grows with redirect? (2) Why does the cross-Root-Port case never reach link 01 when RC_P2P is false? (3) What would happen if DSP 03:01.0's window were missing the accelerator BAR?
Expected reasoning
The upstream links are crossed twice; the Root Complex rejects before forwarding; nobody below the switch claims the address, so it goes upstream and the Root Complex finds the RP 00:02.0 window claims it — sending it straight back down, where no downstream port claims it → UR.
Solution

Output paths (abbreviated): (1) bus 04 → DSP 03:00.0 → internal bus → DSP 03:01.0 → delivered on bus 05. (2) Completion: bus 05 → DSP 03:01.0 → internal bus → DSP 03:00.0 → delivered on bus 04. (3) bus 04 → DSP 03:00.0 → USP 02:00.0 → RP 00:02.0 → Root Complex → UR (no cross-RP routing). (4) With redirect: … → Root Complex → RP 00:02.0 → USP 02:00.0 → DSP 03:01.0 → delivered. The simulator is deliberately simple (it ignores I/O windows, prefetchable/non-prefetchable distinctions and ACS on completions); extending it is the extension task.

Advanced lab — Predict IOMMU groups from ACS

Safe lab

Objective
Predict which functions share an IOMMU group from ACS capabilities, then check against sysfs.
Prerequisites
Module 02.
Setup
A machine with at least one switch or multi-function device (many servers; some desktops' chipset ports).
Procedure
  1. For each bridge, record ACSCap/ACSCtl (Source Validation, Request Redirect, Completion Redirect, Upstream Forwarding).
  2. Rule of thumb: a function is isolated if every bridge between it and the Root Complex has Request Redirect, Completion Redirect and Upstream Forwarding enabled (and multi-function devices need ACS for peer functions).
  3. Write your predicted groups; compare with /sys/kernel/iommu_groups.
Observations
Matches and mismatches.
Questions
Explain every mismatch. Which bridge would you need ACS on to split the largest group?
Expected reasoning
Bridges without ACS merge everything below them into one group; Root Ports without ACS may also be grouped with their siblings on some platforms; kernel quirks can declare ACS-equivalent isolation for known hardware.
Solution

Typical findings: server switches advertise ACS and their downstream functions form separate groups; consumer chipset ports often lack ACS, so devices below them share a group with the chipset's Root Ports. Mismatches usually come from kernel quirks (vendor-specific isolation knowledge) — the kernel source's PCI quirks file lists them. Exact rules are kernel Version-dependent.

Extension: find the kernel's ACS quirk entries for your Root Port's vendor ID.

Senior forensic lab — P2P throughput halved after a kernel upgrade

Safe lab Paper exercise.

Objective
Explain a regression in GPU-direct style storage reads.
Prerequisites
All above.
Setup
Synthetic evidence: eight NVMe SSDs and two accelerators share a Gen4 switch (x16 upstream). Before: NVMe → accelerator P2P reads total 48 GB/s. After kernel upgrade: 26 GB/s; host-memory reads unaffected per drive but aggregate host + P2P traffic is capped near 26 GB/s. Upstream link counters show traffic in both directions roughly equal to the P2P rate. lspci -vvv after upgrade: ACSCtl on downstream ports shows ReqRedir+ CmpltRedir+; before: ReqRedir- CmpltRedir-. IOMMU groups went from one large group to one per device.
Procedure
First abnormal fact, hypotheses, disambiguation, conclusion, options.
Solution

First abnormal fact: ACS redirect bits changed from off to on. Consequence (derived): every P2P TLP now crosses the x16 upstream link up and down, so P2P throughput is bounded by the upstream link (about 26 GB/s usable in this synthetic case) and competes with host traffic. Hypotheses: the new kernel enables ACS redirect for isolation by default, or a driver (VFIO) requested it. Disambiguation: boot with the redirect disabled for these ports (pci=disable_acs_redir= on a test system) and confirm throughput returns and upstream counters drop. Conclusion: topology-level regression caused by isolation policy, not by drives. Options: accept isolation and redesign for host-staged copies; disable redirect where devices are in one trust domain (document the risk); or use ATS with Direct Translated P2P if the hardware and OS support it. Confidence: high.

Extension: write the design-review note in Senior Engineer Thinking style: trade-off, evidence, decision owner.

Interview

Beginner

  1. What is a Root Port?

    Model answer

    A Root Complex port, seen by software as a Type 1 bridge, that starts one hierarchy domain.

  2. How does software see a switch?

    Model answer

    As an upstream Type 1 bridge, an internal bus, and one Type 1 bridge per downstream port.

  3. How are memory requests routed?

    Model answer

    By address, compared with each bridge's base/limit windows.

  4. How are completions routed?

    Model answer

    By ID: the requester's bus number compared with secondary/subordinate ranges.

  5. What is peer-to-peer?

    Model answer

    One device sending requests to another device's BAR instead of host memory.

Intermediate

  1. Why must a 64-bit BAR behind a bridge sometimes be placed below 4 GiB?

    Model answer

    If it is non-prefetchable, only the bridge's 32-bit non-prefetchable window can carry it.

  2. What does Bus Master Enable on a bridge control?

    Model answer

    Whether the bridge forwards requests from its secondary side upstream; clear it and DMA from below stops.

  3. Name four ACS controls.

    Model answer

    Source Validation, Translation Blocking, P2P Request Redirect, P2P Completion Redirect (also Upstream Forwarding, P2P Egress Control, Direct Translated P2P).

  4. Where would you put an analyzer to prove switch-local P2P?

    Model answer

    On the source or target link, and ideally also the upstream link to show the traffic is absent there.

  5. What is an RCiEP?

    Model answer

    An Endpoint integrated in the Root Complex, without a link; it sits on a Root Complex bus.

Advanced

  1. Why does ACS shape IOMMU groups?

    Model answer

    Only traffic that reaches the Root Complex can be checked by the IOMMU; without redirect, siblings can talk directly and cannot be isolated from each other.

  2. Why might a P2P completion get lost while the request succeeded?

    Model answer

    Inconsistent ACS (completion redirect without request redirect), wrong bus ranges after renumbering, or switch bugs.

  3. Compute oversubscription for 12 Gen4 x4 SSDs behind a Gen5 x16 upstream.

    Model answer

    Raw: 12 × ~7.9 GB/s ≈ 94.5 GB/s vs ~63 GB/s → O ≈ 1.5.

  4. Why is cross-Root-Port P2P unreliable to depend on?

    Model answer

    The specification permits but does not require it; support and performance vary by platform.

  5. How do posted-write ordering guarantees interact with P2P plus host notification?

    Model answer

    They hold per path only; a notification to host memory can overtake data written to a peer.

Senior

  1. Design an NVMe JBOF topology for 24 drives and two hosts' worth of bandwidth. What do you check?

    Model answer

    Oversubscription per switch, upstream generation and width, failure domains per switch, DPC, hot-plug resource reservation, management sideband, P2P needs and ACS policy.

  2. A customer wants ACS override to pass devices to VMs. Your answer?

    Model answer

    It makes groups look isolated when traffic can still flow peer-to-peer; acceptable only if all devices are in one trust domain; prefer hardware with ACS.

  3. How would you validate a switch's routing?

    Model answer

    Window-edge addresses (base, limit, limit+1), ID ranges, P2P matrix with ACS combinations, hot-plug renumbering, error containment, all with captures on several links.

  4. Why distrust an lspci -tv diagram in a performance review?

    Model answer

    It shows logical bridges, not physical chips, retimers, bifurcation or degraded links; read LnkSta on every hop.

  5. A P2P read times out. What evidence settles whether the request or the completion was lost?

    Model answer

    Captures at the target link (did the request arrive, did the completion leave) and the upstream link (redirected completion?).

Quiz

  1. Which routing method does a CplD use?

    • Address
    • ID
    • Implicit
    • Broadcast
    Answer and reasoning

    Completions route by Requester ID's bus number.

  2. A switch-local P2P write without ACS redirect appears on:

    • All links
    • The upstream link only
    • The source and target links only
    • No link
    Answer and reasoning

    It goes through the switch's internal bus.

  3. The non-prefetchable memory window of a Type 1 bridge is:

    • 32-bit with 1 MiB granularity
    • 64-bit with 4 KiB granularity
    • Unlimited
    • Defined by the Endpoint
    Answer and reasoning

    Memory Base/Limit hold address bits 31:20.

  4. Which ACS control sends P2P requests to the Root Complex?

    • Source Validation
    • Translation Blocking
    • Upstream Forwarding
    • P2P Request Redirect
    Answer and reasoning

    Request Redirect; Upstream Forwarding governs what is forwarded upstream once redirected.

  5. In Trace 3, who generated the UR?

    Model answer

    The Root Complex (Completer ID RC): it would not route between Root Ports.

  6. Why can't the cross-Root-Port failure be seen on link 01?

    Model answer

    The request was rejected inside the Root Complex and never forwarded.

  7. Compute O for four Gen4 x4 drives behind a Gen4 x8 upstream.

    Model answer

    16 lanes' worth / 8 lanes' worth = 2.

  8. What is a hierarchy domain?

    Model answer

    The tree below one Root Port.

  9. True or false: an RCEC is a kind of Root Port.

    • True
    • False
    Answer and reasoning

    False: it collects events from RCiEPs and has no link.

Teach-back

To a child

Model explanation

"Data travels on boats down streams. At each fork a keeper reads the label and picks a stream. Neighbors can send boats straight to each other, unless the fork's rule says every boat must visit the city's customs first."

To a junior engineer

Model explanation

"Every port is a Type 1 bridge with a bus range and address windows. Memory TLPs go to whichever port's window contains the address; completions go by bus number. P2P inside a switch never touches the upstream link unless ACS redirects it. Cross-Root-Port P2P depends on the platform."

To a senior engineer

Model explanation

"Topology is the routing function plus the isolation function. ACS trades P2P locality for IOMMU visibility; oversubscription and capture-point choice decide what you can measure and how fast it can go. Cross-domain P2P is optional, so designs must be validated per platform."
