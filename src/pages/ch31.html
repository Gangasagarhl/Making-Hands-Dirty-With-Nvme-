The NVM Command Set is the I/O command set that makes an NVMe namespace behave like a block device: an array of fixed-size logical blocks you can read, write, flush, zero, deallocate, compare, verify and reserve. This chapter maps every command in the set, explains where the set sits in the 2.x specification family, and teaches the namespace properties every one of those commands depends on — LBA formats, metadata and end-to-end protection information.

Why this chapter exists

NVMe began life as one specification in which "the NVM command set" was simply the I/O half of the book. In the 2.x family the architecture changed: the Base Specification defines everything common to all command sets (queues, admin commands, status, the command format), and each I/O command set has its own document. The NVM Command Set — the block-storage command set — sits next to the Zoned Namespace, Key Value, Subsystem Local Memory and Computational Programs command sets. When you read a 2.x specification, a trace or a driver, you have to know which book defines which command.

More practically: almost every NVMe trace you will analyse is dominated by NVM Command Set I/O. Read and Write make up most of it, but Flush, Dataset Management (deallocate/TRIM), Write Zeroes and reservations appear in every real system, and each has a distinct traffic signature. Each also has properties — FUA, deallocation semantics, protection checks, reservation conflicts — that turn into bugs when misunderstood.

Learning objectives

  • Place the NVM Command Set (Revision 1.3) correctly relative to the NVMe Base Specification (Revision 2.4) and the other I/O command sets.
  • Recall the NVM Command Set I/O opcodes and the common LBA-range command layout (SLBA, NLB, control flags).
  • Explain Read, Write, Flush, Write Zeroes, Dataset Management, Compare, Verify, Write Uncorrectable and Copy — what each moves, what each guarantees and its PCIe traffic signature.
  • Explain the fused Compare-and-Write operation and reservation concepts (register, acquire, release, report; reservation types; conflicts).
  • Decode LBA formats from Identify Namespace: LBA data size, metadata size, extended vs separate metadata, relative performance.
  • Explain end-to-end protection information conceptually: the guard, application tag and reference tag, PI types, PRACT and PRCHK.
  • Recognise NVM command failures in traces and Linux: LBA out of range, reservation conflict, guard check errors.

Prerequisites

The SQE/CQE format and the Status Field (NVMe Command Structure); Identify Namespace and Format NVM (Admin Commands); namespaces and the 2.x architecture (NVMe 2.x Architecture); logical blocks and the idea of an LBA (What Is Storage?).

The story

Imagine one section of the library where every shelf has numbered slots, and every slot holds exactly one page — no more, no less. You can ask the librarian: "copy pages 100 to 107 for me" (read), "replace pages 100 to 107 with these" (write), "make sure everything you've written so far is glued in, not just lying on your desk" (flush), "make pages 500 to 599 blank" (write zeroes), "I don't need pages 2000 to 2999 any more, you can use that space for something else" (deallocate), "check these pages match what I have" (compare), "check you can still read these pages" (verify). Some pages also have a tiny sticky note on the side with a checksum and the page number, so if a page ever gets swapped or smudged, someone notices.

And if two classes share the section, one teacher can put a "only my class may write here" sign on it — that is a reservation.

An adult version: a warehouse of identical numbered pallet positions run by a warehouse management system. Pick (read) and put-away (write) are by position range; "confirm all put-aways are recorded in the ledger" is flush; "mark positions empty without moving anything" is deallocate; each pallet carries a tamper label (protection information) with a checksum and its position number, checked at every hand-off; and a tenant can lease exclusive put-away rights to a zone (reservation).

What it hides. The numbered slots are logical: the controller's flash translation layer places each block anywhere in NAND and moves it around constantly. "Blank" after deallocation is not necessarily zeroes — what a read returns depends on the namespace's reported deallocation behaviour. Where it misleads. A flush is not a "save" of the user's file — it only concerns data the controller has already accepted into a volatile cache; and the tamper label is only checked where the host and controller are configured to check it. A reservation is not a lock on a file; it governs which hosts' controllers may issue which commands to a namespace.

Beginner explanation

A namespace formatted for the NVM Command Set is a numbered list of equal-size blocks — often 512 bytes or 4096 bytes. Each block has a number called a Logical Block Address (LBA), starting at 0. The namespace's size in blocks is reported in Identify Namespace (NSZE).

Most commands in the set name a range of blocks with two fields: the Starting LBA (SLBA), a 64-bit number in CDW10–11, and the Number of Logical Blocks (NLB), a 16-bit 0's based count in CDW12. NLB = 0 means one block; NLB = 7 means eight. So a single command can name up to 65,536 blocks, but the controller's Maximum Data Transfer Size (MDTS) usually limits data-moving commands to much less.

Some commands move data (Read: device → host; Write and Compare: host → device). Others act on blocks without moving data across PCIe (Write Zeroes, Verify, Write Uncorrectable, Flush). Dataset Management moves only a small list of ranges. Reservation commands move small key/structure buffers.

Engineering explanation

Where the NVM Command Set sits in the specification family

Three practical consequences:

  • Command Set Identifier (CSI). In 2.x, each namespace is associated with an I/O command set identified by a CSI; the NVM Command Set is CSI 0h (long-established), Key Value and Zoned Namespace have their own values. The CSI appears in Identify selectors and the namespace identification descriptors. Verified for CSI 0h = NVM Command Set.
  • Two Identify Namespace structures. The NVM-specific namespace structure (CNS 00h for the NVM Command Set) carries LBA formats and PI capabilities; command-set-independent namespace data and per-command-set extensions live in other CNS structures.
  • Commands common to I/O sets. Commands such as Flush and the reservation commands are usable across I/O command sets; in the 2.x structure they are described in the Base Specification rather than in the NVM Command Set document. Uncertain — confirm current placement in the Base 2.4 table of contents before citing it.

In NVMe 1.4 and earlier, all of this was a single specification ("NVM Express Revision 1.4") and the NVM command set had no separate revision number. The NVM Command Set specification first appeared with the 2.0 library (as Revision 1.0) and is at Revision 1.3 in the August 2026 release. Older drivers, datasheets and analyzer decoders often cite 1.x section names that no longer exist.

The common LBA-range command layout

Read, Write, Compare, Write Zeroes, Verify and Write Uncorrectable share a layout for CDW10–15. Not every command uses every field.

Read (02h) and Write (01h)

Read and Write are the heart of the set and get full end-to-end chapters (READ, WRITE). Here are the controls they share:

  • Force Unit Access (FUA), CDW12 bit 30. For a Write: the data must be stored on non-volatile media before the command completes (not just in a volatile cache). For a Read: the data must be read from non-volatile media, after any pending volatile-cache content for those blocks has been committed.
  • Limited Retry (LR), CDW12 bit 31. Asks the controller to apply limited error-recovery effort and fail quickly rather than retry for a long time — useful when the host has another copy (RAID, replication).
  • PRINFO, CDW12 bits 29:26: Protection Information Action (PRACT, bit 29) and Protection Information Check (PRCHK, bits 28:26: guard, application tag, reference tag). Explained below.
  • Dataset Management hints (CDW13 bits 7:0): access frequency, latency, sequential, incompressible. Hints only; the controller may ignore them.
  • Directives (Write: directive type in CDW12, directive-specific value in CDW13 upper half) for streams and data placement, if enabled. Version-dependent

Flush (00h)

Flush commits data and metadata from any volatile write cache to non-volatile media, for writes that have completed before the Flush was submitted (or, more precisely, that the host has seen complete). If Identify Controller VWC reports no volatile write cache, Flush has nothing to do and completes quickly. Flush transfers no data; its traffic signature is SQE fetch → (possibly long pause) → CQE. Whether NSID = FFFFFFFFh (flush all namespaces) is supported is reported in Identify Controller in newer revisions. Version-dependent Full treatment: FLUSH.

Flush does not order or wait for writes that are still outstanding. A host that wants "write X then make it durable" must wait for X's completion before submitting Flush (or use FUA on X). This is the most common durability bug in storage software.

Write Zeroes (08h)

Write Zeroes sets a range of blocks to zero (and the protection information to the defined values, if PI is enabled) without transferring a buffer. A Deallocate bit in CDW12 lets the host ask the controller to deallocate the blocks instead of writing zeroes, provided reads of deallocated blocks are guaranteed to return zeroes (reported in the namespace's deallocation behaviour fields). Because no data moves over PCIe, Write Zeroes is far cheaper on the link than a Write of zeroes. Linux uses it for BLKZEROOUT and fallocate zeroing. Uncertain on the exact Deallocate bit position (CDW12 bit 25 in long-standing revisions) — confirm in the NVM Command Set specification.

Dataset Management (09h)

Dataset Management (DSM) carries a list of up to 256 LBA ranges and attributes. CDW10 bits 7:0 hold the Number of Ranges (NR), 0's based. CDW11 holds attribute flags: Integral Dataset for Read (IDR, bit 0), Integral Dataset for Write (IDW, bit 1), and Attribute – Deallocate (AD, bit 2). The data buffer contains 16-byte range descriptors:

Dataset Management range descriptor (16 bytes)
BytesField
3:0Context Attributes (per-range hints)
7:4Length in logical blocks (not 0's based)
15:8Starting LBA

With AD set, DSM is the NVMe equivalent of ATA TRIM / SCSI UNMAP: it tells the controller that the data in those ranges is no longer needed, letting the flash translation layer drop mappings and reduce garbage-collection work. What a later read of a deallocated block returns (all zeroes, all ones, or unchanged) is reported per namespace. Full treatment: Dataset Management.

A DSM with AD set is a hint in one sense and a state change in another. The controller may decline to deallocate some blocks, yet if the namespace reports that deallocated blocks read as zeroes, hosts and filesystems may depend on that behaviour. Validation must test both what is deallocated and what reads return.

Compare (05h) and fused Compare-and-Write

Compare sends host data and asks the controller to compare it with the stored blocks; a mismatch completes with Compare Failure (media and data integrity status 85h). Alone it is a verification tool. Fused with a Write (FUSE = 01b on the Compare, 10b on the Write, in adjacent SQ slots), it becomes an atomic compare-and-write: the Write executes only if the Compare matched, and no other command may modify the blocks in between. This is how clustered systems implement atomic test-and-set on shared storage. Support is reported in Identify Controller (Fused Operation Support).

Verify (0Ch)

Verify checks that the specified blocks can be read and, if PI is enabled and checks are requested, that their protection information is correct — without transferring the data to the host. It is a cheap scrub: the link stays idle; only the CQE carries the result.

Write Uncorrectable (04h)

Write Uncorrectable marks blocks as invalid so that subsequent reads return an Unrecovered Read Error until the blocks are written again. It exists for testing error handling paths in hosts and RAID software. In a validation lab it is how you manufacture a media error on purpose.

Copy (19h)

Copy reads one or more source ranges and writes them to a destination range in the same namespace, inside the controller. The host supplies a list of source range descriptors in a data buffer; the destination SLBA is in the command. Copy avoids moving data across PCIe twice and is used for garbage collection by host-managed layouts and for snapshots. Descriptor formats have multiplied across revisions (including cross-namespace copy in later revisions). Version-dependent

Reservations

Reservations let multiple hosts sharing a namespace (through different controllers of one NVM subsystem, or over fabrics) coordinate access, in the same spirit as SCSI Persistent Reservations. The concepts:

  • Host Identifier and reservation key. Each host registers a 64-bit key with Reservation Register. Registration is per host (all controllers of the same host share it).
  • Reservation holder and type. A registrant takes a reservation with Reservation Acquire, choosing a type: Write Exclusive (1h), Exclusive Access (2h), Write Exclusive – Registrants Only (3h), Exclusive Access – Registrants Only (4h), Write Exclusive – All Registrants (5h), Exclusive Access – All Registrants (6h).
  • Preempt. Acquire can preempt another host's registration (and optionally abort its commands) — the tool for fencing a failed cluster node.
  • Release / Clear. Reservation Release releases the reservation or clears all registrations.
  • Report. Reservation Report returns the reservation status data structure: generation counter, type, registrant list.
  • Conflict. A command not permitted by the current reservation completes with Reservation Conflict (generic status 83h). Notifications of preemption and release can be delivered through a log page and asynchronous events.

Reservation types are about who may write and who may read. "Write Exclusive" lets everyone read but only the holder write; "Exclusive Access" blocks reads too. "Registrants Only" extends the permission to every registered host; "All Registrants" makes every registrant a holder. Draw the 6 × (holder, registrant, non-registrant) × (read, write) table once and you will never confuse them again.

Metadata: extended versus separate

When MS > 0, each logical block carries extra bytes. They can travel two ways:

Extended LBAs make every block 520 bytes (or 4104, etc.) in the host buffer, which breaks the "block = power of two" assumption of most operating systems; this is why general-purpose hosts favour separate metadata (or none). Separate metadata uses the SQE's Metadata Pointer (MPTR), introduced in NVMe Command Structure.

End-to-end protection information

Protection Information (PI) is a small tuple stored in the metadata of each block, designed to detect corruption or misplacement anywhere between the application and the media. The classic 8-byte format (inherited from T10 DIF in SCSI) has three fields:

Two command controls, together the PRINFO field, decide who generates and who checks PI:

  • PRACT (Protection Information Action, CDW12 bit 29). Set: the controller inserts PI on writes and strips it on reads — the host sees plain data (with an 8-byte metadata format, the metadata is not transferred at all). Clear: the host supplies and receives PI in the metadata and the controller passes it through.
  • PRCHK (Protection Information Check, CDW12 bits 28:26: bit 28 guard, bit 27 application tag, bit 26 reference tag). Which fields the controller checks.

A check failure completes the command with a media and data integrity status: End-to-end Guard Check Error (82h), End-to-end Application Tag Check Error (83h), or End-to-end Reference Tag Check Error (84h), all with SCT 2h. Linux prints these as 0x282, 0x283, 0x284.

NVMe 2.0 added extended protection information formats with 32-bit and 64-bit guards (CRC-32C / CRC-64 based) and storage tags, described by Extended LBA Format structures and using additional command fields. This chapter teaches the concept with the classic 16-bit guard; consult the NVM Command Set specification, Revision 1.3, for the extended formats' exact fields before decoding them.

The ladder for the central concept: an LBA-range command

"Do this to pages 100 to 107 of my section" — one slip names a start page, a count and a verb.

An NVM I/O command: opcode (Read/Write/Write Zeroes/Verify…), NSID, SLBA in CDW10–11, NLB (0's based) in CDW12, flags (FUA, LR, PRINFO), and a data pointer when data moves.

The controller checks SLBA + NLB ≤ NSZE and the transfer ≤ MDTS, translates LBAs to physical NAND locations through its mapping table, schedules NAND operations across channels and dies, and moves data with its DMA engine.

The NVM Command Set Specification 1.3 defines each command's CDW10–15, behaviour and command-set status values; the Base Specification defines the queues, format and generic statuses.

Over PCIe: doorbell MWr, SQE MRd/CplD, then — depending on the command — data MWr (Read), data MRd/CplD (Write, Compare, DSM range list) or nothing (Write Zeroes, Verify, Flush), then CQE MWr and MSI-X MWr.

The analyzer view distinguishes commands by data pattern as much as by opcode: Write Zeroes of 1 GiB looks like two tiny exchanges and a long gap; a Write of 1 GiB of zeroes is thousands of read completions.

For a failing command, check range validity (LBA Out of Range), format (PI enabled? extended metadata?), reservation state (Reservation Conflict), and ONCS support (Invalid Command Opcode) before suspecting media.

The sixteen questions, answered for an LBA-range command

1. What is it?
An I/O command naming a namespace, a starting LBA and a block count, with optional data.
2. Why was it created?
To expose flash as a simple, OS-friendly block device with minimal per-command overhead.
3. What problem does it solve?
Uniform addressing of storage regardless of internal NAND geometry, with one compact command per contiguous range.
4. What existed before it?
SCSI READ(10/16)/WRITE(10/16) CDBs and ATA READ/WRITE DMA EXT; NVMe keeps the LBA model and drops the legacy layers.
5. Why is the current design better?
Fixed fields at fixed offsets, a 64-bit SLBA, rich per-command controls (FUA, LR, PI, hints) and no translation layer in the host.
6. Who creates it?
The host NVMe driver, from block-layer requests.
7. Who consumes it?
The controller's I/O path (front-end, FTL, NAND back-end, DMA).
8. Where does it live?
In an I/O SQ; data in host buffers described by PRP/SGL; metadata possibly via MPTR.
9. What memory/registers are involved?
I/O SQ/CQ, doorbells, data/metadata buffers, PRP lists; Identify Namespace (NSZE, FLBAS, LBAF, DPS) and Identify Controller (MDTS, ONCS, VWC).
10. What happens before it?
Namespace discovery and format selection; the block layer splits requests to fit MDTS and alignment.
11. What happens after it?
CQE, interrupt, block-layer completion, possibly a Flush for durability.
12. What happens if it is wrong?
LBA Out of Range, Invalid Field, PI check errors, data at the wrong LBA, reservation conflicts.
13. What does the protocol analyzer show?
The command's SQE, its data traffic signature, and its CQE.
14. What does Linux show?
Block-layer stats (/proc/diskstats, iostat), nvme tracepoints with SLBA/length, error messages with status, queue limits in sysfs.
15. What would a validation engineer test?
Boundary LBAs (0, NSZE − 1, NSZE), NLB extremes, MDTS edges, every flag, every PI type and check combination, deallocated-read behaviour, reservations under multiple hosts.
16. What would a senior engineer suspect when it fails?
Host-side splitting/alignment, format/PI configuration mismatch between host and namespace, shared-namespace reservations, then the controller.

Hardware view

Every NVM command ends up in the controller's flash translation layer (FTL), which maps LBAs to physical NAND pages. Each command type exercises a different part of the controller:

What each NVM command does inside a typical controller (implementation-dependent)

WriteDMA read from host into write bufferAllocate new physical location, update mapping, invalidate oldProgram (often deferred and aggregated)
FlushnonePersist mapping table updates if cachedProgram pending write-buffer content

Protection information is checked by hardware engines at several points: when data enters the controller from PCIe, before it is written to NAND, when it is read back, and before it is sent to the host. A guard error therefore tells you that a block was corrupted somewhere along the path, and the controller's own logs (if available) may say where. Many consumer drives support no PI at all — DPC = 0 — so the whole mechanism is absent.

Whether Flush and FUA cost anything depends on hardware. Drives with power-loss protection capacitors can report no volatile write cache (VWC = 0): accepted writes are already safe, so Flush is trivial. Drives without it buffer writes in DRAM or SRAM and must program NAND on Flush or FUA — which is why FUA writes can be several times slower on such drives.

Traffic signatures (which commands move data over PCIe and in which direction) follow from each command's data-transfer definition and opcode direction bits. "Write Zeroes is cheaper than writing zeroes" is reasoned from the absence of a data transfer, not a specification promise about time.

Whether deallocation actually frees space immediately, how long Flush takes, whether Write Zeroes is implemented as a map operation or a media write, whether DSM hints are used, the controller's internal PI check points, and the relative performance of LBA formats are implementation-dependent. Deallocated-read behaviour is reported by the namespace and must be read, not assumed.

The split of the NVM Command Set into its own document (2.0 library), extended LBA formats and extended PI (2.0), Copy descriptor formats, Flush broadcast support reporting, directive and data-placement fields, and new commands such as Cancel or I/O management for Flexible Data Placement are revision-dependent. Revision 1.3 of the NVM Command Set accompanies Base 2.4.

Check in the specification:

  • The exact bits of CDW12 bits 25:16 and CDW13 for each command (deallocate, storage tag check, directive type).
  • Placement of Flush and reservation commands in Base vs NVM Command Set for your revision.
  • The extended PI formats' guard algorithms and tag widths.
  • Atomicity guarantees (AWUN, AWUPF, NAWUN, NAWUPF, boundaries) before relying on any multi-block write being atomic.

The specification does not say that deallocated blocks read as zero unless the namespace reports so; that a Flush is fast; that DSM hints are honoured; or in what order overlapping commands submitted together are executed.

Never assume a write is durable before Flush or FUA when VWC = 1. Never assume overlapping writes in flight execute in submission order. Never assume a 4 KiB write is atomic across power loss unless the atomicity fields say so. Never assume PI is checked just because the namespace is formatted with it — PRCHK chooses what is checked per command.

Reading it. The doorbell jumped by two, so two SQEs are fetched (rows 2–3; the controller chose two 64-byte reads). The DSM's only data is a single 16-byte read (rows 6–7); note the range length (0x800) is a 1-based count, unlike NLB. Write Zeroes for 32 MiB generated zero data TLPs — its 182 µs is entirely internal. Had the host instead issued Writes of 32 MiB of zero bytes, the controller would have had to fetch them: 32 MiB / 512-byte MRRS = 65,536 MRd TLPs answered by at least 131,072 CplD TLPs (at most 256 bytes each at MPS 256). Avoiding that is the whole point of Write Zeroes.

When a command fails within a few microseconds with no data TLPs, the controller rejected it during validation — range, format, reservation, opcode support. When it fails after data or after tens of microseconds, the controller tried the media. Timing is evidence.

Linux view

Linux maps block-layer operations onto NVM commands: reads → Read; writes → Write; REQ_FUA → FUA bit; flush requests → Flush; discard → Dataset Management with Attribute – Deallocate; write-zeroes → Write Zeroes; persistent-reservation ioctls on the block device → the reservation commands. Implementation-dependent (driver policy; e.g. discards may be disabled by quirks).

Code / pseudocode

The script decodes the LBA-format portion of a synthetic Identify Namespace structure (the reference system's namespace 1) and builds and checks Type 1 protection information with the CRC-16 T10-DIF guard. It asserts the published CRC check value for "123456789" (0xD0DB) so you know the CRC is right.

#!/usr/bin/env python3
"""Two NVM Command Set helpers, standard library only.
1. Decode the LBA-format part of a (synthetic) Identify Namespace structure.
2. Build and check the 8-byte protection information tuple (16-bit guard)."""
import struct

def decode_lbafs(idns):
    nsze, ncap, nuse = struct.unpack_from("<QQQ", idns, 0)
    nlbaf, flbas, mc, dpc, dps = idns[25], idns[26], idns[27], idns[28], idns[29]
    cur = flbas & 0x0F                      # low 4 bits of the format index
    print(f"NSZE={nsze} NCAP={ncap} NUSE={nuse}  NLBAF={nlbaf} (0's based)")
    print(f"FLBAS=0x{flbas:02X}: format {cur}, metadata "
          f"{'extended (interleaved)' if flbas & 0x10 else 'separate buffer'}")
    pit = dps & 7
    where = ("first" if dps & 8 else "last") + " 8 bytes of metadata"
    print(f"MC=0x{mc:02X} DPC=0x{dpc:02X} DPS=0x{dps:02X} -> "
          + (f"PI type {pit}, in the {where}" if pit else "protection information disabled"))
    for i in range(nlbaf + 1):
        (lbaf,) = struct.unpack_from("<I", idns, 128 + 4 * i)
        ms, lbads, rp = lbaf & 0xFFFF, (lbaf >> 16) & 0xFF, (lbaf >> 24) & 3
        mark = "  <- in use" if i == cur else ""
        print(f"  LBAF{i}: data {1 << lbads:5d} B  metadata {ms:2d} B  RP={rp}{mark}")
    lbads = (struct.unpack_from("<I", idns, 128 + 4 * cur)[0] >> 16) & 0xFF
    print(f"capacity = {nsze} x {1 << lbads} B = {nsze * (1 << lbads) / 1e9:.1f} GB")

def crc16_t10dif(data):
    crc = 0
    for b in data:
        crc ^= b << 8
        for _ in range(8):
            crc = ((crc << 1) ^ 0x8BB7) if crc & 0x8000 else crc << 1
            crc &= 0xFFFF
    return crc

def pi_tuple(block, app_tag, ref_tag):
    # Guard, Application Tag, Reference Tag; PI fields are big-endian on the media
    return struct.pack(">HHI", crc16_t10dif(block), app_tag, ref_tag)

def check(block, pi, lba, type1=True):
    guard, app, ref = struct.unpack(">HHI", pi)
    ok_guard = guard == crc16_t10dif(block)
    ok_ref = (ref == (lba & 0xFFFFFFFF)) if type1 else True
    return ok_guard, ok_ref

if __name__ == "__main__":
    assert crc16_t10dif(b"123456789") == 0xD0DB      # published check value
    idns = bytearray(4096)
    struct.pack_into("<QQQ", idns, 0, 0x74706DB0, 0x74706DB0, 0x1A2B3C)
    idns[25], idns[26], idns[28], idns[29] = 3, 0x00, 0x1F, 0x00
    for i, (ms, lbads) in enumerate([(0, 9), (8, 9), (0, 12), (8, 12)]):
        struct.pack_into("<I", idns, 128 + 4 * i, ms | lbads << 16)
    decode_lbafs(bytes(idns))
    block = bytes(range(256)) * 2                      # one 512-byte block
    pi = pi_tuple(block, 0x0000, 1048576)
    print("PI tuple for LBA 1048576:", pi.hex(" "))
    print("check good block :", check(block, pi, 1048576))
    bad = bytearray(block); bad[100] ^= 0x01
    print("check flipped bit:", check(bytes(bad), pi, 1048576))
    print("check wrong LBA  :", check(block, pi, 1048577))

Expected output: NSZE/NCAP 1953525168, four LBA formats with format 0 (512 B, no metadata) in use, "protection information disabled", capacity ≈ 1000.2 GB, a PI tuple 4f 10 00 00 00 10 00 00 for LBA 1048576 (guard 0x4F10, application tag 0, reference tag 0x0010_0000), then check results (True, True), (False, True) for a flipped bit (guard fails) and (True, False) for the wrong LBA (reference tag fails).

    switch op:
      READ:         return Read (02h)    + FUA if op.fua

    if ns.pi_type != 0:

Worked example

Example 1 — choosing a format and computing capacity

Synthetic example for teaching. Identify Namespace for NSID 2 reports NSZE = 0x0000_0000_0E8E_0DB6 (244,190,646), NLBAF = 1, FLBAS = 0x01, LBAF0 = 0x0009_0000, LBAF1 = 0x000C_0000.

  • FLBAS bits 3:0 = 1 → LBAF1 in use. LBAF1: MS = 0, LBADS = 0x0C = 12 → 4096-byte blocks, RP = 0.
  • Capacity = 244,190,646 × 4096 = 1,000,204,886,016 bytes ≈ 1.0 TB (the same capacity as namespace 1's 1,953,525,168 × 512).
  • A 4 KiB read is NLB = 0 (one block) here, but NLB = 7 on namespace 1.

Example 2 — a Write with host-generated Type 1 PI

Namespace formatted 512 + 8 with separate metadata (FLBAS bit 4 = 0), PI Type 1 in the last 8 bytes. The host writes 2 blocks at LBA 0x10_0000 and generates PI itself:

  • Data buffer: 1024 bytes (PRP1). Metadata buffer: 16 bytes (MPTR).
  • Metadata block 0: guard = CRC16(data[0:512]), app tag = 0, ref tag = 0x0010_0000. Block 1: guard = CRC16(data[512:1024]), app tag = 0, ref tag = 0x0010_0001.
  • CDW12: NLB = 1, PRACT = 0, PRCHK = 111b (bits 28:26), FUA = 0 → 0x1C00_0001.
  • CDW14: initial reference tag = 0x0010_0000 (for Type 1 it must match the low 32 bits of SLBA). CDW15: application tag mask = 0 (do not check the app tag), app tag = 0 — the PRCHK app-tag bit has no effect with a zero mask.

If a software bug placed the second block's data at LBA 0x10_0002, a later read with reference-tag checking would fail with End-to-end Reference Tag Check Error (SCT 2h, SC 84h): PI turns silent misplacement into a loud error.

Example 3 — a DSM range descriptor in bytes

Deallocate 2048 blocks starting at LBA 0x20_0000: 00 00 00 00 (context attributes) 00 08 00 00 (length 0x800, not 0's based) 00 00 20 00 00 00 00 00 (SLBA). Command: OPC 09h, CDW10 = 0 (NR 0's based → one range), CDW11 = 0x4 (AD).

Common mistakes

  • Mixing 0's based and 1-based counts. NLB and DSM NR are 0's based; the DSM range length is not.
  • Assuming 512-byte blocks. Many namespaces use 4096-byte LBAs; the same byte offset is a different LBA.
  • Flushing before writes complete and believing the writes are durable.
  • Assuming discard returns zeroes. Only if the namespace says so.
  • Setting PRACT and also providing PI in an 8-byte metadata buffer — with PRACT = 1 and MS = 8, the metadata is not transferred, so the host's PI is ignored.
  • Type 1 reference tag ≠ SLBA low bits — every PI-checked command then fails with a reference tag error.
  • Sending optional commands without checking ONCS → Invalid Command Opcode.
  • Treating Reservation Conflict as a device error and retrying forever: it is a policy decision of the cluster.
  • Confusing Verify with Compare. Verify checks readability (and PI); Compare checks content against host data.

Senior engineer insight

A senior engineer thinks of the NVM Command Set as a set of contracts with explicit limits: atomicity units, deallocation behaviour, cache volatility, protection type, reservation type. Every one is advertised by the device, and every one is frequently assumed rather than read. Most field incidents involving "data corruption" on NVMe turn out to be a host relying on a property the namespace never promised — zeroes after discard, atomic 16 KiB writes, durable writes without Flush.

Second, use the traffic signature as a fast classifier. In a large capture, sort commands by (opcode, bytes moved, latency). Write Zeroes with data, DSM with megabytes of range lists, or Reads that are slower than Writes stand out immediately and are worth a look.

Third, PI is the cheapest forensic tool in storage. When a platform supports it, enabling Type 1 PI with host generation turns silent misplacement and corruption into precise, LBA-tagged errors that tell you which layer to blame. Many teams only discover this after a long corruption hunt.

Answers

1: Namespace 1: SLBA = 1 GiB / 512 = 2,097,152 = 0x20_0000 → CDW10 = 0x0020_0000, CDW11 = 0, NLB = 256 − 1 = 255 → CDW12 = 0x0000_00FF. Namespace 2: SLBA = 262,144 = 0x4_0000 → CDW10 = 0x0004_0000, NLB = 32 − 1 = 31 → CDW12 = 0x0000_001F. (Both need MDTS ≥ 128 KiB.)

2: NR = 255 → 256 ranges × 16 bytes = 4096 bytes.

3: Flush, Write Zeroes, Verify, Write Uncorrectable (and Copy apart from descriptors). With no data transfer, the SQE-fetch-to-CQE time isolates controller-internal and media time from link transfer time.

4: Under Write Exclusive, a non-registrant may read but not write. Under Exclusive Access – Registrants Only, a non-registrant may neither read nor write; registrants may.

5: Guard (PRCHK bit 28 → the 100b pattern). The data's CRC did not match the stored guard: corruption somewhere between PI generation and check, or a CRC algorithm mismatch.

6: It decides whether metadata is interleaved with data in the data buffer (extended LBA) or transferred through MPTR, which changes buffer sizes, PRP layouts and alignment.

Quiz

  1. Which document defines the Read command's CDW10–15 in the 2.x family?

    • NVMe Base Specification
    • NVM Command Set Specification
    • NVMe over PCIe Transport Specification
    • PCI Express Base Specification
    Answer and reasoning

    The NVM Command Set Specification (Revision 1.3 in the 2026 set). The Base defines the common format; the transport defines how it moves.

  2. Opcode 08h on an I/O queue is:

    • Verify
    • Dataset Management
    • Write Zeroes
    • Compare
    Answer and reasoning

    08h Write Zeroes; 09h DSM; 0Ch Verify; 05h Compare.

  3. NLB = 0 in a Read means:

    • One block
    • No blocks
    • Maximum transfer
    • Invalid field
    Answer and reasoning

    NLB is 0's based.

  4. FUA on a Write guarantees:

    • The write is atomic
    • The write executes before later writes
    • The cache is flushed for all blocks
    • This command's data is on non-volatile media before completion
    Answer and reasoning

    FUA concerns only the command's own data; it implies nothing about ordering or atomicity, and nothing about other cached data.

  5. LBADS = 12 means a logical block of:

    • 12 bytes
    • 512 bytes
    • 4096 bytes
    • 12 KiB
    Answer and reasoning

    212 = 4096.

  6. In PI Type 1, the reference tag is:

    • Not checked
    • The low 32 bits of the LBA
    • A host-chosen value incrementing from CDW14
    • The application tag mask
    Answer and reasoning

    Type 1 binds the tag to the LBA; Type 2 uses the command's initial value; Type 3 does not check it.

  7. What status does a write blocked by another host's reservation return?

    Model answer

    Reservation Conflict: SCT 0h (generic), SC 83h.

  8. Why is Write Zeroes preferred over writing a buffer of zeroes?

    Model answer

    It transfers no data over PCIe and lets the controller implement zeroing as a mapping operation; a zero-buffer write consumes link bandwidth, host memory bandwidth, and NAND program/erase cycles.

  9. What makes a Compare-and-Write atomic?

    Model answer

    Fusing: Compare with FUSE = 01b in one SQ slot immediately followed by Write with FUSE = 10b. The controller executes them as a unit; the Write occurs only if the Compare matched and no other command intervenes on those LBAs.

Interview questions

  1. Beginner. Name the mandatory NVM I/O commands.

    Model answer

    Read, Write and Flush. Others (Compare, Write Zeroes, DSM, Verify, Write Uncorrectable, reservations, Copy) are optional and reported in ONCS or related fields.

  2. Beginner. What is the difference between Flush and FUA?

    Model answer

    Flush makes all previously completed writes in the volatile cache durable; FUA makes one command's data durable (or read from media) before it completes.

  3. Intermediate. What is an LBA format, and how do you change it?

    Model answer

    An entry in Identify Namespace giving data size (LBADS), metadata size (MS) and relative performance (RP). The one in use is chosen by FLBAS and changed by Format NVM, which erases the namespace.

  4. Intermediate. Explain DSM deallocate and what reads of deallocated blocks return.

    Model answer

    DSM with AD tells the controller the ranges are unused so it can drop mappings. Read behaviour for deallocated blocks is reported per namespace (e.g. zeroes, ones, or not reported); hosts must check before relying on it, or use Write Zeroes when zeroes are required.

  5. Advanced. Walk through end-to-end protection on a read with PRACT = 0 and PRCHK = 111b.

    Model answer

    The controller reads data and PI from media, checks the guard (CRC-16 over the data), application tag (under the CDW15 mask) and reference tag (Type 1: LBA, Type 2: from CDW14), and if all pass transfers data plus PI to the host (extended or via MPTR); the host can check again. A failure completes with SCT 2h and SC 82h/83h/84h.

  6. Advanced. How would you test reservations?

    Model answer

    Two or more hosts (or host IDs) on different controllers; for each of the six types, check read/write permission for holder, registrant and non-registrant; preempt and preempt-and-abort with I/O in flight; persistence across resets and power cycles (Persist Through Power Loss); notifications (log page and AER); Report correctness and generation counter.

  7. Senior. A database reports torn pages after power loss on a drive with VWC = 1. How do you approach it?

    Model answer

    Establish what the database assumes (atomic write size, durability points). Read AWUN/AWUPF/NAWUPF and boundaries; check whether the database's page size fits the power-fail atomicity. Trace write, FUA and Flush ordering: are Flushes issued after the relevant write CQEs? Then test with controlled power cuts. Most often the host assumed atomicity the device never promised, or flushed too early.

  8. Senior. Why did NVMe 2.0 split command sets into separate specifications, and what does it change for you?

    Model answer

    To let new command sets (ZNS, KV, SLM, Computational Programs) evolve independently on a shared base. For an engineer it means citing the right document and revision for each command, checking CSI in Identify, and knowing that NVM-specific fields (LBA formats, PI) live in the NVM Command Set document.

Model explanation for the child

"The pages get moved around a lot in the back room, by machines, very fast. Once in a long while a machine might put a page in the wrong slot or smudge it. So every page has a little sticky note with a secret number made from the words on the page, and the page's own slot number. When you ask for page 100, the librarian checks the note: if the note says 101, or the secret number doesn't match the words, she knows something went wrong and tells you instead of giving you the wrong page."

Chapter summary

The NVM Command Set (Revision 1.3, alongside Base 2.4) turns a namespace into an array of logical blocks. Its commands — Read, Write, Flush (mandatory), and Write Uncorrectable, Compare, Write Zeroes, Dataset Management, Verify, reservations and Copy (optional) — share an LBA-range layout: SLBA in CDW10–11, 0's based NLB in CDW12 with LR, FUA and PRINFO. Each has a distinct PCIe traffic signature. The namespace's LBA format (LBADS, MS), metadata placement (extended or separate via MPTR) and protection information (guard, application tag, reference tag; Types 1–3; PRACT/PRCHK) define the contract every command depends on, and must be read from Identify rather than assumed.

Do not move on until you can:

  • list the NVM Command Set opcodes and which are mandatory
  • build CDW10–12 for any LBA-range command by hand
  • predict each command's PCIe traffic signature
  • decode LBA formats and FLBAS/DPS from Identify Namespace
  • explain PI generation and checking with PRACT and PRCHK, and name the three check-error statuses
  • explain the six reservation types and Reservation Conflict
  • say which document and revision defines each piece
