1B Deep Dive — DMA and Address Translation

Every byte an NVMe SSD moves goes by DMA. Every DMA uses an address that someone had to compute, translate and permit. Most of the scariest storage bugs — silent corruption, “impossible” data in the wrong buffer, a system that hangs only with the IOMMU on — live in this module. It builds on §1.7 Virtual memory, §1.8 Physical memory and §1.15 DMA.

1B.2 A fresh story — the delivery robot and the address book

🧒 Kid analogy

A delivery robot (the device) brings parcels to an enormous apartment building (memory). The robot cannot read people's names — it only understands door numbers. Families use nicknames for their rooms (“Mia's bedroom”) — those are virtual addresses. The building manager (the OS) keeps the book that says which nickname is which door.

Before a delivery, the family asks the manager to write down the door numbers on the delivery slip (mapping) and promises not to move rooms until the parcel arrives (pinning). In some buildings, a security guard at the entrance (IOMMU) holds a second list: the robot is given “guest door numbers” and the guard translates each one to a real door — and refuses entry to any door not on the list.

🧩 Where the analogy breaks
  • Represents: devices cannot use virtual addresses; pinning; mapping; IOMMU translation and protection.
  • Hides: translation is per page, not per room; the guard caches translations (IOTLB) and cache misses cost time; a parcel can be split across many doors.
  • Misleads: a refused robot usually does not know it was refused — a posted write blocked by the IOMMU is typically just dropped and logged by the host, while the device believes it delivered impl.

💡 Senior insight — step 10 is where corruption is born

If the driver unmaps (step 10) before the device's last write (step 7) lands — for example after a timeout and abort race — a later mapping may reuse the IOVA for a different buffer, and the device's late write lands in somebody else's data. No error is reported anywhere. This is why reset and abort paths must guarantee the device has stopped DMA before memory is released.

1B.6 Specification discipline

📘 Specification — sources

NVMe Base Specification Rev. 2.4 and NVM Command Set Rev. 1.3 define data pointers (PRP, SGL), memory page size (CC.MPS) and queue base addresses. PCI Express Base Specification defines memory request TLPs, Bus Master Enable, and (optional) ATS. IOMMU behaviour is defined by platform architecture documents (Intel VT-d, AMD IOMMU, Arm SMMU), not by NVMe. Linux behaviour is defined by kernel documentation (DMA API) and source impl.

1B.7 Hardware view

  • Must participate: device DMA engine, PCIe link, root complex, memory controller, DRAM.
  • May participate: IOMMU and its IOTLB; device-side ATC (Address Translation Cache) if ATS is used; switches; inter-socket links.
  • Observable: TLP addresses and lengths on the link; IOMMU fault logs; kernel DMA debug output (CONFIG_DMA_API_DEBUG on test kernels).
  • Unobservable without special tools: IOTLB hits/misses, cache snoop behaviour, device-internal DMA queues.

🧪 Lab 1B.1 (beginner) — Is my IOMMU on? SAFE

Objective: determine translation mode for your NVMe device. Procedure: run the Linux-view commands above. Questions: which IOMMU (if any)? which group type? Expected reasoning: group type “DMA”/“DMA-FQ” → translated; “identity” → passthrough; no groups → IOMMU disabled or absent.

Solution

Extension: find the other devices in the same IOMMU group and explain why grouping matters for device assignment to VMs.

🧪 Lab 1B.2 (intermediate) — Predict the PRP layout SAFE

Objective: apply page rules. Setup: paper. Memory page size 4 KiB. For each case give PRP1, PRP2 meaning: (a) 4 KiB buffer at offset 0; (b) 8 KiB buffer at offset 0; (c) 8 KiB buffer starting at offset 0x200 in its first page; (d) 64 KiB at offset 0.

Solution

(a) PRP1 = page address, PRP2 unused. (b) PRP1 = page 1, PRP2 = page 2 address (exactly two pages). (c) The data spans three pages (3.5 KiB + 4 KiB + 0.5 KiB): PRP1 = page1+0x200, PRP2 = pointer to a PRP list with two entries. (d) 16 pages: PRP1 = page 1, PRP2 = pointer to a PRP list with 15 entries. Full PRP rules are in Part XII. derived

Extension: how many PRP-list entries fit in one 4 KiB list page, and what happens when more are needed?

🧪 Lab 1B.3 (advanced) — IOMMU cost on throughput CAUTION

Objective: measure translation overhead. Setup: dedicated test box, a spare NVMe namespace or file, ability to change kernel boot parameters. Procedure: run fio --name=r --filename=/dev/nvme1n1 --rw=randread --bs=4k --iodepth=64 --numjobs=4 --direct=1 --runtime=60 --time_based --readonly with IOMMU translated mode and with passthrough. Record IOPS, mean and p99 latency, CPU usage.

⚠️ Warning

Use --readonly and a non-system device. Changing IOMMU modes affects every device on the machine; do not do it on a production host.

Solution

Differences range from negligible to significant depending on platform, IOTLB behaviour and mapping strategy impl. The skill is attributing a difference to translation by changing exactly one variable.

Extension: repeat with 128 KiB blocks and explain why the relative cost changes.

🧪 Lab 1B.4 (senior forensic) — Who produced the bad address? SAFE

Setup: synthetic evidence. The SQE fetched for CID 0x33 (Read, 10 KiB = 2 KiB + 4 KiB + 4 KiB across three pages) contains PRP1 = 0x3_1000_0800, PRP2 = 0x3_2000_0000 (list). The list contains 0x3_1100_0000, 0x3_1200_0000. The IOMMU logs a write fault at 0x3_1000_1800.

Question: driver bug or controller bug?

Solution

With PRP1 offset 0x800, the first page holds only 0x800 bytes (0x800–0xFFF); the controller must then move to the first list entry. A write to 0x3_1000_1800 means the controller kept incrementing linearly past the end of the first page instead of following the PRP list — a controller PRP-offset handling bug (confidence medium-high, pending confirmation that the driver's mapping for page 1 really is a single 4 KiB page). The driver's structures were correct per the PRP rules.

Extension: design a validation test that would have caught this before shipping (unaligned PRP1 offsets × transfer sizes).

1B.13 Interview questions

Interview questions

  1. Beginner What is DMA?
    Model answer

    A device reading/writing system memory directly as a bus master, without the CPU copying each byte.

  2. Beginner Why can't a device use a virtual address?
    Model answer

    Virtual addresses are translated by the CPU's MMU with per-process page tables the device cannot access.

  3. Beginner What is pinning?
    Model answer

    Preventing pages from being moved or swapped while a device may access them.

  4. Beginner What is an IOMMU?
    Model answer

    Hardware that translates and permission-checks device memory accesses.

  5. Beginner Is a CQE write a DMA?
    Model answer

    Yes — a device-initiated Memory Write into host memory.

  6. Intermediate Coherent vs streaming DMA mappings?
    Model answer

    Coherent: long-lived, shared by CPU and device concurrently (queues). Streaming: per-transfer, ownership handed to device then back (data buffers).

  7. Intermediate Why do PRP lists exist?
    Model answer

    To describe buffers spanning more pages than PRP1/PRP2 can directly, since buffers are physically scattered.

  8. Intermediate What is a bounce buffer and when is it used?
    Model answer

    A reachable intermediate buffer used when the device cannot access the real buffer (addressing limits, encrypted guest memory); costs a copy.

  9. Intermediate Why must PCIe memory requests not cross 4 KiB boundaries?
    Model answer

    It is a PCIe rule for requests; DMA engines split transfers at 4 KiB address boundaries, which also matches page granularity.

  10. Intermediate What happens to a posted write blocked by the IOMMU?
    Model answer

    Typically dropped and logged by the host; the device generally receives no indication impl.

  11. Advanced What is ATS?
    Model answer

    Address Translation Services: a device can request translations from the IOMMU and cache them in its own ATC, then issue pre-translated requests.

  12. Advanced How does an IOTLB miss show up in a trace?
    Model answer

    Indirectly — as longer latency for some MRd completions; the walk itself is not on the PCIe link.

  13. Advanced Why are reset paths dangerous for DMA?
    Model answer

    The device may still DMA after the host considers commands dead; memory must not be freed/reused until DMA has provably stopped.

  14. Advanced What does CAP.CQR imply?
    Model answer

    Contiguous Queues Required: I/O queues must be physically contiguous in memory (no PRP-list-based queues).

  15. Advanced Why is the low part of an address the same in VA and PA?
    Model answer

    Translation replaces only the page number; the in-page offset is preserved.

  16. Senior Silent corruption on a fleet — how do you start?
    Model answer

    Characterise the corruption (size, alignment, content source), correlate with resets/timeouts, enable IOMMU to convert silent wrong writes into faults, collect fault addresses, map to commands.

  17. Senior How would you validate a controller's PRP engine?
    Model answer

    Sweep PRP1 offsets × sizes × list chaining, random page placements, above-4 GiB addresses, IOMMU-on fault detection, compare captured addresses with expected ones.

  18. Senior Passthrough IOMMU in production: pros/cons?
    Model answer

    Pro: lower overhead. Con: no protection from errant DMA, harder to detect device addressing bugs, security exposure to malicious devices.

  19. Senior Device reports Data Transfer Error. Host or device?
    Model answer

    Check whether the device received UR/CA/timeouts for its DMA reads (host side) versus internal errors; AER on both ends and capture discriminate.

  20. Senior How would you design the abort/reset path to be DMA-safe?
    Model answer

    Quiesce the controller (disable, or reset with confirmation via CSTS), optionally clear Bus Master Enable, only then unmap/free buffers; never reuse IOVAs before quiescence.

Worked example — counting TLPs for one 4 KiB read

Assume Max_Payload_Size = 256 bytes, Max_Read_Request_Size irrelevant for a read command (the device writes), PRP1 only, one MSI-X vector, no coalescing. derived

  1. Doorbell: 1 MWr down.
  2. SQE fetch: 1 MRd up (64 B), 1 CplD down (64 B, possibly split by the root complex — typically not for 64 B).
  3. Data: 4096 / 256 = 16 MWr up.
  4. CQE: 1 MWr up (16 B).
  5. Interrupt: 1 MWr up (4 B).
  6. CQ head doorbell: 1 MWr down.

Total ≈ 21 TLPs: 3 host-initiated, 18 device-initiated (plus 1 completion). Data efficiency: each 256-byte data TLP carries roughly 20–30 bytes of framing, header, sequence number and LCRC overhead on Gen3–5 derived, so about 90% of link bytes in the data phase are payload. Doubling MPS to 512 B halves the data TLP count and nudges efficiency upward.

Code — a tiny simulation of a queue, doorbell and DMA

#!/usr/bin/env python3
"""Toy model: host memory, a submission queue, a doorbell, a 'device' that DMAs.
Runs anywhere; touches no hardware. Teaches who owns what, and when."""
MEM = bytearray(1 << 16)             # 64 KiB of pretend host memory
SQ_BASE, SQ_ENTRIES, SQE = 0x1000, 8, 64
DATA_BASE = 0x8000
sq_tail_doorbell = 0                   # lives "in the device" (MMIO register)

def host_submit(slot, opcode, lba, buf):
    sqe = bytearray(SQE)
    sqe[0] = opcode                     # CDW0 byte 0: opcode
    sqe[24:32] = buf.to_bytes(8, "little")   # PRP1 at bytes 24-31
    sqe[40:48] = lba.to_bytes(8, "little")   # CDW10-11: starting LBA (NVM Read)
    MEM[SQ_BASE + slot*SQE : SQ_BASE + (slot+1)*SQE] = sqe   # 1) write SQE in host memory
    return (slot + 1) % SQ_ENTRIES                           # 2) new tail for the doorbell

class Device:
    def __init__(self): self.head = 0; self.media = {7: b"HELLO-NVMe".ljust(64, b".")}
    def doorbell(self, tail):                # 3) host MMIO write lands here
        while self.head != tail:
            sqe = MEM[SQ_BASE + self.head*SQE : SQ_BASE + (self.head+1)*SQE]   # 4) DMA read (fetch)
            prp1 = int.from_bytes(sqe[24:32], "little")
            lba  = int.from_bytes(sqe[40:48], "little")
            if sqe[0] == 0x02:               # Read
                MEM[prp1:prp1+64] = self.media.get(lba, bytes(64))           # 5) DMA write (data)
            self.head = (self.head + 1) % SQ_ENTRIES

dev = Device()
sq_tail_doorbell = host_submit(0, 0x02, 7, DATA_BASE)
dev.doorbell(sq_tail_doorbell)
print(bytes(MEM[DATA_BASE:DATA_BASE+16]))   # b'HELLO-NVMe......'

The model is deliberately incomplete (no completion queue, no phase tag, no interrupt). Lab 1.1 asks you to add them.

Common mistakes

  • Confusing CPU registers with device registers.
  • Putting a virtual address where a DMA address belongs.
  • Assuming an interrupt means success.
  • Assuming KB = KiB, or that a 0's-based field holds the real count.
  • Believing the SSD “receives” commands — it fetches them.
  • Treating an all-ones register value as real data.
  • Forgetting the barrier between writing an SQE and ringing the doorbell.

Debugging connection

Every NVMe failure investigation later in this book starts with three Chapter 1 questions: Who was supposed to act? (host CPU, device, IOMMU, link) At which address? (which space, which mapping) Was the action posted or non-posted? (does a missing response mean failure, or is no response expected?). Answering these three correctly eliminates most wrong hypotheses before you open a single specification.

💡 Senior insight

Juniors look for the error message. Seniors look for the first deviation from expected behaviour, which is usually silent: a doorbell with no fetch, a fetch with wrong bytes, a data write to an address no PRP entry named. Error messages are almost always downstream consequences. Train yourself now to ask “what should have happened next, and did it?”

  4. In your simulation, what goes wrong if the host reads a CQE slot before the device has written it, and how does the phase bit prevent it?
Solution

1. LnkSta below LnkCap can be normal (power saving at idle on some platforms, or a slot wired narrower) or a sign of signal-integrity problems; compare under load and check the slot's wiring impl. 2. Linux typically creates one I/O queue (and vector) per CPU up to the device's limits, plus the admin vector; fewer vectors than CPUs means queues are shared. 3. SQ1 tail = BAR0 + 1000h + 2 × (4 << DSTRD); CQ1 head = BAR0 + 1000h + 3 × (4 << DSTRD); with DSTRD = 0: BAR0+1008h and BAR0+100Ch. 4. Without a phase bit, stale entries from the previous lap look valid; the host compares the entry's phase with its expected phase (which starts at 1 and flips on each wrap), so old entries are ignored.

# Sketch of the completion side (add to the toy model)
CQ_BASE, CQ_ENTRIES, CQE = 0x2000, 4, 16
class CQ:
    def __init__(s): s.tail = 0; s.phase = 1          # device-side producer state
    def post(s, cid, sqhd, status=0):
        e = bytearray(CQE)
        e[8:10]  = sqhd.to_bytes(2, "little")          # DW2: SQ head pointer
        e[12:14] = cid.to_bytes(2, "little")           # DW3 bits 15:0: command identifier
        e[14:16] = ((status << 1) | s.phase).to_bytes(2, "little")  # DW3 bit 16 = phase
        MEM[CQ_BASE + s.tail*CQE : CQ_BASE + (s.tail+1)*CQE] = e
        s.tail += 1
        if s.tail == CQ_ENTRIES: s.tail, s.phase = 0, s.phase ^ 1
host_head, host_phase = 0, 1
def host_poll():
    global host_head, host_phase
    e = MEM[CQ_BASE + host_head*CQE : CQ_BASE + (host_head+1)*CQE]
    if (int.from_bytes(e[14:16], "little") & 1) != host_phase: return None   # not new
    host_head += 1
    if host_head == CQ_ENTRIES: host_head, host_phase = 0, host_phase ^ 1
    return int.from_bytes(e[12:14], "little")                              # CID

Quiz — Chapter 1

  1. How many bytes are in an NVMe submission queue entry and a completion queue entry?

    Answer

    64 and 16 bytes.

  2. What is 0x1000 in decimal, and what NVMe register region starts at that offset?

    Answer

    4096; the doorbell registers.

  3. A drive is sold as 2 TB. Approximately how many GiB will a binary-reporting tool show?

    Answer

    2 × 1012 / 230 ≈ 1,863 GiB.

  4. Why is a register read on the I/O fast path a performance problem?

    Answer

    Reads are non-posted; the core stalls for the full round trip (often ~1 µs), wasting thousands of cycles per access.

  5. Name the three address kinds involved in a DMA from a user buffer.

    Answer

    Virtual (user), physical, and device-visible DMA address/IOVA.

  6. Which PCI Command register bit must be set before a device can DMA?

    Answer

    Bus Master Enable.

  7. What does a CPU see when it reads a register of a device whose link is down?

    Answer

    Typically all ones (e.g. FFFFFFFFh), synthesised by the platform after the failed request impl.

  8. True or false: an MSI-X interrupt is a special wire.

    Answer

    False — it is a posted Memory Write TLP to an address programmed by the OS.

  9. What NVMe class code identifies an NVMe controller?

    Answer

    Base class 01h, sub-class 08h, programming interface 02h.

  10. Why do PRP lists exist?

    Answer

    Because a virtually contiguous buffer may be physically scattered, so the device needs a list of page addresses.

  11. What is a 0's-based value? Give the real count for MQES = 0x3FF.

    Answer

    A field storing count − 1; 0x3FF means 1024 entries.

  12. Compute raw per-direction bandwidth of a PCIe Gen4 x4 link.

    Answer

    16 GT/s × 4 × 128/130 ÷ 8 ≈ 7.88 GB/s.

  13. Why must a barrier be placed between writing an SQE and writing the doorbell?

    Answer

    So the SQE contents are visible to the device before it is told to fetch them.

  14. What is the difference between polling and interrupts?

    Answer

    Polling repeatedly checks for completion (low latency, CPU cost); interrupts notify the CPU asynchronously (efficient, adds handling latency).

  15. Which component translates device-visible addresses to physical addresses?

    Answer

    The IOMMU (when enabled).

Interview questions — Chapter 1

  1. Beginner Explain DMA to a non-engineer.
    Model answer

    The storage device copies data straight into the computer's memory by itself, so the processor doesn't have to carry every byte.

  2. Beginner What does a device driver do?
    Model answer

    It configures and operates a specific kind of device and presents it to the OS through a standard interface.

  3. Intermediate Walk me through what happens between read() and the data arriving.
    Model answer

    Syscall → filesystem maps offset to LBA → block layer request → driver builds SQE with DMA addresses → barrier + doorbell → device fetches SQE → reads media → DMAs data → posts CQE → MSI-X → ISR consumes CQE, rings CQ head doorbell → request completes → syscall returns.

  4. Advanced Why did NVMe avoid register reads in the submission path?
    Model answer

    MMIO reads are non-posted and stall the CPU for a round trip; at millions of IOPS they would consume whole cores. Doorbell writes are posted and cheap.

  5. Senior An SSD returns success but the data is wrong. Where do you look?
    Model answer

    Characterise corruption; check for resets/timeouts; enable IOMMU to catch stray DMA; capture SQE/PRP and data TLP addresses; check end-to-end protection info if available; distinguish media/FTL corruption (wrong data at right address) from DMA corruption (right data at wrong address).

Chapter summary

  • A computer is a collection of workers moving information: cores compute, memory holds, devices specialise, buses connect.
  • Addresses only make sense inside an address space; devices use DMA addresses, not virtual addresses.
  • Device registers have side effects; reads are expensive, writes are posted.
  • Drivers set up devices through registers; devices then do the bulk work by DMA and report via interrupts, which are themselves memory writes.
  • Every later NVMe/PCIe concept is a structured use of these primitives.
