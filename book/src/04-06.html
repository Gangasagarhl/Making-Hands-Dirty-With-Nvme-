PART XII

PRP and SGL

The 64-byte command never carries user data; it carries directions to the data. NVMe has two direction formats: Physical Region Page entries (PRPs) — a list of page addresses — and Scatter Gather Lists (SGLs) — a list of (address, length) descriptors. Most data-corruption bugs and DMA faults that are not media errors trace back to wrong directions. Chapter 36 teaches PRPs with numbers you can compute by hand and an executable builder/validator; Chapter 37 teaches SGLs and compares the two; Chapter 38 is a forensic lab of valid and malformed cases.

36 Physical Region Pages (PRP)

📘 Specification baseline

DOCUMENT: NVMe Base Specification (PRP entry and PRP list definitions, data pointer) and NVMe over PCIe Transport Specification (PRPs are the required data-pointer mechanism for admin commands on PCIe) version. REVISION: Base 2.4 / PCIe Transport 1.4 baseline. OLDER VERSIONS: the PRP rules are essentially unchanged since NVMe 1.0; their location in the document set moved with the 2.0 restructuring. SOURCE: nvmexpress.org.

36.1 Why this chapter exists

Host memory given to I/O is a set of scattered physical pages; the controller needs the physical (or IOMMU-virtual, IOVA) address of every byte it will move. PRPs are NVMe's compact, page-oriented answer. They are simple enough to compute on paper, and strict enough that one wrong offset produces either a clean error (PRP Offset Invalid) or — far worse — silent data placement into the wrong memory.

36.2 Learning objectives

  • Beginner: explain PRP1, PRP2, PRP list, memory page size.
  • Intermediate: compute pages touched, PRP1 coverage, whether PRP2 is a data pointer or a list pointer, and list size.
  • Advanced: build chained PRP lists for large transfers and handle a PRP list starting at a non-zero offset.
  • Senior: diagnose DMA faults and corruption caused by malformed PRPs from a trace.
  • Trace: predict the controller's MRd of PRP lists and the data TLP addresses.
  • Debugging/validation: design a PRP conformance test matrix.

Prerequisites: Ch 29 (DPTR at bytes 24–39), Ch 32 (data DMA), IOMMU basics.

🧒 Kid analogy — the warehouse delivery note

A delivery company (the controller) must deliver 16 boxes of books to your house, but your house has no single empty room big enough: there's space in the kitchen, the attic, the garage and a bedroom. All rooms are the same size (a "page"). The delivery note has only two lines. Line 1 (PRP1): "first room, and you may start halfway into it" (an offset). Line 2 (PRP2): if only one more room is needed, "the second room"; if more rooms are needed, "the list of rooms is pinned on the fridge" — a PRP list. If the fridge list is full, its last line says "continued on the bathroom door" — chaining.

🧩 Where the analogy breaks

Only the first room may be entered halfway; every other room must be filled from its door (offset 0). The note never says how many boxes — that comes from the command (NLB × LBA size). And the "rooms" are addressed by bus addresses that may be translated by an IOMMU, not by physical location.

36.4 The rules

offset = PRP1 mod MPS     pages = ⌈(offset + length) / MPS⌉     PRP1 covers min(MPS − offset, length)
  • length — bytes to transfer = (NLB + 1) × LBA size (+ interleaved metadata if formatted so).
  • MPS — memory page size from CC.MPS.
  • pages — number of memory pages the transfer touches.
pagesPRP2PRP list
1Not used (reserved/ignored)none
2Address of the second page — offset must be 0none
≥ 3PRP list pointer (qword aligned; may have an offset in its page)pages − 1 entries, each page-aligned; chain if they do not fit
  • All PRP entries: bits 1:0 = 0 verified. Entries other than PRP1 that point to data: offset 0 verified. Violations may be reported as 0/13h PRP Offset Invalid verified; whether every controller checks every entry is impl.
  • Entries per list page = MPS / 8 = 512 for 4 KiB. If the list starts at offset o, the first list page holds (MPS − o)/8 entries derived.
  • The last entry in a list page is a chain pointer only if more entries remain after it; otherwise it is a data entry verified.
  • PRPs never describe more than the command's length; extra list entries are not read derived.
  • PRP lists for queue memory (Create I/O SQ/CQ with PC=0) follow the same entry format but describe queue pages, not data.

36.6 Code — PRP list builder, visualiser and validator

Inputs: page size, buffer start address, buffer length, and the addresses of the remaining pages. Outputs: PRP1, PRP2, the PRP list pages (with chaining), and validation of malformed pointers. Assumptions are stated in the docstring.

#!/usr/bin/env python3
"""prp_tool.py - build, visualise and validate NVMe PRP data pointers.
EXECUTABLE teaching tool (no device access). Assumptions, stated explicitly:
  * MPS = memory page size chosen by host in CC.MPS (4 KiB here);
  * data pages are given as a list of host physical/IOVA page addresses
    (they need NOT be contiguous - that is the point of PRPs);
  * PRP list pages come from a fake allocator starting at LIST_BASE;
  * rules modelled: PRP1 may carry an offset (dword aligned); every later
    data entry must be page aligned; PRP2 is a data pointer when exactly two
    pages are touched, a PRP-list pointer when more; the last slot of a full
    list page chains to the next list page."""
import math

MPS = 4096
LIST_BASE = 0x7F000000

def pages_touched(addr, length, mps=MPS):
    off = addr % mps
    return math.ceil((off + length) / mps)

def build(first_addr, length, more_pages, mps=MPS):
    """first_addr: address of first byte (may be unaligned).
    more_pages: page-aligned addresses of pages 2..n."""
    n = pages_touched(first_addr, length, mps)
    assert len(more_pages) >= n - 1, f"need {n-1} more pages, got {len(more_pages)}"
    data = more_pages[:n - 1]
    mem, lists = {}, []
    prp1, prp2 = first_addr, 0
    if n == 2:
        prp2 = data[0]
    elif n > 2:
        per = mps // 8                       # 512 entries per 4 KiB list page
        nxt = LIST_BASE
        prp2 = nxt
        remaining = list(data)
        while remaining:
            page = nxt
            if len(remaining) <= per:
                entries, remaining = remaining, []
            else:
                nxt = page + mps
                entries, remaining = remaining[:per - 1] + [nxt], remaining[per - 1:]
            mem[page] = entries
            lists.append(page)
    return {"n": n, "prp1": prp1, "prp2": prp2, "lists": lists, "mem": mem, "len": length}

def show(r, mps=MPS):
    off = r["prp1"] % mps
    print(f"transfer {r['len']} B, first offset {off:#x} -> {r['n']} page(s)")
    print(f"  PRP1 = {r['prp1']:#012x}  covers {min(mps - off, r['len'])} B")
    if r["n"] == 1:
        print("  PRP2 = unused (transfer fits in PRP1's page)")
    elif r["n"] == 2:
        print(f"  PRP2 = {r['prp2']:#012x}  DATA page (exactly two pages touched)")
    else:
        print(f"  PRP2 = {r['prp2']:#012x}  -> PRP LIST pointer")
        for p in r["lists"]:
            ents = r["mem"][p]
            last = ents[-1]
            chained = p != r["lists"][-1]
            print(f"    list page {p:#x}: {len(ents)} entries"
                  + (f", last entry {last:#x} = CHAIN to next list page" if chained else ""))
            for i, e in enumerate(ents[:3]):
                print(f"      [{i}] {e:#012x}")
            if len(ents) > 3:
                print(f"      ... [{len(ents)-1}] {ents[-1]:#012x}")

def validate(prp1, prp2, length, mem, mps=MPS):
    """Return list of problems a controller could reject (PRP Offset Invalid,
    Data Transfer Error) or that would silently corrupt data."""
    probs = []
    if prp1 & 3:
        probs.append("PRP1 bits 1:0 non-zero (must be dword aligned)")
    n = pages_touched(prp1, length, mps)
    if n == 2 and prp2 % mps:
        probs.append(f"PRP2 {prp2:#x} used as data pointer but has offset {prp2 % mps:#x} "
                     "-> expect 'PRP Offset Invalid' or wrong data placement")
    if n > 2:
        if prp2 & 7:
            probs.append(f"PRP list pointer {prp2:#x} not qword aligned")
        page = prp2 - (prp2 % mps)
        if page not in mem:
            probs.append(f"PRP2 {prp2:#x} points at memory that holds no PRP list "
                         "-> controller DMA-reads garbage (IOMMU fault / Data Transfer Error)")
        else:
            need = n - 1
            idx = (prp2 % mps) // 8
            per = mps // 8
            while need:
                ents = mem.get(page)
                if ents is None:
                    probs.append(f"chain points to {page:#x} which is not a list page"); break
                e = ents[idx] if idx < len(ents) else None
                if e is None:
                    probs.append("list ended early: fewer entries than pages"); break
                if idx == per - 1 and need > 1:
                    page, idx = e, 0          # chain entry
                    continue
                if e % mps:
                    probs.append(f"list entry {e:#x} has non-zero offset (must be page aligned)")
                need -= 1; idx += 1
    return probs or ["OK - structurally valid (does not prove the pages belong to this I/O)"]

if __name__ == "__main__":
    base = 0x112340000
    pages = [base + i * MPS for i in range(1, 600)]
    print("Case A: 16 KiB read, page-aligned buffer")
    show(build(base, 16384, pages))
    print("\nCase B: 16 KiB read, buffer starts at offset 0x200")
    show(build(base + 0x200, 16384, pages))
    print("\nCase C: 8 KiB, aligned (PRP2 is a data pointer)")
    show(build(base, 8192, pages))
    print("\nCase D: 2 MiB + 8 KiB aligned, list chaining")
    show(build(base, 2 * 1024 * 1024 + 8192, pages))
    print("\n--- validation of broken pointers ---")
    good = build(base, 16384, pages)
    print("good      :", validate(good["prp1"], good["prp2"], 16384, good["mem"]))
    print("unaligned :", validate(base + 0x800, base + 0x1800, 4096, {}))
    print("wrong list:", validate(base, 0x7F001000, 16384, good["mem"]))
    bad = {LIST_BASE: [base + 0x1000, base + 0x2010, base + 0x3000]}
    print("crossing  :", validate(base, LIST_BASE, 16384, bad))

36.7 Hardware view and protocol view

  • The controller must read PRP lists from host memory (MRd → CplD) before or while moving data; for long lists it may prefetch list pages and data in parallel impl.
  • Each data TLP is addressed inside one PRP page, so PRP pages map directly onto TLP address ranges; a page never produces a TLP crossing a 4 KiB boundary (PCIe rule).
  • With an IOMMU, PRP addresses are IOVAs; Linux maps the bio's pages via the DMA API and may coalesce them into contiguous IOVA ranges — the PRPs then look contiguous even though physical pages are not impl.
  • Linux builds PRP lists from DMA pools (a small pool of 256-byte lists and a page-sized pool); small lists therefore start at non-zero offsets within a page version.

36.10 Labs

🧪 Lab 36.1 — Beginner: PRPs by hand SAFE LAB

For MPS 4 KiB compute pages/PRP2/list size for: (a) 12 KiB at offset 0; (b) 12 KiB at offset 0xFFC; (c) 4 B at offset 0xFFC; (d) 64 KiB at offset 0x10.

Solution

(a) 3 pages → list, 2 entries. (b) ⌈(4092+12288)/4096⌉ = 4 → list, 3 entries; PRP1 covers 4 B. (c) 1 page (0xFFC+4 = 0x1000) → PRP2 unused. (d) ⌈(16+65536)/4096⌉ = 17 → list, 16 entries.

🧪 Lab 36.2 — Intermediate: extend the tool SAFE LAB

Add support for a PRP list starting at a non-zero offset (e.g. LIST_BASE + 0xF00) and check that the first list page then holds only 32 entries before chaining.

Solution sketch

Per-page capacity = (MPS − (addr mod MPS)) / 8; chain when remaining > capacity, putting the chain pointer in the last slot of that partial page.

🧪 Lab 36.3 — Advanced: PRP conformance matrix SAFE LAB

Design a validation test matrix for a controller's PRP handling: dimensions offset {0, 4, 0x200, MPS−4}, length {4, 512, MPS−offset, MPS, 2·MPS, 512·MPS, 513·MPS…}, list position {page start, mid-page, last 8 bytes}, malformed variants. State expected outcomes.

Expected reasoning

Valid cases: data placed exactly, no extra list reads beyond need. Malformed: 0/13h expected where offsets are illegal; for undetectable errors (wrong but aligned addresses) expect data in wrong place — must be caught by host-side checks, not the device.

🧪 Lab 36.4 — Senior forensic SAFE LAB

A capture shows: SQE Read NLB=0x3F (512 B LBAs → 32 KiB), PRP1 = 0x5_0000_0E00, PRP2 = 0x6_1000_0000. Controller then MRd 64 bytes at 0x6_1000_0000 and writes data to eight addresses from that list plus PRP1. Is this consistent?

Solution

Pages = ⌈(0xE00 + 32768)/4096⌉ = ⌈36352/4096⌉ = 9 → PRP1 + 8 list entries = 64 bytes. Consistent. The last page receives 32768 − 512 − 7×4096 = 3584 B.

Quiz

  1. When is PRP2 a list pointer?

    Answer

    When the transfer touches more than two memory pages.

  2. Which PRP entries may have a non-zero offset?

    Answer

    PRP1 (and the PRP list pointer, qword-aligned); not data entries after the first.

  3. How many data entries fit in a full 4 KiB list page that must chain?

    Answer

    511 + 1 chain pointer.

36.11 Summary

PRP1 (with offset) + PRP2 (second page or list pointer) + page-aligned list entries with chaining describe any buffer; page count = ⌈(offset+length)/MPS⌉. Next: Chapter 37 — SGL.

37 Scatter Gather Lists (SGL)

37.1 Why this chapter exists

PRPs assume page-granular buffers. Many real buffers are large contiguous regions (huge pages, RDMA memory) or byte-granular fragments. SGLs describe memory as (address, length) segments and add capabilities PRPs lack: discarding part of a read (bit bucket), arbitrary lengths, and — on fabrics — keyed remote memory. SGLs are mandatory on NVMe over Fabrics and optional on PCIe I/O commands (reported by Identify Controller SGLS) verified.

37.2 Learning objectives

  • Decode a 16-byte SGL descriptor: address, length, type, subtype.
  • Explain Data Block, Bit Bucket, Segment and Last Segment descriptors and the rules connecting them.
  • Walk a multi-segment SGL and compute the total length.
  • Compare PRP vs SGL and decide when each is preferable.

Prerequisites: Ch 36, Ch 29 (PSDT).

🧒 Kid analogy

Instead of "room numbers", the delivery note now says "put 4096 boxes starting at the kitchen door; put 8192 boxes starting at the garage; throw 512 boxes in the skip (bit bucket); for more instructions, read the note taped to the attic door (segment)".

🧩 Where the analogy breaks

"Boxes" are bytes, the lengths are exact, and there are strict rules about where a "read more instructions" note may appear (only as the last descriptor in a segment).

37.4 Code — SGL walker

#!/usr/bin/env python3
"""sgl_walk.py - decode 16-byte NVMe SGL descriptors and walk a synthetic SGL.
EXECUTABLE teaching tool; memory is a Python dict, not a device."""
import struct

TYPES = {0x0: "Data Block", 0x1: "Bit Bucket", 0x2: "Segment",
         0x3: "Last Segment", 0x4: "Keyed Data Block (fabrics)",
         0x5: "Transport Data Block (fabrics)"}

def desc(raw):
    addr, length = struct.unpack_from("<QI", raw, 0)
    ident = raw[15]
    return {"addr": addr, "len": length, "type": ident >> 4, "sub": ident & 0xF}

def mk(addr, length, typ, sub=0):
    return struct.pack("<QI3xB", addr, length, (typ << 4) | sub)

def walk(sgl1, mem, total):
    """sgl1: 16-byte descriptor from SQE DPTR. mem: addr -> bytes of a segment."""
    d, moved, hops = desc(sgl1), 0, 0
    pending = [d]
    while pending:
        d = pending.pop(0)
        t = TYPES.get(d["type"], "RESERVED -> SGL Descriptor Type Invalid")
        if d["type"] in (0x0, 0x1):
            act = "transfer" if d["type"] == 0 else "discard (read only)"
            print(f"  {t:13} addr={d['addr']:#014x} len={d['len']:6} -> {act}")
            moved += d["len"]
        elif d["type"] in (0x2, 0x3):
            seg = mem.get(d["addr"])
            if seg is None or d["len"] % 16:
                print(f"  {t:13} addr={d['addr']:#x} len={d['len']} -> INVALID segment pointer/length")
                return
            n = d["len"] // 16
            print(f"  {t:13} addr={d['addr']:#014x} -> {n} descriptors")
            kids = [desc(seg[i*16:(i+1)*16]) for i in range(n)]
            if d["type"] == 0x3 and any(k["type"] in (2, 3) for k in kids):
                print("    !! Last Segment contains a segment descriptor -> invalid")
                return
            if any(k["type"] in (2, 3) for k in kids[:-1]):
                print("    !! segment descriptor not in last slot -> invalid")
                return
            pending = kids + pending
            hops += 1
        else:
            print(f"  {t}"); return
    verdict = "OK" if moved == total else f"MISMATCH (expected {total}) -> Data SGL Length Invalid"
    print(f"  total described = {moved} B over {hops} segment hop(s): {verdict}")

if __name__ == "__main__":
    seg_a = mk(0x200000, 4096, 0) + mk(0x305000, 8192, 0) + mk(0x400000, 32, 3)
    seg_b = mk(0x90000, 512, 1) + mk(0x910000, 3584, 0)
    mem = {0x10000: seg_a, 0x400000: seg_b}
    print("Valid chain: SQE SGL1 = Segment -> Last Segment")
    walk(mk(0x10000, 48, 2), mem, 16384)
    print("Simple: SGL1 is a single Data Block (contiguous 16 KiB)")
    walk(mk(0x800000, 16384, 0), mem, 16384)
    print("Broken: length mismatch")
    walk(mk(0x800000, 12288, 0), mem, 16384)

38.4 Debugging method (use for every case)

  1. Decode SQE: opcode, NLB, PSDT, PRP1, PRP2 / SGL1.
  2. Compute transfer length (LBA format!) and pages (offset!).
  3. Decide PRP2's role; validate alignment of every entry.
  4. Read the list/segments as fetched by the controller (analyzer CplD), not as the driver intended.
  5. Map each data TLP address to a list entry; any TLP outside the expected set is the first bad event.
  6. Check IOMMU faults and completion status (UR/CA on MRd, 0/04h, 0/13h).
  7. Attribute: builder (host), mapping (IOMMU/DMA API), or controller (ignored a rule or mis-walked).
💡 Senior insight

The device can only reject what is syntactically wrong (offset bits, descriptor types, lengths). Everything semantically wrong — a well-aligned pointer to the wrong page — is silently honoured. That is why serious validation pairs a device-side test suite with host-side canaries (guard pages around buffers, DMA-API debugging, IOMMU strict mode).
