PART XI

NVMe Commands

A queue is just a conveyor belt; the commands are the baskets. This Part dissects the 64-byte Submission Queue Entry and the 16-byte Completion Queue Entry bit by bit (Chapter 29), then walks the Admin command set (Chapter 30) and the NVM I/O command set (Chapter 31), and finally follows a READ (Chapter 32), a WRITE (Chapter 33), a FLUSH (Chapter 34) and a Dataset Management deallocate (Chapter 35) end to end from the application down to NAND and back. You will build an executable decoder that turns a hex dump into a field table and a list of expected PCIe events.

29 NVMe Command Structure

📘 Specification baseline

DOCUMENT: NVM Express Base Specification (common command format, completion queue entry, status codes); NVM Command Set Specification (NVM-specific fields, e.g. Read/Write CDW10–15). REVISION: Base 2.4, NVM CS 1.3 (baseline, Aug 2026) version. OLDER VERSIONS THAT MAY DIFFER: NVMe 1.x reserved DW1 of the CQE and CDW2–3 of most commands; later revisions gave some of these bits command-specific meanings (for example, extended protection-information fields). The Command Retry Delay (CRD) bits in the status field appeared in revision 1.4. SOURCE: nvmexpress.org/specifications.

29.1 Why this chapter exists

Every NVMe command, admin or I/O, Read or Identify, uses the same 64-byte envelope, and every result uses the same 16-byte envelope. Once you can decode those two envelopes from raw bytes, every protocol trace, every kernel tracepoint (nvme_setup_cmd prints CDW10–15), and every vendor debug dump becomes readable. This chapter is the Rosetta Stone for the rest of the book.

29.2 Learning objectives

  • Decode all 16 dwords of an SQE, including CDW0 subfields (opcode, FUSE, PSDT, CID).
  • Decode all 4 dwords of a CQE, including SQHD, SQID, CID, phase and the 15-bit status field.
  • Classify a status by Status Code Type (SCT) and Status Code (SC) and decide whether to retry (DNR, CRD).
  • Apply a disciplined 12-step procedure to read any unfamiliar command.
  • Run a decoder on a hex dump and predict the PCIe transactions the command will cause.

Prerequisites: Ch 25 (phase tag, SQHD), Ch 27 (CID scope), little-endian byte order.

🧒 Kid analogy — the request slip

Every request to the librarian is written on the same printed form with 16 boxes. Box 1 says what you want (the opcode) and your ticket number (CID). Box 2 says which library section (namespace). Boxes 7–10 say where your shelf at home is, so the librarian's helper can carry books straight there (data pointer). Boxes 11–16 are "special instructions" whose meaning depends on what you asked for. The answer slip is smaller: four boxes — a little answer, which belt position the librarian has reached, your ticket number, the ink colour and a "how did it go" code.

🧩 Where the analogy breaks

The form is binary, little-endian and position-based: the same bits in CDW10 mean "starting LBA" in a Read and "log page ID" in Get Log Page. Which meaning applies depends on the queue type (admin vs I/O) and the command set of the namespace — the form itself does not say.

The same picture for the 16-byte completion entry. The first two dwords depend on the command. The last two are fixed for every command: DW2 says which SQ and how far the controller has read it, DW3 says which command finished and how.

Quick decode trick: take DW3 bytes 14–15 as a 16-bit little-endian value V. Then P = V & 1, SC = (V >> 1) & FFh, SCT = (V >> 9) & 7, CRD = (V >> 12) & 3, M = (V >> 14) & 1, DNR = V >> 15. Example bytes 03 05 → V = 0503h → P=1, SC=81h, SCT=2 → Unrecovered Read Error. derived

29.6 Reading an NVMe command — the 12-step procedure

  1. Identify the command set: admin queue → admin set; I/O queue → command set of the namespace (NVM, ZNS, KV …), selected via CC.CSS and the namespace's CSI.
  2. Identify the opcode (CDW0[7:0]) in that set's table.
  3. Identify the command format: which CDW10–15 layout applies (e.g. Read/Write layout).
  4. Identify mandatory fields (e.g. SLBA, NLB).
  5. Identify optional fields (FUA, LR, PRINFO, DSM hints) and whether the controller supports them.
  6. Identify data pointers: PSDT, PRP1/PRP2 or SGL1, MPTR; transfer direction.
  7. Identify namespace applicability: NSID meaning (specific, broadcast, unused).
  8. Identify prerequisites: queue exists, namespace attached, format supports PI, reservation held.
  9. Identify completion: what DW0 returns, which statuses are possible.
  10. Identify errors: field validation failures and their SCT/SC.
  11. Identify side effects: media change, cache flush, log updates, async events.
  12. Identify trace consequences: SQE fetch, data MRd/MWr counts and sizes, CQE, interrupt.
⚠️ Command decoding safety

Never infer semantics from the opcode alone. Before you write "this is a Read" check: (1) which command set the queue/namespace uses, (2) controller capabilities (Identify Controller ONCS, OACS…), (3) the Commands Supported and Effects log (LID 05h) for command-set support, (4) namespace context (CSI, LBA format, PI), (5) specification revision, and (6) that reserved fields are zero. Opcode 02h on a ZNS or KV namespace is decoded with that command set's table; opcode values at or above 80h may be vendor-specific in some ranges.

29.7 Code — an executable 64-byte command decoder

Input: a synthetic SQE hex dump (offset columns allowed). Output: a field table, command-set-specific interpretation, data pointer analysis, expected protocol events, plus CQE decoding. It is an offline teaching tool synthetic inputs.

#!/usr/bin/env python3
"""nvme_decode.py - teaching decoder for a 64-byte SQE and a 16-byte CQE.
EXECUTABLE, offline: it parses hex text only and touches no device.
Field names follow the NVMe Base / NVM Command Set layouts; always confirm
against the revision your device reports (Identify Controller VER / CAP)."""
import struct, sys

ADMIN = {0x00: "Delete I/O SQ", 0x01: "Create I/O SQ", 0x02: "Get Log Page",
         0x04: "Delete I/O CQ", 0x05: "Create I/O CQ", 0x06: "Identify",
         0x08: "Abort", 0x09: "Set Features", 0x0A: "Get Features",
         0x0C: "Asynchronous Event Request", 0x0D: "Namespace Management",
         0x10: "Firmware Commit", 0x11: "Firmware Image Download",
         0x80: "Format NVM", 0x84: "Sanitize"}
NVM = {0x00: "Flush", 0x01: "Write", 0x02: "Read", 0x04: "Write Uncorrectable",
       0x05: "Compare", 0x08: "Write Zeroes", 0x09: "Dataset Management",
       0x0C: "Verify", 0x19: "Copy"}
FUSE = ["normal", "fused: first command", "fused: second command", "reserved"]
PSDT = ["PRP", "SGL (MPTR = contiguous metadata buffer)",
        "SGL (MPTR = address of metadata SGL segment)", "reserved"]

def parse_hex(text):
    tok = text.replace(",", " ").split()
    tok = [t for t in tok if not t.endswith(":")]          # drop "0000:" offsets
    data = bytes(int(t, 16) for t in tok)
    return data

def bits(v, hi, lo):
    return (v >> lo) & ((1 << (hi - lo + 1)) - 1)

def decode_sqe(raw, queue="io", mps=4096):
    assert len(raw) == 64, f"SQE must be 64 bytes, got {len(raw)}"
    dw = struct.unpack("<16I", raw)
    opc, fuse, psdt, cid = bits(dw[0], 7, 0), bits(dw[0], 9, 8), bits(dw[0], 15, 14), bits(dw[0], 31, 16)
    table = ADMIN if queue == "admin" else NVM
    name = table.get(opc, "unknown/vendor-specific/other command set - CHECK SPEC")
    mptr = dw[4] | dw[5] << 32
    prp1 = dw[6] | dw[7] << 32
    prp2 = dw[8] | dw[9] << 32
    rows = [("CDW0[7:0]", "OPC", f"{opc:02X}h", f"{name} ({queue} queue)"),
            ("CDW0[9:8]", "FUSE", f"{fuse}", FUSE[fuse]),
            ("CDW0[15:14]", "PSDT", f"{psdt}", PSDT[psdt]),
            ("CDW0[31:16]", "CID", f"{cid:04X}h", "host-chosen tag, echoed in CQE DW3"),
            ("CDW1", "NSID", f"{dw[1]:08X}h",
             "broadcast (all namespaces)" if dw[1] == 0xFFFFFFFF else
             ("0 = not namespace-specific" if dw[1] == 0 else f"namespace {dw[1]}")),
            ("CDW2-3", "cmd-specific", f"{dw[2]:08X}h {dw[3]:08X}h", "reserved for many commands"),
            ("CDW4-5", "MPTR", f"{mptr:016X}h", "metadata pointer" if mptr else "unused"),
            ("CDW6-7", "PRP1/DPTR", f"{prp1:016X}h", f"page offset {prp1 % mps:#x}"),
            ("CDW8-9", "PRP2/DPTR", f"{prp2:016X}h", f"page offset {prp2 % mps:#x}")]
    for i in range(10, 16):
        rows.append((f"CDW{i}", "cmd-specific", f"{dw[i]:08X}h", ""))
    print(f"{'field':12} {'name':13} {'value':20} meaning")
    for r in rows:
        print(f"{r[0]:12} {r[1]:13} {r[2]:20} {r[3]}")
    if prp1 & 0x3:
        print("!! PRP1 bits 1:0 not zero - PRP entries must be dword aligned")
    if queue == "io" and opc in (0x01, 0x02, 0x05, 0x0C, 0x04, 0x08):
        slba = dw[10] | dw[11] << 32
        nlb = bits(dw[12], 15, 0) + 1
        print(f"\n{name}: SLBA={slba:#x} NLB={nlb} blocks (field holds {nlb-1}, 0-based) "
              f"LR={bits(dw[12],31,31)} FUA={bits(dw[12],30,30)} PRINFO={bits(dw[12],29,26):04b}")
        return {"opc": opc, "cid": cid, "slba": slba, "nlb": nlb, "prp1": prp1, "prp2": prp2}
    if queue == "io" and opc == 0x09:
        print(f"\nDSM: NR={bits(dw[10],7,0)+1} ranges, AD={bits(dw[11],2,2)} "
              f"IDW={bits(dw[11],1,1)} IDR={bits(dw[11],0,0)}; range list at PRP1")
    if queue == "admin" and opc == 0x06:
        cns = bits(dw[10], 7, 0)
        names = {0x00: "Identify Namespace (NSID)", 0x01: "Identify Controller",
                 0x02: "Active Namespace ID list"}
        print(f"\nIdentify CNS={cns:02X}h -> {names.get(cns,'other CNS - check spec')}, "
              f"CNTID={bits(dw[10],31,16)}; 4096-byte data buffer at PRP1")
    if queue == "admin" and opc == 0x02:
        lid = bits(dw[10], 7, 0)
        numd = (bits(dw[10], 31, 16) | bits(dw[11], 15, 0) << 16) + 1
        lids = {0x01: "Error Information", 0x02: "SMART / Health Information",
                0x03: "Firmware Slot Information"}
        print(f"\nGet Log Page LID={lid:02X}h ({lids.get(lid,'other - check spec')}), "
              f"RAE={bits(dw[10],15,15)}, NUMD={numd} dwords = {numd*4} bytes")
    if queue == "admin" and opc in (0x01, 0x05):
        print(f"\nCreate I/O {'SQ' if opc == 1 else 'CQ'}: QID={bits(dw[10],15,0)} "
              f"QSIZE={bits(dw[10],31,16)+1} entries (0-based field), PC={bits(dw[11],0,0)}, "
              + (f"CQID={bits(dw[11],31,16)} QPRIO={bits(dw[11],2,1)}" if opc == 1 else
                 f"IEN={bits(dw[11],1,1)} IV={bits(dw[11],31,16)}"))
    return {"opc": opc, "cid": cid}

SCT = {0: "Generic Command Status", 1: "Command Specific Status",
       2: "Media and Data Integrity Errors", 3: "Path Related Status", 7: "Vendor Specific"}
GEN_SC = {0x00: "Successful Completion", 0x01: "Invalid Command Opcode",
          0x02: "Invalid Field in Command", 0x03: "Command ID Conflict",
          0x04: "Data Transfer Error", 0x06: "Internal Error",
          0x07: "Command Abort Requested", 0x08: "Command Aborted due to SQ Deletion",
          0x0B: "Invalid Namespace or Format", 0x13: "PRP Offset Invalid",
          0x80: "LBA Out of Range"}
MEDIA_SC = {0x81: "Unrecovered Read Error", 0x80: "Write Fault"}

def decode_cqe(raw):
    assert len(raw) == 16, "CQE must be 16 bytes"
    dw0, dw1, dw2, dw3 = struct.unpack("<4I", raw)
    sf = bits(dw3, 31, 17)                     # 15-bit status field
    sc, sct = bits(sf, 7, 0), bits(sf, 10, 8)
    crd, more, dnr = bits(sf, 12, 11), bits(sf, 13, 13), bits(sf, 14, 14)
    meaning = (GEN_SC if sct == 0 else MEDIA_SC if sct == 2 else {}).get(sc, "see spec table")
    print(f"DW0={dw0:08X}h (command specific)  DW1={dw1:08X}h")
    print(f"SQHD={bits(dw2,15,0)} SQID={bits(dw2,31,16)} CID={bits(dw3,15,0):04X}h P={bits(dw3,16,16)}")
    print(f"Status: SCT={sct} ({SCT.get(sct,'reserved')}) SC={sc:02X}h ({meaning}) "
          f"CRD={crd} M={more} DNR={dnr}")

if __name__ == "__main__":
    # Synthetic Read: CID 0x0042, NSID 1, SLBA 0x1000, 32 x 512 B = 16 KiB, PRP list
    sqe = """

    decode_cqe(parse_hex("00 00 00 00 00 00 00 00 06 00 01 00 43 00 03 05"))
    print("\n-- admin: Get Log Page, SMART/Health, 512 bytes --")
    glp = bytearray(64)
    struct.pack_into("<I", glp, 0, 0x0007 << 16 | 0x02)        # CID 7, opcode 02h
    struct.pack_into("<I", glp, 4, 0xFFFFFFFF)                 # NSID: controller-wide
    struct.pack_into("<Q", glp, 24, 0x0000000123456000)        # PRP1
    struct.pack_into("<I", glp, 40, (128 - 1) << 16 | 0x02)    # NUMDL=127, LID=02h
    decode_sqe(bytes(glp), queue="admin")

Read the expected events critically: the decoder knows the transfer is 32 × 512 B = 16 KiB and PRP1 is page-aligned, so 4 pages are touched, so PRP2 must be a PRP list pointer — the list itself must be fetched with an extra MRd. That inference is derived from the PRP rules of Chapter 36 and assumes a 512-byte LBA format; with a 4096-byte format the same NLB field would mean 128 KiB.

29.8 Fused operations

FUSE lets two adjacent SQEs in the same SQ execute as one atomic unit. The defined use is Compare (first) + Write (second): the write happens only if the compare matches — an atomic compare-and-write used by cluster filesystems/lock managers verified (support reported in Identify Controller FUSES). Rules: the two commands must be adjacent, have the same NSID and LBA range; if the first fails, the second is aborted with "Command Aborted due to Failed Fused Command" (0/09h); if a part is missing, 0/0Ah.

Solution
  1. V=0000h: P=0 ≠ expected 1 → not a new entry; stop scanning. Do not interpret the rest.
  2. V=0101h: P=1, SC=80h, SCT=0 → LBA Out of Range, DNR=0 (still not worth retrying: fix SLBA/NLB).
  3. V=8001h: P=1, SC=00h, SCT=0, DNR=1 → success with DNR set — DNR has no meaning on success; flag as suspicious device behaviour but treat as success.
  4. DW0=00070007h → NSQA=7, NCQA=7 (0-based) → 8 I/O SQs and 8 I/O CQs allocated. SQHD=1, SQID=0, CID 3, success.
  5. V=C50Fh: P=1, SC=87h, SCT=2 → Deallocated or Unwritten Logical Block; M=1 (error log has more), DNR=1. Reading trimmed blocks with error reporting enabled.

Extension: write a function should_retry(cqe) using DNR, CRD and SCT, and justify each branch.

Quiz

  1. Which bytes of an SQE hold PRP2?

    Answer

    Bytes 32–39 (CDW8–9).

  2. CDW0 = 0x01234001. Decode.

    Answer

    OPC 01h, FUSE 00b, PSDT = bits 15:14 of 0x4001 = 01b (SGL, MPTR contiguous), CID 0x0123.

  3. Why does the CQE carry SQID?

    Answer

    Because several SQs may share one CQ, and CIDs are unique only per SQ.

  4. What does M=1 tell you?

    Answer

    More information is available in the Error Information log page (LID 01h).

30 Admin Commands

30.1 Why this chapter exists

Admin commands are how the host discovers, configures, monitors, updates and erases the device. They are low-rate but high-consequence: a wrong Format NVM or Sanitize destroys data, a wrong Firmware Commit can brick a device, and a missing Asynchronous Event Request hides errors. A senior engineer must know these commands' fields and side effects precisely.

30.2 Learning objectives

  • Recall the admin opcode table and classify each command as read-only, configuring or destructive.
  • Build Identify (CNS 00h, 01h, 02h) and Get Log Page (LID 01h, 02h, 03h) commands with correct NUMD.
  • Use Get/Set Features with SEL and SV; know key FIDs.
  • Explain Abort and AER semantics, firmware download/commit flow, namespace management/attachment, Format NVM and Sanitize.

Prerequisites: Ch 26, Ch 29.

🧒 Kid analogy

The manager's desk has a menu: "describe the store" (Identify), "show me a logbook" (Get Log Page), "change a setting / tell me a setting" (Set/Get Features), "cancel that order" (Abort), "call me if something happens" (Async Event Request), "install new store rules" (firmware), "build or remove a store section" (namespace management), "repaint and empty a section" (Format), "shred everything" (Sanitize).

🧩 Where the analogy breaks

"Call me if something happens" is not a phone number left with the manager: it is a command that stays outstanding in the controller and completes only when an event occurs — possibly hours later. And "cancel that order" is only a best-effort request; the order may complete anyway.

30.6 Set Features (09h) / Get Features (0Ah)

CDW10 FID[7:0] selects the feature; Set Features CDW10 bit 31 SV (Save) asks to persist across resets (if the feature is saveable); Get Features CDW10 bits 10:8 SEL = 000b current, 001b default, 010b saved, 011b supported capabilities. Feature value is in CDW11 (and sometimes a data buffer); the current value comes back in CQE DW0.

30.7 Abort (08h) and Asynchronous Event Request (0Ch)

  • Abort: CDW10 SQID[15:0] + CID[31:16] identify the victim. Abort is best-effort: the CQE DW0 bit 0 = 0 means the command was aborted, 1 means it was not verified. The victim, if aborted, completes with 0/07h Command Abort Requested. Abort Command Limit (ACL in Identify Controller, 0-based) caps concurrent aborts; exceeding it → command-specific 03h.
  • AER: no parameters. Up to AERL+1 may be outstanding. Completes when an event occurs; DW0 bits 2:0 Asynchronous Event Type (0 Error, 1 SMART/Health, 2 Notice, 6 I/O command set specific, 7 vendor), bits 15:8 Asynchronous Event Information, bits 23:16 Log Page Identifier to read. The host must read that log (without RAE) to clear the event and then re-submit an AER verified.

30.8 Firmware commands

  1. Firmware Image Download (11h): CDW10 NUMD (0-based dwords), CDW11 OFST (dword offset). Send the image in pieces; each piece must respect FWUG (Firmware Update Granularity) from Identify Controller.
  2. Firmware Commit (10h): CDW10 FS[2:0] slot, CA[5:3] commit action (000b replace, 001b replace and activate at next reset, 010b activate existing slot at next reset, 011b replace and activate immediately …), BPID[31] boot partition. Completion may say a reset is required (command-specific 0Bh / 10h / 11h etc.).
  3. Verify with Get Log Page LID 03h.
⚠️ Safety

Firmware commands are EXPERT operations. Only use vendor-supplied images, on test hardware, with power stability. Interrupting activation can leave a device unbootable.

30.9 Namespace management, attachment, Format NVM, Sanitize

  • Namespace Management (0Dh): SEL (CDW10[3:0]) 0h create (data buffer with NSZE, NCAP, FLBAS, …; CQE DW0 returns new NSID), 1h delete (NSID). Support in OACS bit 3.
  • Namespace Attachment (15h): SEL 0h attach, 1h detach; data buffer is a controller list. A created namespace is invisible until attached.
  • Format NVM (80h): CDW10 LBAF[3:0] (and upper bits 13:12 in newer revisions version), MSET[4], PI[7:5], PIL[8], SES[11:9] (0 none, 1 user data erase, 2 cryptographic erase). Changes LBA size → every LBA address the host knew changes meaning.
  • Sanitize (84h): SANACT[2:0] 001b exit failure mode, 010b block erase, 011b overwrite, 100b crypto erase; AUSE, OWPASS, OIPBP, NDAS. Affects all namespaces in the subsystem; runs in background; progress in Sanitize Status log (LID 81h) verified.
  • Security Send/Receive (81h/82h): transport for security protocols (e.g. TCG); SECP selects the protocol. Post-quantum cryptography support announced with the 2.4 release relates to security/authentication features — verify specifics in the 2.4 documents version.

🧪 Lab 30.1 — Identify lab SAFE LAB

Objective: separate controller identify, namespace identify and command-set-dependent information; never invent a field meaning. Setup: nvme-cli (read-only).

sudo nvme id-ctrl /dev/nvme0            # CNS 01h
sudo nvme list-ns /dev/nvme0             # CNS 02h (active namespace list)

sudo nvme ns-descs /dev/nvme0 -n 1       # CNS 03h (if supported)

Procedure: for each of these fields fill source (CNS), revision introduced (if you know; else "check spec"), width, interpretation, practical use: MDTS, VER, OACS, ONCS, VWC, SGLS, NN, NSZE, NUSE, FLBAS, LBADS of the current format, DLFEAT.

Observations: note which fields printed by nvme-cli are decoded by the tool vs raw.

Expected reasoning

MDTS (CNS 01h, 1 byte, power of two of MPSMIN units; sets max I/O size → Linux max_hw_sectors_kb). VER (CNS 01h, 4 bytes, MJR/MNR/TER). OACS (CNS 01h, 2 bytes, bitmap of optional admin commands: security, format, firmware, NS management, self-test, directives, doorbell buffer config …). ONCS (CNS 01h, bitmap of optional NVM commands: Compare, Write Uncorrectable, DSM, Write Zeroes, Save/Select in features, reservations, timestamp, verify, copy — bit assignments must be read from the spec). VWC (bit 0 = volatile write cache present; Flush broadcast support bits added in later revisions). SGLS (bitmap; bits 1:0 SGL support/alignment). NN (max NSID). NSZE/NUSE (CNS 00h, 8 bytes each, in LBAs). FLBAS (format index). LBADS (log2 LBA size). DLFEAT (what a read of deallocated blocks returns — key for Ch 35). Where you are not sure of a bit's position, write "check spec" — that is the correct answer.

Extension: compute max I/O size in bytes from MDTS and CAP.MPSMIN and compare with /sys/block/nvme0n1/queue/max_hw_sectors_kb.

🧪 Lab 30.2 — Log page lab SAFE LAB

Objective: understand what a log page is, why it exists, how the host requests it and how the returned data is interpreted. Setup: nvme-cli.

sudo nvme smart-log /dev/nvme0                       # LID 02h
sudo nvme error-log /dev/nvme0 -e 16                 # LID 01h, 16 entries
sudo nvme fw-log /dev/nvme0                          # LID 03h
sudo nvme get-log /dev/nvme0 -i 2 -l 512 -b > smart.bin   # raw bytes (LID 2, 512 B)
xxd smart.bin | head

Procedure: (1) Check LPA in Identify Controller for which optional logs are supported. (2) Fetch SMART decoded and raw; locate composite temperature (bytes 1–2, Kelvin) and percentage used (byte 5) in the raw dump. (3) Fetch error log; check if any entries have non-zero error count and decode their status fields with the Ch 29 decoder.

Expected reasoning

Composite temperature K − 273 = °C. Percentage used may exceed 100. Error log entries with error count 0 are empty. Not every device supports per-namespace SMART or every optional LID — check LPA and the Commands Supported and Effects log before concluding "device broken" from a failed Get Log Page.

Extension: compute data written from "Data Units Written" (each unit = 1000 × 512 bytes) and compare to the drive's TBW rating.

Quiz

  1. Which CNS returns the list of active namespaces?

    Answer

    02h.

  2. Encode Get Log Page for the Error Information log, 4 entries of 64 bytes.

    Answer

    256 bytes = 64 dwords → NUMDL = 63 = 3Fh → CDW10 = 0x003F0001.

  3. Why must the host re-issue AERs?

    Answer

    Each AER completes once per event; without a new outstanding AER the controller cannot report further events.

  4. Which admin commands can destroy user data?

    Answer

    Format NVM, Sanitize, Namespace Management delete (and Firmware Commit indirectly by bricking). Treat them as EXPERT operations.
