PART XXXVII

Interview Academy

Everything you have learned so far is tested here the way industry tests it: out loud, under time pressure, with follow-up questions that punish memorization and reward mental models. The academy is organised in five levels — Beginner, Intermediate, Advanced, Senior and Principal — and every question carries a model answer hidden behind a collapsible block. Do not open the answer until you have said or written your own. The questions deliberately mix conceptual, coding, trace-analysis, architecture, troubleshooting, performance and specification-interpretation styles, because a real interview loop does the same. The following parts (XXXVIII–LXV) then move from single questions to scenarios, a full capstone investigation, bug-report writing, study plans, rubrics and the final certification.

37.0 How to Use the Interview Academy

37.0.1 Why this chapter exists

Interviews for NVMe, PCIe, SSD-firmware, storage-driver and validation roles are not vocabulary tests. A good interviewer starts with a definition (“what is a doorbell?”) and then pushes three or four levels deeper (“what TLP carries it? what happens if the write is posted but the device is in D3hot? how would you prove that on a trace?”). Candidates who memorised definitions collapse at the second follow-up. This chapter explains how the question banks are built, how to practise with them, and how answers are graded, so that you train the skill that is actually being measured: layered reasoning from evidence.

37.0.2 Learning objectives

  • Classify any interview question into one of seven styles and choose the right answer shape for it.
  • Structure an answer as definition → mechanism → evidence → edge case in under two minutes.
  • Recognise when to say “that is implementation-dependent” or “I would check the specification revision” — and why this earns points rather than losing them.
  • Self-grade answers against the rubric in Chapter 63.1.

37.0.3 Prerequisites

The Beginner bank assumes Part I (Foundations) through Part III (Why NVMe exists). Intermediate assumes PCIe from zero, the Transaction Layer, NVMe architecture and queues. Advanced adds Data Link Layer, PRP/SGL, end-to-end flow, interrupts and error handling. Senior and Principal assume everything through Part XX (2026 updates).

🧒 Kid analogy

An interview is like a teacher asking “why is the sky blue?” and then, after every answer, asking “but why?” again. The first answer is easy. The fifth “but why?” shows whether you really understand or just remembered a sentence.

🧩 Where the analogy breaks

A child’s chain of “why” eventually hits philosophy. An engineering interview chain ends at evidence: a register value, a trace row, a spec statement, a measurement. The best answer to the last “why” is often “here is how I would measure it”.

37.0.5 The 4-beat answer

 ┌────────────┐   ┌─────────────┐   ┌─────────────┐   ┌──────────────┐
 │ 1 DEFINE   │ → │ 2 MECHANISM │ → │ 3 EVIDENCE  │ → │ 4 EDGE CASE  │
 │ one line   │   │ who writes  │   │ register /  │   │ what breaks, │
 │            │   │ what, where │   │ trace / log │   │ version, impl│
 └────────────┘   └─────────────┘   └─────────────┘   └──────────────┘

Example, “What is a doorbell?”: (1) A doorbell is a controller register the host writes to tell the controller that a submission queue tail or completion queue head moved. (2) The host writes the new tail index into the SQ y tail doorbell at offset 1000h + (2y) × (4 << CAP.DSTRD) in BAR0; the controller then fetches SQEs from host memory by DMA. (3) On a trace it is a posted Memory Write TLP, usually one DW, to BAR0 + 1000h-range, followed by Memory Read requests from the device toward the SQ base address. (4) Edge cases: a doorbell write to a queue that does not exist, or a value beyond the queue size, is a host error the controller may report through an asynchronous event; on virtualised or shadow-doorbell systems the MMIO write may be elided — version Doorbell Buffer Config exists for that purpose.

37.0.6 Self-grading

For each answer give yourself 0–3 per beat (0 missing, 1 vague, 2 correct, 3 correct with evidence and precision). 9+ out of 12 on most Senior questions maps roughly to rubric level 5–6; consistent 11–12 with explicit uncertainty labelling maps to level 7. See the full Senior Engineer Rubric.

💡 Senior insight

“I don’t know the exact bit position, but it lives in CAP and I would read it with nvme show-regs and check the Base specification revision the device claims in VS” is a strong answer. Interviewers are screening for engineers who will not ship confident wrong conclusions into a root-cause report.

📌 Remember

Every acronym you use in an interview answer should be one you can expand and explain. If you say “RCB”, expect “what is the Read Completion Boundary and why does it change how many CplD TLPs you see?”

37.1 Beginner Interview Bank

37.1.1 Why this chapter exists

Beginner questions verify that the foundational vocabulary is attached to correct mental models: what Peripheral Component Interconnect Express (PCIe) is versus what Non-Volatile Memory Express (NVMe) is, what a queue is, what a namespace is, why Direct Memory Access (DMA) matters. Entry-level and new-graduate loops are dominated by these. Senior candidates also get them — as warm-ups — and lose surprising amounts of credibility when they blur “NVMe completion” and “PCIe completion”.

37.1.2 Learning objectives

  • Answer 25+ foundational questions with correct layer attribution.
  • Avoid the classic conflations listed in the misconceptions material (form factor vs protocol, transport vs command set, controller vs namespace).
  • Give each answer a concrete example (a register, a command, a Linux command).

Prerequisites: Part I, Part II, Part III, first chapters of Part IV and Part IX.

Interview questions — Beginner (conceptual, Linux, simple trace)

  1. Beginner What is the difference between NVMe and PCIe?
    Model answer

    PCIe is a general-purpose, packet-based, point-to-point serial interconnect: it defines electrical signalling, link training, packets (Transaction Layer Packets, TLPs), flow control, configuration space and error reporting. It knows nothing about storage. NVMe is a storage interface and command set: it defines controllers, namespaces, submission/completion queues, commands like Read (02h) and Write (01h), and controller registers. NVMe over PCIe uses PCIe as its transport — the NVMe controller is a PCIe function, its registers live in a Base Address Register (BAR) region, and its queue traffic travels as PCIe memory reads/writes. NVMe can also run over RDMA or TCP (NVMe over Fabrics), and PCIe carries many non-NVMe devices (GPUs, NICs). verified

  2. Beginner Is “M.2” the same thing as NVMe?
    Model answer

    No. M.2 is a form factor and connector specification. An M.2 slot can carry PCIe lanes, SATA, or both depending on keying and the host wiring. An M.2 SSD may be a SATA (AHCI) drive or an NVMe drive. Likewise NVMe devices ship in U.2, U.3, E1.S, E3.S, add-in-card and BGA form factors. Form factor ≠ electrical interface ≠ protocol. Confirm with lspci (class code 01:08:02 = Non-Volatile memory controller, NVMe programming interface) rather than looking at the connector.

  3. Beginner What is a namespace, and how is it different from a controller?
    Model answer

    A controller is the interface entity the host talks to: it owns registers, queues and processes commands. A namespace is a quantity of non-volatile storage, formatted into logical blocks, that commands address by Namespace ID (NSID). One controller can expose many namespaces; in multi-controller subsystems one namespace can be attached to several controllers (shared namespace). In Linux, /dev/nvme0 is the controller character device and /dev/nvme0n1 is namespace 1’s block device. Confusing the two leads to bugs such as sending a Read with NSID 0 or assuming “one drive = one namespace”.

  4. Beginner What is a Submission Queue and a Completion Queue?
    Model answer

    Both are circular buffers in memory (normally host memory) shared between host and controller. The host places 64-byte Submission Queue Entries (SQEs) — commands — into a Submission Queue (SQ) and advances the tail. The controller places 16-byte Completion Queue Entries (CQEs) into a Completion Queue (CQ) and the host advances the head after consuming them. The host is the producer of the SQ and consumer of the CQ; the controller is the reverse. Several SQs may map to one CQ. Admin queue pair is queue ID 0; I/O queues are created with Create I/O CQ (05h) then Create I/O SQ (01h).

  5. Beginner What is a doorbell?
    Model answer

    A doorbell is a controller register (in BAR0, starting at offset 1000h) that the host writes to announce a new SQ tail or a new CQ head. It is a notification, not the command itself: the command bytes sit in host memory and the controller fetches them by DMA after the doorbell write. On PCIe the doorbell write appears as a small posted Memory Write TLP. verified

  6. Beginner What does DMA mean and why does NVMe rely on it?
    Model answer

    Direct Memory Access lets a device read or write system memory itself, without the CPU copying each byte. NVMe controllers fetch SQEs, read write-data, write read-data and post CQEs using DMA. This keeps the CPU free and makes deep queues possible. The CPU’s only per-command MMIO work is the doorbell write (and possibly interrupt handling). DMA is not a CPU copy; on PCIe it is the device acting as requester: Memory Read requests answered by Completions with Data, and Memory Writes.

  7. Beginner What is a PCIe lane and what does “x4” mean?
    Model answer

    A lane is one differential pair transmitting plus one differential pair receiving — a full-duplex serial path. x4 means the link has four lanes; data is striped byte-wise across lanes. Most client NVMe SSDs use x4; some enterprise designs use x2 dual-port or x8. The negotiated width can be lower than the capability (e.g. a damaged lane causes x2), which is visible in lspci -vvv LnkSta versus LnkCap.

  8. Beginner List the PCIe generations and their per-lane transfer rates.
    Model answer

    Gen1 2.5 GT/s, Gen2 5 GT/s (both 8b/10b encoding), Gen3 8 GT/s, Gen4 16 GT/s, Gen5 32 GT/s (128b/130b), Gen6 64 GT/s (PAM4 signalling, FLIT mode with forward error correction). PCIe 7.0 at 128 GT/s was released in 2025 version. GT/s is transfers per second on the wire, not bytes: Gen3 per lane ≈ 8 × 128/130 / 8 ≈ 0.985 GB/s per direction before packet overhead.

  9. Beginner Why is NVMe faster than AHCI/SATA for SSDs?
    Model answer

    AHCI was designed around spinning disks: one command queue of 32 entries, register-heavy command issue (several uncacheable MMIO reads per command), and a SATA link capped at 6 Gb/s. NVMe allows up to 65,535 I/O queues each up to 65,536 entries (limited by CAP.MQES), per-CPU queues without locks, a streamlined 64-byte command, one doorbell write per batch, MSI-X interrupts steerable per queue, and it rides directly on PCIe lanes. The gains are lower software overhead, parallelism, and link bandwidth.

  10. Beginner What is a BAR?
    Model answer

    A Base Address Register in a PCIe function’s configuration header tells system software how big a memory (or I/O) window the function needs; software writes a base address into it during enumeration. For NVMe, BAR0 (often 64-bit, using BAR0/BAR1) maps the controller registers: CAP at 00h, VS at 08h, CC at 14h, CSTS at 1Ch, AQA at 24h, ASQ at 28h, ACQ at 30h, doorbells from 1000h. The MSI-X table usually also lives in a BAR.

  11. Beginner What happens when you run lspci? Where does the data come from?
    Model answer

    lspci reads PCI configuration space via the kernel (sysfs /sys/bus/pci/devices/*/config) and decodes vendor/device IDs, class codes, BARs and capabilities using the pci.ids database. The kernel obtained that configuration space by issuing configuration read requests (CfgRd0/CfgRd1 TLPs) through the root complex, typically via the ECAM memory-mapped region. Non-root users may see only the first 64 bytes.

  12. Beginner What does nvme list show, and which NVMe command does it rely on?
    Model answer

    It lists NVMe namespaces with model, serial, firmware revision, namespace usage and format. The information comes from Identify (admin opcode 06h): Identify Controller (CNS 01h) gives model/serial/firmware; Identify Namespace (CNS 00h) gives size, capacity, utilisation and LBA formats. nvme-cli reads cached sysfs attributes or issues Identify through the controller character device ioctl.

  13. Beginner What is an LBA and what is a logical block size?
    Model answer

    A Logical Block Address numbers fixed-size logical blocks within a namespace, starting at 0. Block size comes from the active LBA format reported by Identify Namespace (FLBAS selects an entry in the LBAF table; LBADS is log2 of the data size, e.g. 9 = 512 B, 12 = 4096 B). LBAs are logical: the Flash Translation Layer maps them to physical NAND locations, which change over time.

  14. Beginner What is the admin queue used for?
    Model answer

    The admin queue pair (queue ID 0) carries management commands: Identify, Create/Delete I/O SQ/CQ, Get/Set Features, Get Log Page, Firmware Download/Commit, Format NVM, Sanitize, Abort, Asynchronous Event Request. Its location and size are programmed by the host in ASQ, ACQ and AQA before setting CC.EN = 1. It is not used for normal data I/O.

  15. Beginner What is an interrupt and what is MSI-X?
    Model answer

    An interrupt notifies the CPU that something needs attention. MSI-X (Message Signalled Interrupts, extended) delivers interrupts as Memory Write TLPs to an address/data pair programmed by the OS in a per-vector table in device BAR space. Each table entry is 16 bytes: message address low/high, message data, vector control (mask bit). NVMe maps each CQ to a vector so completions on different CPUs raise different interrupts. Legacy INTx is emulated with Assert/Deassert messages.

  16. Beginner What is a TLP?
    Model answer

    A Transaction Layer Packet: the PCIe unit that carries memory reads/writes, completions, configuration accesses and messages. It has a 3- or 4-DW header (Fmt, Type, Length, Requester ID, Tag, address or completion fields), optional data payload and optional end-to-end CRC (ECRC). The Data Link Layer adds a sequence number and LCRC; the Physical Layer adds framing. An NVMe command is not a TLP — one NVMe command produces several TLPs.

  17. Beginner What does the phase tag in a CQE do?
    Model answer

    The phase tag (P, bit 16 of CQE DW3) lets the host detect new entries without reading a controller register. The controller inverts the value it writes each time it wraps the CQ. The host remembers the expected phase; an entry whose P matches the expected value is new. After the host wraps its head, it flips its expected phase. Initial CQ memory is zeroed so the first pass uses phase 1.

  18. Beginner What is SMART data on an NVMe drive and how do you read it?
    Model answer

    The SMART / Health Information log page (Log Identifier 02h) reports critical warning bits, composite temperature, available spare, percentage used, data units read/written, host commands, controller busy time, power cycles, power-on hours, unsafe shutdowns, media and data integrity errors, and number of error log entries. Read it with nvme smart-log /dev/nvme0. It is a health summary, not a debugging trace: it tells you that media errors happened, not which command failed.

  19. Beginner What is the difference between a block device and a character device for NVMe in Linux?
    Model answer

    /dev/nvme0n1 is a block device: filesystems and the block layer issue reads/writes through it, with request queues and the page cache. /dev/nvme0 is the controller character device used for admin passthrough ioctls (Identify, Get Log Page). Newer kernels also expose /dev/ng0n1 generic character devices for namespace passthrough, including io_uring passthrough version.

  20. Beginner What is the root complex?
    Model answer

    The root complex connects the CPU/memory subsystem to the PCIe hierarchy. It contains one or more root ports, turns CPU loads/stores to PCIe address ranges into TLPs, turns device DMA TLPs into memory accesses, and generates configuration requests. Error reporting (AER) for a downstream device is typically collected at its root port.

  21. Beginner What does “link training” mean?
    Model answer

    Before data flows, the two ends of a link run the Link Training and Status State Machine (LTSSM): Detect (is a receiver present?), Polling (bit/symbol lock), Configuration (lane numbers, width), then L0 (active). Speed changes above Gen1 go through Recovery, including equalization for Gen3+. Failure to train shows as no device in lspci, or a link at lower speed/width than expected.

  22. Beginner Why are NVMe queue sizes “zero-based”?
    Model answer

    Fields like AQA.ASQS, CAP.MQES and the queue size in Create I/O SQ store size−1, so the value 0 never means an empty queue and the full 16-bit range is usable. A queue of 1024 entries is written as 1023 (3FFh). Forgetting this gives off-by-one queue sizes. A queue of N entries can hold at most N−1 outstanding commands, because full is defined as tail+1 == head.

  23. Beginner A drive shows up as Gen4 x4 in its datasheet but lspci reports 8 GT/s x4. Is this a problem?
    Model answer

    Possibly. It means the link trained at Gen3. Causes: the slot or CPU only supports Gen3, BIOS forces Gen3, a riser/retimer limits speed, or signal-integrity issues forced a fallback. Compare LnkCap (device capability), the root port’s LnkCap, and LnkSta. If both ends support 16 GT/s and LnkSta shows 8 GT/s, investigate. Some devices also downshift in low-power modes — check again under load.

  24. Beginner What does CC.EN do?
    Model answer

    The Enable bit (bit 0 of Controller Configuration, offset 14h). Setting 0→1 tells the controller to start processing using the admin queue addresses in AQA/ASQ/ACQ; the host waits for CSTS.RDY = 1, bounded by CAP.TO (units of 500 ms). Clearing 1→0 performs a controller reset: queues are deleted, outstanding commands are lost, and the host waits for CSTS.RDY = 0.

  25. Beginner Name three log pages and what each is for.
    Model answer

    Error Information (01h): recent error entries with SQID, CID, status, LBA and NSID where applicable. SMART/Health (02h): health counters. Firmware Slot Information (03h): firmware revisions per slot and active slot. Others: Changed Namespace List (04h), Commands Supported and Effects (05h), Device Self-test (06h), Telemetry Host/Controller-Initiated (07h/08h).

  26. Beginner Why is “PCIe Gen5 SSD” not a statement about the NVMe revision?
    Model answer

    Gen5 describes the PCIe link speed (32 GT/s). The NVMe revision (e.g. 1.4, 2.0) is reported by the controller in the VS register and describes which NVMe features/semantics it implements. A Gen5 drive could implement NVMe 2.0; a Gen3 drive could implement 1.4. They are independent axes.

Several beginner answers mention Linux commands. All are read-only inspection; never practise with nvme format, nvme sanitize or setpci writes on a drive holding data you care about.

37.1.3 Beginner coding warm-ups

These are short coding questions frequently used to check that a candidate can manipulate bits correctly.

Interview questions — Beginner coding

  1. Beginner Write a function that computes the SQ y tail doorbell offset given CAP.
    Model answer 
    def sq_tail_doorbell(cap: int, qid: int) -> int:
    dstrd = (cap >> 32) & 0xF          # CAP.DSTRD, bits 35:32
    stride = 4 << dstrd                 # bytes between doorbells
    return 0x1000 + (2 * qid) * stride

def cq_head_doorbell(cap: int, qid: int) -> int:
    dstrd = (cap >> 32) & 0xF
    return 0x1000 + (2 * qid + 1) * (4 << dstrd)

assert sq_tail_doorbell(0, 0) == 0x1000
assert cq_head_doorbell(0, 0) == 0x1004
assert sq_tail_doorbell(0, 3) == 0x1018

    Points: DSTRD extraction, the factor 2 between SQ and CQ, and testing qid 0.

  2. Beginner Given NLB from a Read command, how many bytes are transferred for a 4096-byte LBA format?
    Model answer

    NLB (CDW12 bits 15:0) is zero-based, so bytes = (NLB + 1) × 4096. NLB = 7 → 32 KiB. Metadata, if interleaved (extended LBA), adds (NLB+1) × MS bytes.

  3. Beginner Decode CQE DW3 = 0x0001_0005. What do you know?
    Model answer

    CID = bits 15:0 = 0x0005. Bit 16 = phase tag = 1. Bits 31:17 = status = 0 → SCT 0, SC 00h, successful completion. The CQE also needs DW2 (SQHD, SQID) to know which SQ the CID belongs to: CIDs are unique only per SQ.

37.2 Intermediate Interview Bank

37.2.1 Why this chapter exists

Intermediate questions check that you can follow a single command through all layers, read basic register values, decode TLP headers, and do simple performance arithmetic. This is the level of a driver, firmware or validation engineer with one to three years of experience.

37.2.2 Learning objectives

  • Trace a 4 KiB read from read() to interrupt and name each PCIe transaction with its direction.
  • Decode TLP header fields and CQE status fields by hand.
  • Apply Little’s law and link-efficiency estimates.
  • Explain the controller initialisation sequence register by register.

Prerequisites: Part V, Part VII, Part VIII, Part X, Part XI, Part XIII.

Interview questions — Intermediate

  1. Intermediate Walk me through the PCIe transactions of one 4 KiB NVMe Read, assuming PRP1 only and MSI-X.
    Model answer
    1. Host writes the 64-byte SQE into the SQ in host DRAM (CPU stores; no PCIe traffic).
    2. Host writes SQ tail doorbell: MWr host→device, 1 DW to BAR0+doorbell offset (posted).
    3. Controller fetches the SQE: MRd device→host, 64 bytes (16 DW) at SQ base + tail×64; host returns CplD with 64 bytes.
    4. Controller reads media, then writes data: one or more MWr device→host to PRP1, total 4096 bytes, split by Max Payload Size (e.g. 16 × 256 B at MPS 256).
    5. Controller posts CQE: MWr device→host, 16 bytes to CQ base + slot×16.
    6. Controller signals interrupt: MWr device→host to the MSI-X address with the vector’s data value.
    7. Host processes CQE and writes CQ head doorbell: MWr host→device (may be batched across completions).

    Ordering: PCIe posted-write ordering ensures the data MWrs are not passed by the CQE MWr in the same direction under default ordering rules (Relaxed Ordering, if enabled, changes this and the device must then take care) derived.

  2. Intermediate Describe the NVMe controller initialisation sequence.
    Model answer

    (1) Enumerate PCIe function, assign BAR0, enable Memory Space and Bus Master in the Command register. (2) Read CAP: MQES, TO, DSTRD, CSS, MPSMIN/MPSMAX. (3) If CC.EN = 1, clear it and wait for CSTS.RDY = 0. (4) Allocate admin SQ/CQ, write AQA (ASQS bits 11:0, ACQS bits 27:16, zero-based), ASQ, ACQ. (5) Write CC: CSS, MPS, AMS, IOSQES = 6 (64 B), IOCQES = 4 (16 B), EN = 1. (6) Poll CSTS.RDY = 1 up to CAP.TO × 500 ms; check CSTS.CFS. (7) Identify Controller, Identify active namespace list, Identify Namespace. (8) Set Features Number of Queues (FID 07h). (9) Create I/O CQs then I/O SQs. (10) Configure MSI-X vectors, submit Asynchronous Event Requests, set up other features (APST, volatile write cache, etc.).

  3. Intermediate Decode this TLP header: DW0 = 0x4000_0001, DW1 = 0x0000_000F, DW2 = 0xFEB0_1008.
    Model answer

    DW0: Fmt = bits 31:29 = 010 (3-DW header with data), Type = 00000 → Memory Write, 32-bit address. Length = 1 DW. DW1: Requester ID = 0000h (bus 0, dev 0, fn 0 — root complex), Tag 00h, Last DW BE = 0h, First DW BE = Fh (all 4 bytes). DW2: address = FEB01008h (bits 1:0 reserved). A 1-DW host-originated write into what is likely a device BAR at offset 1008h from FEB00000h — consistent with an SQ 1 tail doorbell if DSTRD = 0 and the BAR base is FEB00000h. synthetic Confirm by checking the BAR value in config space.

  4. Intermediate What is the difference between a posted and a non-posted request? Classify MWr, MRd, CfgWr, Msg.
    Model answer

    Posted requests receive no completion: Memory Write and Messages (including MSI-X, which is just an MWr). Non-posted requests require a completion: Memory Read (CplD or Cpl with error status), I/O Read/Write, Configuration Read/Write (configuration writes are non-posted and get a Cpl). Posted writes therefore cannot report errors to the requester through a completion; errors are reported via AER/error messages instead.

  5. Intermediate Explain Max Payload Size and Max Read Request Size and their impact on NVMe throughput.
    Model answer

    MPS (Device Control, 128–4096 B, set no larger than the smallest MPS supported along the path) caps the data payload in one TLP. MRRS caps the size a requester may ask for in one MRd. For NVMe writes the controller reads host data with MRds limited by MRRS; the completer returns CplDs limited by MPS and split at Read Completion Boundary (RCB) multiples. For reads, the device writes host memory with MWrs limited by MPS. Larger MPS reduces header overhead: payload efficiency ≈ MPS / (MPS + ~20–30 B overhead per TLP). At 128 B that is ~82%; at 512 B ~95% derived.

  6. Intermediate A drive delivers 500 K IOPS at QD 64 per drive. What is the average latency?
    Model answer
    L = N / X
    • L — mean latency (s)
    • N — mean outstanding I/Os (queue depth sustained)
    • X — throughput (IOPS)

    64 / 500 000 = 128 µs. If measured latency is much higher, the queue depth is not actually sustained (host-side bottleneck) or latency is being measured differently (e.g. including submission time in user space).

  7. Intermediate When does a Read need a PRP list?
    Model answer

    With memory page size MPS (CC.MPS, typically 4 KiB): PRP1 points to the first page (may have an offset). If the transfer fits in the remainder of PRP1’s page plus one more page, PRP2 points directly to the second page. If it needs more pages, PRP2 points to a PRP list — an array of 8-byte page pointers; if the list exceeds one page, the last entry chains to the next list page. A page-aligned 8 KiB read uses PRP1 + PRP2 directly; a 12 KiB read uses a PRP list with two entries. An unaligned 8 KiB read touches three pages and needs a list.

  8. Intermediate What is the difference between an SGL and a PRP?
    Model answer

    PRPs are fixed-size page pointers; every entry except the first must be page-aligned, so describing scattered byte-granular buffers is awkward. Scatter Gather Lists use descriptors (Data Block, Bit Bucket, Segment, Last Segment, Keyed Data Block for fabrics) with explicit address and length, so arbitrary byte-aligned buffers are described efficiently. Support for SGLs in NVMe over PCIe I/O commands is optional and advertised in Identify Controller SGLS. PSDT in CDW0 selects PRP vs SGL. Fabrics transports use SGLs.

  9. Intermediate Decode CQE DW3 = 0x8004_8012 (status in bits 31:17).
    Model answer

    CID = bits 15:0 = 0x8012. Upper half = 0x8004; bit 16 (P) = 0x8004 & 1 = 0, so phase = 0. Status (bits 31:17) = 0x8004 >> 1 = 0x4002: SC = bits 7:0 = 02h, SCT = bits 10:8 = 0 (generic command status), CRD = bits 12:11 = 0, M (More) = bit 13 = 0, DNR = bit 14 = 1. Meaning: Invalid Field in Command, Do Not Retry. The host must not retry the identical command; inspect CDW10–15 for an unsupported value. Interviewers deliberately choose values where the phase bit and the status field are easy to confuse — show the shifting explicitly. (Compare: DW3 upper half 0x4004 would give status 0x2002, which is SC 02h with the More bit set instead of DNR.)

  10. Intermediate Why must the host create the I/O CQ before the I/O SQ?
    Model answer

    Create I/O SQ (01h) takes a CQID in CDW11 identifying the completion queue it will post into. If that CQ does not exist the command fails with a command-specific status (Completion Queue Invalid). Deletion is the reverse: delete SQs first, then the CQ, otherwise Delete I/O CQ fails with Invalid Queue Deletion.

  11. Intermediate What is Bus Master Enable and what happens if it is cleared while I/O is outstanding?
    Model answer

    Bit 2 of the PCI Command register. When 0, the function must not issue memory or I/O requests upstream — no DMA, no MSI/MSI-X. With NVMe I/O outstanding, the controller cannot fetch commands, move data or post completions; the host sees timeouts. This happens during driver unbind, some error recovery paths, or a buggy hot-plug flow. On a trace you see the doorbell MWr arrive and then nothing upstream.

  12. Intermediate How do you find the current link speed and width in Linux?
    Model answer 
    sudo lspci -s 0000:03:00.0 -vvv | grep -E 'LnkCap:|LnkSta:'
cat /sys/bus/pci/devices/0000:03:00.0/current_link_speed
cat /sys/bus/pci/devices/0000:03:00.0/current_link_width
cat /sys/bus/pci/devices/0000:03:00.0/max_link_speed

    Compare device and upstream port values. Check under load because ASPM does not change speed but some platforms do dynamic speed changes.

  13. Intermediate What is the Requester ID and why does it matter for DMA?
    Model answer

    The 16-bit Bus/Device/Function identifier of the requester, placed in every request TLP. Completions are routed back using it. The IOMMU uses it (plus PASID if present) to select the translation context, so a DMA with an unexpected Requester ID — e.g. from an SR-IOV VF not set up in the IOMMU, or after a bus renumbering — faults. A changed bus number after hot-plug without re-enumeration causes completions to be misrouted (Unexpected Completion).

  14. Intermediate Explain the difference between Flush, FUA and volatile write cache.
    Model answer

    If Identify Controller VWC indicates a volatile write cache and it is enabled (Feature 06h), a successful Write completion may mean data is in volatile cache. Flush (00h) commits cached data for the namespace to non-volatile media before completing. Force Unit Access (FUA, CDW12 bit 30 in Write/Read) requires that specific write to be on non-volatile media before completion. Filesystems use flush/FUA for journal barriers. Drives with power-loss protection often report no volatile write cache, making Flush cheap.

  15. Intermediate What causes a “Completion Timeout” in PCIe terms?
    Model answer

    A requester issued a non-posted request (e.g. MRd) and did not receive a matching completion (same Requester ID and Tag) within the configured completion timeout range (Device Control 2). It is reported by the requester. If the NVMe controller reports it, the host did not answer the device’s read (e.g. an SQ fetch or write-data fetch), possibly due to IOMMU blocking, root complex problems or a lost CplD. If a root port reports it, a CPU MMIO read to the device went unanswered — the device may be hung or the link down. Default severity is uncorrectable non-fatal.

  16. Intermediate What is AER and what are its three error classes?
    Model answer

    Advanced Error Reporting is an extended capability that logs errors in status registers with mask and severity controls and a header log for the offending TLP. Classes: Correctable (hardware recovered, e.g. Receiver Error, Bad TLP, Bad DLLP, Replay Timer Timeout, REPLAY_NUM Rollover); Uncorrectable Non-Fatal (transaction lost but link OK, e.g. Completion Timeout, Unsupported Request, Poisoned TLP, Completer Abort, Unexpected Completion, ECRC error); Uncorrectable Fatal (link/hardware reliability compromised, e.g. Surprise Down, Data Link Protocol Error, Malformed TLP, Flow Control Protocol Error, Receiver Overflow). Severity of uncorrectable errors is programmable.

  17. Intermediate How do interrupt coalescing and polling affect latency vs CPU usage?
    Model answer

    Coalescing (Feature 08h: aggregation threshold and time) reduces interrupts per completion, lowering CPU overhead at high IOPS but adding up to the aggregation time to latency at low QD. Polling (Linux io_poll / hipri) removes interrupt latency but burns CPU spinning. The right choice depends on QD and latency SLO; measure with fio clat percentiles and CPU utilisation.

  18. Intermediate What is the Commands Supported and Effects log used for?
    Model answer

    Log page 05h lists, per opcode, whether it is supported and what side effects it has (logical block content change, capability change, namespace inventory change, controller capability change, submission/execution constraints). The Linux driver uses it to decide, e.g., to rescan namespaces or quiesce I/O around vendor-specific passthrough commands.

  19. Intermediate What is the significance of the SQ Head Pointer in the CQE?
    Model answer

    CQE DW2 bits 15:0 (SQHD) report how far the controller has consumed the associated SQ. The host uses it to know which SQ slots can be reused — the host must not overwrite slots between its last known SQHD and the tail. A stale or non-advancing SQHD in a trace suggests the controller is not fetching.

  20. Intermediate Two CQEs arrive with the same CID. Is that a bug?
    Model answer

    Not necessarily: CIDs are unique per SQ among outstanding commands. Two CQEs with the same CID but different SQIDs are normal. Same SQID and CID twice for one submission is a bug (duplicate completion) — or the host reused the CID after the first completion, which is legal. Check SQID, timing, and the submission log.

  21. Intermediate What is the difference between Function Level Reset, controller reset and NVM Subsystem Reset?
    Model answer

    Controller reset (CC.EN 1→0) resets the NVMe controller state: queues are deleted, PCIe config state preserved. Function Level Reset (PCIe, via Device Control initiate-FLR) resets the PCIe function including config state such as BARs and MSI-X; the driver must restore config. NVM Subsystem Reset (writing 4E564D65h, “NVMe”, to NSSR at 20h when CAP.NSSRS = 1) resets the whole subsystem and may cause the link to retrain. Conventional resets (hot reset, warm/cold) are PCIe-level and reset everything below.

  22. Intermediate Write pseudocode for consuming completions from a CQ.
    Model answer 
    while True:
    cqe = cq.mem[cq.head]
    if ((cqe.dw3 >> 16) & 1) != cq.phase:
        break                       # no new entry
    rmb()                           # read barrier: phase before payload
    sqid = cqe.dw2 >> 16
    sq[sqid].head = cqe.dw2 & 0xFFFF
    complete(sqid, cqe.dw3 & 0xFFFF, (cqe.dw3 >> 17) & 0x7FFF, cqe.dw0)
    cq.head += 1
    if cq.head == cq.size:
        cq.head = 0
        cq.phase ^= 1
mmio_write32(cq_head_doorbell, cq.head)    # once per batch

    Key points: memory barrier after phase check, phase inversion on wrap, single doorbell per batch.

  23. Intermediate How does the Linux NVMe driver handle an I/O timeout?
    Model answer

    The block layer fires the timeout (nvme_core.io_timeout default 30 s impl). The driver first checks if the controller is alive (CSTS); if CSTS reads all-ones the device is likely gone from the bus. It may poll the CQ in case the interrupt was lost. Otherwise it issues an Abort (admin 08h); if that also times out or the controller is in a bad state, it resets the controller (disables, re-enables, recreates queues) and requeues outstanding requests. Messages appear in dmesg. Exact behaviour varies by kernel version version.

  24. Intermediate What does “CSTS = 0xFFFFFFFF” in a kernel message tell you?
    Model answer

    A memory read to the device returned all ones. That is what the root complex typically synthesises when an MMIO read fails (Unsupported Request, link down, device in a state where it does not respond) impl. It is evidence that the PCIe path is broken, not that the controller set every status bit. Next: check lspci for the device, link status at the root port, AER logs, Surprise Down, and whether config reads also return all ones.

  25. Intermediate What is ASPM and how could it cause NVMe latency spikes?
    Model answer

    Active State Power Management lets the link enter L0s or L1 autonomously when idle. Exiting L1 takes microseconds (exit latency reported in LnkCap). A low-QD workload with idle gaps pays the exit latency on the first transaction after idleness, showing as tail-latency spikes. L1 substates (L1.1/L1.2) save more power with longer exits. Diagnose by comparing latency with ASPM disabled (pcie_aspm=off boot parameter, on a test system) and checking LnkCtl ASPM bits.

  26. Intermediate What is a Completion with Unsupported Request status and who generates it?
    Model answer

    A completer that receives a non-posted request it cannot handle (address not claimed by any BAR, disabled memory space, unsupported type) returns a Cpl with status UR (001b). For posted requests no completion is sent, but the error is logged via AER. A host MMIO read to a device whose Memory Space Enable bit is cleared, or to an unassigned BAR, gets UR.
