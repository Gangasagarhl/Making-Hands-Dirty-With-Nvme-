📘 Specification baseline

DOCUMENTS: NVM Express Base Specification 2.4 (controller properties: definitions and semantics) and NVMe over PCIe Transport Specification 1.4 (memory-mapped placement in BAR0, doorbells, PCIe-only registers) version. STATUS: current baseline — confirm on nvmexpress.org. OLDER VERSIONS THAT MAY DIFFER: NVMe 1.0–1.4 controllers lack 2.x fields (e.g. CAP.CRMS, CC.CRIME, CSTS.ST, NSSD, CRTO); CMB control registers (CMBMSC, CMBSTS…) and PMR registers arrived in 1.4; boot partition registers in 1.3. Reserved bits in an older controller read as 0. SOURCE: nvmexpress.org; Linux include/linux/nvme.h (openly readable register and field definitions).

24.1 Why this chapter exists

The register block in BAR0 is where the host and the controller first shake hands and where, when things go wrong, the controller says so (CSTS.CFS). Every NVMe bring-up, every reset, every "drive not ready" ticket and every driver port goes through these registers. The master curriculum demands depth: for each register — address, width, fields, purpose, reset behaviour, host interaction, controller interaction, trace consequences — without inventing field values. This chapter delivers that, then assembles the registers into the full controller initialization sequence and lets you execute it against a simulated controller.

24.2 Learning objectives

  • Beginner: name the registers at 00h–37h and the doorbell region, and say what each is for.
  • Intermediate: decode CAP, VS, CC, CSTS and AQA values by hand and with code.
  • Advanced: perform and justify every step of the controller initialization sequence; compute doorbell addresses for any DSTRD; reason about timeouts from CAP.TO.
  • Senior: diagnose initialization failures from a register trace; reason about reset behaviour and version differences; design register-level conformance tests.
  • Trace analysis: decode every MMIO TLP to BAR0 into a register access with meaning.
  • Validation: verify RO fields are stable, RW fields behave, invalid configurations are handled per spec.

24.4 Story

🧒 Kid analogy

The librarian's desk has a control panel. A brass plate you can only read (CAP: "I can hold 1024 slips per box, I need up to 20 seconds to wake up, my bells are 4 steps apart"). A version sticker (VS). A row of switches you set (CC: "start working", "use page size 4 KiB", "slips are 64 bytes"). Status lights (CSTS: ready, fatal, shutting down). Two hooks where you hang the addresses of the very first request box and answer box (ASQ, ACQ) and a dial for their sizes (AQA). And a long wall of bells (doorbells), one pair for each box pair.

🧩 Where the analogy breaks

The panel is not just read and set at leisure: some switches must only be changed while the desk is off (most CC fields with EN=0), some lights take time to change after you flip a switch (RDY after EN), and pressing the wrong bell (an invalid doorbell offset or value) is reported as an error event rather than ignored.

The executable decoder below reproduces this decode and also decodes VS, CC, CSTS examples and doorbell offsets:

#!/usr/bin/env python3
"""Decode NVMe controller registers from SYNTHETIC values (no hardware access).
Field positions follow the NVMe Base Specification register definitions; fields
marked (2.x) were added in the 2.0-era revisions -- confirm against your revision."""

def f(v, hi, lo):
    return (v >> lo) & ((1 << (hi - lo + 1)) - 1)

def decode_cap(cap):
    css = f(cap, 44, 37)
    out = {
        "MQES  (15:0)  max queue entries": f"{f(cap,15,0)} (0's based) -> {f(cap,15,0) + 1} entries",
        "CQR   (16)    contiguous queues required": f(cap, 16, 16),
        "AMS   (18:17) arbitration supported": f"WRR+urgent={f(cap,17,17)} vendor={f(cap,18,18)}",
        "TO    (31:24) timeout": f"{f(cap,31,24)} x 500 ms = {f(cap,31,24) * 0.5:g} s",
        "DSTRD (35:32) doorbell stride": f"{f(cap,35,32)} -> {4 << f(cap,35,32)} bytes",
        "NSSRS (36)    subsystem reset supported": f(cap, 36, 36),
        "CSS   (44:37) command sets supported": f"{css:#04x}: NVM={css & 1} "
                        f"IOCS={(css >> 6) & 1} admin-only={(css >> 7) & 1}",
        "BPS   (45)    boot partitions": f(cap, 45, 45),
        "MPSMIN(51:48) min page size": f"{4096 << f(cap,51,48)} bytes",
        "MPSMAX(55:52) max page size": f"{4096 << f(cap,55,52)} bytes",
        "PMRS  (56)    persistent memory region": f(cap, 56, 56),
        "CMBS  (57)    controller memory buffer": f(cap, 57, 57),
        "CRMS  (60:59) ready modes (2.x)": f"with-media={f(cap,59,59)} independent={f(cap,60,60)}",
    }
    for k, val in out.items():
        print(f"  {k:42} {val}")

def decode_vs(vs):
    print(f"  VS {vs:#010x} -> NVMe {f(vs,31,16)}.{f(vs,15,8)}.{f(vs,7,0)}")

def decode_cc(cc):
    print(f"  CC {cc:#010x}: EN={f(cc,0,0)} CSS={f(cc,6,4):03b}b MPS={f(cc,10,7)} "
          f"({4096 << f(cc,10,7)} B) AMS={f(cc,13,11):03b}b SHN={f(cc,15,14):02b}b "
          f"IOSQES={f(cc,19,16)} ({1 << f(cc,19,16)} B) IOCQES={f(cc,23,20)} ({1 << f(cc,23,20)} B)")

def decode_csts(csts):
    shst = {0: "normal", 1: "shutdown in progress", 2: "shutdown complete", 3: "reserved"}
    print(f"  CSTS {csts:#010x}: RDY={f(csts,0,0)} CFS={f(csts,1,1)} "
          f"SHST={shst[f(csts,3,2)]} NSSRO={f(csts,4,4)} PP={f(csts,5,5)}")

def doorbell(qid, dstrd, completion):
    return 0x1000 + (2 * qid + (1 if completion else 0)) * (4 << dstrd)

CAP = 0x1A40_0830_2803_03FF        # synthetic, chosen for teaching
print(f"CAP = {CAP:#018x}")
decode_cap(CAP)
decode_vs(0x0002_0400)
decode_cc(0x0046_0001)              # EN=1, CSS=000b, MPS=0, IOSQES=6, IOCQES=4
decode_csts(0x0000_0001)
decode_csts(0x0000_0003)            # RDY=1 and CFS=1: fatal status
for q in (0, 1, 2):
    print(f"  queue {q}: SQ{q}TDBL @ {doorbell(q, 0, False):#06x}  CQ{q}HDBL @ {doorbell(q, 0, True):#06x}")
print(f"  with DSTRD=2: SQ1TDBL @ {doorbell(1, 2, False):#06x}")

24.7 VS — Version (08h, 32-bit, RO)

Bits 31:16Bits 15:8Bits 7:0
MJR — Major VersionMNR — Minor VersionTER — Tertiary Version

Examples: 0001_0400h = 1.4.0; 0002_0000h = 2.0.0; 0002_0400h = 2.4.0. Purpose: reports the Base Specification version the controller complies with verified. Pitfall: VS tells you the revision claimed, not which optional features exist; feature support is in CAP and Identify. Older 1.0 controllers may report VS = 0 for features not defined then; host drivers treat VS as a hint and rely on capability fields. Trace: one MRd early in probe; Linux logs a warning for some version/feature mismatches impl.

24.8 INTMS / INTMC — Interrupt Mask Set / Clear (0Ch / 10h)

Each bit corresponds to an interrupt vector. Writing 1 to a bit in INTMS masks that vector; writing 1 to the same bit in INTMC unmasks it; reading either returns the current mask. These registers are for pin-based and MSI interrupts only: when MSI-X is used, masking is done in the MSI-X table's Vector Control, and host software shall not use INTMS/INTMC (access is undefined) verified (confirm wording). They do not exist as properties on fabrics. Trace consequence: on modern MSI-X systems you should never see accesses to 0Ch/10h in the I/O path; if you do, the host fell back to MSI/INTx — check why (MSI-X allocation failure, quirk).

Reset behaviour: 0000_0000h after a controller reset (all fields default) verified. Host interaction: one write with configuration fields, then a write setting EN (Linux writes them together in one store: e.g. 0046_0001h). 🔧 Worked CC values

0046_0001h = IOCQES 4 (16 B), IOSQES 6 (64 B), SHN 00b, AMS RR, MPS 0 (4 KiB), CSS NVM, EN 1. During normal shutdown Linux writes the same value with SHN=01b → 0046_4001h. To reset: 0046_0000h.

24.11 NSSR — NVM Subsystem Reset (20h, 32-bit, optional)

Writing 4E564D65h ("NVMe" in ASCII, little-endian bytes 65 4D 56 4E) initiates an NVM Subsystem Reset if CAP.NSSRS = 1; other values have no effect. Reads return 0 (or the spec-defined value) verified. Effects: every controller in the subsystem is reset; on PCIe the link(s) may go down and retrain, so the host may see a surprise-down style event; CSTS.NSSRO is set afterwards. Trace consequence: one MWr to BAR0+20h followed by link recovery or Detect-to-L0 re-training on the analyzer and a full re-enumeration/re-init sequence. Linux: nvme subsystem-reset /dev/nvmeX (EXPERT, disruptive).

24.13 CMB, Boot Partition, PMR, NSSD, CRTO — the optional block

  • CMBLOC (38h): BIR (bits 2:0) selects the BAR holding the Controller Memory Buffer; OFST (bits 31:12) gives its offset in units of CMBSZ.SZU. CMBSZ (3Ch): support bits — SQS (bit 0, SQs in CMB), CQS (1), LISTS (2, PRP/SGL lists), RDS (3, read data), WDS (4, write data); SZU (11:8, size unit: 4 KiB × 16SZU); SZ (31:12, size in SZU units). In 1.4+, CMBMSC (50h) must enable the CMB memory space and set its controller base address before use version. A CMB lets queues or data live in device memory — the host then writes SQEs via MMIO (often write-combining) and the controller avoids a DMA fetch.
  • BPINFO/BPRSEL/BPMBL (40h–4Fh): read boot partitions (a small read-only-at-boot area) without enabling the controller — useful for early boot firmware version.
  • PMR registers (E00h–E1Bh): Persistent Memory Region — a byte-addressable persistent region exposed through a BAR impl support.
  • NSSD (64h): NVM Subsystem Shutdown (2.0+) — initiate a subsystem-scope shutdown with a defined value version (check spec for the value).
  • CRTO (68h): Controller Ready Timeouts (2.0+) — CRWMT (bits 15:0, ready-with-media timeout) and CRIMT (bits 31:16, ready-independent-of-media timeout), in 500 ms units; hosts use them instead of CAP.TO when the ready modes apply version.

24.14 Doorbells

SQyTDBL = 1000h + (2y) × (4 << CAP.DSTRD) ; CQyHDBL = 1000h + (2y + 1) × (4 << CAP.DSTRD)
  • y — queue identifier (0 = admin).
  • CAP.DSTRD — doorbell stride field.
DoorbellBits 15:0Written whenController reaction
SQyTDBLSQT — new SQ tailHost has written one or more SQEsController may fetch entries from old tail to new tail − 1 (arbitration permitting)
CQyHDBLCQH — new CQ headHost has consumed CQEsController may reuse those CQ slots; may affect interrupt (re)assertion

Rules verified: queues are circular; full when tail + 1 == head (mod size), so one slot is always empty; the host must not write a tail that overruns the head or a head beyond the last posted CQE. Writing a doorbell for a non-existent queue, or an invalid value, is reported as an error via the Asynchronous Event mechanism (Error status: invalid doorbell register / invalid doorbell write value) if an Asynchronous Event Request is outstanding. Doorbells are write-only; reading them returns no meaningful value. Virtualized environments may use a Doorbell Buffer Config admin command (shadow doorbells) to reduce MMIO exits version.

📡 Why one slot is always empty

With head == tail meaning "empty", a completely full ring would also have head == tail. Reserving one slot makes "full" = (tail + 1) mod N == head. Hence a queue of MQES+1 entries holds at most MQES outstanding commands. derived

  2. Driver disables the controller and waits for RDY = 0

    Firmware or a boot loader may have left the controller running. The driver clears CC.EN and then reads CSTS again and again until RDY is 0. Admin queue registers may only be changed while the controller is disabled.

    Where: BAR0 + 14h (CC), then BAR0 + 1Ch (CSTS)PCIe: Yes · MWr 4 B host → device, then repeated MRd 4 B + CplD
    CC was 0046_0001h → driver writes 0046_0000h CSTS reads: 0000_0001h, 0000_0001h, 0000_0000h → RDY = 0, done
  3. Driver allocates the admin queues and a data buffer in RAM

    The driver takes page-aligned, DMA-able memory for the Admin Submission Queue, the Admin Completion Queue and a 4 KiB buffer for the Identify data. It zeroes the completion queue so every phase tag starts at 0.

    Where: Host memoryPCIe: No. The CPU writes its own RAM.
    Admin SQ: 32 × 64 B = 2 KiB at 0x1_0000_0000 Admin CQ: 32 × 16 B = 512 B at 0x1_0000_1000 (zeroed) Identify buffer: 4 KiB at 0x1_0000_2000
  4. Driver programs AQA, ASQ and ACQ

    The admin queue is the only queue described by registers. AQA holds both sizes (0's based); ASQ and ACQ hold the bus addresses of the two rings.

    Where: BAR0 + 24h (AQA), 28h (ASQ), 30h (ACQ)PCIe: Yes · MWr host → device (4 B for AQA; 8 B or two 4-B writes each for ASQ and ACQ)
    AQA = 001F_001Fh → ACQS = 31, ASQS = 31 → 32 entries each ASQ = 0000_0001_0000_0000h ACQ = 0000_0001_0000_1000h
  5. Driver writes CC with EN = 1

    One write sets the configuration fields and enables the controller. IOSQES and IOCQES are only needed later for I/O queues, but Linux sets them here.

    Where: BAR0 + 14h (CC)PCIe: Yes, host → device · MWr 4 B (posted)
    CC = 0046_0001h IOCQES = 4 (16-B CQE) · IOSQES = 6 (64-B SQE) · SHN = 00b AMS = 000b (round robin) · MPS = 0 (4 KiB pages) · CSS = 000b (NVM) · EN = 1
  6. Controller initialises and sets CSTS.RDY = 1

    On EN going 0 → 1 the controller checks the configuration, latches AQA/ASQ/ACQ and gets ready. When it is ready it sets RDY. The driver sees it only by polling CSTS, and gives up after CAP.TO.

    Where: Inside the SSD; result visible in BAR0 + 1ChPCIe: Only the driver's MRd of CSTS. The controller's internal work does not cross the link.
    CSTS reads 0000_0000h … then 0000_0001h after a few ms RDY = 1 and CFS = 0 → admin queue is live CFS = 1 instead would mean a fatal controller error → reset
  7. Driver submits Identify Controller

    The driver writes a 64-byte Identify command (CNS = 01h) into slot 0 of the Admin SQ, then rings the SQ 0 tail doorbell. Only the doorbell value crosses the link.

    Where: Admin SQ slot 0; doorbell at BAR0 + 1000hPCIe: SQE write No · doorbell Yes, MWr 4 B host → device
    OPC = 06h · CID = 0 · NSID = 0 PRP1 = 0x1_0000_2000 · CDW10 = 0000_0001h (CNS = 01h) SQ0TDBL ← 1
  8. Controller fetches the command from the Admin SQ

    The controller reads 64 bytes at the ASQ address. This is the first DMA of the controller's life, and the first proof that ASQ was programmed correctly.

    Where: Host memory 0x1_0000_0000PCIe: Yes, both ways · MRd 64 B device → host, CplD 64 B back
    A wrong ASQ here shows up as an IOMMU fault or a fetch of garbage.
  9. Controller writes 4 KiB of Identify data, then the completion

    The controller writes the Identify Controller structure into the PRP1 buffer, then a 16-byte completion entry into slot 0 of the Admin CQ, then (if enabled) an interrupt message. The admin CQ uses interrupt vector 0.

    Where: 0x1_0000_2000 (data), 0x1_0000_1000 (CQE)PCIe: Yes, device → host · MWr 4096 B split by Max Payload Size (e.g. 16 × 256 B), MWr 16 B, then the interrupt MWr
    CQE: CID = 0 · SQID = 0 · SQHD = 1 · P = 1 · Status = 0 (success)
  10. Driver reads the completion and rings the CQ 0 head doorbell

    The driver sees P = 1 in slot 0, matches CID 0, reads the Identify data (MDTS, SQES, CQES, number of namespaces…) and frees the slot by writing the CQ 0 head doorbell. Next come Set Features (Number of Queues) and creating I/O queues (Chapter 27).

    Where: Admin CQ slot 0; doorbell at BAR0 + 1004hPCIe: CQE read No · doorbell Yes, MWr 4 B host → device
    CQ0HDBL ← 1 Identify: MDTS = 5 → 2^5 × 4 KiB = 128 KiB per command (example)

24.15.2 Execute the handshake in simulation

#!/usr/bin/env python3
"""SIMULATION of the NVMe controller-enable handshake against a toy controller model.
The toy controller is synthetic: it becomes ready after a fixed number of polls and
checks a few of the rules a real controller enforces. No hardware is touched."""

CAP = 0x1A40_0830_2803_03FF          # synthetic CAP from the decode example

class ToyController:
    def __init__(self):
        self.regs = {"CC": 0, "CSTS": 1, "AQA": 0, "ASQ": 0, "ACQ": 0}   # left enabled by firmware
        self._countdown = 0
    def write(self, name, value):
        self.regs[name] = value
        if name == "CC":
            en = value & 1
            if not en:                         # disable: reset in progress
                self._countdown = 3
            else:
                aqa = self.regs["AQA"]
                ok = (aqa & 0xFFF) >= 1 and ((aqa >> 16) & 0xFFF) >= 1   # >= 2 entries each
                # Toy rule: bad admin-queue config -> never ready. What a REAL controller
                # does here is implementation-dependent (it may also report CSTS.CFS=1).
                self._countdown = 4 if ok else -1
    def read(self, name):
        if name == "CSTS" and self._countdown > 0:
            self._countdown -= 1
            if self._countdown == 0:
                want = self.regs["CC"] & 1
                self.regs["CSTS"] = (self.regs["CSTS"] & ~1) | want
        return self.regs[name]

def wait_rdy(ctrl, want, to_units):
    budget = to_units * 500                # CAP.TO is in 500 ms units; 1 poll = 1 ms here
    for ms in range(budget):
        csts = ctrl.read("CSTS")
        if csts & 2:
            raise RuntimeError("CSTS.CFS=1: controller fatal status -> reset path")
        if (csts & 1) == want:
            return ms
    raise TimeoutError(f"CSTS.RDY never reached {want} within {to_units * 0.5:g} s")

def enable(ctrl, asq_entries=32, acq_entries=32, asq=0x1_0000_0000, acq=0x1_0000_1000, mps=0):
    to = (CAP >> 24) & 0xFF
    mpsmin, mpsmax = (CAP >> 48) & 0xF, (CAP >> 52) & 0xF
    assert mpsmin <= mps <= mpsmax, "CC.MPS outside CAP.MPSMIN..MPSMAX"
    print("1. CC.EN=0 and wait for CSTS.RDY=0")
    ctrl.write("CC", ctrl.regs["CC"] & ~1)
    print(f"   RDY=0 after {wait_rdy(ctrl, 0, to)} polls")
    print("2. program AQA/ASQ/ACQ (sizes are 0's based)")
    ctrl.write("AQA", ((acq_entries - 1) << 16) | (asq_entries - 1))
    ctrl.write("ASQ", asq)
    ctrl.write("ACQ", acq)
    cc = (4 << 20) | (6 << 16) | (0 << 14) | (0 << 11) | (mps << 7) | (0 << 4)
    print(f"3. write CC={cc:#010x} (IOCQES=4, IOSQES=6, SHN=0, AMS=RR, MPS={mps}, CSS=NVM)")
    ctrl.write("CC", cc)
    print("4. set CC.EN=1")
    ctrl.write("CC", cc | 1)
    print(f"5. CSTS.RDY=1 after {wait_rdy(ctrl, 1, to)} polls -> admin queue usable")
    print("6. next: Identify Controller (CNS 01h), Identify namespaces, Set Features Number of Queues,")
    print("   Create I/O CQ (05h) then Create I/O SQ (01h), then Asynchronous Event Requests")

enable(ToyController())
print("--- same sequence with 1-entry admin queues (AQA fields = 0, invalid) ---")
try:
    enable(ToyController(), asq_entries=1, acq_entries=1)
except TimeoutError as e:
    print("   FAILED:", e)

24.16 Reading a register: the 11-step discipline applied to CSTS

  1. Locate: BAR0 + 1Ch (property offset 1Ch).
  2. Width: 32 bits; use a 32-bit read.
  3. Reset value: RDY = 0 after reset; other bits per spec.
  4. Decode: RDY(0), CFS(1), SHST(3:2), NSSRO(4), PP(5), ST(6).
  5. Access: RO except NSSRO (RW1C) — verified in the spec.
  6. Side effects: reading has none; writing 1 to NSSRO clears it.
  7. Sequencing: RDY follows CC.EN with delay ≤ TO; SHST follows CC.SHN.
  8. Related: CC (EN, SHN), CAP.TO, CRTO, NSSR, PCIe link state.
  9. Software owner: the NVMe driver (and only it, while bound).
  10. Hardware behaviour: controller updates on state changes.
  11. Trace implications: polling loops of MRd to 1Ch; all-ones means unreachable device.

💡 Senior insight

When reviewing a new driver or a firmware bring-up, demand a register trace of the first second: CAP/VS read, CC.EN=0 + RDY=0 wait, AQA/ASQ/ACQ, CC with EN=1, RDY wait, first doorbell, first SQE fetch address. 🧪 Lab 24.2 — Intermediate: compute doorbells and queue capacities SAFE

For DSTRD = 0, 1, 3 compute SQ5TDBL and CQ5HDBL. For a queue created with QSIZE = 3FFh, how many commands can be outstanding?

Solution

Stride 4/8/32 bytes. SQ5TDBL = 1000h + 10×stride = 1028h / 1050h / 1140h. CQ5HDBL = 1000h + 11×stride = 102Ch / 1058h / 1160h. QSIZE 3FFh → 1024 entries → at most 1023 outstanding (one slot empty).

🧪 Lab 24.4 — Senior forensic: trace 24.C SAFE

Model answer

Symptom: first admin command timeout. First bad event: SQE fetch MRd to 4_3A21_5000h rejected by IOMMU. Quiz

  1. At which offset is CSTS and which bit means "fatal"?

    Answer

    1Ch; bit 1 (CFS).

  2. Units of CAP.TO?

    Answer

    500 milliseconds.

  3. Why must I/O CQs be created before I/O SQs?

    Answer

    Create I/O SQ names the CQ (CQID) it posts completions to; the CQ must exist.

  4. Are AQA sizes 0's based?

    Answer

    Yes — like MQES and Create Queue QSIZE.

  5. When should INTMS/INTMC be used?

    Answer

    Only with pin-based or MSI interrupts, never with MSI-X (use the MSI-X table mask bits).

  6. What value does NSSR require?

    Answer

    4E564D65h ("NVMe").

Interview questions

  1. Beginner Name the NVMe registers involved in enabling a controller.
    Model answer

    CAP (limits, TO), CC (configuration + EN), CSTS (RDY, CFS), AQA/ASQ/ACQ (admin queues).

  2. Beginner What is a doorbell?
    Model answer

    A write-only MMIO register per queue: SQ tail doorbell announces new commands, CQ head doorbell releases consumed completions.

  3. Intermediate Decode MPS and why it matters.
    Model answer

    CC.MPS sets the host memory page size (4 KiB × 2^MPS) used for PRP entries and queue alignment; must be within CAP.MPSMIN..MPSMAX and match the host's PRP construction.

  4. Intermediate What happens if the host doesn't wait for RDY=0 after EN=0?
    Model answer

    It may reconfigure or re-enable while the controller is still resetting; results are undefined — stale state, RDY seen from the previous enable, or failures.

  5. Advanced How do 2.x ready modes change initialization?
    Model answer

    CAP.CRMS advertises ready-with-media vs ready-independent-of-media; CC.CRIME selects; CRTO provides corresponding timeouts; with CRIME the controller may become ready before media is ready, and namespaces report readiness separately — hosts must handle namespace-not-ready conditions. Verify details in the spec.

  6. Senior Design a register conformance test suite.
    Model answer

    RO stability (CAP/VS identical across reads and resets); reserved bits read 0 and writes ignored; CC writes only effective when allowed; RDY transitions within TO across 1000s of cycles; SHN/SHST behaviour under load; NSSRO set/clear semantics; doorbell error events for invalid offsets/values; 32-bit split accesses of 64-bit registers; behaviour across FLR, hot reset, NSSR; version-gated fields absent on older VS.
