PART X

NVMe Queues

Everything an NVMe (Non-Volatile Memory Express) controller does for a host starts with a 64-byte entry appearing in a ring buffer in host memory and ends with a 16-byte entry appearing in another ring buffer. This Part teaches those rings so precisely that you can compute, by hand, the head, tail, phase tag and doorbell value for any moment in a trace. Chapter 25 builds the general model (producer, consumer, full/empty, phase), Chapter 26 brings up the one queue pair the controller knows about at reset (the Admin queue), Chapter 27 uses it to create I/O queues, and Chapter 28 dissects the doorbell write all the way down to the PCIe (Peripheral Component Interconnect Express) Memory Write TLP (Transaction Layer Packet). If you can do the worked examples in this Part without looking, you can read 80% of an NVMe protocol trace.

25.1 Why this chapter exists

An NVMe device is fast for one structural reason: the host and the controller almost never wait for each other. They share circular queues in host memory; the host produces commands into a Submission Queue (SQ) and the controller produces results into a Completion Queue (CQ). Each side only tells the other "how far I have got" — with a doorbell register write in one direction and with a CQ entry (CQE) in the other. No locks are shared across the PCIe link. Every NVMe performance property (deep queues, per-CPU queues, interrupt steering, low latency) and almost every NVMe hang you will ever debug ("command timeout", "controller is down", "missing interrupt") is a consequence of this ring discipline. So we learn the rings first and the commands second.

25.2 Learning objectives

  • Beginner: name the SQ, CQ, Admin queue, I/O queue and say who produces and who consumes each.
  • Intermediate: compute the number of occupied slots, the empty condition and the full condition ((tail + 1) mod size == head) for any head/tail pair.
  • Advanced: step a CQ through a wrap and predict the phase tag value of every slot; explain why the phase tag removes the need for the host to read a controller register to find new completions.
  • Senior: given a partial trace, reconstruct each queue's head, tail and phase and identify the first event inconsistent with the ring rules.
  • Trace-analysis: map ring events to PCIe transactions (doorbell MWr, SQE MRd, CQE MWr, MSI-X MWr).
  • Debugging: distinguish "controller never fetched", "controller fetched but never completed" and "controller completed but host never noticed".
  • Validation: design tests for wrap-around, full-queue, phase inversion and SQHD feedback.

25.3 Prerequisites

You need: what MMIO (memory-mapped I/O) and DMA (direct memory access) are; that the NVMe controller registers live in BAR0 (Base Address Register 0) space; and that an MWr (Memory Write request) is posted while an MRd (Memory Read request) needs a CplD (Completion with Data). The controller registers CAP, CC, CSTS, AQA, ASQ and ACQ are used here and explained more in Chapter 26.

25.4 The story — the supermarket checkout

🧒 Kid analogy

Imagine a supermarket with a round conveyor belt at the checkout. You (the host) put shopping baskets on the belt at the spot marked "next empty spot" — that spot is the tail. The cashier (the controller) picks baskets up from the spot marked "next basket to scan" — that is the head. The belt is round, so when you reach the end you start again at the beginning. You must never put a basket on a spot where the cashier has not yet taken the old basket away — so you always leave one spot empty, which is how you can tell "belt full" from "belt empty".

When you put baskets down you ring a little bell (the doorbell) and shout the number of your latest spot. The cashier does not keep looking at the belt — they wait for the bell.

When a basket is done, the cashier puts a receipt on a second round belt that comes back to you (the completion queue). Receipts printed on the first trip around are printed in blue ink; on the second trip around, red ink; then blue again. You know a receipt is new if its ink colour is the colour you expect for this trip. That ink colour is the phase tag.

🧩 Where the analogy breaks
  • A supermarket cashier scans baskets in order. An NVMe controller fetches SQEs in order from one SQ but may complete them in any order. That is why every receipt must carry the basket's ticket number (CID) and SQ identifier.
  • Receipts are not tied to the basket's position on the belt. A CQ can serve several SQs; the controller writes the next free CQ slot, regardless of which SQ the command came from.
  • There are many checkouts (up to 65,535 I/O queue pairs in the specification limit; a real controller reports far fewer) and an extra "manager's desk" queue (the Admin queue) for store management rather than shopping.
  • The cashier does not physically remove the basket; "taking the basket" just means the controller has DMA-read the 64 bytes. The host learns that the slot is reusable only from the SQHD value in a later CQE.

25.5 Beginner view — the six words

Submission Queue (SQ): a fixed-size array of command slots. Completion Queue (CQ): a fixed-size array of completion slots. Producer: the side that writes new entries and advances the tail. Consumer: the side that reads entries and advances the head. Queue depth (size): number of slots. Phase tag: one bit in every CQE that flips meaning on every lap around the CQ.

📌 Remember

The owner of an index is the side that advances it. The host owns SQ tail and CQ head; the controller owns SQ head and CQ tail. Each side learns the other's index only through the one feedback channel: doorbell (host→controller) or CQE fields (controller→host).

25.6 Engineering view — ring arithmetic

Let the queue have N slots numbered 0…N−1. Indices always wrap modulo N.

used = (tail − head) mod N     free = N − 1 − used
  • N — queue size in entries (the Create command and AQA fields encode N−1, a 0-based value).
  • head — index of the next entry the consumer will read.
  • tail — index of the next free slot the producer will write.
  • used — entries written but not yet consumed.
  • free — slots the producer may still fill; one slot is always sacrificed.
EMPTY ⇔ head == tail      FULL ⇔ (tail + 1) mod N == head
  • The full rule means a queue of N slots holds at most N − 1 outstanding entries verified. Without the sacrificed slot, head == tail would be ambiguous (empty or full?).

25.6.1 The phase tag, precisely

The host cannot cheaply ask "what is your CQ tail?" — there is no CQ tail register the host reads in normal operation. Instead every CQE carries a Phase Tag (P) bit, DW3 bit 16 verified. The rules:

  1. Host allocates CQ memory and clears it to zero before creating the queue, so every slot initially has P = 0. (The specification requires the host to initialise the phase tags to 0 in a newly created CQ. verified)
  2. On the controller's first lap it writes every CQE with P = 1.
  3. When the controller's CQ tail wraps from N−1 to 0, it inverts the value it writes: second lap P = 0, third lap P = 1, …
  4. The host keeps an expected_phase, starting at 1, and inverts it whenever its CQ head wraps from N−1 to 0.
  5. Host rule: the CQE at CQ[head] is new iff CQE.P == expected_phase. Stop at the first slot where it differs.

25.6.2 Worked example — phase-tag flip across a wrap

CQ size N = 4. Host zeroed the memory. Trace the bit in every slot as completions arrive two at a time and the host consumes them.

⚠️ Classic bug

A driver that forgets to zero CQ memory before Create I/O CQ, or reuses a CQ buffer after a controller reset without clearing it, will see "ghost completions" with P=1 on the first lap. The symptom is completions for CIDs the driver never issued, or double completion → use-after-free in the block layer. derived

25.7 Hardware view

🔧 What the silicon does
  • Queue memory is ordinary host DRAM allocated by the driver with a DMA-coherent allocator. The controller is given the base address (and for non-contiguous queues a PRP list) at creation time. With CAP.CQR = 1 the controller requires physically contiguous queues verified.
  • Doorbell registers are flip-flops/SRAM in the controller's BAR0 space. Writing them is cheap for the CPU (a posted write) and wakes the controller's fetch engine.
  • Fetch engine: when SQ tail (doorbell) ≠ internal SQ head, it issues MRd TLPs to read SQEs. Many controllers fetch several SQEs in one MRd (e.g. 64–512 bytes) impl.
  • Completion engine: writes 16-byte CQEs with MWr TLPs, then (optionally) the MSI-X message — itself just another MWr to the address the host programmed in the MSI-X table.
  • Arbitration: with many SQs, the controller chooses which SQ to fetch from by round robin (mandatory) or weighted round robin with urgent priority (optional, CAP.AMS) verified. Inside one SQ, fetch order is in order; execution and completion order are not guaranteed.

📭 What the spec does not say

It does not say how many SQEs a controller fetches per MRd, how quickly it reacts to a doorbell, which order it completes commands in, or how it splits internal resources across queues. All of that is impl and is exactly what makes two compliant SSDs behave very differently under the same workload.

That asymmetry is deliberate: posted writes from the CPU are cheap, reads across PCIe are expensive (hundreds of nanoseconds), so the host never reads device registers in the I/O fast path. derived

All commands above only read. nvme show-regs maps BAR0 and reads registers; on some kernels it needs root and may be refused if the device is bound to another driver. Never use setpci or direct BAR writes to "poke" doorbells on a device that holds data.

What these prove: the number of hardware contexts, the CPU→queue mapping, and the interrupt distribution. What they cannot prove: real-time head/tail values or whether a particular CQE was written — for that you need a driver tracepoint (nvme:nvme_complete_rq, nvme:nvme_sq) or a protocol analyzer.

25.13 Code — an executable SQ/CQ simulator with doorbells and phase tags

The program below models one SQ/CQ pair, a host and a controller that communicate only through the shared rings and two doorbell values — exactly like the real thing. It implements the full/empty rules, SQHD feedback and phase inversion, and lets you inject the six classic faults required by this course: wrong tail, wrong queue ID, duplicate CID, CQ overflow (full CQ), stale phase and missing completion.

#!/usr/bin/env python3
"""nvme_qsim.py - teaching simulator for one NVMe SQ/CQ pair.
SIMULATION ONLY: models ring arithmetic, doorbells and phase tags.
It does not model PCIe, real controller timing or any real device."""
import random

class Ring:
    def __init__(self, size):
        assert size >= 2, "NVMe queues need at least 2 entries"
        self.size = size
        self.slots = [None] * size
        self.head = 0          # consumer index
        self.tail = 0          # producer index
    def empty(self):
        return self.head == self.tail
    def full(self):
        return (self.tail + 1) % self.size == self.head
    def used(self):
        return (self.tail - self.head) % self.size

class Controller:
    """Device side. Only sees memory + doorbell values the host gives it."""
    def __init__(self, sq, cq, sqid, faults):
        self.sq, self.cq, self.sqid = sq, cq, sqid
        self.sq_tail_db = 0     # last value host rang into SQyTDBL
        self.cq_head_db = 0     # last value host rang into CQyHDBL
        self.phase = 1          # controller's current CQ phase (starts at 1)
        self.cq_tail = 0
        self.faults = faults
        self.inflight_cids = set()
        self.log = []

    def ring_sq_doorbell(self, value, qid):
        if qid != self.sqid:
            self.log.append(f"  [ctrl] doorbell write for SQ{qid}: no such queue -> ignored "
                            "(real HW: undefined/async error 'Invalid Doorbell Write')")
            return
        if value >= self.sq.size:
            self.log.append(f"  [ctrl] SQ tail {value} >= size {self.sq.size}: invalid doorbell value")
            return
        self.sq_tail_db = value
        self.log.append(f"  [ctrl] SQ{qid}TDBL <- {value}")

    def ring_cq_doorbell(self, value):
        self.cq_head_db = value
        self.log.append(f"  [ctrl] CQ{self.sqid}HDBL <- {value}")

    def cq_full(self):
        return (self.cq_tail + 1) % self.cq.size == self.cq_head_db

    def run(self, budget=99):
        """Fetch commands between our SQ head and the doorbell tail, complete them."""
        done = 0
        while self.sq.head != self.sq_tail_db and done < budget:
            if self.cq_full():
                self.log.append("  [ctrl] CQ full (tail+1 == head) -> must stall, cannot post")
                return
            cmd = self.sq.slots[self.sq.head]
            self.log.append(f"  [ctrl] fetch SQ[{self.sq.head}] opcode={cmd['opc']:02X}h cid={cmd['cid']}")
            self.sq.head = (self.sq.head + 1) % self.sq.size
            status = 0x0000
            if cmd['nsid'] == 0:
                status = 0x000B          # zeroed slot = opcode 00h NSID 0 -> Invalid Namespace or Format
            elif cmd['cid'] in self.inflight_cids:
                status = 0x0003          # Generic SCT 0, SC 03h Command ID Conflict (detection is impl-dependent)
            if status == 0:
                self.inflight_cids.add(cmd['cid'])
            if status == 0 and cmd['cid'] in self.faults.get('drop_cid', ()):
                self.log.append(f"  [ctrl] (fault) cid={cmd['cid']} never completes (held/lost) - no CQE")
                done += 1
                continue
            phase = self.phase if not self.faults.get('stale_phase') else self.phase ^ 1
            cqe = {'dw0': 0, 'sqhd': self.sq.head, 'sqid': self.sqid,
                   'cid': cmd['cid'], 'p': phase, 'status': status}
            self.cq.slots[self.cq_tail] = cqe
            self.log.append(f"  [ctrl] post CQ[{self.cq_tail}] cid={cqe['cid']} P={phase} "
                            f"SQHD={cqe['sqhd']} status={status:04X}h -> MSI-X")
            self.cq_tail = (self.cq_tail + 1) % self.cq.size
            if self.cq_tail == 0:
                self.phase ^= 1          # wrap => invert phase for next pass
            self.inflight_cids.discard(cmd['cid']) if status == 0 else None
            done += 1

class Host:
    def __init__(self, depth, faults=None, cq_depth=None):
        self.faults = faults or {}
        self.sq, self.cq = Ring(depth), Ring(cq_depth or depth)
        self.sq.slots = [{'opc': 0x00, 'cid': 0, 'nsid': 0}] * depth   # zeroed SQ memory
        self.cq.slots = [{'p': 0}] * self.cq.size          # host zeroes CQ memory => P=0
        self.expected_phase = 1
        self.ctrl = Controller(self.sq, self.cq, 1, self.faults)
        self.next_cid = 0
        self.sq_head_seen = 0                        # learned from CQE.SQHD

    def submit(self, opc=0x02):
        if (self.sq.tail + 1) % self.sq.size == self.sq_head_seen:
            print("  [host] SQ full - cannot submit (tail+1 == head)")
            return False
        cid = self.next_cid
        if self.faults.get('dup_cid') and cid == 2:
            cid = 1                                   # fault: reuse an in-flight CID
        self.next_cid += 1
        self.sq.slots[self.sq.tail] = {'opc': opc, 'cid': cid, 'nsid': 1}
        self.sq.tail = (self.sq.tail + 1) % self.sq.size
        print(f"  [host] write SQE cid={cid} into SQ[{(self.sq.tail-1) % self.sq.size}], tail -> {self.sq.tail}")
        return True

    def doorbell(self):
        val = self.sq.tail
        if self.faults.get('wrong_tail'):
            val = (val + 1) % self.sq.size            # fault: one too far
        qid = self.faults.get('wrong_qid', 1)
        self.ctrl.ring_sq_doorbell(val, qid)

    def reap(self):
        n = 0
        while True:
            e = self.cq.slots[self.cq.head]
            if e['p'] != self.expected_phase:
                break                                  # not new yet
            print(f"  [host] reap CQ[{self.cq.head}] cid={e['cid']} status={e['status']:04X}h "
                  f"SQHD={e['sqhd']}")
            self.sq_head_seen = e['sqhd']
            self.cq.head = (self.cq.head + 1) % self.cq.size
            if self.cq.head == 0:
                self.expected_phase ^= 1
            n += 1
        if n:
            self.ctrl.ring_cq_doorbell(self.cq.head)
        else:
            print(f"  [host] no new CQE at CQ[{self.cq.head}] (expect P={self.expected_phase})")
        return n

def flush(ctrl):
    for line in ctrl.log:
        print(line)
    ctrl.log.clear()

def scenario(name, depth, rounds, per_round, faults=None, reap=True, cq_depth=None):
    print(f"=== {name} (SQ depth={depth}, CQ depth={cq_depth or depth}) ===")
    h = Host(depth, faults, cq_depth)
    for r in range(rounds):
        for _ in range(per_round):
            h.submit()
        h.doorbell(); flush(h.ctrl)
        h.ctrl.run(); flush(h.ctrl)
        if reap:
            h.reap(); flush(h.ctrl)
    print(f"  final: SQ head/tail={h.sq.head}/{h.sq.tail} CQ ctrl-tail={h.ctrl.cq_tail} "
          f"host-head={h.cq.head} host-phase={h.expected_phase} ctrl-phase={h.ctrl.phase}\n")

if __name__ == "__main__":
    scenario("normal: wrap twice, watch phase flip", 4, 4, 2)

25.15 Common mistakes

  • Believing a queue of N entries holds N commands. It holds N−1.
  • Encoding the size as N instead of N−1 in AQA or Create commands (0-based fields).
  • Thinking the host learns SQ progress from a register. It learns it only from CQE.SQHD.
  • Assuming completion order = submission order.
  • Expecting the phase tag to be 1 for "valid". It is valid when it matches the expected lap value.
  • Re-using CQ memory after a reset without zeroing it.
💡 Senior insight

When someone says "the drive hung", ask for four numbers per queue: last SQ tail doorbell value, last SQHD the host saw, last CQ head doorbell value, and the CQ slot/phase of the last CQE written. Ninety percent of "hangs" fall out of those four numbers: if tail ≠ SQHD and no MRd was seen, the controller never fetched; if a CQE was written but the CQ head never moved, the host lost the interrupt or misjudged the phase; if the CQ is full, the host is the bottleneck.

Quiz

  1. An SQ has N = 64, head = 10, tail = 9. How many commands are outstanding?

    Answer

    (9 − 10) mod 64 = 63 = N − 1 → the queue is full.

  2. Who owns the CQ tail and how does the host learn it?

    Answer

    The controller. The host never reads it; it infers it by scanning CQEs whose phase tag matches its expected phase.

  3. Why does the host need CQE.SQHD?

    Answer

    It is the only way the host learns which SQ slots the controller has consumed and may be reused; without it the host cannot evaluate the SQ full condition.

  4. Can two SQs share one CQ? Can one SQ use two CQs?

    Answer

    Yes; no. Mapping is many SQs to one CQ.

  5. A CQE has P = 1 and the host expects 0. New or old?

    Answer

    Old (left over from the previous lap). The host stops scanning.

Interview questions

  1. Beginner What is a queue pair in NVMe?
    Model answerAn SQ and the CQ it is associated with; the host submits to the SQ and the controller reports results in the CQ. The admin pair is QID 0; I/O pairs are created by admin commands.
  2. Beginner Why is one slot always left empty?
    Model answerSo that head == tail means only "empty"; full is tail + 1 == head.
  3. Intermediate Explain the phase tag and why it avoids an MMIO read.
    Model answerEach CQE's P bit equals the controller's lap parity; the host compares with its own expected lap parity, so it can find all new entries in its own memory (cache-friendly), with no PCIe read of a tail register, which would cost ~1 µs.
  4. Intermediate Why do NVMe drivers create one queue per CPU?
    Model answerEach CPU then owns its SQ tail and CQ head with no cross-CPU locking or cache-line bouncing, and the CQ's MSI-X vector can target the same CPU.
  5. Advanced The controller completes out of order. What breaks if the driver assumed in-order?
    Model answerIt would retire the wrong request (wrong buffer returned to the application) — data corruption visible above the block layer; CID matching is mandatory.
  6. Senior A customer shows an analyzer capture where the CQE was written but Linux timed out the I/O. What do you check?
    Model answerCQE phase vs the CQ's lap count since creation; CQ address vs the address the driver programmed (written to wrong memory/IOMMU fault?); MSI-X MWr presence and its address/data vs the MSI-X table; whether vector was masked; interrupt affinity/CPU offline; and whether CID/SQID in the CQE matches an outstanding request.

25.16 Summary

NVMe is two kinds of rings in host memory plus two kinds of index publication: doorbell writes for the host's indices and CQE fields (SQHD, phase) for the controller's. Full is tail+1 == head, empty is head == tail, and the phase bit is lap parity. Everything else in this Part builds on that.

26 The Admin Queue

26.1 Why this chapter exists

At reset the controller knows about exactly one queue pair: the Admin Submission Queue and Admin Completion Queue (queue ID 0). Every other capability — learning what the controller is (Identify), reading its health (Get Log Page), configuring it (Set Features), and creating every I/O queue — is done by commands on this pair. If admin bring-up fails, nothing else exists. Understanding the exact register handshake that creates the admin queue is also the single best way to debug "controller never becomes ready" failures.

26.2 Learning objectives

  • Program AQA, ASQ and ACQ correctly, including the 0-based size encoding and alignment.
  • Sequence controller enable: CC.EN=0 → wait CSTS.RDY=0 → configure → CC.EN=1 → wait CSTS.RDY=1.
  • Explain why admin commands use PRPs (not SGLs) over PCIe and why admin commands are low-rate.
  • Issue Identify, Get Log Page, Get/Set Features conceptually and know which fields to fill.
  • Explain the queue-creation order (CQ before SQ) and deletion order (SQ before CQ).

Prerequisites: Chapter 25 (ring rules). Register definitions (CAP 00h, CC 14h, CSTS 1Ch, AQA 24h, ASQ 28h, ACQ 30h).

🧒 Kid analogy — the manager's desk

The supermarket has normal checkouts for shopping (I/O queues), but before the store opens, only the manager's desk exists. You go there to ask "what is this store?" (Identify), "show me the incident book" (Get Log Page), "open checkout number 3 and use belt number 3 for receipts" (Create I/O CQ/SQ), or "change the store temperature" (Set Features). The manager's desk is slow and you rarely use it, but nothing opens without it.

🧩 Where the analogy breaks

The manager's desk is not physically different hardware — the admin queue uses the same ring mechanics, doorbells (SQ0TDBL at 1000h, CQ0HDBL at 1000h + (4 << DSTRD)) and CQE format. What differs is its creation (registers, not commands), its command set (admin opcodes), and that it cannot be deleted.

26.5 Specification — what makes the admin queue special

  • Queue ID 0 for both admin SQ and CQ; created by register writes at enable, not by commands; cannot be deleted verified.
  • Admin commands over PCIe use PRPs; SGLs are not supported for admin commands on the PCIe transport (PSDT shall be 00b) verified. (Fabrics transports differ version.)
  • Admin queue memory must be physically contiguous — there is no PRP list for ASQ/ACQ.
  • The Admin CQ receives completions of admin commands only, including Asynchronous Event Request completions, which arrive "late" (whenever an event happens).
  • Admin command set opcodes are separate from I/O command set opcodes: opcode 02h is Get Log Page on the admin queue and Read on an NVM I/O queue. The queue decides the opcode table.

26.6a Following one Identify Controller command end to end

The admin queue uses exactly the same ring mechanics as an I/O queue; only the queue number (0) and the command set differ. Here is the very first command most drivers send, Identify Controller, step by step. The admin queues are the ones set up in §24.15: Admin SQ at 0x1_0000_0000, Admin CQ at 0x1_0000_1000, and a 4 KiB buffer at 0x1_0000_2000. synthetic

Software starts itDevice starts itInside the SSD (not visible on PCIe)PCIe link
  1. Driver writes the 64-byte Identify command into Admin SQ slot 0

    The driver fills slot 0 of the Admin Submission Queue in RAM. Admin commands on PCIe always use PRPs, so PSDT = 00b and PRP1 points to the 4 KiB buffer.

    Where: Host memory, Admin SQ slot 0 (0x1_0000_0000 + 0 × 64)PCIe: No. The CPU writes its own RAM.
    CDW0 = 0000_0006h → OPC 06h (Identify), FUSE 0, PSDT 00b, CID 0x0000 NSID = 0 (not used for CNS 01h) PRP1 = 0x1_0000_2000 PRP2 = 0 (4 KiB in one page) CDW10 = 0000_0001h → CNS = 01h (Identify Controller), CNTID = 0
  2. Driver rings the SQ 0 tail doorbell

    The driver writes the new tail (1) to the admin SQ tail doorbell. It means "slot 0 holds new work".

    Where: Device register at BAR0 + 1000h (SQ0TDBL = 1000h + (2·0)·(4 << 0))PCIe: Yes, host → device · MWr, 4 bytes (posted)
    Value written: 1 Only this number crosses PCIe; the command is still in RAM.
  3. Controller fetches the command

    The controller sees the tail move from 0 to 1 and reads slot 0 from the address it latched from ASQ at enable time.

    Where: Host memory, Admin SQ slot 0PCIe: Yes, both ways · MRd 64 B (device → host), then CplD with 64 bytes
    The controller now knows: Identify, CNS 01h, put 4096 bytes at 0x1_0000_2000, CID 0. Its internal SQ 0 head moves to 1.
  4. Controller prepares the Identify Controller data

    The controller assembles the 4096-byte Identify Controller structure: vendor ID, serial number, model, firmware revision, MDTS, SQES/CQES, number of namespaces and many capability fields. How firmware stores and builds it is up to the design.

    Where: Inside the SSDPCIe: No. Nothing appears on the link during this step.
    Usually fast (microseconds to a few milliseconds) impl.
  5. Controller writes 4 KiB of Identify data into the host buffer

    The DMA engine writes the whole structure to PRP1. The CPU is not involved and does not know yet.

    Where: Host memory 0x1_0000_2000 … 0x1_0000_2FFFPCIe: Yes, device → host · MWr TLPs, each ≤ Max Payload Size (e.g. 16 × 256 B)
    Bytes 0–1 = PCI Vendor ID, 4–23 = serial number (ASCII), 24–63 = model number (ASCII), byte 77 = MDTS, byte 512 = SQES, byte 513 = CQES …
  6. Controller writes the 16-byte completion entry into Admin CQ slot 0

    It writes the completion into the next free slot of the Admin Completion Queue, with phase tag 1 because this is the first lap.

    Where: Host memory, Admin CQ slot 0 (0x1_0000_1000)PCIe: Yes, device → host · MWr, 16 bytes
    DW0 = 0 (unused by Identify) DW2: SQHD = 1, SQID = 0 DW3: CID = 0x0000, P = 1, Status = 0 (success)
  7. Controller sends the interrupt

    The admin Completion Queue is tied to interrupt vector 0. With MSI-X this is a memory write to the address in MSI-X table entry 0. A driver may also simply poll the CQ during early bring-up.

    Where: Interrupt address/data from MSI-X table entry 0 (or MSI, or INTx)PCIe: Yes, device → host · MWr, 4 bytes (MSI/MSI-X); INTx would be an Assert_INTx message
    PCIe ordering keeps the interrupt write behind the data and CQE writes.
  8. Driver reads the completion and the Identify data

    The driver checks P = 1 at Admin CQ slot 0, matches CID 0, sees status 0 and then parses the buffer. These numbers set the limits for everything that follows.

    Where: Host memory, Admin CQ slot 0 and the 4 KiB bufferPCIe: No. The CPU reads its own RAM.
    MDTS = 5 → max transfer 2^5 × 4 KiB = 128 KiB SQES = 66h → 64-B SQEs · CQES = 44h → 16-B CQEs · NN = 1
  9. Driver rings the CQ 0 head doorbell

    The driver tells the controller that slot 0 of the Admin CQ is free again.

    Where: Device register at BAR0 + 1004h (CQ0HDBL = 1000h + (2·0+1)·(4 << 0))PCIe: Yes, host → device · MWr, 4 bytes (posted)
    Value written: 1 Next admin commands: Set Features (Number of Queues), then Create I/O CQ / SQ.

Compare with the I/O Read in Chapter 39: the same nine moves, but on queue 0, with an admin opcode, and with data that comes from the controller itself rather than from NAND.

Questions: Why does Linux choose a fixed admin depth rather than the maximum? What would happen if MPS were set larger than the OS page size?

Solution

Admin traffic is low-rate; a small depth wastes no memory (Linux uses a fixed admin depth constant, version). MPS larger than the OS page size would make PRP construction impossible for buffers made of OS pages that are not MPS-aligned and contiguous — Linux sets MPS to match its page size (or the closest supported).

Extension: correlate the "nvme nvme0: … I/O queues" kernel message at boot (journalctl -k | grep nvme) with Set Features Number of Queues.

Quiz

  1. AQA = 003F001Fh. Sizes?

    Answer

    ACQS = 3Fh → 64-entry admin CQ; ASQS = 1Fh → 32-entry admin SQ.

  2. Can an admin command use an SGL on PCIe?

    Answer

    No. PSDT must be 00b (PRP) for admin commands over PCIe.

  3. Why create the I/O CQ before the I/O SQ?

    Answer

    Create I/O SQ names an existing CQID; if the CQ does not exist, the command fails with Completion Queue Invalid (command-specific status 00h).
