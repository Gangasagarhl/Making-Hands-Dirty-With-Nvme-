📌 Spec-reading discipline

shall = requirement; should = recommendation (deviation allowed with reason); may = permission/option. Informative notes, examples and rationale do not create requirements. Reserved fields: senders set to zero and receivers typically ignore them, as the document’s conventions specify — read the conventions section of each document rather than assuming identical rules everywhere.

PART LXXIII

An Important Distinction: NVMe, PCIe, and NVMe over PCIe

The learner studies two technologies that are connected but independent. NVMe defines storage protocol semantics. PCIe provides the transport/interconnect in the PCIe deployment. NVMe over PCIe defines the binding between them. Collapsing the three into one concept is the root of many wrong diagnoses.

73.1 Three Things, Not One

📘 Specification baseline

DOCUMENTS: PCI Express Base Specification (PCI-SIG); NVM Express Base Specification 2.4 (NVM Express); NVMe over PCIe Transport Specification 1.4 (NVM Express) — revisions per course brief. STATUS: separate standards bodies and documents. verified

73.1.1 Why this chapter exists

“The NVMe link is down”, “the PCIe command failed”, “NVMe TLP” — these phrases are common and wrong. Each mixes layers. When an engineer mixes layers, they also mix owners, tools and specifications, and spend days in the wrong document. This chapter draws the boundaries sharply.

  • State which specification owns each concept from link training to namespaces.
  • Explain what the NVMe over PCIe transport binding adds.
  • Attribute symptoms to the correct layer and document.
🧒 Kid analogy — language, road, and the rule for posting letters

NVMe is a language for asking a library for books. PCIe is a road. “NVMe over PCIe” is the rule that says: “when you use that road, put your request in this box at this address and ring this bell.” You could speak the same language over a different road (a phone line — TCP), and you could drive other things on the same road (graphics cards, network cards).

🧩 Where the analogy breaks

The binding is more than a mailbox rule: it decides that queues live in memory the device reaches by DMA, that registers sit in a BAR, that interrupts are MSI/MSI-X, and how PRPs describe memory. Those choices shape NVMe’s performance profile on PCIe deeply.

73.1.5 Failure attribution exercise

🎯 Exercise — which layer, which document?
  1. Link trains at Gen3 instead of Gen4.
  2. Namespace shows 0 capacity.
  3. CSTS reads FFFFFFFFh.
  4. CQE phase tag never flips although doorbell writes are seen in the trace.
  5. Correctable Receiver Errors increase.
  6. Zone Invalid Write.
  7. NVMe/TCP connection reset after digest error.
Answers

(1) PCIe physical/LTSSM — PCIe Base. (2) NVMe namespace/format — NVMe Base + NVM CS. (3) PCIe accessibility (device gone/contained) observed through an NVMe register — PCIe first. (4) Binding/controller: doorbell reached the device (PCIe ok); controller did not fetch/complete — NVMe over PCIe + controller implementation. (5) PCIe physical — PCIe Base. (6) ZNS command set. (7) NVMe/TCP transport.

Interview questions

  1. Beginner Is NVMe a kind of PCIe?
    Model answerNo. NVMe is a storage protocol; PCIe is one interconnect it can run over, via the NVMe over PCIe transport binding. NVMe also runs over TCP and RDMA.
  2. Intermediate What does the NVMe over PCIe binding define?
    Model answerHow NVMe controller registers and doorbells are memory-mapped in a BAR, that queues and data buffers live in memory accessed by device DMA, PRP usage, and MSI/MSI-X interrupt usage, among others.
  3. Senior Why does keeping these layers separate matter for a debug team?
    Model answerIt decides which evidence to collect (LTSSM/TLP vs NVMe command/CQE), which owner to engage (platform, PCIe IP, controller firmware, driver), which specification to cite, and prevents consequence-as-cause errors.
📌 Summary

NVMe = storage semantics. PCIe = interconnect. NVMe over PCIe = the binding. Always name the layer, the owner and the document when you describe a symptom.
