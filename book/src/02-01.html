PART IV

PCIe From Zero

An NVMe SSD is, electrically and logically, a PCI Express (PCIe) Endpoint. Every doorbell write, every Submission Queue Entry fetch, every data transfer and every interrupt you will meet later in this book is carried by PCIe packets over PCIe lanes. This Part builds PCIe from nothing: why it replaced shared parallel buses, how the topology is wired (Root Complex, Root Ports, Switches, Endpoints), what a lane physically is, how the generations differ in signaling and encoding, how the three-layer protocol stack divides responsibility, and how two chips that have never met agree on a link width, a speed and a set of equalization coefficients through the Link Training and Status State Machine (LTSSM). If an NVMe drive "disappears", "runs at half speed" or "throws AER errors", the root cause very often lives in the material of this Part.

📭 Source discipline used throughout Parts IV–VI

Every statement in these Parts belongs to one of four worlds, and we keep them separate: (1) PCIe normative behavior — what the PCIe Base Specification requires (e.g. a Memory Read is non-posted and must be completed); (2) NVMe behavior — what the NVMe specifications layer on top (e.g. the host writes a doorbell register in BAR0 with a Memory Write); (3) device implementation behavior — what a particular SSD controller, switch or root complex chooses to do inside what the specs allow (e.g. how many reads it keeps in flight, how many credits it advertises); (4) protocol analyzer presentation — how a tool chooses to draw and name what it captured. A conclusion drawn from world 4 must be checked against world 1 before it is believed.

4 The PCIe Mental Model

4.1 Why this chapter exists

Before bit fields, before state machines, you need a correct picture in your head of what is connected to what. Engineers who carry the wrong picture — "PCIe is a bus that every device listens to" — make predictable mistakes: they expect broadcast behavior, they misread lspci trees, they blame the SSD for a problem in an upstream switch, and they cannot explain why one device's link failure does not take out its neighbors. This chapter builds the right picture: PCI Express (PCIe) is a packet-switched, point-to-point, serial interconnect organized as a tree, whose software model deliberately pretends to be the old PCI bus so that operating systems did not need to be rewritten.

4.2 Learning objectives

  • Beginner: explain why a shared parallel bus stopped scaling and what "point-to-point" means.
  • Intermediate: name and place Root Complex, Root Port, Switch (upstream and downstream ports), PCI-to-PCI bridge, Endpoint, link, lane, width and generation on a diagram.
  • Advanced: explain how the hierarchy is enumerated as buses/devices/functions (Bus:Device.Function, BDF) and how a switch routes a TLP by address, by ID, or implicitly.
  • Senior: reason about shared-uplink bottlenecks, failure domains, and peer-to-peer paths in a multi-SSD system.
  • Trace-analysis: given a capture point on one link, state which traffic you can and cannot see.
  • Debugging: use lspci -tv and sysfs to locate an NVMe device in the tree and identify every link between it and the CPU.
  • Validation: design a test that proves a reported bottleneck is in a switch uplink rather than the SSD.

4.3 Prerequisites

Only basic computer architecture: a CPU, memory, and the idea that devices are accessed through addresses (Parts I–III of this book). No PCIe knowledge assumed. Physical details are deferred to Chapter 5; packets to Chapter 10.

4.4 Story: the railway that replaced the high street

🧒 Kid analogy

Imagine a town where every shop delivers goods along one single high street. Only one truck may drive on it at a time; everyone else waits. When the town grows, the street jams. So the town builds a railway: each shop gets its own private track to a station. Big stations (switches) connect several tracks to one larger track heading to the central station (the Root Complex) near the town hall (the CPU and memory). Trains carry sealed parcels with an address label. Two shops can ship at the same time, on their own tracks, in both directions at once.

🌍 Engineering analogy

PCIe is closer to a small, lossless, credit-controlled packet network (think switched Ethernet with guaranteed delivery on each hop) than to a bus. Each link is a full-duplex pipe between exactly two ports. Switches forward packets using routing information inside the packet header. The difference from Ethernet: PCIe guarantees per-hop reliable, in-order delivery (with replay) and never drops a packet because a buffer is full — the sender simply is not allowed to send until the receiver has granted buffer space (credits, Chapter 16).

🧩 Where the analogy breaks

The railway analogy represents private point-to-point tracks, stations as switches, and addressed parcels. It hides three things: (1) a "track" is really a bundle of 1–16 lanes, each a pair of one-way differential wires per direction; (2) the stations do not inspect parcels at leisure — forwarding is cut-through or store-and-forward in hardware in hundreds of nanoseconds; (3) the parcel service has a strict rulebook about which parcels may overtake which (ordering). It becomes misleading if you conclude that PCIe has no shared resources: the uplink from a switch to the root port is shared by every device below that switch, and the root complex's internal fabric and memory controller are shared too.

4.5 Beginner view: bus versus point-to-point

Conventional PCI (1990s) was a shared parallel bus: 32 or 64 data/address wires plus control wires, routed to every slot. At any moment one bus master owned the bus after arbitration; every other device listened and ignored addresses that were not theirs. Its weaknesses compound as speed rises:

  • Clock skew: 32+ signals must arrive within the same clock window. At hundreds of MHz the differences in trace length across a motherboard consume the whole timing budget.
  • Electrical loading: every extra slot adds capacitance and reflections to every wire, so faster buses support fewer slots.
  • Half duplex and shared bandwidth: 133 MB/s (32-bit, 33 MHz) was shared by all devices, in one direction at a time.
  • Pin count: wide parallel buses need many pins per device.

PCI Express (first released 2003) answered with serial, differential, point-to-point links. Each lane has one differential pair transmitting and one receiving, so a lane is full duplex. The clock is embedded in the data stream and recovered by the receiver (Clock and Data Recovery, CDR), which removes the skew problem within a lane; skew between lanes is removed by the receiver's lane-to-lane deskew logic. To gain bandwidth, PCIe either clocks faster (new generations) or bundles more lanes (wider links).

📌 Remember

PCIe changed the wires completely but kept the software model (configuration space, Base Address Registers, Bus/Device/Function numbering). That is why lspci still shows "buses" even though no physical bus exists: each link and each switch's internal routing fabric is modeled as a "virtual PCI bus".

4.6 Engineering view: the components

Root Complex (RC)

The Root Complex is the interface between the CPU/memory subsystem and the PCIe hierarchy. It is not one standardized chip: in modern systems it is a block inside the CPU package (or the chipset/PCH for chipset-attached lanes). It generates configuration, memory and I/O requests on behalf of the CPU, and it accepts DMA requests from devices and turns them into memory-controller transactions — often after translation by an IOMMU. Its internal structure is impl; the spec defines its externally visible behavior.

Root Port (RP)

A Root Port is a PCIe port on the Root Complex that begins one hierarchy branch. Software sees it as a PCI-to-PCI bridge (Type 1 configuration header) with a secondary bus number. Each Root Port owns exactly one link. When an NVMe drive is directly attached to the CPU (typical for an M.2 or U.2 slot wired to CPU lanes), the chain is CPU → Root Port → link → NVMe Endpoint.

Switch

A switch has one Upstream Port (toward the root) and multiple Downstream Ports (toward devices). Software sees it as a set of virtual PCI-to-PCI bridges joined by an internal virtual bus: one bridge for the upstream port, one per downstream port. The switch forwards TLPs between ports by examining routing fields: address routing (memory and I/O requests, compared against each bridge's base/limit windows), ID routing (configuration requests and completions, compared against secondary/subordinate bus number ranges), and implicit routing (some messages, e.g. "route to root complex" or "broadcast from root").

Bridge

"Bridge" in PCIe software terms means any function with a Type 1 header that forwards between a primary and secondary bus: root ports, switch ports, and real PCIe-to-PCI(-X) bridges for legacy devices. Bridges hold the Primary/Secondary/Subordinate Bus Number registers and memory base/limit windows that make routing work.

Endpoint (EP)

An Endpoint is a function that is the requester or completer of transactions on its own behalf — a leaf of the tree. It has a Type 0 configuration header with Base Address Registers (BARs). An NVMe SSD controller is a PCIe Endpoint whose class code is 01h (mass storage) / 08h (non-volatile memory controller) / 02h (NVM Express) verified. One physical device may expose multiple functions (multi-function devices, and with SR-IOV, many virtual functions).

Link, lane, width, generation

  • Lane: one differential TX pair plus one differential RX pair — four wires — carrying one bit stream in each direction.
  • Link: the connection between two ports, made of 1, 2, 4, 8 or 16 lanes (x32 and x12 existed in older specs and were later removed or rarely implemented version).
  • Width: the number of lanes the link actually trained to (e.g. x4). It can be lower than the maximum either side supports.
  • Generation / speed: the data rate per lane, in gigatransfers per second (GT/s): 2.5, 5, 8, 16, 32, 64, 128 GT/s for Gen1–Gen7 (Chapter 6).

4.7 Hardware view

🔧 Hardware

Must participate in any NVMe transaction: the root complex (and its root port), every switch on the path, every link's PHY on both sides, and the SSD's PCIe controller IP. May participate: retimers (a retimer is a physical-layer device that is LTSSM-aware and re-drives the signal; it is not a switch and has no configuration-space bus of its own), redrivers (analog amplifiers, protocol-unaware), and the IOMMU. Observable: configuration space of every port and function, link status registers, AER error logs, traffic on a link if you insert an interposer/analyzer. Generally unobservable: the root complex's internal fabric queues, switch internal buffer occupancy (some switches expose vendor counters impl), and the SSD controller's internal request scheduling.

4.8 Specification and protocol view: how packets find their way

📘 Specification

The PCIe Base Specification defines three routing methods for TLPs verified: address-based (Memory and I/O requests), ID-based (Configuration requests, Completions, ID-routed Messages), and implicit (certain Messages: routed to Root Complex, broadcast from Root Complex, local — terminate at receiver, gathered and routed to RC). Enumeration software assigns bus numbers depth-first and programs each bridge's Secondary and Subordinate Bus Number so ID routing works, and programs memory base/limit windows so address routing works.

Mechanism, step by step — an NVMe doorbell write from CPU to the SSD behind Switch DSP 2 in Figure 4.1:

  1. CPU core executes a store to an uncached MMIO address inside the SSD's BAR0 + 1000h region. What changes: a write leaves the core. Evidence: none externally yet.
  2. Root Complex decodes the address as belonging to Root Port B's memory window and builds a Memory Write TLP (posted). Evidence: visible on the Root Port B link with an analyzer.
  3. Switch Upstream Port receives the TLP, checks it, and compares the address against each downstream bridge's memory base/limit. It matches DSP 2. Evidence: switch-internal; usually only inferable.
  4. DSP 2 transmits the TLP on its link. Evidence: visible on the DSP 2 link.
  5. SSD receives the TLP, its BAR decode hits the doorbell register, and the NVMe controller updates its tail pointer. Evidence: later behavior (it starts fetching SQ entries — Memory Read TLPs going upstream).

The SSD's subsequent DMA read of the Submission Queue travels upstream: address-routed toward the root (because the address is not inside any downstream window, the switch forwards it upstream). The completions coming back are ID-routed to the SSD's Requester ID (its BDF).

4.9 Trace view: what a single capture point can see

🔍 Trace visibility rule

An analyzer on a link sees only that link. On the DSP 2 link above, you see the doorbell write, the SSD's reads, completions, and the SSD's interrupt write, but not traffic of the other two SSDs — even though their traffic competes for the same uplink. A "slow" trace on DSP 2 with long gaps between a Memory Read and its completion therefore does not prove the SSD or root complex is slow: the delay may be uplink contention invisible from this capture point.

4.10 Linux view

# Tree view: shows root ports, switches and endpoints with their bus numbers
lspci -tv

# Find NVMe controllers (class 0108) and their BDF
lspci -d ::0108

# Walk the sysfs path: every directory component is a port on the way to the root
readlink -f /sys/class/nvme/nvme0/device

# Inspect a bridge's bus numbers and windows (read-only)
lspci -vv -s 00:01.1 | grep -E 'Bus:|Memory behind|Prefetchable'

What these can prove: the logical hierarchy as enumerated (which bridge sits above which device), bus-number assignments, memory windows. What they cannot prove: physical retimers/redrivers (invisible to config space), the actual bandwidth delivered, or whether two "sibling" devices are electrically independent. Example of what readlink returns, illustrative only: a path like /sys/devices/pci0000:00/0000:00:01.1/0000:01:00.0/0000:02:02.0/0000:04:00.0, meaning root port 00:01.1 → switch upstream 01:00.0 → switch downstream 02:02.0 → SSD 04:00.0 synthetic.

4.11 Code: modeling routing

# Simulation: how a switch chooses an egress port (address and ID routing)
class Bridge:
    def __init__(self, name, sec, sub, mem_base, mem_limit):
        self.name, self.sec, self.sub = name, sec, sub
        self.mem_base, self.mem_limit = mem_base, mem_limit

dsps = [Bridge("DSP1", 3, 3, 0xFE000000, 0xFE0FFFFF),
        Bridge("DSP2", 4, 4, 0xFE100000, 0xFE1FFFFF),
        Bridge("DSP3", 5, 5, 0xFE200000, 0xFE2FFFFF)]

def route_memory(addr):
    for b in dsps:
        if b.mem_base <= addr <= b.mem_limit:
            return b.name
    return "UPSTREAM"            # not claimed below us: send toward root

def route_id(bus):
    for b in dsps:
        if b.sec <= bus <= b.sub:
            return b.name
    return "UPSTREAM"

print(route_memory(0xFE101008))  # DSP2 (doorbell)
print(route_memory(0x123400100)) # UPSTREAM (DMA to host memory)
print(route_id(4))               # DSP2 (completion to bus 4 device)

4.12 Worked example: oversubscription math

Three Gen4 x4 SSDs sit behind a switch whose uplink is Gen4 x8. Per direction, Gen4 delivers 16 GT/s × 128/130 ÷ 8 = 1.969 GB/s per lane derived. Downstream aggregate: 3 × 4 × 1.969 = 23.6 GB/s; uplink: 8 × 1.969 = 15.75 GB/s. Oversubscription 23.6 / 15.75 ≈ 1.5:1. If each SSD can read at 7 GB/s, three concurrent sequential readers want 21 GB/s, but at most ~15.75 GB/s raw link rate (and less after TLP overhead, ≈ 13–14 GB/s with 256-byte payloads, see Chapter 10) can reach the host. The SSDs are not "slow" — the topology is.

4.13 Common mistakes

  • Calling a switch a "hub" and expecting broadcast. Switches route; only specific message types are broadcast.
  • Reading the bus number in lspci as a physical bus. Bus 03 is just the number assigned to the link below some bridge.
  • Assuming the CPU's root port and the SSD negotiate the link "through the OS". Link training is hardware; the OS only observes and can request retraining.
  • Ignoring the switch uplink when computing aggregate bandwidth.
  • Assuming chipset-attached M.2 slots have the same path as CPU-attached ones; chipset lanes share the CPU–chipset link impl.

4.15 Senior insight

💡 Senior insight

Topology is a performance and a reliability decision. Two SSDs under one switch form a shared failure domain: a switch firmware hang or uplink retrain hits both. In storage servers, architects deliberately spread mirror pairs across root ports and sockets. When someone reports "NVMe latency spikes", the first diagram you draw is the tree from the CPU socket to the drive, annotated with each link's width and speed — before you look at a single NVMe command.

🧪 Lab 4.1 — Map your NVMe path to the CPU SAFE

Objective: draw the exact PCIe path from each NVMe controller to its root port. Prerequisites: Linux machine with an NVMe SSD, pciutils. Setup: none; all commands read-only.

  1. Run lspci -tv and locate devices with "Non-Volatile memory controller".
  2. For each, run readlink -f /sys/class/nvme/nvmeN/device and split the path into BDFs.
  3. For every BDF on the path run lspci -vv -s BDF | grep -E 'LnkCap|LnkSta'.
  4. Draw the tree with width and speed on every link.

Observations: count links between the SSD and the root. Questions: Is any link narrower or slower than the SSD's own link? Do two SSDs share an ancestor? Expected reasoning: the minimum bandwidth along the path bounds throughput; a shared ancestor bounds aggregate throughput.

Solution

A directly attached drive shows two components in the sysfs path after the host bridge: the root port and the endpoint. A drive behind a switch shows root port → switch upstream port → switch downstream port → endpoint (three bridges). The narrowest link along the path determines the ceiling; if two drives share the switch upstream port, its link bounds their sum.

Extension: repeat on a dual-socket server and note which socket's root complex each drive hangs off (cat /sys/class/nvme/nvme0/device/numa_node).

🧪 Lab 4.2 — Senior forensic: prove an uplink bottleneck CAUTION

Objective: distinguish an SSD limit from a shared-uplink limit. Prerequisites: ≥2 NVMe drives behind one switch, fio, test drives with no valuable data (use read-only workloads: --rw=read --readonly). Procedure: run 128 KiB sequential reads, QD 32, on drive A alone; then B alone; then A+B concurrently; then A plus a drive C under a different root port. Observations: per-drive GB/s. Expected reasoning: if A+B ≈ uplink limit while A+C ≈ A + C, the shared uplink is the bottleneck.

Solution

Compare the A+B sum against the derived uplink ceiling (lanes × per-lane rate × TLP efficiency). Within ~10% of that ceiling with each drive below its solo number is strong evidence of uplink saturation; A+C scaling linearly rules out a CPU/memory limit.

Extension: measure P99 latency at QD1 during the concurrent run to show contention effects on latency, not just bandwidth.

Quiz

  1. Why does lspci show bus numbers if PCIe has no shared bus?

    Answer

    PCIe preserves the PCI software model; each link and each switch's internal fabric is presented as a virtual PCI bus behind a PCI-to-PCI bridge so enumeration and ID routing work unchanged.

  2. Which routing method is used for a completion returning to an SSD?

    Answer

    ID routing, using the Requester ID (bus/device/function) copied into the completion.

  3. A Gen4 x8 switch uplink serves four Gen4 x4 SSDs. Oversubscription ratio?

    Answer

    16 lanes downstream / 8 lanes upstream at equal speed = 2:1.

  4. Is a retimer visible in lspci?

    Answer

    Normally no; retimers participate in link training but do not appear as functions in configuration space (some expose sideband management interfaces, implementation-dependent).

Interview questions

  1. Beginner What is the difference between a lane and a link?
    Model answerA lane is one TX differential pair plus one RX differential pair; a link is the set of lanes (x1–x16) connecting two ports and operating as one logical connection.
  2. Beginner What is a Root Complex?
    Model answerThe entity connecting the CPU/memory to the PCIe hierarchy, containing root ports; it issues requests for the CPU and services device DMA to memory.
  3. Beginner Why is PCIe full duplex?
    Model answerEach lane has separate transmit and receive differential pairs, so both directions carry traffic simultaneously.
  4. Beginner What header type does a switch port have?
    Model answerType 1 (bridge); endpoints have Type 0.
  5. Beginner Name the three TLP routing methods.
    Model answerAddress, ID, implicit.
  6. Intermediate How does a switch decide to forward a Memory Write upstream?
    Model answerIf the address does not fall into any downstream port's memory base/limit (or prefetchable) window, and arrives on a downstream port, it is forwarded upstream; arriving on the upstream port and matching no window it is handled as unsupported.
  7. Intermediate Explain bifurcation.
    Model answerA root port's lanes split into multiple narrower independent links (e.g. x16 → 4×x4), each its own root port/link, configured by platform firmware; no switch involved.
  8. Intermediate What happens to a config read to an empty slot?
    Model answerThe downstream port with link down returns a completion with UR (or the RC synthesizes all-ones); software reads FFFFh Vendor ID.
  9. Intermediate Why might two drives in the same chassis have different latency?
    Model answerDifferent paths: switch hops, chipset vs CPU attach, NUMA distance, link speed.
  10. Intermediate What is a multi-function device?
    Model answerOne device number exposing several functions (0–7, or more with ARI), each with its own config space.
  11. Advanced How does ACS affect peer-to-peer NVMe traffic?
    Model answerACS Source Validation/P2P Request Redirect can force P2P requests upstream to the root complex for IOMMU checks, adding latency or blocking P2P if the RC does not forward.
  12. Advanced Can a switch reorder TLPs?
    Model answerOnly within ordering rules: e.g. posted may pass non-posted; relaxed-ordering-marked traffic may be reordered as permitted. It must not violate required orderings.
  13. Advanced Why does enumeration use depth-first bus numbering?
    Model answerSo each bridge's descendants occupy a contiguous range [secondary, subordinate], enabling simple range-based ID routing.
  14. Advanced What is a Root Complex Integrated Endpoint?
    Model answerAn endpoint built into the RC with no physical link; it appears on the root bus and has no link status of its own.
  15. Advanced Where would you insert an analyzer to see all traffic of 3 SSDs behind one switch?
    Model answerOn the switch uplink; but that view loses per-downstream timing inside the switch.
  16. Senior Design an 8-SSD server for redundancy and bandwidth.
    Model answerSpread drives across sockets/root ports, avoid oversubscribed switches for hot paths, put mirror pairs in different failure domains, align NUMA of application threads with drive locality.
  17. Senior A customer says "drive X is slow". What topology evidence do you request?
    Model answerlspci -tvvv with LnkSta for every port on the path, NUMA node, concurrent workloads on siblings, AER logs.
  18. Senior When is a switch preferable to bifurcation?
    Model answerWhen more devices than root ports are needed, for hot-plug isolation, P2P locality, or when the platform cannot bifurcate; at the cost of latency (~100+ ns per hop, implementation-dependent) and oversubscription.
  19. Senior How would a switch firmware bug manifest differently from an SSD bug?
    Model answerAffects multiple downstream devices, correlates with upstream link events, often visible as completion timeouts on several BDFs simultaneously.
  20. Senior What can configuration space never tell you about topology?
    Model answerPhysical retimers/redrivers, cable/board quality, signal margin, and actual delivered bandwidth.

4.16 Summary

PCIe replaced a shared parallel bus with point-to-point serial links arranged as a tree: Root Complex at the top, root ports beginning branches, switches fanning out, endpoints (such as NVMe SSDs) at the leaves. Packets are routed by address, ID, or implicitly. The software model of buses, bridges and BDFs survives unchanged. Throughput and failure domains are properties of the whole path, not just the device.

5 PCIe Physical Architecture

5.1 Why this chapter exists

The physical layer is where "the SSD only runs at x2" and "the link keeps retraining" are born. You need to know what a lane is made of, how a receiver recovers a clock from data, how width and speed are negotiated, and which compatibility rules let a Gen5 x4 SSD work in a Gen3 x16 slot.

5.2 Learning objectives

  • Beginner: describe a lane as two differential pairs and a link as 1–16 lanes.
  • Intermediate: explain differential signaling, AC coupling, embedded clocking, lane reversal, polarity inversion.
  • Advanced: explain width and speed negotiation outcomes and how the "lowest common denominator" rule works.
  • Senior: diagnose degraded links from LnkCap/LnkSta and correlate with signal integrity, reference clock and retimer issues.
  • Trace/debug/validation: know which physical events an analyzer can record (ordered sets, electrical idle, speed changes) and how to validate that a link meets its expected width/speed under stress.

5.4 Story and analogy

🧒 Kid analogy

Two friends talk with flashlights across a valley. Each has a flashlight pointed at the other (TX) and eyes watching the other's flashlight (RX). If they want to talk faster, they can add more flashlight pairs side by side (more lanes) or blink faster (higher generation). They first agree how many flashlights both can see and how fast both can blink before chatting.

🧩 Where the analogy breaks

Real lanes use differential signals — two wires carrying opposite voltages, where only the difference matters — not a single light. Bits on separate lanes are not independent messages: one packet is striped byte-by-byte across all lanes of the link. And "blinking faster" requires both sides to equalize — pre-distort and filter the signal — which a flashlight never does.

5.5 Beginner: lane, differential pair, TX, RX

A differential pair is two wires, D+ and D−, driven with complementary voltages. The receiver looks only at (D+ − D−). Noise that hits both wires equally (common-mode noise) cancels. Swings can be small (hundreds of millivolts), which saves power and allows high rates. A lane = one TX pair from this side to the other + one RX pair in the opposite direction. One device's TX connects to the other's RX. The pairs are AC coupled through series capacitors (on the transmitter side of the channel), so the two chips need not share a DC common-mode voltage — and that capacitor is exactly what the receiver-detect circuit in Detect probes.

5.6 Engineering: how bits cross a lane

Serialization and embedded clock

The transmitter serializes symbols into a bit stream at the line rate. No separate data clock is sent; the receiver's CDR locks a local clock onto the transitions in the data. To guarantee enough transitions and DC balance, data is encoded (8b/10b for Gen1–2) or scrambled with a sync header (128b/130b for Gen3–5); Gen6+ uses PAM4 with FLIT encoding (Chapter 6). A 100 MHz reference clock (REFCLK) is commonly distributed to both sides so their PLLs run at matching frequencies; architectures include common clock, separate reference clocks with no spread spectrum (SRNS), and separate with independent spread spectrum (SRIS) verified. Clocking mismatches between what the platform provides and what the device was configured for are a classic cause of link instability.

Byte striping across lanes

On a multi-lane link, consecutive bytes of a packet go to consecutive lanes: byte 0 on lane 0, byte 1 on lane 1, ... byte 4 on lane 0 again for x4. Every lane carries a share of every packet. That is why a single bad lane corrupts packets on the whole link, and why the link must deskew lanes (align them using ordered sets that are sent simultaneously on all lanes).

Lane reversal and polarity inversion

Polarity inversion: if D+ and D− of a pair are swapped on the board, the receiver detects inverted training sequences and inverts internally — mandatory support verified. Lane reversal: if lane 0 of one side is wired to lane 3 of the other (board routing convenience), the link can still train with reversed lane numbering; support is optional for one side as long as the pair can resolve it impl.

Link width negotiation

During Configuration the downstream port proposes link and lane numbers in TS1 ordered sets on lanes where it detected a receiver; the upstream port echoes those it can accept. The result is the largest supported width that both sides and the detected, working lanes allow. If lane 2 of an x4 link is broken, the link cannot form an x3 (non-standard) and typically falls back to x2 using lanes 0–1, or x1 derived.

Speed negotiation

Every link first trains at 2.5 GT/s (Gen1). Each side advertises supported rates in TS1/TS2 "data rate identifier" fields. After reaching L0, if both support higher rates, the LTSSM goes through Recovery to change speed (and for 8 GT/s and above, performs equalization). Speed is therefore negotiated after the link already works at Gen1 — a key debugging fact: a link that "comes up at Gen1 but never Gen4" has a problem in the speed-change/equalization path, not in basic detection (Chapter 9).

Compatibility

  • Speed: every generation must support all lower data rates, so Gen5 devices interoperate with Gen3 ports at Gen3 verified.
  • Width: a x4 card in a x16 slot trains to x4 ("up-plugging"); a x16 card in a physically open-ended x4 slot trains to x4 ("down-plugging") if the device supports narrower widths — all PCIe devices must support x1 verified.
  • Result: link = min(speed both support, signal quality permits) × min(width both support, working lanes).

5.7 Hardware view

🔧 Hardware

Per lane, the transmitter has a serializer, a de-emphasis/FIR equalizer (pre-cursor, main cursor, post-cursor taps from Gen3), and a driver; the receiver has termination, a CTLE (continuous-time linear equalizer), often a DFE (decision feedback equalizer), CDR and a deserializer. Channel loss grows with frequency and trace length: as rates double, the allowed channel loss budget is consumed faster, so Gen5/Gen6 platforms often need retimers for long traces or risers. Form factors: M.2 (up to x4), U.2 (x4, or 2×x2 dual-port), U.3, EDSFF E1.S/E1.L/E3 (x4/x8/x16) impl.

Illustrative, abbreviated output synthetic: LnkCap: Port #0, Speed 16GT/s, Width x4 and LnkSta: Speed 8GT/s (downgraded), Width x2 (downgraded). Recent pciutils versions annotate "(downgraded)" version. Can prove: what was negotiated at the moment of reading. Cannot prove: why — signal integrity, BIOS speed caps (LnkCtl2 Target Link Speed), retimer limits, or a slot wired with fewer lanes all look identical in LnkSta. Always compare both ends of the link: the endpoint and its parent port.

⚠️ Warning

Do not use setpci writes to force speeds or retrain links on a system with mounted filesystems or valuable data. A retrain that fails takes the device offline; a write to the wrong register can hang the machine. Read-only commands are always safe.

5.9 Worked example

An SSD reports LnkCap 16 GT/s x4; LnkSta 16 GT/s x2. The parent root port reports LnkCap 16 GT/s x4, LnkSta 16 GT/s x2. Both ends agree and speed is full, so equalization at Gen4 succeeded on the working lanes. Width x2 points to lanes 2–3: either physically not routed (slot wired x2 — check motherboard manual: some M.2 slots share lanes with SATA ports), a damaged connector, or a receiver that was not detected on lanes 2–3 during Detect. Expected throughput ceiling: 2 × 1.969 = 3.94 GB/s per direction — matches a user complaint of "~3.5 GB/s instead of 7 GB/s".

Quiz

  1. How many signal wires in a x8 link?

    Answer

    8 lanes × 2 pairs × 2 wires = 32.

  2. At what speed does every link initially train?

    Answer

    2.5 GT/s (Gen1); higher speeds are reached later via Recovery.

  3. Why can't a x4 link with one broken lane run as x3?

    Answer

    x3 is not a defined width; the link falls back to a supported width such as x2 or x1 using contiguous working lanes starting at lane 0 (or reversed).

  4. What does AC coupling enable?

    Answer

    Different DC common-mode levels at each end, and the charge-time-based receiver detection.

Interview questions

  1. Beginner What is a differential pair?
    Model answerTwo complementary wires; the receiver uses their voltage difference, rejecting common-mode noise.
  2. Intermediate What do LnkCap and LnkSta mean?
    Model answerLink Capabilities (max speed/width the port supports) and Link Status (currently negotiated).
  3. Advanced Why are retimers needed at Gen5?
    Model answerHigher Nyquist frequency increases channel loss; long traces exceed loss budget; retimers recover and retransmit, splitting the channel into two compliant segments.
  4. Advanced What is SRIS?
    Model answerSeparate Reference clocks with Independent Spread spectrum; requires larger elastic buffers and more frequent SKP ordered sets.
  5. Senior Both ends show Gen3 although both support Gen4. Investigate.
    Model answerCheck Target Link Speed in LnkCtl2 (BIOS cap), equalization status bits in Link Status 2 / 16 GT/s capability, AER history, riser/retimer support, try forcing a retrain at Gen4 in a lab setting.
💡 Senior insight

"Negotiated" is not "healthy". A link at full width and speed can still be marginal, logging thousands of correctable errors that each cost a replay. Always pair LnkSta with error counters.
