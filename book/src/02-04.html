PART V

PCIe Transaction Layer

Everything an NVMe controller does on the host side is a Transaction Layer Packet (TLP): the host's doorbell write, the controller's fetch of a 64-byte Submission Queue Entry, the PRP-list read, the data transfer, the 16-byte Completion Queue Entry, the MSI-X interrupt. This Part teaches TLPs from first principles, then field by field with bit positions, then the three rules that govern their behavior in flight: posted vs non-posted semantics, tag-based matching of split transactions, and ordering. It ends with a working Python decoder that you can feed synthetic headers and that shows every field in binary, hex and decimal.

10 Transaction Layer Packets (TLPs)

10.1 Why this chapter exists

If you can read TLPs, you can see NVMe working. Every claim an SSD or driver makes about "I submitted", "I fetched", "I completed", "I interrupted" can be checked against the TLPs on the link. This chapter answers: what is a TLP, why does it exist, what is it made of, and which TLP types matter — and then traces a whole NVMe read command as TLPs.

  • Beginner: define TLP, header, payload, digest, requester, completer.
  • Intermediate: list MRd, MWr, CfgRd/CfgWr, Cpl, CplD, Msg and AtomicOp, with posted/non-posted classification.
  • Advanced: map every step of an NVMe command to TLPs and directions.
  • Senior: apply TLP decoding safety: never infer a transaction from a label; separate PCIe normative, NVMe, implementation and analyzer-presentation facts.
  • Trace: read normal, slow, failed and ambiguous synthetic NVMe TLP traces.
  • Debug/validation: identify which missing TLP explains a stuck command.

Prerequisites: layer model, topology and routing.

10.2 Story and analogy

🧒 Kid analogy

A TLP is a letter in an envelope. The envelope (header) says what kind of letter it is ("please send me something" or "here's something for you"), who sent it, which question number it is, and where it goes. The contents (payload) are the actual data — only some letters have contents. A wax seal (digest/ECRC) can optionally prove nobody changed the letter on its whole journey.

🧩 Where the analogy breaks

Letters can be lost; TLPs essentially cannot (per-link replay recovers corruption — a missing completion means something failed, not that the post office misplaced it). Envelope sizes are strictly limited (payload ≤ Max Payload Size), and the "reply letter" to a read must quote the question number (Tag) and the asker's identity (Requester ID) exactly.

10.3 What a TLP is and why it exists

A Transaction Layer Packet is the unit by which PCIe carries a request or a completion between two functions, end to end, possibly through switches. It exists because PCIe is a split-transaction packet network: a read is not one bus cycle that holds the interconnect until data arrives; it is a request packet, and later one or more completion packets, with the link free for other traffic in between. TLPs carry everything a PCI bus cycle used to express (address, byte enables, command type) plus what a packet network needs (requester identity, tag, length, traffic class, attributes).

The Data Link Layer then adds a sequence number and LCRC; the Physical Layer adds framing (Figure 7.1). A DW (doubleword) is 4 bytes.

10.4 Request / completion relationship

A requester issues a request TLP; a completer services it. For non-posted requests the completer must return completion TLP(s) carrying the requester's Requester ID and Tag so the requester can match them (Chapter 13). For posted requests no completion is returned (Chapter 12). Completions are ID-routed back to the requester.

📌 Remember: MSI-X is a Memory Write

An NVMe interrupt in MSI-X mode is just a posted MWr of a 32-bit message data value to an address the host programmed into the MSI-X table. On a trace it looks like any other MWr; you recognize it only by its address (in the interrupt address range, e.g. FEExxxxxh on x86 impl) and context.

10.6 PCIe transaction lifecycle (conceptual model)

REQUEST CREATED      requester's TL forms header; needs a free tag (non-posted) and flow-control credits
      |
TLP TRANSMITTED      DLL assigns Seq#, LCRC, stores in replay buffer; PL frames and sends
      |
LINK DELIVERY        per hop: LCRC check, Ack/Nak, replay if needed; switches route and re-transmit
      |
COMPLETER PROCESSING completer decodes address/ID; executes (memory read, register access)
      |

REQUESTER MATCHING   requester finds outstanding entry by Tag (+ID), checks Byte Count / Lower Address,

📭 What this model is and is not

This six-step chain is a conceptual model conceptual of what the specification requires to be observable. It is not a literal universal internal implementation: a root complex may pipeline steps, split one CPU request into several TLPs, coalesce posted writes from a write-combining buffer into one TLP, or service a read from a cache; an SSD controller may prefetch SQEs before a doorbell is observed by firmware. The spec defines what goes on the link and the rules (ordering, completion, timeouts), not how chips organize work internally.

The six-step model above, drawn as one real journey. The NVMe SSD fetches a 64-byte Submission Queue Entry: it is the requester of a Memory Read, the root complex is the completer, and a switch sits in between. Watch which layer adds what, which hop routes by address and which by ID, and that every link hop is acknowledged separately. Values match the worked example in §10.7 synthetic.

  1. The SSD's Transaction Layer builds the Memory Read request

    The controller wants SQ1 slot 5. Its Transaction Layer takes a free tag, records it in its outstanding-request table, checks it has a Non-Posted Header credit for the link, and forms a 4DW MRd header (64-bit address, so 16 bytes). An MRd carries no payload: only the header travels.

    Where: SSD Transaction Layer (requester)PCIe: not yet on the wire · MRd, 4DW header, Length 16 DW = 64 bytes
    Fmt/Type = 001b/0 0000 (MRd, 4DW) Requester ID = 0300h (03:00.0) Tag = 0Ah Length = 16 DW First/Last BE = 1111b/1111b Address = 1_2340_0140h (SQ1 base 1_2340_0000h + 5 × 64)
  2. The Data Link Layer adds a sequence number and LCRC

    The SSD's Data Link Layer prepends a 12-bit sequence number (in a 2-byte field) and appends a 32-bit LCRC computed over the sequence number and the TLP. It keeps a copy in its replay buffer until the other end of this link acknowledges it.

    Where: SSD Data Link LayerPCIe: link-local fields; they are stripped and regenerated at every hop
    Seq = 412h LCRC = 32-bit CRC (value not shown) Replay buffer: [412h: MRd Tag 0Ah]
  3. The Physical Layer frames, scrambles and transmits on Link A

    The Physical Layer marks the start of the packet (in 128b/130b an STP token, which also carries the TLP length; in 8b/10b STP and END symbols), scrambles the bytes, stripes them across the 4 lanes and serializes them toward the switch's downstream port.

    Where: SSD Physical Layer → Link APCIe: Yes, upstream (device → switch) · about 4 + 2 + 16 + 4 bytes on the wire
    Gen4 x4: ≈ 26 B × 8 / 63 Gb/s ≈ 3.3 ns to serialize (derived) The figure's STP/Seq split is conceptual: in 128b/130b the sequence number sits inside the 4-byte STP token.
  4. The switch checks the LCRC and returns an ACK DLLP

    The switch's downstream port checks LCRC and sequence order. Good, so its Data Link Layer sends an ACK DLLP naming sequence 412h (ACKs may be coalesced to cover several TLPs). The SSD then discards its replay copy. A bad LCRC would produce a NAK and a replay from the SSD instead (Chapter 15).

    Where: switch downstream port ↔ SSD Data Link LayersPCIe: Yes, downstream · ACK DLLP (8 bytes incl. framing), link-local, never forwarded
    ACK AckNak_Seq_Num = 412h SSD replay buffer: [ ] (empty)
  5. The switch routes the request by address and forwards it on Link 1

    Address 1_2340_0140h is not inside the down port's memory window (FE00_0000h–FE0F_FFFFh), so the request goes to the up port. The switch does not change the header (Requester ID, Tag and address are untouched) but its up port adds its own sequence number and LCRC for Link 1 and keeps its own replay copy. The root port then ACKs that hop.

    Where: inside the switch, then Link 1PCIe: Yes, upstream · same MRd, new Seq/LCRC on Link 1 · consumes NPH credit at the root port
    Link 1: Seq = 0C7h (switch's counter, unrelated to 412h) Root port → switch: ACK 0C7h
  6. The root complex reads host memory

    The root port's Transaction Layer decodes the address as system memory, passes it through the IOMMU (if enabled) and reads 64 bytes from RAM. This is the slowest part of the round trip and is invisible on the link.

    Where: root complex ↔ host memoryPCIe: No · host-internal memory access
    Reads 1_2340_0140h … 1_2340_017Fh (the 64-byte SQE, opcode 02h Read) In the §10.7 trace the whole round trip is 1290 − 540 = 750 ns.
  7. The root complex sends a Completion with Data

    The completer builds a CplD with a 3DW (12-byte) header, copying the Requester ID and Tag from the request, adding its own Completer ID, the Byte Count still owed and the Lower Address, followed by the 64 bytes of data. It sends it down Link 1 with its own sequence number and LCRC.

    Where: root complex → Link 1PCIe: Yes, downstream · CplD, 3DW header + 16 DW data
    Completer ID 0000h Requester ID 0300h Tag 0Ah Status SC (000b) Byte Count 64 Lower Address 40h Length 16 DW Link 1: Seq = 2A0h, then switch → root port: ACK 2A0h
  8. The switch routes the completion by ID

    Completions carry no address to route on. The switch reads the bus number from the Requester ID (03) and sends the TLP to the port whose secondary–subordinate bus range contains bus 03: the down port. It goes out on Link A with a fresh sequence number and LCRC.

    Where: inside the switch, then Link APCIe: Yes, downstream · same CplD, new Seq/LCRC on Link A
    Requester ID 0300h → bus 03 → down port (buses 03–03) Link A: Seq = 1B3h
  9. The SSD matches the completion to its request by tag

    After the SSD's Physical and Data Link Layers accept the packet, its Transaction Layer looks up Tag 0Ah (with its own Requester ID) in the outstanding-request table. Byte Count = 64 equals what is still owed, so this was the last completion: the tag is freed, the completion timer stopped and the SQE handed to the command processor.

    Where: SSD Transaction LayerPCIe: No further TLP · tag 0Ah may now be reused
    Lookup 0Ah → "64 B for SQ1 slot 5" → received 64 of 64 → done If no completion had come back: Completion Timeout (Chapter 12), not a retry.
  10. The SSD acknowledges the CplD on Link A

    The SSD's Data Link Layer ACKs sequence 1B3h so the switch can drop its replay copy. ACKs are per link: the root complex never learns, from ACKs, that the SSD received the data.

    Where: SSD → switch Data Link LayersPCIe: Yes, upstream · ACK DLLP, link-local
    ACK AckNak_Seq_Num = 1B3h Total for one SQE fetch: 2 TLPs end to end, 4 TLP transmissions (2 per link), 4 ACKs.

Only the Transaction Layer header crosses end to end unchanged. Sequence numbers, LCRCs, framing and ACKs exist per link and are rebuilt at every hop. That is why an analyzer on Link A and one on Link 1 show the same Tag 0Ah but different sequence numbers.

10.8 TLP decoding safety

⚠️ Never infer a transaction solely from a label

An analyzer row labelled "Read" may be an MRd, a CfgRd, an IORd — or the tool's merged "transaction" view of an MRd and its CplDs. Decide using the evidence: Fmt, Type, Length, Requester ID, Completer ID, Address, Tag, byte enables, completion status, Byte Count, TC, attributes, payload, and context (what came before, which link, which direction). If a field is not in the capture (truncated header, filtered column, FLIT-mode decode unavailable), the correct statement is: "Insufficient trace evidence."

📡 Four worlds, one TLP

Take row 20 above. PCIe normative: it is a posted 4DW Memory Write of 4 DW, must follow earlier posted writes from the same requester (no RO). NVMe: the address is inside the I/O Completion Queue the host created; the 16 bytes are a CQE whose DW3 holds CID and phase tag. Implementation: whether the controller writes one CQE per TLP or coalesces several CQEs into one larger write is a controller choice. Analyzer presentation: the tool may label it "NVMe Completion" if it has NVMe decode enabled and knows the queue base addresses — a convenience inference, not wire truth.

10.9 Linux view

🧪 Lab 10.1 — Narrate the TLPs of an NVMe write SAFE

Objective: predict the TLP sequence of an 8 KiB NVMe Write with PRP1 and PRP2 (two pages), MRRS = 512, MPS = 256. Steps: list every TLP, direction, type, length. Questions: how many MRd for data? How many CplD minimum?

Solution

Doorbell MWr ↓; SQE MRd ↑ (16 DW) + CplD ↓; data: 8192 / 512 = 16 MRd ↑ (each Len 128 DW), each returned as at least 2 CplD of 256 B (MPS) → ≥ 32 CplD ↓ (more if the completer splits at RCB boundaries); CQE MWr ↑; MSI-X MWr ↑; CQ head doorbell MWr ↓. No PRP list fetch because two pages fit in PRP1+PRP2. Requests are bounded by MRRS, completions by MPS.

Extension: repeat for 16 KiB (needs a PRP list → one extra MRd for the list).

    Model answerNowhere at PCIe level silently — but a doorbell to a wrong address can be accepted silently by the SSD (NVMe defines an Invalid Doorbell async event, which may not be enabled), and writes are posted so the host never learns.

11 TLP Header Anatomy

11.1 Why this chapter exists

Analyzer GUIs, AER header logs (lspci prints them as four hex DWs), FPGA debug captures and simulation waveforms all hand you raw header DWs. This chapter teaches you to decode them by hand and with code, and tells you, for every field, what a wrong value looks like in practice.

  • Locate every non-FLIT header field by DW, byte and bit.
  • Decode MRd, MWr and CplD headers byte by byte in binary and hex.
  • Apply byte-enable, length, 4 KiB boundary, Byte Count and Lower Address rules.
  • Run and extend a Python teaching decoder.

Prerequisites: Chapter 10; binary/hex fluency.

🧒 Kid analogy

A header is a form with boxes in fixed places: box 1 says "what kind of letter", box 2 "how many pages", box 3 "who sent it", box 4 "question number", box 5 "address". Because the boxes are always in the same place, a machine can read it in a flash.

🧩 Where the analogy breaks

Some boxes change meaning depending on box 1 (completion headers reuse DW1–DW2 for completer ID, status and byte count), some boxes are split across bytes (Length is 10 bits spanning byte 2 and 3; tag bits T9/T8 live in byte 1), and the form changed in FLIT mode.

11.2 Byte order convention

Headers are transmitted byte 0 first. Within the header, the spec draws each DW with byte 0 on the left holding bits [31:24] of that DW — i.e. header fields read naturally as big-endian 32-bit words. Payload bytes, by contrast, are in address order: payload byte 0 is the byte at the lowest address. A little-endian host value 00000005h therefore appears in the payload as 05 00 00 00 verified.

2Bus Number[7:0]Device[4:0] | Function[2:0]Reserved[3:0] | Extended Register Number[3:0]Register Number[5:0] | R[1:0]

Config requests are 3DW, Length = 1, TC0, attributes 0, Last DW BE = 0000 verified. Byte offset = (ExtReg << 8) | (Reg << 2), covering the 4 KiB extended configuration space.

11.9 Byte enables worked example

Write 6 bytes to byte addresses 0x…1002–0x…1007. DW at 0x1000 covers bytes 1000–1003, of which 1002 and 1003 are written: First DW BE = 1100b (bit n enables byte n of the DW). DW at 0x1004: all four bytes: Last DW BE = 1111b. Length = 2 DW. Address field = 0x…1000 (DW aligned; bits [1:0] are not address bits). Byte 7 of the header = F C → FCh.

11.11 Byte Count and Lower Address with split completions

Request: MRd for 512 bytes starting at byte address 0x…1020. Read Completion Boundary (RCB) = 64 bytes, MPS = 256 synthetic. The completer chooses to split at 256-byte-aligned points (allowed: split completions must end on RCB-aligned addresses except the last).

11.12 The teaching TLP decoder (Python)

This decoder takes a synthetic hexadecimal header (optionally followed by payload) and prints, for every field: binary bits, hex value, decimal value and meaning. It validates a handful of rules (Length/BE, 4 KiB crossing, 4DW below 4 GiB, poisoned data). It covers non-FLIT headers only; FLIT-mode headers (PCIe 6.0+) are different, and 10-bit tag interpretation depends on whether the requester enabled 10-bit tags — the decoder states both facts. Run with no arguments to decode six built-in synthetic examples, or pass hex bytes.

#!/usr/bin/env python3
"""Teaching decoder for NON-FLIT PCIe TLP headers (3DW / 4DW), PCIe 1.x-5.x style.

SYNTHETIC-INPUT TEACHING TOOL. Not a compliance checker. FLIT-mode (PCIe 6.0+)
headers use a different format and are NOT decoded here. 10-bit tag
interpretation (T9/T8) assumes the 10-bit Tag fields defined since PCIe 4.0;
whether a requester actually used 10-bit tags depends on its configuration.
"""
import sys

FMT = {0b000: ("3DW", False), 0b001: ("4DW", False),
       0b010: ("3DW", True),  0b011: ("4DW", True), 0b100: ("PREFIX", None)}
CPL_STATUS = {0b000: "SC  Successful Completion",
              0b001: "UR  Unsupported Request",
              0b010: "CRS Configuration Request Retry Status (named RRS in 6.0+)",
              0b100: "CA  Completer Abort"}
MSG_ROUTE = {0: "routed to Root Complex", 1: "routed by address", 2: "routed by ID",
             3: "broadcast from Root Complex", 4: "local - terminate at receiver",
             5: "gathered and routed to Root Complex"}

def kind(fmt, typ):
    data = fmt in (0b010, 0b011)
    if typ == 0b00000: return "MWr (Memory Write, posted)" if data else "MRd (Memory Read, non-posted)"
    if typ == 0b00001: return "MRdLk (locked Memory Read, legacy)"
    if typ == 0b00010: return "IOWr (I/O Write)" if data else "IORd (I/O Read)"
    if typ == 0b00100: return "CfgWr0 (Type 0 Config Write)" if data else "CfgRd0 (Type 0 Config Read)"
    if typ == 0b00101: return "CfgWr1 (Type 1 Config Write)" if data else "CfgRd1 (Type 1 Config Read)"
    if typ == 0b01010: return "CplD (Completion with Data)" if data else "Cpl (Completion without Data)"
    if typ == 0b01011: return "CplDLk (locked Completion with Data)" if data else "CplLk"
    if typ == 0b01100: return "FetchAdd (AtomicOp)"
    if typ == 0b01101: return "Swap (AtomicOp)"
    if typ == 0b01110: return "CAS (AtomicOp Compare-and-Swap)"
    if typ >> 3 == 0b10: return ("MsgD" if data else "Msg") + " (Message, " + MSG_ROUTE.get(typ & 7, "reserved routing") + ")"
    return "UNKNOWN/reserved Type for this Fmt"

def row(name, value, width, meaning):
    print(f"  {name:<16} bits={value:0{width}b}  hex=0x{value:0{(width+3)//4}X}  dec={value:<10d} {meaning}")

def decode(hexstr):
    b = bytes.fromhex(hexstr.replace(" ", "").replace("_", ""))
    print("=" * 96)
    print("Input:", " ".join(f"{x:02X}" for x in b))
    if len(b) < 12:
        print("  Insufficient trace evidence: fewer than 12 header bytes."); return
    warn = []
    fmt, typ = b[0] >> 5, b[0] & 0x1F
    if fmt not in FMT:
        print(f"  Fmt={fmt:03b} reserved - cannot decode"); return
    hdr, has_data = FMT[fmt]
    if hdr == "PREFIX":
        print("  Fmt=100: TLP Prefix - prefix decoding not covered by this teaching tool"); return
    k = kind(fmt, typ)
    t9, tc, t8 = b[1] >> 7, (b[1] >> 4) & 7, (b[1] >> 3) & 1
    attr2, ln, th = (b[1] >> 2) & 1, (b[1] >> 1) & 1, b[1] & 1
    td, ep, attr10, at = b[2] >> 7, (b[2] >> 6) & 1, (b[2] >> 4) & 3, (b[2] >> 2) & 3
    length = ((b[2] & 3) << 8) | b[3]
    ndw = 1024 if length == 0 else length
    print(f"TLP kind: {k}   header={hdr}   payload={'yes' if has_data else 'no'}")
    print(" DW0")
    row("Fmt", fmt, 3, f"{hdr}, {'with' if has_data else 'no'} data")
    row("Type", typ, 5, k)
    row("TC", tc, 3, f"Traffic Class {tc}")
    row("Attr[2] IDO", attr2, 1, "ID-based Ordering" + (" SET" if attr2 else " clear"))
    row("Attr[1] RO", attr10 >> 1, 1, "Relaxed Ordering" + (" SET" if attr10 >> 1 else " clear"))
    row("Attr[0] NS", attr10 & 1, 1, "No Snoop" + (" SET" if attr10 & 1 else " clear"))
    row("LN", ln, 1, "Lightweight Notification")
    row("TH", th, 1, "TLP Processing Hints present" if th else "no processing hints")
    row("TD", td, 1, "ECRC digest present at end of TLP" if td else "no ECRC")
    row("EP", ep, 1, "POISONED - payload must not be trusted" if ep else "not poisoned")
    row("AT", at, 2, {0: "untranslated address", 1: "translation request", 2: "translated address"}.get(at, "reserved"))
    is_cpl = typ in (0b01010, 0b01011)
    if (is_cpl or typ >> 3 == 0b10) and not has_data:
        row("Length", length, 10, "reserved for this TLP type (no payload)")
    else:
        row("Length", length, 10, f"{ndw} DW = {ndw*4} bytes" + (" (0 encodes 1024 DW)" if length == 0 else ""))
    if ep: warn.append("EP=1: data poisoned upstream; receiver handling is error-policy dependent")
    if is_cpl:            # completions
        cpl_id = (b[4] << 8) | b[5]
        status, bcm = b[6] >> 5, (b[6] >> 4) & 1
        bc = ((b[6] & 0xF) << 8) | b[7]
        req_id = (b[8] << 8) | b[9]
        tag8 = b[10]
        lower = b[11] & 0x7F
        tag10 = (t9 << 9) | (t8 << 8) | tag8
        print(" DW1/DW2 (completion)")
        row("Completer ID", cpl_id, 16, f"{cpl_id>>8:02X}:{(cpl_id>>3)&0x1F:02X}.{cpl_id&7}")
        row("Status", status, 3, CPL_STATUS.get(status, "reserved status"))
        row("BCM", bcm, 1, "Byte Count Modified (PCI-X legacy)" if bcm else "clear")
        row("Byte Count", bc, 12, f"{4096 if bc == 0 else bc} bytes remaining incl. this completion")
        row("Requester ID", req_id, 16, f"{req_id>>8:02X}:{(req_id>>3)&0x1F:02X}.{req_id&7} (routing target)")
        row("Tag[7:0]", tag8, 8, f"10-bit tag if T9/T8 in use: 0x{tag10:03X}")
        row("Lower Address", lower, 7, "low 7 bits of starting byte address of this completion's data")
        if status != 0 and has_data: warn.append("CplD with non-SC status is unexpected")
        if status == 0 and not has_data and typ == 0b01010:
            warn.append("Cpl (no data) with SC: normal for non-posted writes (CfgWr/IOWr); for a read it is malformed")
    else:                                           # requests
        req_id = (b[4] << 8) | b[5]
        tag8 = b[6]
        last_be, first_be = b[7] >> 4, b[7] & 0xF
        tag10 = (t9 << 9) | (t8 << 8) | tag8
        print(" DW1 (request)")
        row("Requester ID", req_id, 16, f"{req_id>>8:02X}:{(req_id>>3)&0x1F:02X}.{req_id&7}")
        if typ >> 3 == 0b10:
            row("Tag", tag8, 8, "Tag (not used for completion matching on messages)")
            row("Message Code", b[7], 8, "message code (see spec message tables)")
        else:
            row("Tag[7:0]", tag8, 8, f"T9={t9} T8={t8} -> 10-bit tag 0x{tag10:03X} (only if 10-bit tags enabled)")
            row("Last DW BE", last_be, 4, "byte enables for last DW")
            row("First DW BE", first_be, 4, "byte enables for first DW")
            if ndw == 1 and last_be != 0: warn.append("Length=1 requires Last DW BE=0000")
            if ndw > 1 and last_be == 0: warn.append("Length>1 requires non-zero Last DW BE")
            if ndw > 1 and first_be == 0: warn.append("Length>1 requires non-zero First DW BE")
            if ndw == 1 and first_be == 0 and typ == 0: warn.append("zero-length request (FirstBE=0): legal, used e.g. for flush semantics")
        if typ in (0b00100, 0b00101):              # config
            bus, dev, fn = b[8], b[9] >> 3, b[9] & 7
            reg = (((b[10] & 0xF) << 6) | (b[11] >> 2)) * 4
            print(" DW2 (configuration)")
            row("Bus", bus, 8, f"target bus {bus:02X}")
            row("Device", dev, 5, f"target device {dev:02X}")
            row("Function", fn, 3, f"target function {fn}")
            row("Register", reg, 12, f"config offset 0x{reg:03X}")
        elif hdr == "3DW" and typ >> 3 != 0b10:
            addr = ((b[8] << 24) | (b[9] << 16) | (b[10] << 8) | b[11]) & ~3
            ph = b[11] & 3
            print(" DW2 (32-bit address)")
            row("Address[31:2]", addr, 32, f"byte address 0x{addr:08X}")
            row("PH / R", ph, 2, "processing hint" if th else "reserved (00)")
            check_4k(addr, ndw, warn)
        elif hdr == "4DW" and typ >> 3 != 0b10:
            addr = int.from_bytes(b[8:16], "big") & ~3 if len(b) >= 16 else None
            if addr is None:
                print("  Insufficient trace evidence: 4DW header but fewer than 16 bytes."); return
            print(" DW2-3 (64-bit address)")
            row("Address[63:2]", addr, 64, f"byte address 0x{addr:016X}")
            if addr < (1 << 32): warn.append("64-bit (4DW) format used for an address below 4 GiB: spec requires 3DW form")
            check_4k(addr, ndw, warn)
    hdr_bytes = 12 if hdr == "3DW" else 16
    if has_data and len(b) > hdr_bytes:
        payload = b[hdr_bytes:]
        print(f" Payload bytes present in input: {len(payload)} (expected {ndw*4}" + (" + 4 ECRC" if td else "") + ")")
        print("  Payload is in address order (byte 0 = lowest address); a little-endian 32-bit value 5 appears as 05 00 00 00")
    for w in warn: print("  WARNING:", w)

def check_4k(addr, ndw, warn):
    if (addr & 0xFFF) + ndw * 4 > 4096:
        warn.append("request crosses a 4 KiB boundary - Malformed TLP for memory requests")

🧪 Lab 11.1 — Decode by hand, then verify with code SAFE

Objective: decode three headers manually, then confirm. Setup: save the decoder as tlpdec.py. Headers (synthetic): (1) 60 00 00 40 03 00 00 FF 00 00 00 01 50 00 01 00; (2) 0A 00 00 00 00 00 80 04 03 00 13 00; (3) 44 00 00 01 00 00 02 0F 03 00 00 04. Solution

(1) MWr 4DW, Length 64 DW = 256 B, Req 03:00.0, BEs FF, address 1_5000_0100h → SSD writing read data into a host buffer (second 256 B chunk). (2) Cpl without data, Completer 00:00.0, Status 100 = CA, Byte Count 4, Requester 03:00.0, Tag 13h → the root complex aborted a request from the SSD (e.g. an access the RC refused; cause implementation-dependent). (3) CfgWr0, Length 1, Requester 00:00.0, Tag 02h, FirstBE F, target 03:00.0 offset 004h → the Command register (and Status) dword; e.g. setting Memory Space Enable/Bus Master Enable. Its payload is not included in the input.

Quiz

  1. Byte 0 = 4Ah. What is it?

    Answer

    CplD (Fmt 010, Type 01010).

  2. Length field 000h in a MWr means?

    Answer

    1024 DW (4096 bytes) — only legal if MPS allows, which in practice it rarely does.

  3. Where are the upper bits of a 10-bit tag?

    Answer

    T9 at DW0 byte 1 bit 7, T8 at byte 1 bit 3.

  4. A completion has Byte Count 0x080 and Length 16 DW. Is it the last?

    Answer

    No: 128 bytes remain, this carries 64 → another 64 bytes follow.

  5. Which BE value is required for Length = 1?

    Answer

    Last DW BE = 0000.

Interview questions

  1. Beginner What does Fmt tell you?
    Model answerHeader size (3/4 DW), whether data follows, or a prefix.
  2. Intermediate How do you compute a config register offset from a CfgRd header?
    Model answer(ExtReg << 8) | (Reg << 2).
  3. Intermediate Why is the address DW-aligned?
    Model answerByte granularity comes from byte enables; the low two bits are used for PH.
  4. Advanced Explain Byte Count vs Length in a completion.
    Model answerLength is payload in this TLP (DW); Byte Count is bytes remaining for the whole request including this TLP.
  5. Advanced Why does a 4DW MRd below 4 GiB matter?
    Model answerRequesters must use 3DW for addresses below 4 GiB; receivers' handling of violation varies; good compliance-check item.
  6. Senior How would you validate an analyzer's decode of a FLIT-mode capture?
    Model answerConfirm the link negotiated FLIT mode, the decoder version supports 6.x FLIT headers, cross-check a known transaction (e.g. a config read of Vendor ID) against expected values.
