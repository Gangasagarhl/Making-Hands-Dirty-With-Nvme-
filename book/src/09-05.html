PART XL

Engineering Bug Report Training

A root cause that nobody can act on is worth very little. The bug report is the product of an investigation: it transfers evidence, reasoning and next steps to people who were not in the room — firmware teams, platform vendors, managers, the engineer who will hit the same bug in three years. This part gives a template, a fully worked excellent report, and a poor report dissected line by line.

40.1 Writing Bug Reports That Get Bugs Fixed

40.1.1 Why this chapter exists

Most escalations stall not because the bug is hard but because the report is unusable: no versions, no reproduction, no first abnormal event, conclusions without evidence, or evidence without conclusions. A reader on the receiving end must be able to answer three questions in under a minute: What failed? Where is the proof? What do you want me to do?

40.1.2 Learning objectives

  • Fill every section of the standard template with precise, verifiable content.
  • State the first abnormal event with a pointer to the exact evidence row.
  • Separate observation, inference and recommendation; label confidence.
  • Write a regression test that fails on the buggy build and passes on the fix.
  • Critique a poor report and rewrite it.

Prerequisites: Part XV (Error handling), the capstone, scenario method in 38.1.

🧒 Kid analogy

If you tell a doctor “I feel bad”, they can’t help much. If you say “since Tuesday, my left knee hurts when I climb stairs, not when I walk on flat ground, and it is swollen here”, they can. A bug report is telling the engineer exactly where it hurts, when, and how you know.

🧩 Where the analogy breaks

A patient is not expected to diagnose. An engineering bug report is expected to contain your diagnosis — but clearly separated from the observations, so the reader can disagree with the diagnosis while still trusting the data.

40.1.4 A fully worked excellent report

📘 Context

The following report is synthetic. The host component is a fictional user-space NVMe driver named udrv; the device and platform are placeholders. It illustrates the style; it is not a record of a real defect.

📝 Report UDRV-1342 SAFE

Title

Read of exactly 513 pages (e.g. 2 MiB at non-page-aligned buffer) returns wrong data in last page; PRP list page overwritten — udrv 5.4

Environment

Server “LAB-R2” (synthetic), root port 0000:80:03.0 direct-attached to SSD in U.2 bay 3, no switch, no retimer. IOMMU disabled for udrv (VFIO no-IOMMU mode for the lab — note this hides DMA faults). BIOS 2.14.

Hardware

SSD model “X-3200” (placeholder), HW rev B; 3/3 units reproduce. Different SSD model “Y-800”: 0/2 reproduce (see Root cause for why).

Firmware

SSD firmware 4.2.1 (slot 1, active). Platform BMC 1.9.

OS

Kernel 6.x (vendor build), hugepages 2 MiB × 1024, udrv 5.4.0 commit 9f3c2e1 (synthetic), fio 3.x with udrv ioengine.

PCIe generation / link width

Device LnkCap 16 GT/s x4; root port LnkCap 32 GT/s x16 (bifurcated x4); LnkSta 16 GT/s x4 on both ends, measured with lspci -vvv before and after the test.

NVMe revision

VS = 0001_0400h (1.4). CAP.MPSMIN = 0 (4 KiB); CC.MPS = 0. MDTS = 0 (no limit reported). PRPs used (SGLs not supported by X-3200 for I/O). Y-800 reports MDTS = 9 (2 MiB).

Reproduction steps

  1. Write a known pattern: fio --ioengine=udrv --rw=write --bs=2M --size=1G --verify_pattern=0xA5A5… with page-aligned buffers.
  2. Read back with buffer offset 512 B: --rw=read --bs=2M --iomem_align=512 --verify=pattern (the unaligned buffer spans 513 pages).
  3. Observe verification failures. Repro rate: 100% of 2 MiB reads with offset ∉ {0}; 0% with offset 0.
  4. Minimal reproducer: udrv_test prp_boundary --pages=513 (attached) — fails in 1 iteration.

Expected result

All 2 MiB reads return the written pattern. Basis: identical reads with aligned buffers succeed; the PRP rules (first entry may carry an offset; list entries page-aligned; a list page’s last entry is a chain pointer only when more entries follow) allow this transfer.

Actual result

The last 512 bytes of the user buffer contain stale data; the CQE reports success (SC 00h). Occasionally a subsequent unrelated command fails with Invalid Field or a Data Transfer Error.

Trace evidence

Capture udrv1342_cap1 (analyzer, both directions, headers + first 64 B of payload, 16 GT/s x4 interposer; failure reproduced with interposer present). Annotated excerpt:

Synthetic excerpt — 2 MiB read with 512-byte buffer offset
#DirTLPAddressLenNote
12↑MRdSQE @ 2_0000_3C4016 DWSQE: opc 02h, NLB 1FFh (512 blocks × 4 KiB = 2 MiB), PRP1 = 3_1000_0200, PRP2 = 2_4000_0000 (list)
14↑MRd ×82_4000_0000 …128 DW eachDevice reads the full list page (512 entries, MRRS 512)
15↓CplD ×16—64 DW eachEntry 511 = 2_4000_1000 (points to a second list page)

Calculation: buffer offset 512 B → PRP1 covers 4096 − 512 = 3584 B; remaining 2 MiB − 3584 B = 2093568 B = 511 full pages + 512 B → 512 more pages → 512 list entries. 512 entries fit exactly in one 4 KiB list page (512 × 8 B), so no chain pointer is needed; entry 511 must be a data pointer derived. udrv wrote a chain pointer in entry 511 and placed the last data page pointer in the second list page.

First abnormal event

Row 14–15: the PRP list fetched by the device contains a chain pointer in entry 511 although exactly 512 entries are required. This is a host-side construction error; row 8206 is its consequence. Note: the trace marks row 8206 as first-bad because it is the first visible misbehaviour on the wire; the report identifies the earlier list content (rows 14–15) as the first abnormal event because the list was already wrong when fetched.

Root cause

Confirmed (code inspection + trace + fix verified): prp_build() in udrv/src/prp.c chains when remaining_entries >= entries_per_page instead of > entries_per_page. The off-by-one triggers only when exactly 512 entries are needed (513 pages touched). Y-800 does not reproduce because its MDTS (2 MiB) causes udrv to split the I/O, so no single command needs 512 entries.

Eliminated: device PRP handling bug (device behaviour matches the PRP rules given the list it received); memory corruption (pattern reproducible and address-exact); link errors (no AER, no Nak in capture).

Secondary effect (Strong evidence): the device wrote user data into udrv’s second PRP list page, which is pooled and reused; later commands that use that pool page as a list read garbage entries, explaining sporadic Invalid Field / Data Transfer Errors.

Workaround

Set udrv.max_io_size=1M (forces splitting) — cost: ~3% lower sequential throughput at QD1, none measurable at QD8+.

Permanent fix

Owner: udrv maintainers. Change comparison to strict greater-than; add assertion that a list page’s last slot holds a chain pointer only if entries remain. Patch udrv!2211 attached.

Regression test

udrv_test prp_boundary: for page counts {1, 2, 3, 511, 512, 513, 514, 1024, 1025, 1026} × buffer offsets {0, 8, 512, 4088} × read/write, verify data and verify PRP list structure by a software model. Fails on 5.4.0 (513 pages, offset ≠ 0), passes with patch; runtime 40 s; added to CI.

Quiz

  1. Why must the “Actual result” section avoid interpretation?

    Answer

    So the reader can trust the observation even if they disagree with your diagnosis. Mixing interpretation in makes the data look biased and forces the reader to re-derive the facts.

  2. What makes a regression test trustworthy?

    Answer

    It demonstrably fails on the buggy build and passes on the fixed build, has explicit pass criteria and bounded runtime, and covers the boundary conditions around the bug (neighbouring values), not just the single failing case.

  3. The capstone’s report should name which owner for the permanent fix?

    Answer

    The device firmware team (HMB re-enable handling), with an optional host workaround owned by the driver team.

47.1.3 Sample set — topic: NVMe queues and doorbells

A. Recall (5)

  1. What is the size of an SQE and a CQE?

    Answer

    64 bytes and 16 bytes (standard sizes configured via CC.IOSQES = 6 and CC.IOCQES = 4, i.e. 2^6 and 2^4).

  2. Where does the doorbell region start in BAR0?

    Answer

    Offset 1000h.

  3. Which register field gives the maximum queue entries supported?

    Answer

    CAP.MQES, bits 15:0, zero-based.

  4. Which bit of CQE DW3 is the phase tag?

    Answer

    Bit 16.

  5. Opcode of Create I/O Completion Queue?

    Answer

    05h (admin).

B. Understanding (5)

  1. Why is a queue with N slots able to hold only N−1 outstanding entries?

    Answer

    Because head == tail means empty; if all N were used, full would also be head == tail, which is ambiguous. Full is defined as (tail + 1) mod N == head.

  2. Why does the host update the CQ head doorbell at all?

    Answer

    So the controller knows which CQ slots are free; without it the controller would eventually consider the CQ full and stop posting.

  3. Why can many SQs share one CQ but not vice-versa?

    Answer

    Each SQ is bound to exactly one CQ at creation (CQID field); a CQ is just a destination. Sharing lets a CPU collect completions from several SQs (e.g. different priorities) in one place.

  4. Why is the doorbell write posted, and what does that imply for error reporting?

    Answer

    It is a Memory Write, which PCIe defines as posted: no completion returns, so the host cannot know from the write itself whether it arrived. Errors appear via AER or by the absence of subsequent device activity.

  5. Why does the controller report SQHD in each CQE?

    Answer

    To tell the host how far it has consumed the SQ so the host can reuse slots — the host has no other cheap way to know.

C. Application (5)

  1. CAP.DSTRD = 2. Offset of CQ 3 head doorbell?

    Answer

    Stride = 4 << 2 = 16 B. Offset = 1000h + (2×3+1)×16 = 1000h + 112 = 1070h.

  2. Host wants 256-entry I/O queues. What value goes in QSIZE?

    Answer

    255 (FFh), zero-based.

  3. SQ size 16, head 14, tail 3. How many commands outstanding? How many free slots?

    Answer

    (3 − 14) mod 16 = 5 outstanding (slots 14, 15, 0, 1, 2). Free usable = 16 − 1 − 5 = 10.

  4. Host consumed CQEs in slots 1022, 1023, 0, 1 of a 1024-entry CQ. Expected phase after?

    Answer

    Phase flips when the head wraps from 1023 to 0; if it was 1 before, it is now 0. New head = 2; write 2 to the CQ head doorbell.

  5. Number of Queues Set Features returned DW0 = 0003_0007. How many I/O SQs and CQs may the host create?

    Answer

    Bits 15:0 = NSQA = 7 → 8 SQs; bits 31:16 = NCQA = 3 → 4 CQs (both zero-based).

D. Debugging (3)

  1. Analyzer shows SQ tail doorbell writes but no SQE fetches. Hypotheses?

    Answer

    Bus Master Enable cleared; controller not enabled/ready (CSTS.RDY = 0) or in fatal state; doorbell written to wrong offset (stride) or wrong queue ID that doesn’t exist; tail value invalid (≥ queue size) → controller flags invalid doorbell and ignores; device lacks NP credits/tags; link problems. Check Command register, CSTS, doorbell offset vs CAP.DSTRD, AER, async events.

  2. The host sees CQEs but they all appear “old” after a reset. What went wrong?

    Answer

    Host reset its expected phase to 1 but did not clear CQ memory, which still holds entries with phase 1 from before — the host consumes stale entries. Or vice versa: memory zeroed but expected phase left at 0. Fix: zero CQ memory on (re)creation and reset phase to 1.

  3. Completion latency is fine but throughput collapses when 8 SQs share a 64-entry CQ. Why?

    Answer

    CQ fills; the controller stops posting until head advances; SQ processing stalls. Size CQ for the sum of outstanding commands or reduce sharing.

E. Senior thinking (2)

  1. Should a driver write the SQ doorbell for every command or batch? Discuss.

    Answer

    Batching reduces MMIO writes (each is an uncached posted write — costly in virtualised environments and at very high IOPS) but adds latency for the first command in a batch. Linux uses a “last request in plug/batch” hint to ring once. Shadow doorbells (Doorbell Buffer Config) reduce MMIO exits in VMs. The decision depends on latency targets and virtualisation.

  2. Design-review question: a firmware engineer proposes allowing the controller to post CQEs out of order across SQs sharing a CQ. Is that a problem?

    Answer

    Completion order is not guaranteed in NVMe — commands may complete in any order, and hosts must match by SQID/CID. So it is permitted; review should instead focus on fairness and starvation, and on whether any host software wrongly assumes ordering (bug-for-bug compatibility risk).

🧪 F. Lab — Inspect queue registers SAFE

Objective: read CAP, compute doorbell stride, and relate queue count to the driver’s configuration.

Steps:

sudo nvme show-regs /dev/nvme0 -H | head -40      # decode CAP, CC, CSTS, AQA
sudo nvme get-feature /dev/nvme0 -f 0x07 -H        # Number of Queues
ls /sys/block/nvme0n1/mq/ | wc -l                  # blk-mq hardware queues
grep nvme /proc/interrupts | head

Questions: Does the number of mq directories match the number of I/O queues granted? Which CPUs map to which vectors?

Solution

Usually the driver creates up to min(CPUs, granted queues) default queues, plus optional read/poll queues if configured — counts may differ by kernel version version. Each I/O queue’s vector appears in /proc/interrupts; affinity lists show CPU mapping. CAP.DSTRD is commonly 0 on physical devices impl.

Extension: repeat inside a VM with an emulated NVMe controller and compare CAP and queue counts.

10 quick questions

  1. Direction of the SQE fetch MRd?

    Answer

    Upstream: device → host.

  2. Is an MSI-X message posted or non-posted?

    Answer

    Posted (it is a Memory Write).

  3. What TLP returns SQE bytes to the device?

    Answer

    Completion with Data (CplD).

  4. Size of one MSI-X table entry?

    Answer

    16 bytes.

  5. Which field links a CQ to an MSI-X vector?

    Answer

    IV (Interrupt Vector) in Create I/O CQ CDW11, with IEN set.

  6. For a Write, who issues MRds for data?

    Answer

    The device (controller) as requester.

  7. What signals a new CQE to a polling host?

    Answer

    The phase tag matching the expected phase.

  8. Which register bit masks all MSI-X vectors of a function?

    Answer

    Function Mask in MSI-X Message Control.

  9. What happens to an interrupt while its vector is masked?

    Answer

    Its PBA pending bit is set; the message is sent when unmasked.

  10. Which NVMe feature configures interrupt coalescing?

    Answer

    Feature 08h (Interrupt Coalescing); per-vector disable via Feature 09h.

5 application questions

  1. Count TLPs (both directions, excluding DLLPs) for a 16 KiB page-aligned read using a PRP list, MPS 256, one interrupt, one CQ doorbell.

    Answer

    Doorbell MWr 1; SQE MRd 1 + CplD ≥1; PRP list MRd 1 (3 entries, 24 B) + CplD 1; data MWr 16384/256 = 64; CQE MWr 1; MSI-X MWr 1; CQ head doorbell MWr 1. Total ≈ 71 (assuming single CplDs).

  2. Same for a 16 KiB write with MRRS 512.

    Answer

    Doorbell 1; SQE MRd+CplD 2; list MRd+CplD 2; data MRd 32 + CplD ≥ 64 (256-B max each); CQE 1; MSI-X 1; CQ doorbell 1. ≈ 104.

  3. Estimate link time for 64 data MWrs of 256 B at Gen4 x4 (≈ 7.88 GB/s raw, ~24 B overhead per TLP).

    Answer

    64 × 280 B ≈ 17.9 KB → ≈ 2.3 µs derived.

  4. The host processes 6 CQEs per interrupt on average at 600 K IOPS. Interrupt rate?

    Answer

    100 K interrupts/s.

  5. If coalescing time is 100 µs and QD is 1, worst added latency?

    Answer

    Up to ~100 µs per I/O if the threshold is never reached — coalescing hurts QD1.

3 trace questions

  1. MWr to FEE0_xxxx appears before the CQE MWr. Is that possible? Is it a bug?

    Answer

    It is a device bug if it happens for the same completion: the interrupt must follow the CQE so the host finds it. Ordering of posted writes ensures that if the device sends the CQE first, it arrives first. Check that both are for the same vector/queue.

  2. A CQE MWr with 4 DW payload goes to address ending in …08. Abnormal?

    Answer

    Yes — CQEs are 16-byte aligned slots; an address ending in 8 suggests a wrong base or entry size (e.g. device thinks CQE size differs from CC.IOCQES).

  3. Two MSI-X MWrs with identical address/data 2 µs apart, but only one CQE. Explanation?

    Answer

    Possibly the second is for another CQ sharing the same vector, a spurious interrupt, or a CQE that the analyzer filter hid. Check vector sharing and filters before calling it a bug.

1 design question

  1. Design an interrupt strategy for a storage server with 64 CPUs and 16 NVMe drives, targeting low p99 at moderate load and high throughput at peak.

    Answer

    Per-CPU queues per drive limited by MSI-X vectors (e.g. 16–32 per drive), managed affinity aligned with NUMA locality of each drive’s root port, adaptive coalescing (low threshold at low load), optional polling queues for latency-critical tenants, monitor interrupt rate and p99; justify trade-offs.
