33B Projects 7–12: From DMA to a Debugging Assistant

33B.1 Why this chapter exists

Projects 1–6 (Chapter 33A) built isolated models. Projects 7–12 connect them: data movement through PRPs, correlation of NVMe commands with the TLPs that implement them, ingestion of real exports, automated summarisation, rule-based classification, and finally a debugging assistant that may use a large language model (LLM) but never lets it invent evidence.

  • Simulate PRP construction and the DMA TLPs it implies.
  • Correlate NVMe commands with PCIe transactions by address and identifiers.
  • Ingest analyzer exports with provenance and without silent data loss.
  • Build a summarizer, a classifier with falsifiers, and a guarded assistant pipeline.

Prerequisites: Projects 1–6; PRP, MPS, MRRS, DMA, MSI-X.

🧒 Kid analogy — the parcel-tracking room

A parcel company has a room where every scanner beep from every truck arrives. One worker turns beeps into neat lines (ingestion), another matches "picked up" with "delivered" for each tracking number (correlation), another spots parcels that were picked up but never delivered (anomaly detection), and the manager asks: what went wrong first, and why? Nobody is allowed to make up a beep that did not happen.

🧩 Where the analogy breaks

Parcels have globally unique tracking numbers. PCIe tags are reused constantly and are unique only among outstanding requests from one requester; NVMe CIDs are unique only among outstanding commands in one SQ. Correlation needs time windows and composite keys, not a single number.

33B.2 Project 7 — Simulate DMA (PRP construction and data TLPs)

Requirements: given a host buffer address, a length and CC.MPS, produce PRP1/PRP2/PRP list according to the PRP rules (first entry may have an offset; later entries page-aligned; PRP2 is the second page or a list pointer), then enumerate the data TLPs a controller could emit without crossing page boundaries or exceeding Max_Payload_Size. Architecture: page arithmetic → PRP builder → TLP chunker (bounded by MPS for writes to host; by MRRS for device reads of host memory in the write-command direction). Milestones: M1 one/two-page cases; M2 PRP list; M3 chained PRP lists when the list exceeds one page; M4 write direction (MRd ≤ MRRS, CplD ≤ MPS, completions split on Read Completion Boundary); M5 SGL equivalent. Expected output:

#!/usr/bin/env python3
"""Project 7 starter - build PRP1/PRP2/PRP list for a host buffer and simulate the DMA
(simulation, stdlib only). Memory page size = 2^(12+CC.MPS). Rules modeled:
 - PRP1 may carry an offset into its page; every later entry is page-aligned.
 - Transfer fits in PRP1's page            -> PRP2 unused.
 - Transfer spans exactly two pages        -> PRP2 = second page address.
 - Transfer spans more than two pages      -> PRP2 = address of a PRP list.
 (Chained lists when one list page is exhausted are left as an extension.)"""
def build_prps(buf_addr, length, mps=0):
    page = 1 << (12 + mps)
    first_chunk = page - (buf_addr % page)
    pages = [buf_addr]
    remaining = length - first_chunk
    nxt = buf_addr - (buf_addr % page) + page
    while remaining > 0:
        pages.append(nxt); nxt += page; remaining -= page
    if len(pages) == 1:
        return {"PRP1": pages[0], "PRP2": 0, "list": []}
    if len(pages) == 2:
        return {"PRP1": pages[0], "PRP2": pages[1], "list": []}
    return {"PRP1": pages[0], "PRP2": "-> PRP list", "list": pages[1:]}

def dma_tlps(prps, length, mps=0, max_payload=256):
    """Yield (addr, bytes) MWr chunks a controller might emit for a READ command.
    Chunks never cross a memory page or exceed Max_Payload_Size. Real controllers may
    split further; the exact TLP pattern is implementation-dependent."""
    page = 1 << (12 + mps)
    addrs = [prps["PRP1"]] + (prps["list"] or ([prps["PRP2"]] if prps["PRP2"] else []))
    left = length
    for a in addrs:
        in_page = min(page - (a % page), left)
        off = 0
        while off < in_page:
            n = min(max_payload, in_page - off, 4096 - ((a + off) % 4096))
            yield (a + off, n); off += n
        left -= in_page

if __name__ == "__main__":
    for addr, ln in ((0x2A400000, 4096), (0x2A400200, 4096), (0x2A400000, 16384)):
        p = build_prps(addr, ln)
        shown = {k: (hex(v) if isinstance(v, int) else v) for k, v in p.items() if k != "list"}
        print(f"buf={addr:#x} len={ln}: {shown} list={[hex(x) for x in p['list']]}")
    tl = list(dma_tlps(build_prps(0x2A400200, 4096), 4096))
    print(f"4 KiB read into offset 0x200 buffer: {len(tl)} MWr TLPs at MPS=256 B; "
          f"first={tl[0][0]:#x}/{tl[0][1]} last={tl[-1][0]:#x}/{tl[-1][1]}")
buf=0x2a400000 len=4096: {'PRP1': '0x2a400000', 'PRP2': '0x0'} list=[]
buf=0x2a400200 len=4096: {'PRP1': '0x2a400200', 'PRP2': '0x2a401000'} list=[]
buf=0x2a400000 len=16384: {'PRP1': '0x2a400000', 'PRP2': '-> PRP list'} list=['0x2a401000', '0x2a402000', '0x2a403000']
4 KiB read into offset 0x200 buffer: 16 MWr TLPs at MPS=256 B; first=0x2a400200/256 last=0x2a401100/256

Tests / acceptance: a 4 KiB buffer at a page-aligned address needs PRP1 only; the same length at offset 200h needs PRP2 (two pages); 16 KiB aligned needs a list with three entries; no generated TLP crosses a 4 KiB boundary (a PCIe rule for memory requests verified) or exceeds MPS. Failure cases: offsets in PRP list entries (they must be page-aligned — check the exact rule and the dword-alignment requirement of PRP1 in your revision); forgetting that MPS (PCIe) and CC.MPS (NVMe page size) are different things; assuming the chunking shown is what a real controller does (it is one legal pattern; the actual split is impl). Extensions: chained lists; MRRS-bounded reads; compute link efficiency from header overhead vs payload.

33B.3 Project 8 — Correlate NVMe command → PCIe TLP

Requirements: given parsed SQEs (Project 4), queue base addresses, BAR0 and the MSI-X address, assign every TLP a role: doorbell, SQE fetch (with slot), data for CID x, CQE for CID x, interrupt, or UNCORRELATED. Compute per-command latency doorbell → CQE. Architecture: address-range index (BAR0 doorbell window, SQ rings, CQ rings, PRP pages per CID, MSI-X address) → role assignment → per-CID timeline. Milestones: M1 role assignment; M2 per-CID timeline; M3 use CQE payload (CID + SQID) to confirm the association; M4 handle several commands in flight sharing pages over time (time-windowed address ownership). Expected output:

#!/usr/bin/env python3
"""Project 8 starter - correlate NVMe commands with PCIe TLPs (simulation, stdlib only).
Correlation keys (all DERIVED from protocol rules, not from any analyzer feature):
  doorbell MWr  -> address decodes to SQ y tail; data = new tail
  SQE fetch MRd -> address inside SQ y ring at slot = old tail .. new tail-1
  data MWr/MRd  -> address inside a PRP page of that command
  CQE MWr       -> address inside CQ ring; payload CID + SQID identify the command
  MSI-X MWr     -> vector mapped to the CQ"""
BAR0, SQ1, CQ1, MSIX = 0xFEB00000, 0x1F000000, 0x1F100000, 0xFEE00000
CMDS = {0x12: {"op": "Read", "prp": [0x2A400000]}}       # CID -> parsed SQE (from Project 4)
TLPS = [  # SYNTHETIC normalized events: (t_ns, type, addr, info)
    (1000, "MWr", BAR0 + 0x1008, {"data": 1}),
    (1450, "MRd", SQ1 + 0 * 64, {"len_dw": 16}),
    (9800, "MWr", 0x2A400000, {"len_dw": 64}),
    (9900, "MWr", 0x2A400100, {"len_dw": 64}),
    (12000, "MWr", CQ1 + 0 * 16, {"cid": 0x12, "sqid": 1, "status": 0}),
    (12050, "MWr", MSIX, {"vector": 1}),
]

def role(t, addr, info):
    if t == "MWr" and BAR0 + 0x1000 <= addr < BAR0 + 0x2000:
        return "doorbell"
    if t == "MRd" and SQ1 <= addr < SQ1 + 64 * 64:
        return f"SQE fetch slot {(addr - SQ1) // 64}"
    if t == "MWr" and CQ1 <= addr < CQ1 + 16 * 64:
        return f"CQE for CID {info['cid']:#x}"
    if t == "MWr" and addr == MSIX:
        return "MSI-X interrupt"
    for cid, c in CMDS.items():
        for p in c["prp"]:
            if p <= addr < p + 4096:
                return f"data for CID {cid:#x} ({c['op']})"
    return "UNCORRELATED"

if __name__ == "__main__":
    t0 = TLPS[0][0]
    for t, typ, addr, info in TLPS:
        print(f"+{t - t0:>6} ns {typ:<4} {addr:#010x} -> {role(typ, addr, info)}")
    print(f"command latency doorbell->CQE: {TLPS[4][0] - t0} ns (synthetic)")
+     0 ns MWr  0xfeb01008 -> doorbell
+   450 ns MRd  0x1f000000 -> SQE fetch slot 0
+  8800 ns MWr  0x2a400000 -> data for CID 0x12 (Read)
+  8900 ns MWr  0x2a400100 -> data for CID 0x12 (Read)
+ 11000 ns MWr  0x1f100000 -> CQE for CID 0x12
+ 11050 ns MWr  0xfee00000 -> MSI-X interrupt
command latency doorbell->CQE: 11000 ns (synthetic)

Tests / acceptance: every TLP gets exactly one role; doorbell offsets decode to the right queue (reuse Project 6); a data TLP outside all PRP pages is UNCORRELATED and flagged (a candidate DMA-address bug). Failure cases: buffer reuse — the same physical page belongs to different commands at different times, so correlation must be time-windowed; IOMMU: device-visible addresses are I/O virtual addresses, not CPU physical addresses (correlate with what the device sees); SQE fetch MRds may cover several entries at once impl. Extensions: read SQ ring contents from the CplD payloads of the fetches so the correlator learns CIDs and PRPs from the trace itself (no host-side information needed).

💡 Senior insight

The most powerful correlation trick is to decode the SQE from the fetch completion's payload. The trace then tells you the command, CID, NSID, PRPs and LBAs — and every later data TLP can be attributed by address. That is exactly what protocol analyzers with NVMe decoding do conceptually; doing it yourself shows you where their attribution can go wrong.

33B.4 Project 9 — Analyze a real trace

Requirements: ingest an analyzer export (CSV/text) into the normalized event model of Chapter 34, with a per-tool column mapping, provenance (source row) on every event, rejection of unparsable rows with counts, and capture-quality checks (time monotonicity, span, gaps, truncation). Architecture: column map (config) → row parser → validator → event list + rejects + metadata. Milestones: M1 mapping and parse; M2 rejects with reasons; M3 quality report; M4 hash and record provenance (tool, version, capture settings); M5 handle multi-link captures. Expected output on a synthetic export containing one garbled row and one out-of-order timestamp:

#!/usr/bin/env python3
"""Project 9 starter - ingest an analyzer CSV export into the normalized event model
(executable, stdlib only). Analyzer export formats differ by vendor and version, so
the column mapping is a CONFIG you write after inspecting YOUR export header - never
assume it. Rows that do not parse are kept and counted, never silently dropped."""
import csv, io, json

COLUMN_MAP = {            # your export's header -> normalized field  (edit per tool)
    "Time(ns)": "t_ns", "Dir": "dir", "Packet": "type", "ReqID": "req_id",
    "Tag": "tag", "Address": "addr", "Length": "len_dw", "Status": "status",
}
REQUIRED = {"t_ns", "type"}

def ingest(text):
    reader = csv.DictReader(io.StringIO(text))
    missing = [c for c in COLUMN_MAP if c not in reader.fieldnames]
    if missing:
        raise SystemExit(f"export lacks columns {missing}: fix COLUMN_MAP, do not guess")
    events, rejects = [], []
    for n, row in enumerate(reader, start=1):
        ev = {COLUMN_MAP[k]: (v.strip() if v else None) for k, v in row.items() if k in COLUMN_MAP}
        ev["src_row"] = n                       # provenance: every event points back to the raw row
        try:
            ev["t_ns"] = int(ev["t_ns"])
            ev["tag"] = int(ev["tag"]) if ev.get("tag") else None
            ev["len_dw"] = int(ev["len_dw"]) if ev.get("len_dw") else 0
            if not all(ev.get(k) is not None for k in REQUIRED):
                raise ValueError("required field empty")
            events.append(ev)
        except (ValueError, TypeError) as e:
            rejects.append({"src_row": n, "reason": str(e), "raw": row})
    ts = [e["t_ns"] for e in events]
    monotonic = all(a <= b for a, b in zip(ts, ts[1:]))
    return events, rejects, {"events": len(events), "rejects": len(rejects), "monotonic_time": monotonic,
                             "span_ns": (max(ts) - min(ts)) if ts else 0}

if __name__ == "__main__":
    SAMPLE = ("Time(ns),Dir,Packet,ReqID,Tag,Address,Length,Status\n"
              "100,US,MRd,03:00.0,5,0x1F000000,16,\n"
              "550,DS,CplD,03:00.0,5,,16,SC\n"
              "garbled,DS,CplD,03:00.0,6,,16,SC\n"
              "540,US,MWr,03:00.0,,0xFEE00000,1,\n")
    ev, rej, meta = ingest(SAMPLE)
    print(json.dumps(meta)); print("first event:", json.dumps(ev[0])); print("reject:", rej[0]["reason"])
{"events": 3, "rejects": 1, "monotonic_time": false, "span_ns": 450}
first event: {"t_ns": 100, "dir": "US", "type": "MRd", "req_id": "03:00.0", "tag": 5, "addr": "0x1F000000", "len_dw": 16, "status": null, "src_row": 1}
reject: invalid literal for int() with base 10: 'garbled'

Tests / acceptance: missing columns abort with a clear message (never guess a mapping); every event has src_row; rejects are counted and reported; non-monotonic time is reported. Failure cases: silently dropping rows (destroys the evidence chain); assuming two exports from different tool versions have the same columns; mixing timestamps from different clock domains. Extensions: a mapping per analyzer family; automatic detection of capture truncation (buffer full) from metadata.

⚠️ Real traces and confidentiality

Real captures may contain customer data (payloads) and proprietary details. Strip payloads you do not need, follow your organisation's data-handling rules, and never paste confidential captures into external services. Analyzer software display formats are vendor-specific; this book never imitates them and only works with exported data you own.

33B.6 Project 11 — Build a failure classifier

Requirements: given a set of evidence flags (produced by the summarizer and by log parsers), rank candidate root causes by how much of their required evidence is present, eliminate candidates contradicted by evidence, and print for each candidate the missing evidence and a falsification test. Architecture: rule table (id, layer, needs, against, hypothesis, falsifier) → matcher → ranked list + eliminated list. Milestones: M1 rule table; M2 elimination; M3 confidence labels; M4 "next evidence to collect" recommendations; M5 rules loaded from a reviewed data file with an owner per rule. Expected output for evidence {doorbell seen, CQE posted, no MSI-X, host timeout}:

#!/usr/bin/env python3
"""Project 11 starter - rule-based failure classifier over normalized evidence
(executable, stdlib only). Each rule names the evidence it needs, the layer it points to,
and what would FALSIFY it. Output is ranked hypotheses, never a single 'answer'."""
RULES = [
    {"id": "R1", "layer": "PCIe link", "needs": {"aer_correctable_burst", "ltssm_recovery"}, "against": set(),
     "hyp": "signal-integrity / link instability", "falsify": "same failure with zero Recovery entries and clean AER"},
    {"id": "R2", "layer": "PCIe transaction", "needs": {"cpl_status_ur"}, "against": set(),
     "hyp": "request to unmapped/invalid address (IOMMU/BAR/PRP)", "falsify": "UR address lies inside a valid, mapped PRP page"},
    {"id": "R3", "layer": "PCIe transaction", "needs": {"unpaired_mrd"},
     "against": {"cpl_for_tag"}, "hyp": "completion timeout path (completer never answered)", "falsify": "completion found later in an untruncated capture"},
    {"id": "R4", "layer": "NVMe queue", "needs": {"doorbell_seen", "no_sqe_fetch"}, "against": {"cqe_posted"},
     "hyp": "controller not fetching (CSTS.CFS, disabled, wrong doorbell offset)", "falsify": "SQE fetch MRd present for that slot"},
    {"id": "R5", "layer": "NVMe completion", "needs": {"cqe_posted", "no_msix"}, "against": {"msix_seen"},
     "hyp": "interrupt path (MSI-X masked/misprogrammed, coalescing)", "falsify": "MSI-X MWr present after CQE"},
    {"id": "R6", "layer": "host software", "needs": {"cqe_posted", "host_timeout"}, "against": {"host_consumed_cqe"},
     "hyp": "host missed completion (phase-tag/CQ-head bug)", "falsify": "host log shows CQE consumed before timeout"},
]

def classify(evidence):
    out, eliminated = [], []
    for r in RULES:
        if r["against"] & evidence:
            eliminated.append((r["id"], r["hyp"], sorted(r["against"] & evidence)))
            continue
        hit = r["needs"] & evidence
        score = len(hit) / len(r["needs"])
        if score:
            conf = "HIGH" if score == 1 and len(r["needs"]) > 1 else "MEDIUM" if score == 1 else "LOW"
            out.append((score, r["id"], conf, r["layer"], r["hyp"], sorted(r["needs"] - evidence), r["falsify"]))
    return sorted(out, key=lambda x: -x[0]), eliminated

if __name__ == "__main__":
    ev = {"doorbell_seen", "cqe_posted", "no_msix", "host_timeout"}
    ranked, eliminated = classify(ev)
    for s, rid, conf, layer, hyp, missing, fals in ranked:
        print(f"{rid} {conf:<6} [{layer}] {hyp}\n      missing evidence: {missing or 'none'}; falsify by: {fals}")
    for rid, hyp, why in eliminated:
        print(f"{rid} ELIMINATED  {hyp}  (contradicted by {why})")
R5 HIGH   [NVMe completion] interrupt path (MSI-X masked/misprogrammed, coalescing)
      missing evidence: none; falsify by: MSI-X MWr present after CQE
R6 HIGH   [host software] host missed completion (phase-tag/CQ-head bug)
      missing evidence: none; falsify by: host log shows CQE consumed before timeout

The output is deliberately ambiguous: two hypotheses (interrupt path vs host reaping) are equally supported. That is correct — the evidence given cannot separate them. The falsifiers tell you the disambiguating experiment: look for the MSI-X MWr after the CQE on the analyzer, or for evidence the host consumed the CQE. A classifier that confidently chose one would be lying. Tests / acceptance: contradicted rules are eliminated with the contradicting evidence named; a rule with all evidence present and more than one item is HIGH; single-item matches are MEDIUM. Failure cases: rules without falsifiers; scoring presented as probability; a rule base nobody reviews. Extensions: weight evidence by reliability (analyzer > driver log > user report); feed back confirmed root causes to tune rules.

📘 Confidence is not probability

The HIGH/MEDIUM/LOW labels here are ordinal judgements about evidence coverage, not calculated probabilities. Calling them probabilities requires a statistical model and data — see the confidence model in Chapter 35.

🧪 Lab 33B.1 — Mutation testing your pipeline SAFE

Objective: measure whether your summarizer detects what it should. Procedure: write a script that takes the clean part of the sample trace (seq 1–14), applies one mutation at a time (delete a completion; flip a status to UR/CA; duplicate a tag; delay a completion by 5 µs; truncate the capture), runs the summarizer and checks the expected anomaly appears and nothing else. Questions: which mutation produced an unexpected extra anomaly, and is that a bug or a correct consequence?

Solution / expected reasoning

Deleting the only completion of a request yields UNPAIRED_REQ; if the deleted completion was one half of a split pair, the request stays unpaired (correct). Duplicating a tag yields both TAG_REUSE and an UNPAIRED_REQ for the superseded request — a correct consequence, documented as such. Delay yields SLOW_CPL only if it crosses the threshold. Truncation yields UNPAIRED_REQ at the end of capture, which a mature tool marks as "possibly truncated" rather than failure.

Quiz

  1. Why must correlation of data TLPs be time-windowed?

    Answer

    Host buffers are reused: the same page belongs to different commands at different times.

  2. What is the minimal key for pairing a completion to a request?

    Answer

    Requester ID and Tag (plus a time window, because tags are reused after completion).

  3. Why does the classifier output two equally ranked hypotheses for the sample evidence?

    Answer

    The evidence supports both equally; only a new observation (MSI-X MWr presence, host consumption) can separate them.

Interview questions

  1. Advanced How would you attribute data TLPs to NVMe commands using only the trace?
    Model answer

    Decode SQEs from the CplD payloads of the SQE fetch reads, build PRP page sets per CID (fetching PRP lists from their CplDs as well), then attribute data TLPs by address within a time window from fetch to CQE.

  2. Senior Where would you allow an LLM in a debugging pipeline, and where not?
    Model answer

Automated Trace Analysis

Captures from a fast link hold millions of packets. Humans find root causes in them by knowing where to look; machines can help by doing the bookkeeping — pairing, correlating, timing, flagging — deterministically and reproducibly. This Part designs that machine: a pipeline from raw input to an HTML report, with explicit schemas, correlation identifiers, timestamps, state machines and a rule engine, and with an optional reasoning layer that sits on top of, never in place of, deterministic decoding.

34 Automated Forensic Trace Analysis

📘 Baseline

Packet formats and pairing rules come from the PCIe Base Specification (requests, completions, tags, completion status) and the NVMe Base/NVM Command Set/PCIe transport specifications (SQE/CQE, doorbells). Analyzer export formats, timestamp methods and decode naming are impl — vendor- and version-specific. Every trace in this chapter is synthetic.

34.1 Why this chapter exists

A manual trace review scales to hundreds of packets; real failures hide among millions. Automation does not replace understanding — it amplifies it, by applying the same rules you would apply, everywhere, without fatigue, and by making every conclusion reproducible from the raw input. Its danger is false confidence: a tool that silently drops rows, mis-keys correlations or invents structure produces convincing wrong answers. This chapter designs automation that is honest about what it saw.

  • Beginner: describe each stage of the analysis pipeline and its input/output.
  • Intermediate: define the event model and JSON schemas; choose correlation keys for TLPs and NVMe commands.
  • Advanced: implement pairing, anomaly detection and first-abnormal-event identification; handle split completions, tag reuse and truncation.
  • Senior: design the rule engine and specification-knowledge layer so that every hypothesis carries evidence, a layer and a falsifier.
  • Trace-analysis: run the summarizer on a synthetic trace and interpret every line.
  • Debugging: diagnose the analyzer itself (false positives, missed anomalies) with mutation tests.
  • Validation: use golden traces and trace diffs as regression gates.

Prerequisites: Projects 3–6 and 7–11; TLP, Cpl, CplD, UR, CA.

🧒 Kid analogy — the referee's video room

In a big football match, cameras record everything. In the video room, a computer lines up all the camera clocks, labels every player, and marks moments like "ball crossed the line" automatically. The referee then watches only the marked moments and decides. The computer never draws a ball where there was none — it only points to frames.

🧩 Where the analogy breaks

Video shows the whole field; a PCIe capture shows one link. Anything that happened inside the device, inside the host, or on another link is invisible. The tool must state its capture scope, and absence of evidence on this link is not evidence of absence elsewhere.

34.5 Correlation IDs, timestamps and state machines

Correlation IDs. Non-posted PCIe requests: key (Requester ID, Tag), valid from request until the final completion (Byte Count reaching the remaining amount), then reusable. NVMe commands: key (SQID, CID), valid from submission until the CQE is consumed — CIDs are unique only among outstanding commands of one SQ, so the event model uses a synthetic cmd_uid that includes the fetch event id. Posted writes have no tag-based pairing: data MWrs are attributed by address range (PRP pages) within the command's time window; CQE MWrs by CQ ring address and their payload (CID, SQID); MSI-X MWrs by message address/data.

Timestamps. Use one time base per capture (analyzer clock), record units explicitly, check monotonicity, and when merging host logs record the alignment method (e.g. a marker MMIO write at a known host time) and its uncertainty. Never compute sub-microsecond latencies across clock domains.

State machines. Per NVMe command: SUBMITTED (doorbell covering its slot) → FETCHED (SQE fetch CplD) → DATA (first data TLP) → COMPLETED (CQE MWr) → SIGNALLED (MSI-X, or skipped under coalescing/polling) → host consumes (CQ head doorbell). Impossible transitions — CQE before FETCHED, data after COMPLETED for the same cmd_uid, a doorbell tail that moves backward by other than a wrap — are anomalies. Per tag: FREE → OUTSTANDING → (PARTIAL)* → FREE; a new request on an OUTSTANDING key is TAG_REUSE. Per link: LTSSM states from the capture, with Recovery entries counted and correlated with replays.

34.7 Reference implementation: the trace summarizer

The following summarizer is the deterministic heart of Project 10. It reads a CSV of normalized TLP events (columns seq,t_ns,dir,type,req_id,tag,addr,len_dw,status), pairs memory-read requests to completions by (Requester ID, Tag) including split completions, and reports unpaired requests, unexpected completions, non-successful status, tag reuse, slow completions, latency statistics and the first abnormal event. It runs on an embedded synthetic sample or on a file you pass.

#!/usr/bin/env python3
"""trace_summarizer.py - deterministic summarizer for a SYNTHETIC PCIe TLP trace (CSV).

Input columns: seq,t_ns,dir,type,req_id,tag,addr,len_dw,status
  dir    : DS (downstream, Root Complex -> device) or US (upstream, device -> host)
  type   : MRd, MWr, CplD, Cpl
  req_id : Bus:Dev.Fn of the REQUESTER (completions carry the requester's ID)
  tag    : transaction tag (decimal)
  len_dw : payload / requested length in DW (0 for Cpl without data)
  status : SC, UR, CA (completions only; blank for requests)
Pairs non-posted requests to completions by (req_id, tag), handles split
completions, and reports unpaired requests, unexpected completions,
non-SC status, tag reuse, latency statistics and the FIRST abnormal event.
Standard library only. Usage: python3 trace_summarizer.py [trace.csv]
"""
import csv, io, sys, statistics

SAMPLE = """seq,t_ns,dir,type,req_id,tag,addr,len_dw,status
1,1000,DS,MWr,00:00.0,0,0xFEB01008,1,
2,1450,US,MRd,03:00.0,5,0x1F000000,16,
3,1900,DS,CplD,03:00.0,5,,16,SC
4,2100,US,MRd,03:00.0,6,0x2A400000,32,
5,2160,US,MRd,03:00.0,7,0x2A400080,32,
6,2700,DS,CplD,03:00.0,6,,16,SC
7,2780,DS,CplD,03:00.0,6,,16,SC
8,2950,DS,CplD,03:00.0,7,,32,SC
9,3300,US,MWr,03:00.0,0,0x1F100000,4,
10,3350,US,MWr,03:00.0,0,0xFEE00000,1,
11,5000,DS,MWr,00:00.0,0,0xFEB01008,1,
12,5400,US,MRd,03:00.0,8,0x1F000040,16,
13,5420,US,MRd,03:00.0,9,0x2A500000,32,
14,5900,DS,CplD,03:00.0,8,,16,SC
15,6100,DS,Cpl,03:00.0,9,,0,UR
16,6300,US,MRd,03:00.0,10,0x2A600000,32,
17,6350,US,MRd,03:00.0,10,0x2A600080,32,
18,7000,DS,CplD,03:00.0,11,,32,SC
"""

LATENCY_WARN_NS = 2000          # synthetic threshold for "slow" completions
NONPOSTED = {"MRd"}             # this simplified model only tracks memory reads
COMPLETIONS = {"CplD", "Cpl"}

def load(text):
    rows = list(csv.DictReader(io.StringIO(text)))
    for r in rows:
        r["seq"], r["t_ns"] = int(r["seq"]), int(r["t_ns"])
        r["tag"], r["len_dw"] = int(r["tag"]), int(r["len_dw"] or 0)
    return sorted(rows, key=lambda r: (r["t_ns"], r["seq"]))

def summarize(rows):
    outstanding = {}   # (req_id, tag) -> {"req": row, "remaining": dw}
    pairs, anomalies, counts = [], [], {}
    def flag(row, kind, detail):
        anomalies.append({"seq": row["seq"], "t_ns": row["t_ns"], "kind": kind, "detail": detail})
    for r in rows:
        counts[r["type"]] = counts.get(r["type"], 0) + 1
        key = (r["req_id"], r["tag"])
        if r["type"] in NONPOSTED:
            if key in outstanding:
                old = outstanding[key]["req"]
                flag(r, "TAG_REUSE", f"tag {r['tag']} reused while seq {old['seq']} still outstanding")
                flag(old, "UNPAIRED_REQ", f"{key} superseded by seq {r['seq']} before completing")
            outstanding[key] = {"req": r, "remaining": r["len_dw"]}
        elif r["type"] in COMPLETIONS:
            if key not in outstanding:
                flag(r, "UNEXPECTED_CPL", f"completion for {key} with no outstanding request")
                continue
            o = outstanding[key]
            if r["status"] != "SC":
                flag(r, "CPL_STATUS", f"{r['status']} for request seq {o['req']['seq']} addr {o['req']['addr']}")
                del outstanding[key]
                continue
            o["remaining"] -= r["len_dw"]
            if o["remaining"] <= 0:
                lat = r["t_ns"] - o["req"]["t_ns"]
                pairs.append({"req_seq": o["req"]["seq"], "cpl_seq": r["seq"], "latency_ns": lat})
                if lat > LATENCY_WARN_NS:
                    flag(r, "SLOW_CPL", f"latency {lat} ns > {LATENCY_WARN_NS} ns")
                del outstanding[key]
    end_t = rows[-1]["t_ns"] if rows else 0
    for key, o in outstanding.items():
        flag(o["req"], "UNPAIRED_REQ",
             f"{key} still waiting for {o['remaining']} DW at end of capture (t={end_t} ns)")
    anomalies.sort(key=lambda a: (a["t_ns"], a["seq"]))
    return pairs, anomalies, counts

def pct(sorted_vals, p):
    """nearest-rank percentile"""
    k = max(1, -(-p * len(sorted_vals) // 100))
    return sorted_vals[k - 1]

def report(rows, pairs, anomalies, counts):
    print(f"events: {len(rows)}  by type: {dict(sorted(counts.items()))}")
    print(f"completed pairs: {len(pairs)}")
    lats = sorted(p["latency_ns"] for p in pairs)
    if lats:
        print(f"latency ns: min={lats[0]} p50={pct(lats,50)} p99={pct(lats,99)} "
              f"max={lats[-1]} mean={statistics.mean(lats):.1f}")
    print(f"anomalies: {len(anomalies)}")
    for a in anomalies:
        print(f"  seq {a['seq']:>3} t={a['t_ns']:>5} {a['kind']:<15} {a['detail']}")
    if anomalies:
        f = anomalies[0]
        print(f"FIRST ABNORMAL EVENT: seq {f['seq']} at t={f['t_ns']} ns -> {f['kind']}")
    else:
        print("FIRST ABNORMAL EVENT: none detected by these rules")

if __name__ == "__main__":
    text = open(sys.argv[1]).read() if len(sys.argv) > 1 else SAMPLE
    rows = load(text)
    report(rows, *summarize(rows))

Interpretation, evidence-first. Evidence A (seq 13 → 15): the device read host address 2A500000 and the Root Complex returned UR. That supports "the address was not valid for this device at that time" — an IOMMU mapping not present, a buffer freed early, or a corrupted PRP. Evidence B (seq 16/17): tag reuse while outstanding weakens the idea that the device is healthy after the UR — or indicates the capture missed a completion. Evidence C (seq 18): an unexpected completion for tag 11 is insufficient on its own; with a missing request it suggests capture loss or a tag error. Conclusion: the first abnormal event is seq 15; the most actionable hypothesis is an invalid DMA address for the command whose data lived at 2A500000 (confidence MEDIUM until the host's IOMMU fault log or the SQE's PRP entries are checked). The events after 15 are likely consequences — but that is a hypothesis too.

💡 Design choices you must be able to defend
  • Unpaired requests are timestamped at issue time because that is where causality starts; a "detected at" time (issue + timeout) can be added. This choice affects which event is "first".
  • End-of-capture unpaired requests should be marked as possibly truncated when they were issued within one completion-timeout window of the capture end.
  • Split completions are summed until the requested length is satisfied; a production tool should use Byte Count and Lower Address rather than Length sums.
  • Only MRd is tracked as non-posted here; configuration and I/O requests, and atomic operations, are also non-posted and should be added.

34.10 Rule engine and specification knowledge

Rules are data, reviewed like code: each has an id, a condition over normalized events, the layer it implicates, a source note (which document and revision the expected behaviour comes from — taken from your field dictionary, not invented), an owner and test cases. The specification-knowledge store holds short passages or summaries you wrote while reading, each with an id, document and revision; rules and hypotheses refer to those ids. When a revision changes, the revision-diff method (Chapter 30B) tells you which rules to re-review.

34.11 Testing the analyzer

  • Golden traces: known-good captures per configuration; the pipeline must report zero anomalies (or a documented baseline).
  • Mutation testing: inject each anomaly type into golden traces; measure detection rate and collateral false positives (Lab 33B.1).
  • Known-cause corpus: past investigations with confirmed root causes; the hypothesis list must contain the true cause and must not be HIGH for a contradicted one.
  • Trace diffing: compare failing vs golden at the command-timeline level (not packet-by-packet); the first divergence is a candidate first abnormal event.
📭 What no specification says

No specification defines analyzer export formats, how analyzers group packets into "transactions", or how they timestamp. Your pipeline's correctness depends on those implementation details — document them per tool version.

🏭 Implementation-dependent

SQE fetch batching, data TLP sizes, completion splitting, interrupt coalescing and the gap between CQE and MSI-X vary by controller, firmware, platform and settings. Thresholds (e.g. "slow") must be calibrated per configuration from golden traces, not copied.

Quiz

    Answer

  4. What is a cmd_uid and why is it needed?

    Answer

    A unique id per command instance (e.g. sqid:cid:fetch_eid) because CIDs are reused after completion.

Interview questions

  1. Beginner What does a trace summarizer do?
    Model answer

    Pairs requests and completions, computes latencies, flags anomalies and reports the first abnormal event — deterministically.

  2. Intermediate How do you pair PCIe completions to requests?
    Model answer

    By (Requester ID, Tag) while the request is outstanding, accounting for split completions via Byte Count.

  3. Advanced How do you avoid false positives at the edges of a capture?
    Model answer

    Mark events within one timeout window of start/end as edge-of-capture; don't count missing partners there as failures.

  4. Senior How would you validate an automated analysis pipeline before trusting it on a customer escalation?
    Model answer

    Golden traces with zero anomalies, mutation tests with measured detection and false-positive rates, a known-cause corpus, determinism checks, and a human review of a sample of findings.
