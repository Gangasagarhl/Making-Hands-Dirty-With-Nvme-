PART XXVII

Failure Library

A troubleshooting encyclopedia of 30 failure patterns, organized from the wire upward: physical and data link (Chapter 81), transaction layer and AER (Chapter 82), NVMe (Chapter 83), and system-level interrupts, performance, power and reset (Chapter 84). Every entry uses the same card: symptoms · likely layers · trace signature · Linux evidence · NVMe evidence · PCIe evidence · first check · disambiguating experiment · likely root causes · remediation · regression test. Trace signatures are synthetic descriptions of what an analyzer would typically show; status-code names follow the NVMe Base Specification — confirm exact code points in the revision you work with.

81 Failure Library I: Physical and Data Link Layer

81.1 Why this chapter exists — and how to use the library

Under pressure you need pattern recognition plus discipline. The cards give you the pattern; the "first check" and "disambiguating experiment" rows enforce the discipline (Chapter 79). Use them as starting hypotheses, never as conclusions: every card's "likely root causes" are ranked by typical frequency in practice, which is impl-dependent and varies by platform.

  • Recognize each link-level failure from Linux, NVMe and PCIe evidence.
  • Name the first check and the experiment that separates the top two causes.
  • Propose remediation and a regression test.
🧒 Kid analogy — the doctor's symptom book

A doctor's book says "fever + rash + sore throat: maybe A, maybe B; first take temperature, then do test X to tell them apart". It does not say "it is A". This library is that book for SSD links and queues.

🧩 Where the analogy breaks

Patients rarely let you swap their organs; you can swap drives, slots, cables and firmware. Use swap experiments generously — they are the cheapest disambiguators in hardware debugging.

F1 — Link never reaches L0

SymptomsDevice absent from lspci; or present only after rescan; BIOS does not see the drive
Likely layersPhysical (power, reset, refclk, lanes), device firmware boot
Trace signatureReceiver detect repeatedly; TS1s without progressing to TS2/Configuration; or no electrical activity from the device at all; LTSSM cycling Detect ↔ Polling
Linux evidenceNothing for the device; port may log pciehp ... Link Down or nothing; lspci -vv on the root port: LnkSta shows training or Width x0 / DLActive- (if Data Link Layer Link Active reporting is supported)
NVMe evidenceNone (controller never reachable)
PCIe evidencePort Link Status; port AER (Surprise Down if it was up before)
First checkPower and seating; same drive in a known-good slot; another drive in this slot
Disambiguating experimentSwap test (fails with drive or with slot?); analyzer/scope: is PERST# deasserted, refclk present, does the device transmit TS1?
Likely root causesBad connector/riser/cable; missing refclk or wrong clocking mode (SRIS vs common); PERST# timing; device firmware not booting (dead drive); slot disabled/bifurcation misconfigured in BIOS
RemediationHardware repair/replacement; BIOS slot/bifurcation fix; clocking configuration; RMA drive
Regression test500 cold boots + 500 warm resets: device enumerates at expected speed/width every time

F2 — Intermittent link Recovery

SymptomsThroughput dips, latency blips, sometimes no visible symptom; occasionally escalates to link down
Likely layersPhysical (signal integrity, equalization, clocking), Data Link
Trace signatureL0 → Recovery (TS1/TS2) → L0, often preceded by bad LCRC TLPs, Naks, or receiver errors; possibly speed change attempts
Linux evidenceAER correctable RxErr/BadTLP/Replay Timer Timeout; rising aer_dev_correctable
NVMe evidenceUsually none (lossless recovery); latency tail
PCIe evidenceLink Status 2/equalization status bits (if exposed), Lane Error Status in Secondary PCIe extended cap
First checkCorrectable error rate vs time and temperature; which side reports (receiver side)
Disambiguating experimentForce lower speed (lab) — errors vanish? Swap slot/drive/cable; lane margining per lane if supported
Likely root causesMarginal channel (loss, crosstalk, connector), poor equalization presets, retimer issues, refclk jitter/SSC mismatch, power noise
RemediationChannel fix, retimer firmware/config, equalization tuning by platform vendor, clocking fix
Regression test24–72 h stress across temperature corners; Recovery count and correctable error rate below threshold

F3 — Width downgrade

SymptomsSequential throughput roughly halves (x4 → x2) or quarters; kernel "limited by ... x2 link" message
Likely layersPhysical lanes, slot wiring/bifurcation
Trace signatureDuring Configuration, lanes 2–3 fail detect or never send TS with matching link/lane numbers; link forms x2
Linux evidenceLnkSta Width x2 vs LnkCap x4; probe-time bandwidth message
NVMe evidenceNone
PCIe evidencePort and device LnkCap/LnkSta; Lane Error Status
First checkPort LnkCap width and platform slot documentation (is the slot physically x2?)
Disambiguating experimentSwap drive and slot; inspect connector; analyzer training capture to see which lanes fail
Likely root causesSlot wired x2 or bifurcated; damaged/dirty lanes; riser/cable fault; lane reversal unsupported in a particular routing
RemediationCorrect slot/BIOS setting; hardware repair
Regression testBoot-time check script comparing width to expected inventory; alert on mismatch

F4 — Speed downgrade

SymptomsThroughput ceiling at a lower generation's value; (downgraded) in lspci
Likely layersPhysical (equalization), policy (target speed), platform capability
Trace signatureSpeed change attempts via Recovery, equalization phases failing, fallback to lower rate; or no attempt at all (policy)
Linux evidenceLnkSta speed < min(port, device LnkCap); LnkCtl2 target speed
NVMe evidenceNone
PCIe evidenceLnkCtl2 target, Link Status 2 equalization-complete bits version
First checkPort LnkCap and LnkCtl2 target on both ends (policy or capability?)
Disambiguating experimentIf target speed is max: capture training to see equalization failure vs no attempt; swap slot/drive
Likely root causesPlatform limit (not a fault); BIOS speed cap; channel too lossy for the rate; retimer config; device EQ bug
RemediationBIOS setting, channel improvement, firmware updates
Regression testExpected-speed check after every boot/resume/reset in qualification

F5 — Receiver errors

SymptomsAER corrected RxErr messages; possibly no user-visible effect
Likely layersPhysical
Trace signatureAnalyzer symbol/framing errors on one direction; followed by Nak or Recovery
Linux evidence[ 0] RxErr, reporting device identifies the receiving side; aer_dev_correctable
NVMe evidenceNone
PCIe evidenceAER Correctable Status bit 0 (sticky until cleared)
First checkRate and direction (which device reports)
Disambiguating experimentSwap the transmitter side component; temperature sweep; lower speed
Likely root causesChannel margin, transmitter EQ, receiver CDR, interposer (if probing!)
RemediationAs F2; remove interposer and compare
Regression testError-rate threshold over a long soak

F6 — Bad DLLP

SymptomsCorrected BadDLLP errors; occasionally sluggish flow control
Likely layersData Link (CRC on DLLPs), Physical underneath
Trace signatureDLLPs (Ack/UpdateFC) with CRC errors; missing Acks lead to replay timer expiry
Linux evidenceAER correctable bit 7 BadDLLP
NVMe evidenceNone
PCIe evidenceAER status; analyzer DLLP view
First checkCo-occurrence with RxErr/BadTLP (common physical cause)
Disambiguating experimentSame as F2/F5
Likely root causesSignal integrity; rarely a DLLP generation bug
RemediationAs F2
Regression testAs F2

F7 — Replay: timeouts and REPLAY_NUM rollover

SymptomsCorrected Replay Timer Timeout / REPLAY_NUM Rollover; throughput dips; rollovers trigger Recovery
Likely layersData Link
Trace signatureTLPs transmitted, no Ack within replay timer, same sequence numbers retransmitted; after repeated replays, Recovery
Linux evidenceAER bits 12 (Timeout) / 8 (Rollover) reported by the transmitter
NVMe evidenceLatency tail
PCIe evidenceAER; analyzer shows missing/bad Acks in the opposite direction
First checkAre Acks lost (opposite-direction errors) or never sent (receiver problem)?
Disambiguating experimentCapture both directions: look for corrupted Acks vs absent Acks
Likely root causesReverse-direction signal integrity; receiver that cannot keep up / bug; misconfigured Ack latency timer impl
RemediationFix reverse channel; firmware fix
Regression testSoak with replay counters (if accessible) or AER rates

Quiz

  1. Replay Timer Timeout is reported by which side?

    Answer

    The transmitter of the unacknowledged TLPs.

  2. LnkSta x2 on an x4 device. First check?

    Answer

    The port's LnkCap and the platform's slot wiring/bifurcation.

82 Failure Library II: Transaction Layer and AER

Transaction-layer failures change what software sees: data that never arrives, requests that are refused, payloads marked bad. Unlike most link errors they are uncorrectable and propagate up as NVMe errors, timeouts or containment events.

  • Decode the logged TLP header of each uncorrectable error.
  • Identify requester vs completer responsibility.
  • Choose between configuration, routing, IOMMU and device bugs.

F8 — Malformed TLP

SymptomsUncorrectable (often fatal by default severity) error; link reset or DPC containment; device disappears
Likely layersTransaction (transmitter bug or configuration mismatch)
Trace signatureTLP whose fields violate rules: payload > MPS, Length vs actual payload mismatch, 4DW header with zero upper address, crossing a 4 KiB boundary in a memory request, invalid byte enables
Linux evidenceAER Uncorrected MalfTLP, logged TLP header (decode with Lab 2), DPC/link reset messages
NVMe evidenceSubsequent timeouts/reset
PCIe evidenceReceiver's AER Header Log; DevCtl MPS on both ends
First checkDecode the header log; compare payload size with MPS programmed at the receiver
Disambiguating experimentRead MPS on every device in the path at failure time; reproduce with MPS forced to the path minimum (lab)
Likely root causesMPS mismatch after hot-plug or reconfiguration; transmitter bug splitting at wrong boundary; switch bug
RemediationConsistent MPS policy; firmware fix
Regression testHot-plug and MPS-variation matrix with large transfers; zero MalfTLP

F9 — Completion timeout

SymptomsAER CmpltTO; NVMe command timeouts ~io_timeout later; data transfer errors
Likely layersTransaction (completer, routing, switch), sometimes IOMMU/root complex, sometimes Data Link (lost completions after link issues)
Trace signatureNon-Posted request (MRd) with no CplD for its (Requester ID, Tag) within the timeout range; possibly a late CplD flagged as Unexpected Completion
Linux evidence[14] CmpltTO from the requester (the SSD for DMA reads; the root port for MMIO reads); TLP header may be logged
NVMe evidenceTimeouts, Data Transfer Error statuses
PCIe evidenceDevCtl2 timeout range; AER
First checkWho is the requester? Decode the address: SQ, PRP list, data buffer, or an MMIO register?
Disambiguating experimentTwo-probe capture (TL-7) to localize where the completion is lost; IOMMU fault logs; check whether the completer was in a low-power or reset state
Likely root causesCompletion dropped in a switch/RC; completer hung; completion timeout value too short for the platform; device in D3/reset while host accessed MMIO
RemediationFirmware fix in the component that loses it; adjust timeout range (with care); fix power-management ordering
Regression testMixed-load soak with completion-timeout counters; Lab 9 detector over captures

F10 — Unsupported Request (UR)

SymptomsDMA failures, IOMMU faults, NVMe Data Transfer Errors; or host MMIO reads returning all-ones
Likely layersTransaction (address decode), IOMMU, host driver
Trace signatureRequest answered by Cpl with status UR (Non-Posted), or a Posted write silently dropped with error logged at the completer
Linux evidenceAER UnsupReq; DMAR/AMD-Vi IOMMU fault lines
NVMe evidenceCQE status Data Transfer Error or similar impl
PCIe evidenceAER header log contains the offending address
First checkDecode address; is it a valid, mapped IOVA / BAR address?
Disambiguating experimentInstrument DMA map/unmap; run with IOMMU strict mode; compare with IOMMU passthrough (lab)
Likely root causesUse-after-unmap (TL-5), wrong IOVA, BAR not assigned / Memory Space disabled, device accessing after reset
RemediationDriver lifetime fixes; resource assignment fix
Regression testIOMMU-strict stress with fault injection on timeouts

F11 — Poisoned transaction

SymptomsAER PoisonedTLP; NVMe write fails or read data flagged; host memory error logs (machine check)
Likely layersHost memory subsystem or device internal memory errors, forwarded as poisoned data
Trace signatureTLP with EP=1 (CplD to the SSD for write data, or MWr from the SSD for read data)
Linux evidenceAER PoisonedTLP, EDAC/MCE memory errors
NVMe evidenceError status on the affected command; possibly controller internal error logs
PCIe evidenceEP bit in header log
First checkDirection: who generated the poisoned TLP?
Disambiguating experimentCorrelate with host memory errors (host origin) vs device internal error counters (device origin)
Likely root causesUncorrectable DRAM error on host; device internal SRAM/DRAM error
RemediationReplace faulty memory; device RMA
Regression testMemory test; device burn-in with data verification

F12 — AER storm / uncorrectable error with containment

SymptomsThousands of AER messages; system sluggish; device reset/containment (DPC); possible removal
Likely layersAny; storm usually physical (corrected) or a repeating transaction error
Trace signatureContinuous error condition plus ERR_COR/ERR_NONFATAL/ERR_FATAL messages upstream
Linux evidenceRate-limited AER lines; DPC containment events; error-recovery callbacks ("frozen state", reset)
NVMe evidenceTimeouts during recovery; controller re-initialization
PCIe evidenceAER counters, header logs, DPC status
First checkFirst error in the storm (earliest timestamp) and its type
Disambiguating experimentMask correctable reporting temporarily (lab) to see if the system stabilizes — confirms storm-induced load vs real fault effects
Likely root causesPhysical layer degradation; device stuck repeating an erroneous request; misconfigured severity
RemediationFix underlying cause; error-rate thresholds; platform firmware-first policy review
Regression testError injection (where the platform supports it) with recovery validation

Quiz

  1. Which field of an AER message most directly localizes a transaction-layer bug?

    Answer

    The logged TLP header (address, requester, tag, type).

  2. Completion timeout reported by the root port: what kind of access failed?

    Answer

    A host-initiated Non-Posted request — typically an MMIO read or config read to the device.
