6 PCIe Generations

6.1 Why this chapter exists

"Gen4 x4" is the most common phrase in NVMe product sheets, and the most commonly mis-computed. Engineers confuse GT/s with Gb/s, forget encoding overhead, forget that PCIe numbers are per direction, double-count by adding both directions, and, worst of all, confuse the PCIe generation of the link with the NVMe specification revision of the controller. This chapter makes the math explicit so you can derive every number yourself.

⚠️ Do not confuse

PCIe 4.0 (a PCI-SIG physical/link specification, 16 GT/s) and NVMe 1.4 / 2.0 / 2.4 (NVM Express command-set and controller specifications) are independent. A drive can implement NVMe 1.3 over a Gen4 link, or NVMe 2.x over a Gen3 link. lspci tells you the PCIe link; nvme id-ctrl (field VER) tells you the NVMe revision the controller claims.

6.2 Learning objectives

  • Explain GT/s, line encoding (8b/10b, 128b/130b, PAM4 + FLIT with FEC) and why the encoding changed.
  • Derive per-lane per-direction usable bandwidth for every generation, and scale to x4/x8/x16.
  • Estimate application-visible NVMe throughput after TLP and DLLP overhead.
  • Explain latency implications (serialization, FEC) and backward compatibility.
  • Validate a vendor bandwidth claim and spot marketing that sums both directions.

6.4 Analogy

🧒 Kid analogy

Each generation is a faster train on the same kind of track. But every train also carries some non-passenger cars: the engine and the guard's van (encoding and packet overhead). Early trains had 2 guard cars for every 8 passenger cars (8b/10b: 20% overhead). Later trains had 2 guard cars for every 128 passenger cars (128b/130b: ~1.5%). The newest trains pack passengers into fixed 256-seat carriages with a few seats reserved for repair crews (FLIT with FEC and CRC).

🧩 Where the analogy breaks

"Guard cars" lump together two distinct overheads: line encoding (applies to every bit, below the packet layer) and packet framing/headers (per TLP, depends on payload size). The second one is often bigger and depends on your workload, not the generation.

6.5 Beginner: GT/s is not GB/s

GT/s (gigatransfers per second) counts symbols on the wire per lane. For Gen1–Gen5 (NRZ, two voltage levels) one transfer = one bit, so 16 GT/s = 16 Gbit/s raw. For Gen6+ (PAM4, four voltage levels) one symbol carries 2 bits; 64 GT/s is achieved at 32 GBaud. Raw bits include encoding overhead; you must remove it, then divide by 8 to get bytes.

BWlane,dir = R × E ÷ 8
  • BWlane,dir — usable bytes per second per lane per direction, after line encoding only (before TLP/DLLP overhead)
  • R — data rate in GT/s (bits per second per lane for NRZ generations; for Gen6+ the GT/s figure is already the bit rate)
  • E — encoding efficiency: 8/10 = 0.8 (8b/10b), 128/130 ≈ 0.984615 (128b/130b), ≈ 1.0 at the encoding level for Gen6 1b/1b FLIT mode (overhead moves into the FLIT's CRC/FEC bytes, see below)
  • ÷ 8 — bits to bytes

📘 Gen6 FLIT arithmetic, stated carefully

In PCIe 6.0 FLIT mode, a 256-byte FLIT carries 236 bytes of TLP content, 6 bytes of Data Link Layer payload (DLP, which carries the information DLLPs carried previously), 8 bytes of CRC, and 6 bytes of FEC verified. Whether you count DLP bytes as "useful" changes the efficiency between 236/256 = 92.2% and 242/256 = 94.5%; both numbers appear in public material derived. Crucially, FLIT mode also removes per-TLP framing tokens and per-TLP LCRC and uses a different TLP header format, so per-TLP overhead in FLIT mode is lower than in Gen5. Comparing Gen5 vs Gen6 efficiency requires including both effects. FLIT mode is also used at lower rates when both sides negotiate it in 6.0+ version.

6.7 Why the encoding changed

8b/10b (Gen1, Gen2)

Each 8-bit byte becomes a 10-bit symbol chosen from a table to guarantee transitions (for CDR) and DC balance (running disparity). Special "K" symbols (e.g. COM = K28.5) mark framing and ordered sets. Cost: 20% of the line rate.

128b/130b (Gen3–Gen5)

To reach 8 GT/s (instead of 10 GT/s that 8b/10b would have needed for ~2× Gen2 throughput), Gen3 adopted 130-bit blocks: a 2-bit sync header (01b = Data block, 10b = Ordered Set block) followed by 128 bits of payload. Data bytes are scrambled with a pseudo-random polynomial to provide transitions and spectral spreading; scrambling is statistical, not guaranteed like 8b/10b. Framing moved from K-symbols into tokens inside data blocks (STP, SDP, END Data Stream, EDB, IDL). Cost: 2/130 ≈ 1.54%.

PAM4 + FLIT (Gen6, Gen7)

Doubling NRZ to 64 GT/s would have required a ~32 GHz Nyquist frequency with unacceptable channel loss. PAM4 sends 2 bits per symbol at 32 GBaud, keeping Nyquist at 16 GHz like Gen5, but with three eyes each ~1/3 the height, so raw bit error rate is far worse (on the order of 10−6 first-bit error rate target vs 10−12 for NRZ generations verified). A lightweight FEC corrects most errors; a strong CRC detects the rest; Data Link Layer retry handles residual errors. Fixed-size FLITs make FEC and CRC practical.

6.8 Engineering: from link rate to NVMe throughput

Line rate after encoding is not what fio reports. Each TLP carries headers, and the link also carries DLLPs and periodic SKP ordered sets. For Gen3–Gen5 (non-FLIT) a TLP on the wire costs approximately:

Wire bytes per TLP ≈ framing(4) + sequence/DLL(2, inside the 4-byte STP token in 128b/130b) + header(12 or 16) + payload + ECRC(0 or 4) + LCRC(4)
  • framing — STP token (Gen3+) or STP + END symbols (Gen1/2); together with the sequence number about 6–8 bytes of DLL/PL overhead per TLP
  • header — 3DW (12 bytes) for 32-bit addresses and completions, 4DW (16 bytes) for 64-bit addresses
  • ECRC — optional end-to-end CRC (TD bit set)
  • LCRC — 32-bit link CRC, always present on TLPs in non-FLIT mode

Worked example (Gen4 x4 NVMe read): a 128 KiB read is delivered by the SSD as Memory Write TLPs into host memory (the SSD writes read data to the host). With Max Payload Size (MPS) = 256 bytes and 64-bit addresses (4DW header), each TLP carries 256 bytes using ≈ 256 + 16 + 8 = 280 wire bytes. Efficiency ≈ 256/280 = 91.4%. Subtract ~1–3% for Ack/UpdateFC DLLPs and SKP ordered sets impl. Usable ≈ 7.88 GB/s × 0.914 × ~0.98 ≈ 7.05 GB/s derived. Real Gen4 x4 drives quote ~7.0–7.4 GB/s sequential read, consistent with this ceiling. With MPS = 128 bytes efficiency drops to 128/152 ≈ 84%, ceiling ≈ 6.5 GB/s: MPS matters.

6.9 Latency implications

  • Serialization: a 280-byte TLP takes 280 × 8 / (4 lanes × 16 Gb/s × 128/130) ≈ 35.6 ns on Gen4 x4; 71 ns on Gen3 x4; ~1.1 µs on Gen1 x1 (280 × 10 bits / 2.5 Gb/s) derived. Faster generations reduce per-packet latency but NVMe command latency (tens of µs, dominated by NAND) changes little — bandwidth improves much more than 4 KiB QD1 latency.
  • FEC in Gen6: adds a small fixed decode latency; PCI-SIG's design target was low single-digit nanoseconds uncertain (exact values are implementation-dependent).
  • Retimers add tens of ns each way impl.
  • Replays on a marginal link add round-trip delays and can dominate tail latency.

6.10 Compatibility

Higher-generation devices must support all lower rates; links train at 2.5 GT/s and upshift. Connectors (CEM card-edge, M.2, U.2) are mechanically compatible across generations within a form factor, but the electrical channel (board, riser, cable) may only be validated for lower speeds: the device and port can both be Gen5 while the channel limits the link to Gen4. FLIT mode is negotiated; Gen6 devices talking to Gen5 ports use non-FLIT 128b/130b at ≤32 GT/s.

📭 What the spec does not say

The PCIe specification does not promise any application throughput; it defines signaling and protocol. Achieved throughput depends on MPS, MRRS, outstanding request limits (tags), completion credit sizing, root-complex memory bandwidth, IOMMU translation costs and SSD internals — all implementation-dependent.

6.12 Common mistakes

  • Quoting "Gen4 x4 = 64 Gb/s = 8 GB/s" (forgets encoding) or "16 GB/s" (adds both directions).
  • Assuming PAM4 64 GT/s means 128 Gb/s (it is 64 Gb/s at 32 GBaud).
  • Using 1 GB = 230 inconsistently with vendor 109.
  • Blaming the SSD for 5.7 GB/s on Gen4 x4 without checking MPS (64-byte or 128-byte MPS caps throughput).
  • Reporting "NVMe Gen4" — NVMe has revisions, PCIe has generations.

🧪 Lab 6.1 — Compute and validate your drive's ceiling SAFE

Objective: derive the theoretical sequential-read ceiling and compare with measurement. Setup: NVMe drive, fio, read-only test (fio --name=r --filename=/dev/nvme0n1 --rw=read --bs=128k --iodepth=32 --ioengine=libaio --direct=1 --readonly --runtime=30 --time_based). Steps: read speed/width and MPS; compute ceiling with the formula and table above; run fio. Questions: what fraction of the ceiling do you reach? Expected reasoning: 85–98% of the derived ceiling indicates the link is the limit; far below suggests the SSD or host is the limit.

Solution

For Gen4 x4 MPS 256: ceiling ≈ 7.2 GB/s before DLLP overhead, ≈ 7.0 after. A drive measuring 6.9 GB/s is link-bound; a drive measuring 5 GB/s on the same link is device- or host-bound (try higher iodepth, multiple jobs, check CPU).

Extension: repeat with --bs=4k and explain why GB/s drops (command-rate/IOPS limits and per-command overhead, not link encoding).

Quiz

  1. Gen3 x4 per-direction bandwidth after encoding?

    Answer

    4 × 8 × 128/130 ÷ 8 = 3.94 GB/s.

  2. Why did Gen3 choose 8 GT/s and not 10 GT/s?

    Answer

    128b/130b nearly eliminates encoding overhead, so 8 GT/s gives ~2× Gen2's usable bandwidth with lower frequency and channel loss than 10 GT/s.

  3. Does PCIe 5.0 imply NVMe 2.0?

    Answer

    No; independent specifications.

  4. What carries the old DLLP information in Gen6 FLIT mode?

    Answer

    The DLP bytes inside each FLIT.

7 PCIe Layer Model

7.0 Why this chapter exists

Every PCIe error message, every analyzer column and every AER bit belongs to a layer. If you know which layer generated an event, you know which layer's mechanisms to investigate. PCIe defines three layers — Transaction, Data Link, Physical — plus software above (configuration, device drivers) that the spec calls the software layer.

  • State the purpose, responsibilities, packet structures and error types of each layer.
  • Draw how a TLP grows as it passes down the stack and shrinks on the way up.
  • Map AER error bits to layers.
  • Explain what an analyzer can show at each layer and which layer's events are invisible to software.

Prerequisites: Chapter 5, Chapter 6.

🧒 Kid analogy for the whole stack

Sending a birthday present: You (Transaction Layer) write the card and wrap the gift, writing who it is for and whether you want a thank-you note back. The post office counter (Data Link Layer) stamps a tracking number, adds a tamper seal, and keeps a photocopy until the next post office confirms it arrived undamaged. The delivery van (Physical Layer) drives the box on the road, and the drivers of two vans first agree which lanes of the road they will use.

🧩 Where the analogy breaks

The tracking number and tamper seal are checked and removed at every hop (every link), not at the final destination; only the optional ECRC behaves like an end-to-end seal. And the "thank-you note" (completion) is a full separate transaction, not an acknowledgement — the post-office acknowledgement (Ack DLLP) is a different, per-link mechanism.

7.1 Physical Layer

🧒 Kid analogy

The road and the van drivers: they agree which lanes to use and how fast to drive, and they put "start" and "end" signs around every parcel so the receiver knows where one ends.

Purpose: move bits reliably enough (target BER ≤ 10−12 for NRZ generations) between two ports. Responsibilities: two sub-blocks. The electrical sub-block: drivers, receivers, equalization, CDR, receiver detection, electrical idle. The logical sub-block: encoding/scrambling, framing (STP/SDP/END tokens or K-symbols), byte striping and deskew, ordered sets (TS1, TS2, SKP, EIOS, EIEOS, FTS, SDS), and the LTSSM that trains and manages the link (Chapter 8). Packet structures: it does not originate TLPs or DLLPs; it originates ordered sets, which never pass to the Data Link Layer. SKP ordered sets are inserted periodically to compensate for clock differences between the two sides (elastic buffers add/remove SKP symbols).

Errors: Receiver Error (8b/10b disparity/symbol errors, 128b/130b sync header or framing token errors; reported as correctable), framing errors (which in 128b/130b force the link into Recovery), and link failures (link down → Surprise Down at the Data Link level). Trace visibility: an analyzer sees ordered sets, electrical idle, speed changes, LTSSM progression; software sees only summary registers (LnkSta, Link Status 2, equalization status, Receiver Error counts through AER).

7.2 Data Link Layer

🧒 Kid analogy

The post-office counter: numbers every parcel, seals it, keeps a copy, and throws the copy away only when the next office says "got numbers up to 57, all good". If a parcel arrives damaged, the next office says "Nak — resend after 56".

Purpose: reliable, in-order delivery of TLPs across one link. Responsibilities: assign a 12-bit sequence number to each TLP; append 32-bit LCRC; keep transmitted TLPs in a replay buffer until acknowledged; check received LCRC and sequence; send Ack/Nak DLLPs; replay on Nak or replay-timer expiry; exchange flow-control credit information (InitFC, UpdateFC DLLPs) on behalf of the Transaction Layer; carry power-management DLLPs; report link state (DL_Inactive, DL_Init, DL_Active) to the Transaction Layer. Packet structures: DLLPs (Gen1–5: 4 bytes of content + 16-bit CRC = 6 bytes, plus framing; Gen6 FLIT mode: carried in FLIT DLP bytes). Errors: Bad TLP (LCRC failure or bad sequence), Bad DLLP (CRC failure), Replay Timer Timeout, REPLAY_NUM Rollover — all correctable because replay recovers them; Data Link Protocol Error and Surprise Down — uncorrectable. Trace visibility: analyzer sees sequence numbers, Ack/Nak, replays (duplicate sequence numbers), FC DLLPs. Software sees only AER counters/status. Details in Chapter 15.

7.3 Transaction Layer

🧒 Kid analogy

You, writing the letter: "To: memory address 0x1234_0000. From: SSD 03:00.0, request #21. Please send back 64 bytes." You only send it if the receiver has told you it has room in its mailbox (credits).

Purpose: end-to-end requests and completions between requesters and completers. Responsibilities: assembling and disassembling TLPs; split-transaction handling (match completions to outstanding requests by Requester ID + Tag); credit-based flow control (gate transmission by advertised credits); ordering rules; Traffic Class (TC) to Virtual Channel (VC) mapping; optional ECRC generation/check; poisoning (EP bit); address/ID routing in switches. Packet structures: TLPs — header (3 or 4 DW in non-FLIT mode), optional data payload, optional ECRC digest (Chapter 10). Errors: Poisoned TLP Received, ECRC Error, Unsupported Request (UR), Completer Abort (CA), Unexpected Completion, Completion Timeout, Malformed TLP, Receiver Overflow, Flow Control Protocol Error, ACS Violation; plus advisory variants. Trace visibility: analyzers decode headers fully; software sees AER header log (the offending TLP header captured on certain errors) — the single most valuable piece of evidence for transaction-layer errors.

7.5 Analyzer presentation vs protocol truth

📡 The four-step evidence chain
RAW EVENT          symbols/bits captured on the lanes (what physically happened)
    |
PROTOCOL DECODING  descrambling, framing, field extraction per the spec revision assumed
    |
ANALYZER UI        the tool's names, colors, grouping ("Read 64B", "Link Training", "Transaction")
    |
ENGINEER INTERPRETATION   your hypothesis about cause and effect

Every step can introduce error: a capture with bad probe signal integrity can invent errors that never happened on the real link; a decoder configured for the wrong link width or a non-FLIT decoder applied to FLIT traffic produces garbage; a UI may merge a request and its completions into one "transaction" row that hides a split completion or a duplicate; and the engineer may read a label ("Completion Timeout") as a wire event when it is the tool's inference from a missing packet. Before concluding, go back down the chain: what were the raw fields?

7.7 Worked example: which layer?

A log shows "Correctable error: Bad TLP" every few seconds on the root port above an SSD, and the SSD shows "Receiver Error". Layer reasoning: Receiver Error (physical) at the SSD means the SSD's receiver saw symbol/framing errors in downstream traffic; Bad TLP at the root port means upstream TLPs arrived with bad LCRC. Both directions are affected → likely channel/connector/retimer issue rather than one transmitter. Transaction layer is unaffected because replay recovered every TLP — the cost is only bandwidth and latency.

🚀 Advanced: what FLIT mode changes in the layer model

In PCIe 6.0 FLIT mode the division of labor shifts version: the Physical Layer adds FEC over fixed 256-byte FLITs; the Data Link Layer protects and retries whole FLITs (FLIT CRC, FLIT sequence numbers) instead of individual TLPs with LCRC; DLLP information rides in dedicated DLP bytes of each FLIT; and the Transaction Layer uses a new header format with 14-bit tags and different field placement. Concepts — reliable in-order delivery per link, credits, ordering — survive; bit layouts do not. Any tool, decoder or mental shortcut built for 1.x–5.x must be re-validated for FLIT mode.

Objective: build a per-port, per-layer error inventory. Prerequisites: Linux with AER enabled. Setup: none; read-only. Procedure:

  1. For each PCIe function, read aer_dev_correctable, aer_dev_nonfatal, aer_dev_fatal if present.
  2. Map each non-zero counter to Physical / Data Link / Transaction using the table in §7.4.
  3. For each NVMe device, pair its counters with its parent port's counters (the two ends of one link).
for d in /sys/bus/pci/devices/*; do
  f="$d/aer_dev_correctable"; [ -r "$f" ] || continue
  tot=$(awk '/TOTAL/{print $2}' "$f")
  [ "${tot:-0}" != "0" ] && { echo "== ${d##*/}"; cat "$f" | grep -v ' 0$'; }
done

Observations: which ports have errors; whether both ends of a link show errors. Questions: If only the SSD shows RxErr but the root port shows nothing, which direction of the link is affected? Expected reasoning: the receiver reports physical errors, so SSD RxErr means the downstream direction (RP transmitter → SSD receiver).

Solution

Physical errors are reported where they are received. SSD RxErr/BadTLP → problem in the root-port-to-SSD direction; RP BadTLP → SSD-to-RP direction; errors on both ends → shared element (connector, retimer, cable) or global cause (clocking, temperature). Transaction-layer errors (UR, CA, Completion Timeout) are logical and do not indicate signal problems.

Extension: log the counters hourly for a week and correlate with temperature and workload.

7.8 Common mistakes

  • Thinking Ack/Nak acknowledges the NVMe command or the read request. It acknowledges receipt of a TLP over one link.
  • Thinking LCRC protects end-to-end. It is regenerated at every switch; only ECRC is end-to-end.
  • Expecting ordered sets in a TLP-level trace view; many analyzer views hide them by default.
  • Treating correctable errors as harmless. They are recovered, but each costs a replay.

Quiz

  1. Which layer generates SKP ordered sets?

    Answer

    Physical.

  2. Which layer matches completions to requests?

    Answer

    Transaction (by Requester ID and Tag).

  3. Does a switch check LCRC? ECRC?

    Answer

    It checks and regenerates LCRC on every link; it may check ECRC only if it supports it but must forward ECRC unchanged.

  4. Why is Bad TLP correctable?

    Answer

    Replay retransmits the TLP; no data is lost.

Interview questions

  1. Beginner Name PCIe's three layers.
    Model answerTransaction, Data Link, Physical.
  2. Intermediate What's in the replay buffer?
    Model answerCopies of transmitted, not-yet-acknowledged TLPs with their sequence numbers.
  3. Advanced What does the AER header log contain and why is it valuable?
    Model answerThe first 4 DW (or more with prefixes) of the TLP that caused certain errors; it identifies requester, address, tag, type.
  4. Senior An analyzer shows "Completion Timeout" at t=50ms. What do you verify?
    Model answerThat it's an analyzer inference from a missing completion; check if the completion appears later, if a link reset occurred, the tool's timeout setting, and capture point.
  5. Intermediate Which layer owns flow-control credits, and which layer carries them?
    Model answerThe Transaction Layer owns the meaning and gating of credits; the Data Link Layer carries them in InitFC/UpdateFC DLLPs.
  6. Advanced Why can a link be "up" (L0) yet unable to carry TLPs?
    Model answerThe DLL has not completed flow-control initialization (not DL_Active); PHY LinkUp alone is not enough.
  7. Advanced Where is ECRC checked in a switched path?
    Model answerAt the ultimate receiver (and optionally by switches that support checking); switches must forward it unchanged.
  8. Senior Errors appear only on the SSD side of a link. What does that tell you?
    Model answerThe direction toward the SSD is degraded: root port transmitter, channel, or SSD receiver/equalization — not the SSD's transmitter.
  9. Senior How do you justify a decoded conclusion to a reviewer?
    Model answerWalk from raw fields to decode to UI to interpretation, citing the spec section by topic name and stating what was not captured.
