PART XLI

Glossary

262 terms, each with its expansion, a plain-language (kid-level) meaning, the engineering meaning, the most common confusion, and links to the parts of the book where it is taught. Every acronym used in this book links here.

R14 Glossary

Identifiers follow one rule: g- plus the lowercase term with non-alphanumeric characters removed (so MSI-X is #g-msix, NVMe-MI is #g-nvmemi, SR-IOV is #g-sriov). Opcodes, register offsets and bit positions quoted here are for the course baseline (NVMe Base 2.4 family, PCIe Base current revisions) — features added after NVMe 1.0 are version-dependent; confirm against the specification revision you use.

📌 How to use the glossary

Read the Plain line to recall intuition, the Engineering line for the precise meaning, and the Confusion line before using the term in a bug report. The See links take you to the part where the concept is taught.

#

128b/130b
Expansion: 128b/130b encoding. Plain: Writing 128 letters with a 2-letter header. Engineering: Gen3–5 encoding with ~1.5% overhead plus scrambling. See: Part IV — PCIe From Zero, Part XLV — Mathematics Appendix.
8b/10b
Expansion: 8b/10b encoding. Plain: Writing 8 letters using 10 to stay balanced. Engineering: Gen1–2 encoding, 20% overhead. See: Part IV — PCIe From Zero, Part XLV — Mathematics Appendix.

A

Abort
Expansion: Abort (admin opcode 08h). Plain: "Please cancel that request." Engineering: Best-effort request to abort a command identified by SQID and CID. Confusion: May not abort; check DW0 bit 0. See: Part XI — NVMe Commands, Part XV — Error Handling.
ACK
Expansion: Acknowledge (Ack DLLP). Plain: A "got it" note from the next station. Engineering: Data Link Layer Packet that acknowledges receipt of TLPs up to a sequence number, letting the sender purge its retry buffer. Confusion: Not an end-to-end or NVMe-level acknowledgement; says nothing about the command. See: Part VI — PCIe Data Link Layer.
ACQ
Expansion: Admin Completion Queue. Plain: The answer box for setup requests. Engineering: Completion queue 0, base address programmed in the ACQ register (offset 30h); receives CQEs for admin commands. Confusion: Exists before any I/O queue; is not created by a command. See: Part X — NVMe Queues, Part IX — NVMe Architecture.
ACS
Expansion: Access Control Services. Plain: Rules about which doors packets may use inside a switch. Engineering: PCIe capability controlling peer-to-peer routing and redirection in switches/root ports; important for IOMMU isolation and SR-IOV. Confusion: ACS Violation is an AER uncorrectable error, not an IOMMU fault. See: Part XVII — Advanced PCIe.
Admin Command
Expansion: Admin command. Plain: A setup request, not a reading request. Engineering: Commands on the admin queue: create queues, identify, logs, features, firmware, format. See: Part XI — NVMe Commands.
AER
Expansion: Advanced Error Reporting. Plain: A detailed incident report kept by each PCIe port. Engineering: PCIe extended capability (ID 0001h) with uncorrectable/correctable status, mask, severity registers and a header log; errors signalled to the root via ERR_COR/ERR_NONFATAL/ERR_FATAL messages. Confusion: Reports where an error was detected, not its root cause. Not the NVMe Asynchronous Event Request. See: Part XV — Error Handling.
AIC
Expansion: Add-In Card. Plain: A drive shaped like a graphics card that plugs into a slot. Engineering: PCIe CEM form factor SSD (half-height/full-height) plugged directly into a PCIe slot. Confusion: Form factor, not a protocol. See: Part II — Storage Fundamentals.
ANA
Expansion: Asymmetric Namespace Access. Plain: Some doors to a room are faster than others. Engineering: NVMe multipath feature reporting per-controller access state (optimized, non-optimized, inaccessible, ...) for namespace groups. Confusion: Not the same as Linux dm-multipath; native NVMe multipath uses it. See: Part XVIII — NVMe Advanced Features, Part XIX — NVMe over Fabrics.
APST
Expansion: Autonomous Power State Transition. Plain: The drive naps on its own when nobody needs it. Engineering: NVMe feature (Feature ID 0Ch) letting the controller move to lower non-operational power states after configured idle times. Confusion: Separate from PCIe ASPM; both interact with latency. See: Part XVI — Power and Reset.
AQA
Expansion: Admin Queue Attributes. Plain: The size label on the admin boxes. Engineering: Controller register at 24h: ASQS (bits 11:0) and ACQS (bits 27:16), both zero-based. Confusion: Zero-based: 1Fh means 32 entries. See: Part IX — NVMe Architecture.
ARI
Expansion: Alternative Routing-ID Interpretation. Plain: Allowing more than eight rooms per house number. Engineering: PCIe capability that reinterprets Device+Function bits as an 8-bit function number, enabling up to 256 functions (used with SR-IOV). See: Part XVII — Advanced PCIe.
ASPM
Expansion: Active State Power Management. Plain: The road dims its lights when no cars are coming. Engineering: Hardware-autonomous link power states L0s and L1 controlled via Link Control. Confusion: Distinct from software-directed D-states and NVMe power states. See: Part XVI — Power and Reset.
ASQ
Expansion: Admin Submission Queue. Plain: The request box for setup jobs. Engineering: Submission queue 0; base in ASQ register (offset 28h); size in AQA.ASQS. Confusion: Only admin opcodes are valid here. See: Part X — NVMe Queues, Part IX — NVMe Architecture.
Asynchronous Event Request
Expansion: Asynchronous Event Request (admin opcode 0Ch). Plain: A standing request: "tell me if anything happens." Engineering: Admin command left outstanding; the controller completes it to report errors, health/notice events; host then reads the indicated log. Confusion: Not PCIe AER. See: Part XV — Error Handling, Part XI — NVMe Commands.
AT
Expansion: Address Type. Plain: A note saying whether an address is already translated. Engineering: TLP header field (2 bits) used with ATS to indicate untranslated, translation request, or translated addresses. See: Part XVII — Advanced PCIe.
ATS
Expansion: Address Translation Services. Plain: The device keeps its own copy of the address book. Engineering: PCIe capability letting endpoints request IOMMU translations and cache them (ATC). Confusion: Improves performance but complicates invalidation and security. See: Part XVII — Advanced PCIe.

B

BAR
Expansion: Base Address Register. Plain: The house number the computer assigns to a device's mailbox. Engineering: Config-space register defining a memory or I/O window; NVMe BAR0/1 (64-bit) maps controller registers and doorbells. Confusion: BAR sizing uses write-all-ones then read-back. See: Part VII — PCIe Configuration, Part IX — NVMe Architecture.
BCM
Expansion: Byte Count Modified. Plain: A flag saying "this count was trimmed". Engineering: Completion header bit set only by PCI-X completers; PCIe completers set it to 0. Confusion: Rarely relevant on pure PCIe. See: Part V — PCIe Transaction Layer.
BDF
Expansion: Bus/Device/Function. Plain: A device's street, house and room number. Engineering: 16-bit Routing ID: bus (8), device (5), function (3); used as Requester/Completer ID and for config routing. Confusion: With ARI, device+function become one 8-bit function number. See: Part IV — PCIe From Zero, Part VII — PCIe Configuration.
blk-mq
Expansion: Linux multi-queue block layer. Plain: The kernel's per-CPU request lines. Engineering: Linux block layer mapping software queues to hardware contexts; NVMe hardware contexts map to SQ/CQ pairs. See: Part XXI — Linux Practicals.
blktrace
Expansion: Linux block I/O tracer. Plain: A stopwatch for each block request. Engineering: Tool that records block-layer events (queue, dispatch, complete) for analysis with blkparse/btt. Confusion: Does not see PCIe traffic. See: Part XXI — Linux Practicals, Part XXVIII — Performance Engineering.
Block (NAND)
Expansion: NAND erase block. Plain: The smallest shelf you can wipe clean. Engineering: Group of pages erased together; erase granularity (MBs) vs program granularity (KBs) drives the need for an FTL and GC. Confusion: Not a logical block (LBA). See: Part II — Storage Fundamentals.
Boot Partition
Expansion: Boot Partition. Plain: A small reserved area holding startup code. Engineering: Optional NVMe areas readable via BPINFO/BPRSEL registers before full initialisation. See: Part XVIII — NVMe Advanced Features.
Bus Master Enable
Expansion: Command register bit 2. Plain: Permission slip for the device to fetch things itself. Engineering: Must be set for a function to issue memory requests (DMA). Confusion: If clear, NVMe controller cannot fetch SQEs. See: Part VII — PCIe Configuration, Part VIII — DMA.
Byte Count
Expansion: Byte Count (completion). Plain: How much is still to come, including this piece. Engineering: Completion header field giving remaining bytes for the request. Confusion: Not this TLP's length. See: Part V — PCIe Transaction Layer.

C

CA
Expansion: Completer Abort. Plain: "I understood but refuse to do it." Engineering: Completion status (100b) returned when a completer cannot complete a request due to a violation of its own rules; also an AER error bit. Confusion: Different from UR, which means "not supported/unclaimed". See: Part V — PCIe Transaction Layer, Part XV — Error Handling.
CAP
Expansion: Controller Capabilities. Plain: The controller's fact sheet. Engineering: 64-bit register at 00h: MQES, CQR, AMS, TO, DSTRD, NSSRS, CSS, BPS, MPSMIN, MPSMAX and more. Confusion: Read-only; defines limits the host must obey. See: Part IX — NVMe Architecture.
Capsule
Expansion: Command/Response capsule. Plain: An envelope for an NVMe command on a network. Engineering: Fabrics unit containing an SQE (and optional data/SGL) or CQE. See: Part XIX — NVMe over Fabrics.
CC
Expansion: Controller Configuration. Plain: The switch panel the host sets before starting. Engineering: Register at 14h: EN, CSS, MPS, AMS, SHN, IOSQES, IOCQES. Confusion: Setting EN=0 is a controller reset. See: Part IX — NVMe Architecture, Part XVI — Power and Reset.
CEM
Expansion: Card Electromechanical. Plain: The rules for card shape and slot. Engineering: PCI-SIG specification for add-in cards and slots. See: Part II — Storage Fundamentals.
CFS
Expansion: Controller Fatal Status. Plain: The controller's "I'm broken" light. Engineering: CSTS bit 1; set when the controller hits a fatal condition; host must reset. Confusion: Controller-level, not namespace-level. See: Part IX — NVMe Architecture, Part XV — Error Handling.
CID
Expansion: Command Identifier. Plain: A tracking number on each request slip. Engineering: 16-bit identifier in CDW0[31:16]; returned in CQE DW3; unique per SQ among outstanding commands. Confusion: (SQID, CID) is the true unique key. See: Part X — NVMe Queues, Part XI — NVMe Commands.
CLKREQ#
Expansion: Clock Request signal. Plain: "I need the clock now." Engineering: Sideband signal used for clock power management and L1 substates. See: Part XVI — Power and Reset.
CMB
Expansion: Controller Memory Buffer. Plain: A shelf inside the drive the computer may use. Engineering: Optional device memory exposed through a BAR (CMBLOC 38h, CMBSZ 3Ch) for SQs, CQs, PRPs or data. Confusion: Not the same as PMR (persistent). See: Part XVIII — NVMe Advanced Features.
Command Set
Expansion: NVMe I/O Command Set. Plain: A set of request types for one kind of storage. Engineering: Since 2.0: NVM, Zoned Namespace, Key Value, Subsystem Local Memory, Computational Programs command set specifications. Confusion: Command set is not transport. See: Part IX — NVMe Architecture, Part XVIII — NVMe Advanced Features.
Compare
Expansion: Compare (NVM opcode 05h). Plain: "Is this the same as what's stored?" Engineering: Compares host data with stored data; mismatch → Compare Failure status. See: Part XI — NVMe Commands.
Completer ID
Expansion: Completer ID. Plain: Who sent the reply. Engineering: BDF of the completing function in completion headers. See: Part V — PCIe Transaction Layer.
Completion Timeout
Expansion: PCIe Completion Timeout. Plain: Waiting too long for a reply letter. Engineering: Requester-detected uncorrectable error when a non-posted request's completion does not arrive within the configured range (Device Control 2). Confusion: Not an NVMe command timeout. See: Part XV — Error Handling.
Computational Programs
Expansion: Computational Programs Command Set. Plain: Running small programs inside the drive. Engineering: NVMe command set for loading/executing programs on compute namespaces using SLM. See: Part XVIII — NVMe Advanced Features.
Confidence Label
Expansion: Confidence label. Plain: How sure you are, written down. Engineering: Confirmed / Strong evidence / Likely / Possible / Unknown. See: Part LVI — Evidence-Based Debugging.
Config Space
Expansion: Configuration Space. Plain: The device's ID card and settings form. Engineering: 256 bytes (PCI) or 4 KiB (PCIe extended) per function, accessed with CfgRd/CfgWr or ECAM MMIO. See: Part VII — PCIe Configuration.
Controller
Expansion: NVMe Controller. Plain: The librarian. Engineering: Interface entity that processes commands, owns registers and queues; one subsystem may have many. Confusion: Not a namespace; not the physical ASIC necessarily. See: Part IX — NVMe Architecture.
Copy
Expansion: Copy (NVM opcode 19h). Plain: "Move these pages yourself." Engineering: Copies LBA ranges within the device without host data transfer. Confusion: Introduced via Simple Copy TP; check revision. See: Part XI — NVMe Commands.
Cpl
Expansion: Completion (without data). Plain: A reply note with no parcel. Engineering: TLP Fmt/Type 0Ah answering non-posted requests that return no data (writes to config/I/O) or reporting an error status (UR, CA, CRS). Confusion: Not an NVMe CQE. See: Part V — PCIe Transaction Layer.
CplD
Expansion: Completion with Data. Plain: A reply note with the parcel attached. Engineering: TLP Fmt/Type 4Ah carrying data for MRd or CfgRd; matched by Requester ID + Tag; may be split. Confusion: Not an NVMe CQE. See: Part V — PCIe Transaction Layer.
CQ
Expansion: Completion Queue. Plain: The answer box. Engineering: Circular queue in host memory (or CMB) of 16-byte CQEs written by the controller; head owned by host. Confusion: Queue ≠ doorbell. See: Part X — NVMe Queues.
CQE
Expansion: Completion Queue Entry. Plain: One answer card. Engineering: 16-byte structure: DW0 result, DW2 SQHD/SQID, DW3 CID, phase, status. Confusion: Not a PCIe completion TLP. See: Part X — NVMe Queues.
CRD
Expansion: Command Retry Delay. Plain: "Try again after this many minutes." Engineering: CQE status bits 29:28 selecting a host-configured retry delay (NVMe 1.4+). Confusion: Only meaningful if DNR=0. See: Part XV — Error Handling.
Create I/O CQ
Expansion: Create I/O Completion Queue (admin opcode 05h). Plain: Setting up a new answer box with its lamp. Engineering: Creates CQ with QID, size, PC, IEN, IV. Confusion: Must exist before its SQ. See: Part X — NVMe Queues.
Create I/O SQ
Expansion: Create I/O Submission Queue (admin opcode 01h). Plain: Setting up a new request box. Engineering: Creates SQ with QID, size, priority, associated CQ. Confusion: Same numeric opcode as NVM Write — queue type disambiguates. See: Part X — NVMe Queues.
CRS
Expansion: Configuration Request Retry Status. Plain: "Not ready, ask again later." Engineering: Completion status for config requests while a device initialises after reset. Confusion: Not an error per se. See: Part VII — PCIe Configuration, Part XVI — Power and Reset.
CSS
Expansion: Command Sets Supported / Command Set Selected. Plain: Which kinds of requests the librarian understands. Engineering: CAP.CSS advertises; CC.CSS selects. See: Part IX — NVMe Architecture.
CSTS
Expansion: Controller Status. Plain: The controller's status lights. Engineering: Register at 1Ch: RDY, CFS, SHST, NSSRO, PP. Confusion: RDY lags CC.EN by up to CAP.TO × 500 ms. See: Part IX — NVMe Architecture.
CXL
Expansion: Compute Express Link. Plain: A cousin of PCIe that adds shared memory tricks. Engineering: Protocol running over the PCIe physical layer adding cache-coherent (CXL.cache) and memory (CXL.mem) semantics. Confusion: Not NVMe. See: Part XVII — Advanced PCIe.

D

D3cold
Expansion: Device power state D3cold. Plain: Fully unplugged sleep. Engineering: Main power removed; context lost; return requires reset/re-initialisation. See: Part XVI — Power and Reset.
D3hot
Expansion: Device power state D3hot. Plain: Deep sleep with a nightlight on. Engineering: Software-set low-power state with config space accessible; most other access disabled. Confusion: NVMe power states are separate. See: Part XVI — Power and Reset.
Data Units
Expansion: SMART Data Units Read/Written. Plain: Counter of how much was read or written. Engineering: Health log counters in thousands of 512-byte units (1 unit = 512 000 bytes). Confusion: Not bytes, not LBAs. See: Part XV — Error Handling, Part XLV — Mathematics Appendix.
Discovery Controller
Expansion: Discovery Controller. Plain: A directory desk listing the libraries on a network. Engineering: Fabrics controller returning Discovery Log Pages of available subsystems. See: Part XIX — NVMe over Fabrics.
DLLP
Expansion: Data Link Layer Packet. Plain: Small notes between neighbouring stations. Engineering: Ack, Nak, InitFC, UpdateFC, PM and vendor DLLPs; 6 bytes plus framing; never forwarded by switches. Confusion: Not TLPs; carry no transaction. See: Part VI — PCIe Data Link Layer.
DMA
Expansion: Direct Memory Access. Plain: The librarian carries books straight to the tables. Engineering: Device-initiated memory reads/writes on PCIe (bus mastering), translated by the IOMMU. Confusion: Not a CPU copy; not a single TLP. See: Part VIII — DMA.
DNR
Expansion: Do Not Retry. Plain: "Don't bother asking again." Engineering: CQE status bit 31; set when retrying the same command is expected to fail. See: Part XV — Error Handling.
Doorbell
Expansion: Doorbell register. Plain: The bell that says "new slips in the box". Engineering: 32-bit MMIO register per queue (SQ tail, CQ head) from BAR0 + 1000h, stride 4 << DSTRD. Confusion: Contains an index, not the command. See: Part X — NVMe Queues.
DPC
Expansion: Downstream Port Containment. Plain: Shutting a ward's door to stop an infection. Engineering: PCIe capability that disables a link on uncorrectable errors to contain them; software recovers. Confusion: In-flight transactions are lost. See: Part XV — Error Handling, Part XVII — Advanced PCIe.
DSM
Expansion: Dataset Management (NVM opcode 09h). Plain: A note telling the drive which pages you no longer need. Engineering: I/O command carrying range attributes; Deallocate (AD) is the TRIM equivalent. Confusion: Deallocate is not secure erase. See: Part XI — NVMe Commands.
DSTRD
Expansion: Doorbell Stride. Plain: How far apart the doorbells are spaced. Engineering: CAP bits 35:32; stride = 4 << DSTRD bytes. Confusion: Misreading it shifts every doorbell. See: Part IX — NVMe Architecture, Part X — NVMe Queues.
DWPD
Expansion: Drive Writes Per Day. Plain: How many times a day you can fill the drive for its warranty. Engineering: Endurance rating: TBW / (capacity × 365 × years). See: Part XLV — Mathematics Appendix.

E

E1.S
Expansion: EDSFF E1.S form factor. Plain: A ruler-sized slim drive. Engineering: EDSFF short form factor for 1U servers. See: Part II — Storage Fundamentals.
E3.S
Expansion: EDSFF E3.S form factor. Plain: A thicker, shorter enterprise drive. Engineering: EDSFF form factor family E3 (short/long, 1T/2T thickness) with x4/x8/x16 options. See: Part II — Storage Fundamentals.
ECAM
Expansion: Enhanced Configuration Access Mechanism. Plain: Reading ID cards through a window in memory. Engineering: MMIO window mapping each function's 4 KiB config space; CPU accesses become CfgRd/CfgWr TLPs. See: Part VII — PCIe Configuration.
ECC
Expansion: Error-Correcting Code. Plain: Extra writing that lets you fix smudged words. Engineering: Codes (BCH, LDPC) applied to NAND pages and memories to correct bit errors. Confusion: CRC detects; ECC corrects. See: Part II — Storage Fundamentals.
ECRC
Expansion: End-to-end CRC. Plain: A seal checked only at the final destination. Engineering: Optional 32-bit CRC appended to a TLP (TD=1), checked by the ultimate receiver. Confusion: Optional; LCRC is per hop and mandatory. See: Part V — PCIe Transaction Layer, Part XV — Error Handling.
EDSFF
Expansion: Enterprise and Datacenter Standard Form Factor. Plain: A family of new drive shapes for servers. Engineering: SNIA SFF form factors (E1.S, E1.L, E3.S, E3.L). See: Part II — Storage Fundamentals.
Electrical Idle
Expansion: Electrical Idle. Plain: The road's lights switched off. Engineering: Transmitter idle state used in low-power states and training. See: Part IV — PCIe From Zero, Part XVI — Power and Reset.
Endurance Group
Expansion: NVMe Endurance Group. Plain: A group of drawers that wear out together. Engineering: NVMe 1.4 construct grouping NVM sets/namespaces for endurance management and reporting. See: Part XVIII — NVMe Advanced Features.
EP
Expansion: Error Poisoned (TLP bit). Plain: A parcel labelled "contents known damaged". Engineering: TLP header bit marking data known to be corrupt by the source. Confusion: Link CRC passed; the source flagged it. See: Part V — PCIe Transaction Layer, Part XV — Error Handling.
Equalization
Expansion: Link equalization. Plain: Tuning the road so signals arrive clearly. Engineering: Gen3+ LTSSM phases adjusting transmitter presets/receiver settings per lane. Confusion: Failures cause down-training, not usually errors at Gen1. See: Part IV — PCIe From Zero, Part XVII — Advanced PCIe.
Error Information Log
Expansion: Error Information log (Log 01h). Plain: A list of recent mistakes. Engineering: Entries with error count, SQID, CID, status, LBA, NSID. See: Part XV — Error Handling.
Exerciser
Expansion: Protocol exerciser. Plain: A robot that drives on the road on purpose. Engineering: Instrument that generates PCIe traffic/errors to test devices. See: Part XXIX — Validation Engineering.
Exported NVM Subsystem Migration
Expansion: PCIe Exported NVM Subsystem Migration (NVMe 2.4). Plain: Moving a running library to a new building. Engineering: Announced NVMe 2.4 capability related to migrating exported subsystems over PCIe; details only in the normative text. Confusion: Version-dependent. See: Part XX — 2026 NVMe 2.4 Updates.

F

FC
Expansion: Flow Control. Plain: Only send if the other side has room. Engineering: Credit-based scheme per type (Posted/Non-Posted/Completion × header/data), initialised by InitFC and replenished by UpdateFC DLLPs. Confusion: Not to be confused with Fibre Channel (FC-NVMe). See: Part VI — PCIe Data Link Layer.
FC-NVMe
Expansion: NVMe over Fibre Channel. Plain: NVMe carried on Fibre Channel networks. Engineering: INCITS T11 mapping of NVMe-oF onto Fibre Channel. See: Part XIX — NVMe over Fabrics.
FDP
Expansion: Flexible Data Placement. Plain: Letting the computer hint which drawer data goes in. Engineering: NVMe feature (ratified as a technical proposal, 2022) allowing host placement hints via reclaim unit handles. Confusion: Not ZNS; no sequential-write requirement. See: Part XVIII — NVMe Advanced Features.
FEC
Expansion: Forward Error Correction. Plain: Extra bits that fix errors without asking again. Engineering: Lightweight FEC in PCIe 6.0 FLIT mode to cope with PAM4 error rates. Confusion: Combined with CRC and replay. See: Part XVII — Advanced PCIe.
fio
Expansion: Flexible I/O tester. Plain: A workload generator. Engineering: Benchmark tool for generating I/O patterns and measuring latency/IOPS. Confusion: Write jobs on raw devices destroy data. See: Part XXI — Linux Practicals, Part XXVIII — Performance Engineering.
Firmware Commit
Expansion: Firmware Commit (admin opcode 10h). Plain: "Use the new rulebook." Engineering: Activates a downloaded firmware image in a slot, possibly requiring reset. See: Part XI — NVMe Commands.
Firmware Image Download
Expansion: Firmware Image Download (admin opcode 11h). Plain: Delivering pages of the new rulebook. Engineering: Transfers firmware image pieces by offset. See: Part XI — NVMe Commands.
First Error Pointer
Expansion: AER First Error Pointer. Plain: Which problem happened first. Engineering: AER control field identifying the bit of the first uncorrectable error. See: Part XV — Error Handling.
FLIT
Expansion: Flow control unit (PCIe 6.0 FLIT mode). Plain: Fixed-size boxes on the road. Engineering: 256-byte unit carrying TLP bytes, DLP bytes, CRC and FEC; mandatory at 64 GT/s. Confusion: Changes TLP header format and sequence handling. See: Part XVII — Advanced PCIe.
FLR
Expansion: Function Level Reset. Plain: Restarting one appliance without cutting house power. Engineering: Reset of a single function via Device Control "Initiate FLR"; link stays up. Confusion: Differs from Hot Reset and Controller Reset. See: Part XVI — Power and Reset.
Flush
Expansion: Flush (NVM opcode 00h). Plain: "Make sure everything is written in ink." Engineering: Commits volatile write cache contents for the namespace to non-volatile media. Confusion: Meaningless if no volatile write cache. See: Part XI — NVMe Commands.
Format NVM
Expansion: Format NVM (admin opcode 80h). Plain: Wiping a library section and maybe changing page size. Engineering: Low-level format of namespace(s) with selected LBA format and optional secure erase. Confusion: Destroys data. See: Part XI — NVMe Commands.
FTL
Expansion: Flash Translation Layer. Plain: The librarian's catalogue that keeps moving books. Engineering: SSD firmware layer mapping LBAs to physical NAND locations; handles GC, wear levelling, bad blocks. Confusion: Invisible to the host (except ZNS/FDP hints). See: Part II — Storage Fundamentals.
FUA
Expansion: Force Unit Access. Plain: "Write this in ink before saying done." Engineering: Write CDW12 bit 30; completion only after data is non-volatile. See: Part XI — NVMe Commands.
Fused Operation
Expansion: Fused operation. Plain: Two requests stapled together. Engineering: Two commands executed atomically as a unit (e.g. Compare and Write). See: Part XI — NVMe Commands.

G

Garbage Collection
Expansion: Garbage collection (GC). Plain: Re-packing half-empty shelves to free whole shelves. Engineering: FTL process relocating valid pages so blocks can be erased; source of write amplification and latency spikes. See: Part II — Storage Fundamentals.
Get Features
Expansion: Get Features (admin opcode 0Ah). Plain: Asking the drive about a setting. Engineering: Reads a feature value by Feature Identifier (e.g. 07h Number of Queues). See: Part XI — NVMe Commands.
Get Log Page
Expansion: Get Log Page (admin opcode 02h). Plain: Reading the drive's diary pages. Engineering: Returns log pages by Log Identifier (01h Error, 02h SMART/Health, 03h Firmware Slot, ...). Confusion: Lengths are in dwords, zero-based. See: Part XI — NVMe Commands.
GT/s
Expansion: Gigatransfers per second. Plain: How many symbols per second each lane carries. Engineering: Raw signalling rate per lane; bytes/s requires encoding efficiency and /8. Confusion: Not GB/s. See: Part IV — PCIe From Zero, Part XLV — Mathematics Appendix.

H

Header Log
Expansion: AER Header Log. Plain: A photo of the parcel's label that caused trouble. Engineering: Four (or more) DWs capturing the header of the TLP associated with certain uncorrectable errors. Confusion: Not recorded for errors not tied to a received TLP (e.g. Completion Timeout). See: Part XV — Error Handling.
HMB
Expansion: Host Memory Buffer. Plain: The drive borrows part of the computer's desk. Engineering: Host DRAM allocated to the controller via Set Features (Feature 0Dh) — common on DRAM-less SSDs. Confusion: Host-owned; must be handled on reset/suspend. See: Part XVIII — NVMe Advanced Features.
Hot Reset
Expansion: Hot Reset. Plain: Restarting the road and everything after it. Engineering: In-band reset propagated by TS1/TS2 ordered sets (e.g. via Secondary Bus Reset); resets downstream functions. Confusion: Link retrains. See: Part XVI — Power and Reset.

I

I/O Command
Expansion: I/O command. Plain: A reading or writing request. Engineering: Command on an I/O queue interpreted by the namespace's command set. See: Part XI — NVMe Commands.
ID-based Ordering
Expansion: ID-based Ordering (IDO). Plain: Different senders' parcels may overtake each other. Engineering: Attr bit relaxing ordering between different requesters. See: Part V — PCIe Transaction Layer.
Identify
Expansion: Identify (admin opcode 06h). Plain: Asking the drive to describe itself. Engineering: Returns 4 KiB data structures selected by CNS (00h namespace, 01h controller, 02h active NS list, ...). See: Part XI — NVMe Commands.
Interposer
Expansion: Interposer. Plain: A tap placed between the drive and the slot. Engineering: Fixture inserted in the link path for an analyzer; can alter signal integrity. See: Part XXIII — Trace Analysis Laboratory.
Interrupt Coalescing
Expansion: Interrupt Coalescing (Feature 08h). Plain: Waiting to ring the lamp until several answers are ready. Engineering: Aggregation threshold and time for interrupt generation. Confusion: Adds latency. See: Part XIV — Interrupts.
INTMS / INTMC
Expansion: Interrupt Mask Set / Clear. Plain: Switches to silence the old-style bell. Engineering: Registers 0Ch/10h masking pin-based or MSI interrupts; not used with MSI-X. Confusion: Do not use with MSI-X. See: Part IX — NVMe Architecture, Part XIV — Interrupts.
INTx
Expansion: Legacy INTx interrupts. Plain: Raising your hand to get attention. Engineering: Virtual wire interrupts emulated by Assert_INTx/Deassert_INTx messages; level-sensitive and shareable. Confusion: Not used by modern NVMe drivers if MSI-X available. See: Part XIV — Interrupts.
io_uring
Expansion: Linux io_uring interface. Plain: A shared tray between app and kernel. Engineering: Linux asynchronous I/O interface with submission/completion rings; supports polling. Confusion: Kernel rings, not NVMe rings (though analogous). See: Part XXI — Linux Practicals.
IOMMU
Expansion: I/O Memory Management Unit. Plain: A gatekeeper that renames and guards rooms. Engineering: Translates device (I/O virtual) addresses to physical addresses and enforces isolation; Intel VT-d, AMD-Vi, Arm SMMU. Confusion: Faults appear in kernel logs, often with UR completions on the bus. See: Part VIII — DMA.
IOPS
Expansion: I/O Operations Per Second. Plain: How many requests finished each second. Engineering: Completion rate; throughput = IOPS × size; QD = IOPS × latency. Confusion: Meaningless without block size and QD. See: Part XXVIII — Performance Engineering, Part XLV — Mathematics Appendix.
IRQ Affinity
Expansion: IRQ affinity. Plain: Which teacher answers which lamp. Engineering: Linux mapping of interrupt vectors to CPUs (managed for NVMe). See: Part XIV — Interrupts, Part XXI — Linux Practicals.
IV
Expansion: Interrupt Vector. Plain: Which lamp lights when a box has answers. Engineering: Create I/O CQ CDW11 bits 31:16, selecting the MSI-X/MSI vector for that CQ. See: Part XIV — Interrupts.

J

Jammer
Expansion: Protocol jammer. Plain: A prankster that damages parcels on purpose. Engineering: Instrument that injects errors into live traffic for error-handling validation. Confusion: Expert/caution use. See: Part XXIX — Validation Engineering.

K

Keep Alive
Expansion: Keep Alive. Plain: "Are you still there?" pings. Engineering: Admin command/timer for detecting host/controller connection loss, mainly fabrics. See: Part XIX — NVMe over Fabrics.
KV
Expansion: Key Value Command Set. Plain: Storing things by name instead of shelf number. Engineering: NVMe command set storing values addressed by keys (Store, Retrieve, Delete, List, Exist). See: Part XVIII — NVMe Advanced Features.

L

L0
Expansion: Link state L0. Plain: Road fully open. Engineering: Normal operating link state. See: Part IV — PCIe From Zero.
L0s
Expansion: Link state L0s. Plain: Brief nap, one direction at a time. Engineering: Low-latency standby per direction; ASPM-controlled. Confusion: Removed/optional in newer generations' FLIT mode — check revision. See: Part XVI — Power and Reset.
L1
Expansion: Link state L1. Plain: Deeper nap for both directions. Engineering: Low-power link state entered via ASPM or PCI-PM; exit through Recovery. See: Part XVI — Power and Reset.
L1 Substates
Expansion: L1.1 / L1.2. Plain: Even deeper naps with the lights off. Engineering: L1 PM Substates capability using CLKREQ# to turn off more circuitry; long exit latencies. Confusion: Can affect I/O latency after idle. See: Part XVI — Power and Reset.
L2
Expansion: Link state L2. Plain: Asleep with auxiliary power only. Engineering: Link off with Vaux; wake via WAKE# or beacon. See: Part XVI — Power and Reset.
Lane
Expansion: PCIe lane. Plain: One pair of one-way roads in each direction. Engineering: Two differential pairs (TX, RX); links bundle 1–16 lanes. Confusion: Lanes are not independent channels for separate packets. See: Part IV — PCIe From Zero.
LBA
Expansion: Logical Block Address. Plain: A page number in the library section. Engineering: Index of a logical block within a namespace; size from the active LBA format. Confusion: Not always 512 bytes. See: Part II — Storage Fundamentals, Part XI — NVMe Commands.
LBA Format
Expansion: LBA Format (LBAF). Plain: The page size of a library section. Engineering: Identify Namespace descriptor: LBA data size (LBADS), metadata size, relative performance; FLBAS selects active. See: Part XI — NVMe Commands.
LCRC
Expansion: Link CRC. Plain: A seal checked at every hop. Engineering: 32-bit CRC added by the Data Link Layer to each TLP; failure → Nak and replay. Confusion: Per-hop; not end-to-end. See: Part VI — PCIe Data Link Layer.
LDPC
Expansion: Low-Density Parity-Check code. Plain: A strong way to fix many smudged letters. Engineering: ECC widely used in modern NAND controllers with soft-decision decoding. See: Part II — Storage Fundamentals.
Little's Law
Expansion: Little's Law (L = λW). Plain: Average line length equals arrival rate times wait. Engineering: Steady-state relation used to size queue depth. Confusion: Applies to averages, not tails. See: Part XXVIII — Performance Engineering, Part XLV — Mathematics Appendix.
LnkCap / LnkSta
Expansion: Link Capabilities / Link Status. Plain: What the road could do vs what it does now. Engineering: PCIe capability registers for max and current speed/width. Confusion: Capability ≠ current state. See: Part IV — PCIe From Zero, Part XXI — Linux Practicals.
Lower Address
Expansion: Lower Address (completion). Plain: Where in the line this piece starts. Engineering: Low 7 bits of the byte address of the first byte in the completion. See: Part V — PCIe Transaction Layer.
lspci
Expansion: lspci. Plain: A list of everything on the PCI roads. Engineering: pciutils tool showing devices, config space, capabilities. Confusion: Read-only. See: Part XXI — Linux Practicals.
LTR
Expansion: Latency Tolerance Reporting. Plain: "I can wait this long for service." Engineering: Message from endpoints telling the platform their latency tolerance for power management. See: Part XVI — Power and Reset.
LTSSM
Expansion: Link Training and Status State Machine. Plain: The steps two devices follow to start talking. Engineering: Physical-layer state machine: Detect, Polling, Configuration, L0, Recovery, L0s, L1, L2, Hot Reset, Loopback, Disabled. Confusion: Recovery is often normal. See: Part IV — PCIe From Zero.

M

M.2
Expansion: M.2 form factor. Plain: A stick-of-gum-sized card. Engineering: Small form factor connector/card supporting SATA or PCIe (x2/x4) depending on keying and host. Confusion: M.2 is not NVMe. See: Part II — Storage Fundamentals.
Malformed TLP
Expansion: Malformed TLP. Plain: A parcel whose label breaks the rules. Engineering: Uncorrectable error when a TLP violates format rules (length vs payload, MPS exceeded, etc.). Confusion: Often indicates MPS mismatch. See: Part V — PCIe Transaction Layer, Part XV — Error Handling.
MCTP
Expansion: Management Component Transport Protocol. Plain: A side-channel language for management. Engineering: DMTF protocol (DSP0236) carrying NVMe-MI over SMBus/I2C or PCIe VDMs. See: Part XVIII — NVMe Advanced Features.
MDTS
Expansion: Maximum Data Transfer Size. Plain: The biggest parcel the librarian accepts. Engineering: Identify Controller byte 77: max transfer = 2^MDTS × min page size; 0 = no limit reported. See: Part XI — NVMe Commands.
Metadata
Expansion: NVMe metadata. Plain: Sticky notes attached to each page. Engineering: Per-LBA extra bytes, either contiguous with data (extended LBA) or separate (MPTR). See: Part XI — NVMe Commands.
MMIO
Expansion: Memory-Mapped I/O. Plain: Talking to a device by writing to special addresses. Engineering: CPU loads/stores to device BAR regions, carried as MRd/MWr TLPs. Confusion: Uncached; ordering differs from RAM. See: Part IV — PCIe From Zero, Part IX — NVMe Architecture.
MPS
Expansion: Max Payload Size. Plain: The biggest box a truck may carry. Engineering: Device Control field (128–4096 B) limiting TLP payload; must not exceed the receiver's capability. Confusion: Also the abbreviation of CC.MPS (memory page size) — context matters. See: Part V — PCIe Transaction Layer.
MQES
Expansion: Maximum Queue Entries Supported. Plain: The biggest box allowed. Engineering: CAP bits 15:0, zero-based maximum I/O queue size. See: Part IX — NVMe Architecture, Part X — NVMe Queues.
MRd
Expansion: Memory Read Request. Plain: "Please send me what's at this address." Engineering: Non-posted TLP (Fmt/Type 00h/20h) with Tag; answered by CplD. Confusion: An NVMe read produces device MWr, not MRd, for data. See: Part V — PCIe Transaction Layer.
MRRS
Expansion: Max Read Request Size. Plain: The biggest item you may ask for at once. Engineering: Device Control field limiting MRd length (128–4096 B). Confusion: Larger MRRS improves fetch efficiency but can hurt fairness. See: Part V — PCIe Transaction Layer.
MSI
Expansion: Message Signalled Interrupts. Plain: Ringing via a note instead of a wire. Engineering: Interrupt as a memory write with up to 32 vectors in a capability structure. Confusion: MSI-X is preferred for NVMe. See: Part XIV — Interrupts.
MSI-X
Expansion: Message Signalled Interrupts Extended. Plain: A lamp per desk, each with its own switch. Engineering: Up to 2048 vectors with a per-vector table (address, data, mask) in a BAR. Confusion: Delivers notification, not status. See: Part XIV — Interrupts.
Multipath
Expansion: NVMe multipath. Plain: Several doorways into the same room. Engineering: Access to a namespace via multiple controllers/paths; uses ANA. See: Part XIX — NVMe over Fabrics.
MWr
Expansion: Memory Write Request. Plain: "Put this at that address." Engineering: Posted TLP (Fmt/Type 40h/60h) carrying data; no completion. Confusion: Doorbells, CQEs, read data and MSI-X are all MWr. See: Part V — PCIe Transaction Layer.

N

NAK
Expansion: Negative Acknowledge. Plain: "Your parcel arrived damaged, resend." Engineering: DLLP requesting replay of TLPs after a sequence number. Confusion: Link-level; not a command rejection. See: Part VI — PCIe Data Link Layer.
Namespace
Expansion: NVMe Namespace. Plain: A section of the library. Engineering: Formatted quantity of NVM, identified by NSID, with its own LBA format and size. Confusion: Not a partition; not a controller. See: Part IX — NVMe Architecture.
Namespace Management
Expansion: Namespace Management (admin opcode 0Dh). Plain: Creating or deleting library sections. Engineering: Create/Delete namespaces; attachment via Namespace Attachment. See: Part XVIII — NVMe Advanced Features.
NAND
Expansion: NAND flash memory. Plain: Memory that keeps data without power. Engineering: Non-volatile memory organised in dies, planes, blocks, pages; erase-before-write; limited P/E cycles. See: Part II — Storage Fundamentals.
NLB
Expansion: Number of Logical Blocks. Plain: How many pages, minus one. Engineering: CDW12[15:0], zero-based count. Confusion: NLB=0 means 1 block. See: Part XI — NVMe Commands.
NN
Expansion: Number of Namespaces. Plain: How many sections the library may have. Engineering: Identify Controller field: maximum valid NSID. See: Part IX — NVMe Architecture.
No Snoop
Expansion: No Snoop attribute. Plain: "Don't check the CPU caches for this." Engineering: Attr bit indicating hardware coherency snooping not required. Confusion: Platform-dependent effect. See: Part V — PCIe Transaction Layer, Part VIII — DMA.
NQN
Expansion: NVMe Qualified Name. Plain: A globally unique name for a host or subsystem. Engineering: String identifier (e.g. nqn.2014-08.org.nvmexpress:uuid:...) used heavily in fabrics. See: Part XIX — NVMe over Fabrics.
NSID
Expansion: Namespace Identifier. Plain: The section number. Engineering: 32-bit identifier in SQE DW1; FFFFFFFFh is broadcast for some commands. See: Part IX — NVMe Architecture, Part XI — NVMe Commands.
NSSR
Expansion: NVM Subsystem Reset. Plain: Restarting the whole library building. Engineering: Register at 20h; writing 4E564D65h resets the subsystem if CAP.NSSRS=1. Confusion: Bigger scope than controller reset. See: Part XVI — Power and Reset.
Number of Queues
Expansion: Number of Queues (Feature 07h). Plain: Asking how many boxes you may have. Engineering: Requests/returns the number of I/O SQs and CQs allocated (zero-based). See: Part X — NVMe Queues.
NVM
Expansion: Non-Volatile Memory. Plain: Memory that remembers without power. Engineering: Generic term for storage media (NAND, etc.). Confusion: NVM Command Set ≠ NVMe. See: Part II — Storage Fundamentals.
NVM Subsystem
Expansion: NVM Subsystem. Plain: The whole library building. Engineering: Controllers, namespaces, media and ports forming one subsystem identified by NQN. See: Part IX — NVMe Architecture.
NVMe
Expansion: NVM Express. Plain: A fast way for computers to talk to storage. Engineering: Host-controller interface and command architecture with multiple queues; transports PCIe, RDMA, TCP, FC. Confusion: Not PCIe; not a form factor. See: Part III — Why NVMe Exists, Part IX — NVMe Architecture.
NVMe Boot
Expansion: NVMe Boot Specification. Plain: The rules for starting a computer from NVMe. Engineering: Specification covering boot over NVMe (notably NVMe-oF boot) — baseline revision 1.4. See: Part XVIII — NVMe Advanced Features.
nvme-cli
Expansion: nvme command-line tool. Plain: A remote control for NVMe drives. Engineering: Linux utility (linux-nvme/nvme-cli) for admin/IO commands and logs. Confusion: Some subcommands are destructive. See: Part XXI — Linux Practicals.
NVMe-MI
Expansion: NVMe Management Interface. Plain: A maintenance panel for the drive. Engineering: Specification for out-of-band (SMBus/I2C, PCIe VDM via MCTP) and in-band management of NVMe devices. See: Part XVIII — NVMe Advanced Features.
NVMe-oF
Expansion: NVMe over Fabrics. Plain: NVMe over a network. Engineering: Transports NVMe capsules over RDMA, TCP or Fibre Channel. Confusion: No doorbells or PRPs on the wire. See: Part XIX — NVMe over Fabrics.
NVMe/TCP
Expansion: NVMe over TCP. Plain: NVMe sent over ordinary networks. Engineering: Transport specification mapping capsules onto TCP PDUs. See: Part XIX — NVMe over Fabrics.

O

OACS
Expansion: Optional Admin Command Support. Plain: A list of extra admin tricks. Engineering: Identify Controller bytes 256–257 bitmap. See: Part XI — NVMe Commands.
ONCS
Expansion: Optional NVM Command Support. Plain: A list of extra I/O tricks. Engineering: Identify Controller bytes 520–521 bitmap (Compare, Write Uncorrectable, DSM, Write Zeroes, ...). See: Part XI — NVMe Commands.
Ordered Set
Expansion: Physical layer ordered set. Plain: Special signals that manage the road. Engineering: TS1, TS2, SKP, EIOS, EIEOS, FTS sequences for training and maintenance. Confusion: Not packets. See: Part IV — PCIe From Zero.
Over-provisioning
Expansion: Over-provisioning (OP). Plain: Spare empty shelves the customer can't see. Engineering: Physical capacity beyond user capacity; reduces WAF. See: Part II — Storage Fundamentals.

P

P/E cycle
Expansion: Program/Erase cycle. Plain: One write-and-wipe of a shelf. Engineering: NAND endurance unit; rated cycles depend on cell type. See: Part II — Storage Fundamentals.
Page (NAND)
Expansion: NAND page. Plain: One page in a notebook. Engineering: Program/read unit (e.g. 16 KiB) of NAND. Confusion: Not a memory page (MPS) nor an LBA. See: Part II — Storage Fundamentals.
PAM4
Expansion: Pulse Amplitude Modulation 4-level. Plain: Using four colours instead of two. Engineering: Signalling with 2 bits per symbol used by PCIe 6.0 at 64 GT/s. Confusion: Higher raw error rate → FEC. See: Part XVII — Advanced PCIe.
PASID
Expansion: Process Address Space ID. Plain: A label saying which program's address book to use. Engineering: TLP prefix (or FLIT header field) selecting an address space for ATS/SVA. See: Part XVII — Advanced PCIe.
PBA
Expansion: Pending Bit Array. Plain: A list of "missed calls". Engineering: MSI-X structure with one bit per vector set while masked. Confusion: Unrelated to bad blocks. See: Part XIV — Interrupts.
PCIe
Expansion: Peripheral Component Interconnect Express. Plain: A super-fast road inside the computer. Engineering: Packet-based, point-to-point serial interconnect with layered protocol (TL, DLL, PHY). Confusion: Not NVMe. See: Part IV — PCIe From Zero.
Percentage Used
Expansion: SMART Percentage Used. Plain: How much of the drive's life is used up. Engineering: Health log byte 5 vendor estimate of endurance consumed; can exceed 100. See: Part XV — Error Handling.
PERST#
Expansion: PCIe Reset signal. Plain: The big red reset wire. Engineering: Sideband fundamental reset signal on the connector. See: Part XVI — Power and Reset.
PF
Expansion: Physical Function. Plain: The main manager of a device. Engineering: Full-featured PCIe function with SR-IOV capability controlling VFs. See: Part XVII — Advanced PCIe.
Phase Tag
Expansion: CQE Phase Tag (P). Plain: A colour that changes every lap of the answer box. Engineering: CQE DW3 bit 16; inverts each time the controller wraps the CQ. Confusion: Not a status bit. See: Part X — NVMe Queues.
PI
Expansion: Protection Information. Plain: A checksum and label stuck to each page. Engineering: End-to-end data protection (Guard, Application Tag, Reference Tag) in metadata; T10 DIF-like. See: Part XVIII — NVMe Advanced Features.
PMR
Expansion: Persistent Memory Region. Plain: A small permanent shelf inside the drive. Engineering: Optional persistent memory exposed via a BAR (NVMe 1.4). Confusion: Not CMB. See: Part XVIII — NVMe Advanced Features.
Polling
Expansion: Completion polling. Plain: Checking the answer box without waiting for the lamp. Engineering: Driver spins on CQ phase instead of interrupts (Linux poll queues/io_uring IOPOLL). See: Part XIV — Interrupts, Part XXVIII — Performance Engineering.
Port
Expansion: NVM subsystem port. Plain: A doorway into the library. Engineering: Interface (e.g. a PCIe port) through which controllers are reached. See: Part IX — NVMe Architecture.
Posted
Expansion: Posted request. Plain: A letter that needs no reply. Engineering: Request type (MWr, Msg) without completion; ordering rules let posted pass non-posted. Confusion: No end-to-end confirmation. See: Part V — PCIe Transaction Layer.
Power State
Expansion: NVMe Power State. Plain: How much energy the drive is allowed to use. Engineering: Up to 32 power state descriptors in Identify; selected by Feature 02h or APST. Confusion: Separate from PCIe D-states. See: Part XVI — Power and Reset.
PQC
Expansion: Post-Quantum Cryptography. Plain: Locks that future super-computers can't pick. Engineering: Cryptographic algorithms resistant to quantum attacks; announced as an NVMe 2.4 highlight — consult the 2.4 text for scope. Confusion: Do not infer algorithms or commands not in the spec. See: Part XX — 2026 NVMe 2.4 Updates.
Protocol Analyzer
Expansion: PCIe protocol analyzer. Plain: A camera recording every parcel on the road. Engineering: Instrument capturing PCIe symbols/TLPs/DLLPs via interposer or probe, with decode and triggering. Confusion: Decodes are inferences. See: Part XXIII — Trace Analysis Laboratory.
PRP
Expansion: Physical Region Page. Plain: A list of table numbers where data goes. Engineering: 64-bit page pointer entries (PRP1, PRP2, PRP lists) describing data buffers. Confusion: Only PRP1 may have an offset. See: Part XII — PRP and SGL.
PRP List
Expansion: PRP List. Plain: The sheet listing remaining table numbers. Engineering: Page of PRP entries pointed to by PRP2 (or chained from the last entry of a previous list). See: Part XII — PRP and SGL.
PSDT
Expansion: PRP or SGL for Data Transfer. Plain: "Is this a table list or a map?" Engineering: CDW0 bits 15:14 selecting PRPs or SGLs. See: Part XII — PRP and SGL.

Q

QD
Expansion: Queue Depth. Plain: How many requests are waiting or being served. Engineering: Outstanding commands; Little's law links QD, IOPS and latency. Confusion: Driver QD ≠ device-internal parallelism. See: Part XXVIII — Performance Engineering.
QID
Expansion: Queue Identifier. Plain: The window number at the bank. Engineering: Identifies SQ/CQ; 0 = admin. See: Part X — NVMe Queues.
QSIZE
Expansion: Queue Size. Plain: How many slots a box has, minus one. Engineering: Create I/O CQ/SQ CDW10 bits 31:16, zero-based. See: Part X — NVMe Queues.

R

Rate Limiting
Expansion: Rate Limiting (NVMe 2.4). Plain: A speed limit for some traffic. Engineering: Capability announced in the NVMe 2.4 release; mechanism defined only in the normative text. Confusion: Version-dependent. See: Part XX — 2026 NVMe 2.4 Updates.
RC
Expansion: Root Complex. Plain: The roundabout at the centre of town. Engineering: Connects CPU/memory to the PCIe hierarchy; contains root ports. See: Part IV — PCIe From Zero.
RCB
Expansion: Read Completion Boundary. Plain: Where long replies may be split. Engineering: 64 or 128 B alignment at which completers may split read completions. See: Part V — PCIe Transaction Layer.
RDMA
Expansion: Remote Direct Memory Access. Plain: Reaching into another computer's memory directly. Engineering: Network transport family (InfiniBand, RoCE, iWARP) used by NVMe/RDMA. See: Part XIX — NVMe over Fabrics.
RDY
Expansion: Ready. Plain: "Open for business" sign. Engineering: CSTS bit 0; set after CC.EN=1 initialisation completes. See: Part IX — NVMe Architecture.
Recovery
Expansion: LTSSM Recovery. Plain: Pausing the road to fix or change something. Engineering: LTSSM state for retraining, speed change, L1 exit, error recovery. Confusion: Not necessarily a fault. See: Part IV — PCIe From Zero.
Relaxed Ordering
Expansion: Relaxed Ordering attribute. Plain: "This parcel may overtake earlier ones." Engineering: TLP Attr bit allowing relaxation of ordering rules. Confusion: Must not be used where ordering matters (e.g. CQE vs data) without care. See: Part V — PCIe Transaction Layer.
Replay

Requester ID

Reservation
Expansion: NVMe Reservations. Plain: Booking a section so only you can use it. Engineering: Commands for shared-namespace access control (Register, Acquire, Release, Report). See: Part XVIII — NVMe Advanced Features.
Restore Manufacturing Default Settings
Expansion: Restore Manufacturing Default Settings (NVMe 2.4). Plain: Putting settings back as they left the factory. Engineering: Capability announced in NVMe 2.4; consult the normative text for scope. Confusion: Not the same as Format or Sanitize. See: Part XX — 2026 NVMe 2.4 Updates.
Retimer

Retry Buffer

Root Port

S

U.2
Expansion: U.2 (SFF-8639) form factor. Plain: A 2.5-inch drive with a special plug. Engineering: 2.5-inch enterprise form factor/connector supporting PCIe x4 (and SAS/SATA on the same connector family). Confusion: Connector supports several protocols. See: Part II — Storage Fundamentals.
U.3
Expansion: U.3 (SFF-TA-1001). Plain: A universal plug for several drive types. Engineering: Tri-mode backplane convention allowing SAS/SATA/NVMe in the same bay. See: Part II — Storage Fundamentals.
UpdateFC
Expansion: UpdateFC DLLP. Plain: "I've freed up space, you may send more." Engineering: DLLP returning flow-control credits by type. See: Part VI — PCIe Data Link Layer.
UR
Expansion: Unsupported Request. Plain: "No such address / I don't do that." Engineering: Completion status 001b and AER error for requests the receiver doesn't support or claim. Confusion: For posted requests no completion is sent; error is logged/reported. See: Part V — PCIe Transaction Layer, Part XV — Error Handling.

V

VDM
Expansion: Vendor Defined Message. Plain: A custom note on the road. Engineering: Message TLP used for vendor/industry protocols such as MCTP. See: Part V — PCIe Transaction Layer, Part XVIII — NVMe Advanced Features.
Verify
Expansion: Verify (NVM opcode 0Ch). Plain: "Check that you could read it." Engineering: Verifies data/metadata integrity without transferring data. See: Part XI — NVMe Commands.
VF
Expansion: Virtual Function. Plain: A lightweight helper device. Engineering: SR-IOV function with minimal config space, sharing PF resources. Confusion: Not independent hardware. See: Part XVII — Advanced PCIe.
VFIO
Expansion: Virtual Function I/O. Plain: Handing a device directly to a program or VM. Engineering: Linux framework for safe user-space/VM device access through the IOMMU. See: Part XXI — Linux Practicals, Part XVII — Advanced PCIe.
Virtual Channel
Expansion: Virtual Channel (VC). Plain: Separate lanes painted on the same road. Engineering: Independent buffer/flow-control resources for traffic classes. See: Part XVII — Advanced PCIe.
Voltage Monitoring
Expansion: Voltage Monitoring (NVMe 2.4). Plain: Checking the drive's power supply health. Engineering: Capability announced in NVMe 2.4; consult the normative text. Confusion: Version-dependent. See: Part XX — 2026 NVMe 2.4 Updates.
VS
Expansion: Version register. Plain: Which edition of the rulebook the controller follows. Engineering: Register at 08h: MJR (31:16), MNR (15:8), TER (7:0). Confusion: Not a PCIe generation. See: Part IX — NVMe Architecture.
VWC
Expansion: Volatile Write Cache. Plain: A notepad the drive uses before writing in ink. Engineering: Identify Controller field and Feature 06h; if present and enabled, Flush/FUA needed for durability. See: Part XI — NVMe Commands.

W

WAF
Expansion: Write Amplification Factor. Plain: How many times more the drive writes than you asked. Engineering: NAND bytes written / host bytes written. See: Part II — Storage Fundamentals, Part XLV — Mathematics Appendix.
WAKE#
Expansion: Wake signal. Plain: A doorbell for waking the house. Engineering: Sideband signal for wake from L2. See: Part XVI — Power and Reset.
Wear Leveling
Expansion: Wear leveling. Plain: Using all shelves evenly so none wears out first. Engineering: FTL policy distributing P/E cycles. See: Part II — Storage Fundamentals.
Write Amplification
Expansion: Write amplification. Plain: Extra writing the drive does behind your back. Engineering: See WAF; caused by GC, metadata, alignment. See: Part II — Storage Fundamentals.
Write Pointer
Expansion: Zone write pointer. Plain: Bookmark showing the next empty line. Engineering: Per-zone LBA where the next write must occur. See: Part XVIII — NVMe Advanced Features.
Write Uncorrectable
Expansion: Write Uncorrectable (NVM opcode 04h). Plain: Marking pages as deliberately unreadable. Engineering: Marks LBAs invalid so reads return an error until rewritten; used in testing. See: Part XI — NVMe Commands.
Write Zeroes
Expansion: Write Zeroes (NVM opcode 08h). Plain: "Make these pages blank" without sending blanks. Engineering: Sets LBAs to zero (possibly by deallocation) without data transfer. See: Part XI — NVMe Commands.

Z

ZNS
Expansion: Zoned Namespaces. Plain: Notebooks you must fill in order. Engineering: Command set dividing a namespace into zones with write pointers; sequential write requirement; Zone Append. Confusion: Not just "SMR for SSDs"; host must manage zones. See: Part XVIII — NVMe Advanced Features.
Zone Append
Expansion: Zone Append (ZNS). Plain: "Write it at the end and tell me where." Engineering: Command writing at the zone's write pointer and returning the written LBA in the CQE. See: Part XVIII — NVMe Advanced Features.
