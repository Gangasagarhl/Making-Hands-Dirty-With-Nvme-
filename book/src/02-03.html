8 The Link Training and Status State Machine (LTSSM)

8.1 Why this chapter exists

Before a single NVMe command can move, two physical-layer state machines — one in the root port, one in the SSD — must walk from "is anybody there?" to "fully operational link". The Link Training and Status State Machine (LTSSM) defines that walk and everything that happens later: retraining after errors, speed changes, low-power states and resets. When a drive is missing, flapping, slow to appear after boot, or stuck at Gen1, the LTSSM is where the story is written. Software normally sees only its outcome; an analyzer or a vendor debug register shows the path.

Timeout values below are those widely documented for 3.x–5.x; confirm against your revision before using them for compliance work.

  • Intermediate: explain each substate's job, its exit conditions and its timeout.
  • Advanced: explain Recovery as the "repair shop" used for speed change, equalization, error recovery and L1 exit.
  • Senior: map symptoms (missing device, flapping, Gen1-only, slow boot) to the LTSSM state where the link is stuck.

8.2 Story and analogy

🧒 Kid analogy

Two kids in dark rooms connected by a tube. First each taps the tube to check someone is on the other side (Detect). Then they shout "hello hello hello" until they can both hear clearly (Polling). Then they agree "we'll use tubes 1 to 4 and you're kid number 0" (Configuration). Then they chat (L0). If the line gets crackly, they go back to saying "hello, can you hear me?" for a moment (Recovery). When bored, they doze (L0s / L1 / L2).

🧩 Where the analogy breaks

The kids decide things by talking; the LTSSM decides by counting consecutive identical ordered sets and by timeouts. There is no "conversation" with negotiation rounds as such: each side changes state when it has received N consecutive ordered sets with particular field values, or a timer fires. Also, both sides are not symmetric: the downstream port (root port or switch downstream port) leads link and lane numbering and equalization, the upstream port (the SSD) follows.

8.4 State by state

Detect (Detect.Quiet, Detect.Active)

Transmitter in electrical idle. Detect.Quiet waits up to 12 ms (or until a lane leaves electrical idle). Detect.Active performs receiver detection: the transmitter changes its common-mode voltage and measures how fast the line charges. A terminated receiver on the far side (with the AC coupling capacitor) charges slowly; an open line charges fast. If receivers are detected on all lanes → Polling. If none → back to Quiet. If some lanes → wait and retry once, then go to Polling with the detected lanes only — this is where a broken lane first reduces width.

Polling (Polling.Active, Polling.Compliance, Polling.Configuration)

Both sides transmit TS1 ordered sets with PAD for link and lane numbers. Receivers achieve bit lock and symbol lock (8b/10b) or block alignment (128b/130b; but initial training is always at 2.5 GT/s so 8b/10b is used), resolve polarity inversion, and advertise supported data rates. Polling.Compliance is entered when a lane sees no TS but detected a receiver and a compliance condition exists — it transmits the compliance pattern used by test equipment. A device stuck sending compliance patterns in a real system is a known failure signature (e.g. a load-board or a damaged lane).

Configuration

The downstream port proposes link numbers in TS1 on all lanes (Linkwidth.Start), the upstream port echoes link numbers on lanes it accepts (Linkwidth.Accept), the downstream port proposes lane numbers (Lanenum.Wait/Accept), lane reversal is resolved, both sides exchange TS2 (Complete), then send logical idle (Idle). On exit to L0, the Physical Layer reports LinkUp = 1 and the Data Link Layer starts flow-control initialization (InitFC1, InitFC2 — Chapter 16). Only after FC initialization does the link become DL_Active and TLPs can flow; the Data Link Layer Link Active bit in the downstream port's Link Status register reflects this verified.

L0

Normal operation: TLPs, DLLPs, SKP ordered sets. The link is at whatever rate it was trained to; immediately after first training this is 2.5 GT/s.

Recovery

Recovery re-establishes bit/block lock and is used for: changing speed (Recovery.Speed), equalization at 8 GT/s and above (Recovery.Equalization), exiting L1, recovering from errors (e.g. framing errors, replay rollover), and as a path to Hot Reset, Disabled, Loopback, or Configuration. Substates: RcvrLock (send TS1, wait for 8 consecutive TS1/TS2), RcvrCfg (send TS2, wait for 8 consecutive TS2), Speed (electrical idle while switching rate), Equalization (phases 0–3, Chapter 9), Idle (send idle data, then L0). A healthy Recovery takes microseconds; a looping Recovery appears to software as throughput collapse, AER correctable errors, and sometimes as Link Bandwidth Management Status events.

L0s

Low-latency, per-direction standby: a transmitter with nothing to send enters electrical idle and exits by sending Fast Training Sequences (FTS) — the count N_FTS was advertised during training. Optional ASPM state; removed in FLIT mode (6.0) in favor of L0p version.

L1

Deeper link standby: both directions idle, reference clock may be gated (L1 PM Substates L1.1/L1.2 go further). Entry is a DLLP handshake; exit always goes through Recovery. Exit latency is reported in Link Capabilities (L1 Exit Latency) and checked by the OS against device acceptable latency before enabling ASPM.

L2 (and L2/L3 Ready, L3)

Main power removed with auxiliary power present (L2) or absent (L3, not an LTSSM state as such — the link is simply off). Return to operation always restarts from Detect.

Hot Reset

An in-band reset propagated by TS1 with the Hot Reset bit. The upstream component resets its logic (conventional reset semantics for the function) and the link retrains through Detect. Linux uses it via the bridge's Secondary Bus Reset bit ("bus reset") verified.

Disabled

Link deliberately shut down via the Link Disable bit of the downstream port; the far side sees TS1 with the Disable bit and then electrical idle. Used to power off or isolate a device.

Loopback

A loopback master sends data that the loopback slave retransmits unchanged; used for BER testing with test equipment. Not entered in normal operation.

8.5 Hardware and protocol view

🔧 Hardware

The LTSSM runs in the PHY/MAC logic of each port; it is hardware (often with firmware assistance in complex SerDes). Observable: ordered sets on the wire (analyzer, oscilloscope with decoding), LnkSta/LnkSta2 bits, some vendors' LTSSM state/history registers impl. Internal and generally unobservable: receiver equalizer adaptation values, CDR lock state, internal timers.

In LnkSta, "DLActive+" means Data Link Layer Link Active (only reported if the port supports Data Link Layer Link Active Reporting), "Training+" indicates the LTSSM is in Configuration/Recovery at the moment of reading, and "BWMgmt+/ABWMgmt+" flags (Link Bandwidth Management Status / Link Autonomous Bandwidth Status) indicate the link changed speed or width since last cleared verified. Cannot prove: how many recoveries occurred, or the current substate.

⚠️ Warning

Setting the Retrain Link bit (LnkCtl bit 5 of the downstream port) or Secondary Bus Reset via setpci interrupts I/O, can cause data loss for in-flight writes, and may hang a system whose root filesystem is on the device. Do this only on test machines, on non-boot devices, after unmounting.

8.8 Common mistakes

  • Thinking speed is negotiated in Polling. Rates are advertised there, but changes happen in Recovery after L0.
  • Equating "L1" with NVMe power states. ASPM L1 is a link state; NVMe Power States/APST are controller states; they are related only by policy.
  • Assuming Recovery means error. Recovery is also normal for speed change and L1 exit.
  • Reading LnkSta on the endpoint only: Data Link Layer Link Active and many status bits are meaningful only on downstream ports.

Interview questions

    Model answerLink Training and Status State Machine; trains, maintains and power-manages the physical link.

    Model answerMeasuring line charge time after a common-mode step to see whether a terminated receiver is attached.

9 PCIe Link Training in Depth

9.1 Why this chapter exists

The LTSSM tells you which states exist; this chapter shows what is exchanged in them: the TS1 and TS2 training sequences, how lanes and speeds are negotiated, and the equalization procedure that makes 8 GT/s and faster possible. It ends with the lab the master curriculum requires: diagnosing a link that refuses to reach L0.

  • Describe TS1/TS2 fields and how they drive lane, width and speed negotiation.
  • Explain receiver detection and its failure modes.
  • Explain equalization phases 0–3, presets and coefficients, and when equalization reruns.
  • Diagnose training failures and link recovery events from evidence.

Prerequisites: Chapter 8.

🧒 Kid analogy

Training sequences are like name badges kids hold up repeatedly: "I'm on team PAD, seat PAD, I can run at speeds 1, 2, 3, 4". After a few rounds the leader writes team and seat numbers on the badges, everyone holds up their new badge 8 times in a row, and the game begins. Equalization is like adjusting a megaphone's bass and treble until the friend across the field hears each word clearly.

🧩 Where the analogy breaks

Badges are not "read once": receivers require consecutive identical ordered sets to filter noise. And in equalization the listener asks the talker to change the talker's transmitter settings — the megaphone is adjusted remotely by the person hearing it.

9.2 TS1 and TS2 ordered sets

Training Sequences are 16-symbol ordered sets sent on every lane. In 8b/10b mode (all initial training) the layout is:

Symbol0123456–15
FieldCOM (K28.5)Link Number (0–255 or PAD)Lane Number (0–31 or PAD)N_FTSData Rate IdentifierTraining ControlTS identifier: D10.2 (TS1) or D5.2 (TS2)
  • Link/Lane Number: PAD (K23.7) until the downstream port assigns numbers in Configuration.
  • N_FTS: number of Fast Training Sequences this receiver needs to exit L0s.
  • Data Rate Identifier: bit mask of supported rates (2.5, 5, 8, 16, 32 GT/s… plus 64 GT/s in 6.0) and a speed_change bit used in Recovery to request a rate change; also the autonomous-change indication version.
  • Training Control: bits for Hot Reset, Disable Link, Loopback, Disable Scrambling (8b/10b only), Compliance Receive.
  • TS identifier: distinguishes TS1 from TS2. In 128b/130b, TS ordered sets are carried in Ordered Set blocks; symbol 0 identifies TS1 (1Eh) or TS2 (2Dh), and symbols 6–9 carry equalization information (presets, coefficients, the transmitter's full-swing (FS) and low-frequency (LF) values) verified.

Why two kinds: TS1 means "I'm still training / proposing". TS2 means "I've accepted what I received and am ready to move on". Typical rule pattern: a substate exits when 8 consecutive TS2s with matching fields are received and enough TS2s (e.g. 16) have been sent after the first one was received — ensuring both sides advance together.

9.3 Receiver detection

Receiver detection is an analog measurement in Detect.Active: the transmitter steps its common-mode voltage; the time constant of the line depends on whether a receiver termination (DC impedance to ground at the far receiver, typically around 50 Ω single-ended during operation, with a specified high-impedance state when unpowered) is attached through the coupling capacitor. Failure modes: false negative (receiver present but not detected — wrong capacitor value, receiver not powered yet, retimer not ready) and false positive (detection on lanes that are routed to a connector with nothing behind it but some leakage path) impl.

If the USP returns PAD on lanes 2–3 (it cannot use them), the DSP re-proposes a narrower width (x2). If lane numbers come back reversed, the link uses lane reversal if either side supports it.

9.5 Speed negotiation

After first L0 at 2.5 GT/s, the downstream port (typically; either port can initiate) enters Recovery with the speed_change bit set in its TS1s and the highest common rate advertised. In Recovery.RcvrCfg both sides confirm with TS2 (speed_change set), enter Recovery.Speed (electrical idle while PLLs/CDR retune), and return to Recovery.RcvrLock at the new rate. For 8 GT/s and above, the first transition to each rate requires equalization. If RcvrLock cannot be achieved at the new rate within the timeout, the port falls back to the previous rate; implementations may retry or give up and stay low, which is how links end up "stuck at Gen3" impl. The platform can cap the target via the Target Link Speed field of Link Control 2.

9.6 Equalization phases 0–3

At 8 GT/s and above, channel loss closes the eye unless transmitter FIR coefficients (pre-cursor C−1, cursor C0, post-cursor C+1) and receiver equalizers are tuned for the specific channel. Equalization is a closed-loop procedure in Recovery.Equalization. Presets (P0–P10) are standard starting combinations of de-emphasis and preshoot verified.

Equalization is performed separately for 8, 16 and 32 GT/s (each rate's settings differ). PCIe 5.0 added optional mechanisms to bypass intermediate-rate equalization and go directly to the highest rate, and to skip equalization when settings are already known version. Retimers participate in equalization on each of their two sub-links. Results are reported in Link Status 2 (Equalization 8.0 GT/s Complete, Phase 1/2/3 Successful, Link Equalization Request) and in the 16/32 GT/s extended capabilities verified. Software can request re-equalization (Perform Equalization bit in Link Control 3) followed by a retrain — expert use only.

Link recovery is the normal mechanism that keeps marginal links alive: the DLL triggers Recovery after REPLAY_NUM rollover (4 replays of the same TLP), the PHY on framing errors. Recovery is cheap (µs) compared to Detect (ms) and invisible to NVMe unless it repeats or fails.

9.8 Lane margining

PCIe 4.0 introduced Lane Margining at the Receiver: software can ask a receiver to shift its sampling point in time and voltage and report errors, measuring eye margin in-system version. Recent pciutils includes a margining utility (pcilmr) version; support depends on the device impl. Margining runs while the link is in L0 and can cause errors on the measured lane — treat as a CAUTION operation.

Procedure: (1) Determine the furthest LTSSM state reached. (2) List hypotheses consistent with E1–E4. (3) Use E5 to rank. (4) Propose a disambiguating experiment that does not risk data.

Questions: Why does detection succeed while Polling fails? Which evidence rules out "no device"? What would you expect if PERST# were held?

Solution

(1) Furthest state: Polling.Active. Receivers were detected, so the SSD's receivers present termination — the device is physically present and at least partially powered (E2 presence detect agrees). (2) The SSD never transmits recognizable TS1: candidates are PERST# held asserted, missing or incompatible reference clock, SSD firmware/PHY not starting, broken TX pairs. (3) E5 shows a clocking mismatch: the backplane runs separate-reference independent-SSC (SRIS) while the SSD claims common-clock only — its CDR or elastic buffers cannot tolerate the frequency offset/SSC difference, or it never gets a REFCLK at all if the backplane does not route it in SRIS mode. Rank: clocking mismatch (highest), PERST# (check timing), TX lanes damaged (less likely on all four lanes). (4) Experiment: move the SSD to a slot configured for common clock (or change the backplane setting on a test system), or test a known SRIS-capable SSD in the same slot. If the known-good SRIS device trains and the original SSD trains in a common-clock slot, the conclusion is clock-mode incompatibility (high confidence). If PERST# were held, the device would typically keep its PHY in reset — the same TX silence — so a scope on PERST# distinguishes the two.

🧪 Lab 9.2 — Read equalization outcomes on a real system SAFE

Objective: find equalization status for each Gen3+ link. Steps: sudo lspci -vv | grep -E '^[0-9a-f]|LnkSta2|EqualizationComplete'. Observations: for links at ≥8 GT/s, EqualizationComplete+ and Phase1+/2+/3+ are expected. Questions: what does a link at 16 GT/s with Phase3- imply?

    The USP (it evaluates the signal it receives from the DSP).

  3. Is equalization done once for all rates?

    Answer

    No, per rate (8, 16, 32 GT/s), with optional bypass mechanisms in newer revisions.

  4. What triggers Recovery after repeated replays?

    Answer

    REPLAY_NUM rollover in the Data Link Layer.

Interview questions

  1. Beginner What is a TS1?
    Model answerA training ordered set carrying link/lane numbers, N_FTS, supported rates and training control, used during training.
  2. Intermediate Why are presets needed?
    Model answerTo start equalization from a known transmitter shape that likely gives an open-enough eye for phase 1 communication.
  3. Intermediate Why does every link start at 2.5 GT/s?
    Model answerUniversal compatibility; rate capabilities are exchanged during initial training and higher rates are reached via Recovery.
  4. Advanced What happens in Recovery.Speed?
    Model answerTransmitters go to electrical idle while both sides switch rate; then RcvrLock at new rate; failure leads to fallback.
  5. Advanced How do retimers affect equalization?
    Model answerThey split the link into two sub-links equalized separately and must pass/forward training per spec retimer rules; timeouts are extended.
  6. Senior Gen5 SSD trains at Gen5 in one server model, Gen4 in another. Approach?
    Model answerCompare channel (trace length, riser, retimer), BIOS EQ settings/presets, LnkCtl2, equalization status, margining; involve platform SI team with evidence.
  7. Senior What can't software know about training?
    Model answerSubstate history, coefficient values chosen, receiver adaptation, how close to failure the link is (except via margining).
