54 Equalization — Opening the Eye at 8 GT/s and Beyond

📘 Specification baseline

DOCUMENT: PCI Express Base Specification — Physical Layer electrical sub-block, LTSSM Recovery.Equalization substate, Secondary PCI Express Extended Capability (8 GT/s lane equalization control), Physical Layer 16 GT/s / 32 GT/s / 64 GT/s Extended Capabilities, Lane Margining at the Receiver. STATUS: normative. VERSION NOTES: equalization first became mandatory for 8 GT/s (Gen3); each higher rate (16, 32, 64 GT/s) has its own equalization procedure and preset tables; later revisions add options to skip or shorten equalization when previously learned settings are trusted version. Gen6 uses PAM4 signalling with FLIT mode and FEC; Gen7 (128 GT/s, specification released 2025) continues PAM4 version.

54.1 Why this chapter exists

An NVMe SSD that trains to Gen4 x4 instead of Gen5 x4, or that trains to Gen5 and then logs thousands of correctable Receiver Errors, is almost always an equalization or signal-integrity story. You will never decode a TLP that explains it. You need to know how the two ends tune their transmitters, where the result is recorded, and what you can and cannot see from software.

  • Explain inter-symbol interference (ISI) and why channel loss grows with frequency.
  • Describe transmitter de-emphasis/pre-shoot: pre-cursor, cursor, post-cursor coefficients and presets.
  • Walk through equalization Phases 0–3 and who tunes whom.
  • Read Link Status 2 equalization bits and interpret “Equalization Complete / Phase N Successful”.
  • Diagnose speed downgrades and correctable-error storms caused by poor equalization.

Prerequisites: LTSSM states (LTSSM: Detect, Polling, Configuration, L0, Recovery), encoding (8b/10b, 128b/130b), Chapter 53 for why replay storms hurt throughput.

🧒 Kid analogy — shouting across a canyon

Two friends shout numbers across a canyon. Every shout echoes, and the echo of “seven” smears into the next word “three”. So each friend learns to shout the start of a word louder and soften the tail, so the echo matters less. They try different shouting styles (presets), and the listener says “try a bit more emphasis” until every number is heard clearly. Then they swap roles.

🧩 Where the analogy breaks

The receiver also has its own equalizer (CTLE, DFE) that it tunes privately; only transmitter settings are negotiated in-band. And the “listener’s feedback” is not a perceptual judgement but an implementation-specific figure of merit (eye height/width, error counts) that the specification does not define.

54.2 Engineering view

At 8 GT/s and above the PCB trace, connector and package attenuate high frequencies far more than low ones. A long run of identical bits followed by a transition is smeared by ISI. The transmitter compensates with a 3-tap FIR filter: a pre-cursor coefficient (C−1), the cursor (C0), and a post-cursor coefficient (C+1). Combinations are summarised as presets P0–P10, each defining pre-shoot and de-emphasis in dB. verified (preset count and table values per rate: check the electrical chapter of your revision).

Equalization is run inside the LTSSM’s Recovery.Equalization substate when the link changes to a rate that needs it (8 GT/s, then separately 16, 32, 64 GT/s). Software can request re-equalization via Link Control 3 “Perform Equalization”, and a port can request it via the “Link Equalization Request” status. verified The algorithm each receiver uses to evaluate coefficients is impl.

54.3 Hardware view

🔧 Hardware

Each lane has its own transmitter FIR and receiver CTLE/DFE. Equalization is per lane, so one bad lane (damaged connector pin, crosstalk) can force the entire link down in speed or width. Retimers participate in equalization on each of their link segments, which multiplies the number of phases that can fail. M.2 and U.2/E3.S SSDs behind long backplanes with retimers are the classic hard case.

55 Advanced Error Handling — AER, DPC and Recovery

📘 Specification baseline

DOCUMENT: PCI Express Base Specification — Error Signaling and Logging, Advanced Error Reporting (AER) Extended Capability, Downstream Port Containment (DPC) Extended Capability; Linux kernel PCI error recovery documentation (Documentation/PCI/pci-error-recovery.rst, pcieaer-howto.rst). STATUS: normative (PCIe) and informative (Linux). VERSION NOTES: DPC was added as an ECN to 3.x and integrated later; error types have been added over revisions (e.g. ACS Violation, Poisoned TLP Egress Blocked, DMWr-related) version.

55.1 Why this chapter exists

When an NVMe drive is surprise-removed, its link flaps, or its firmware returns a malformed TLP, the platform must decide: log and continue, reset the link, or crash. AER is how errors are reported and logged; DPC is how a downstream port stops a sick device from poisoning the rest of the system; the OS error-recovery framework is how the NVMe driver gets a chance to recover. If you work on enterprise SSDs, hot-plug, or fleet reliability, you will read AER logs weekly.

  • Classify errors: correctable, uncorrectable non-fatal, uncorrectable fatal; and by layer.
  • Read AER registers: status, mask, severity, header log, first error pointer, Root Error Status, Error Source ID.
  • Explain DPC triggering, containment and release.
  • Follow the Linux recovery flow: error_detected → mmio_enabled/slot_reset → resume, and what the NVMe driver does.
  • Diagnose surprise removal vs link instability vs device-internal error.

Prerequisites: completion statuses, link health, AER, ECRC, LCRC.

🧒 Kid analogy — the fire alarm and the fire door

Every room has a smoke detector that writes in a notebook what happened (AER logging). Small problems — burnt toast — are written down and everyone keeps working (correctable). Bigger problems ring the alarm at the head office (the root port). For a real fire, the hallway has a fire door (DPC) that slams shut automatically so the fire cannot spread, even before the head office decides what to do. Afterwards, the caretaker (the OS) checks the room, cleans up, and reopens the door.

🧩 Where the analogy breaks

After DPC closes the “door”, the device behind it is effectively gone: in-flight requests to it are completed with error status by the port, and the device sees its link go down, which typically resets it. The “room” does not keep its state. Also, the notebook (header log) only records the first error of its kind in detail.

55.4 Downstream Port Containment

When triggered, the downstream port transitions its link to a disabled state and sets DPC Trigger Status and Trigger Reason. While contained, requests targeting the device are completed by the port (typically UR or an all-ones read response at the CPU) impl. Software (Linux pcieport DPC service) handles the interrupt, runs driver recovery callbacks, then clears Trigger Status to release the link. Enhanced DPC (eDPC) adds Root Port Programmed I/O (RP PIO) error handling for CPU-originated non-posted requests. verified at concept level; the exact Linux log wording is version.

55.5 Linux recovery and the NVMe driver

// Conceptual flow of PCI error recovery as seen by a driver (Linux pci_error_handlers)
on AER uncorrectable or DPC event at a port:
    for each affected driver: state = err_handler.error_detected(dev, channel_state)
        // NVMe: normal_frozen  -> quiesce queues, return NEED_RESET
        //       perm_failure  -> mark controller dead, return DISCONNECT
    if link was reset (fatal or DPC): reset_link / secondary bus reset
    for each driver: err_handler.slot_reset(dev)    // NVMe: restore config, re-init controller
    for each driver: err_handler.resume(dev)        // NVMe: restart I/O, requeue
if any step returns DISCONNECT: device is removed; I/O fails upward

The Linux NVMe PCI driver implements these callbacks verified (see drivers/nvme/host/pci.c, nvme_err_handler). Exact behaviour and timeouts vary with kernel version version.

🧪 Lab 55.1 — Decode an AER header log SAFE

Objective: decode a synthetic Header Log captured at a root port that logged Malformed TLP: 40000040 3b0001ff 3fe5a000 00000000 (illustrative). The root port and SSD both have MPS = 128 bytes. Steps: decode Fmt/Type, Length, Requester ID, Tag, byte enables and address. Questions: what kind of TLP is this? Who sent it? Why is it malformed?

Solution

DW0 40000040: Fmt 010b (3-DW header with data), Type 00000b ⇒ MWr with 32-bit address; Length 040h = 64 DW = 256 bytes. DW1 3b0001ff: Requester ID 3B00h (bus 3Bh, device 0, function 0 — the SSD), Tag 01h, Last DW BE Fh, First DW BE Fh. DW2 3FE5A000h is the address. DW3 is not part of a 3-DW header and carries no meaning here. The payload (256 B) exceeds the programmed MPS (128 B), which is a Malformed TLP condition at the receiver. Next questions: is the SSD’s DevCtl MPS really 128 (did firmware ignore it, or did software reprogram MPS after the device cached a value)? Lesson: the error name says “malformed”; only the decoded header says “payload larger than MPS, from the SSD”.

Extension: repeat with a 4-DW MRd header and identify the 64-bit address.

Quiz

  1. Which message does a device send for a Completion Timeout with default severity?

    Answer

    ERR_NONFATAL.

  2. What does DPC do that AER alone does not?

    Answer

    It contains the error in hardware by disabling the link at the downstream port, preventing further corrupted traffic before software reacts.

  3. Why do MMIO reads return all ones after a surprise removal?

    Answer

    The request fails (UR/containment) and the Root Complex synthesises an all-ones value for the CPU load; the driver must treat all ones in CSTS as “device gone”.

📘 Specification baseline

DOCUMENTS: PCI Express Base Specification — Single Root I/O Virtualization and Sharing (SR-IOV) Extended Capability, Alternative Routing-ID Interpretation (ARI); NVMe Base Specification 2.4 — Virtualization Enhancements (primary/secondary controllers, flexible resources, Virtualization Management command). 56.1 Why this chapter exists

Cloud hosts give each virtual machine (VM) its own NVMe controller by exposing SR-IOV Virtual Functions (VFs) and passing them through. The VM’s guest driver talks directly to hardware queues — no hypervisor in the data path. To debug or validate this you need to know what is a PCIe concept (PF, VF, routing ID, VF BARs), what is an NVMe concept (primary controller, secondary controller, flexible queue and interrupt resources), and what is entirely implementation-specific (how bandwidth is shared, how isolation is enforced internally).

  • Explain Physical Function (PF) and Virtual Function (VF) and how VF Routing IDs are computed.
  • Read the SR-IOV capability: TotalVFs, InitialVFs, NumVFs, First VF Offset, VF Stride, VF Device ID, VF BARs, VF Enable.
  • Map PF/VF to NVMe primary/secondary controllers and flexible resources (VQ, VI).
  • Enable VFs on Linux and assign them to VMs safely.
  • Diagnose common SR-IOV failures: VF not appearing, VF controller not ready, interrupt starvation, IOMMU group issues.

Prerequisites: BDF and config space (BDF, BAR), MSI-X, NVMe queues (SQ, CQ), IOMMU (IOMMU), IDO.

🧒 Kid analogy — one kitchen, many serving windows

A restaurant has one big kitchen (the SSD) and one head chef (the PF). The owner opens several little serving windows (VFs), each with its own order slot and its own bell. Customers at window 3 cannot see window 5’s orders. The head chef decides how many cooks and order slots each window gets (flexible resources) and can close a window for maintenance.

🧩 Where the analogy breaks

The windows share the same stove (NAND, controller cores, PCIe link), so a greedy window can slow others unless the device enforces QoS — and how it does so is not defined by SR-IOV. Also the windows share the storage only if namespaces are attached to several controllers; by default each VF sees only what the PF administrator attaches to it.

56.3 NVMe view — primary and secondary controllers

In NVMe virtualization, the PF’s controller is a primary controller and each VF’s controller is a secondary controller. The primary controller manages flexible resources: Virtual Queue resources (VQ) and Virtual Interrupt resources (VI), which are assigned to secondary controllers before they are brought online. The admin command Virtualization Management (admin opcode 1Ch) assigns resources and sets secondary controllers online/offline. Identify returns a Primary Controller Capabilities structure and a Secondary Controller List. verified at concept level; confirm exact CNS values and field layouts in Base 2.4 version.

// Typical bring-up order (conceptual; check device documentation)
1. PF driver loaded; read Primary Controller Capabilities (total VQ/VI flexible, granularity)
2. Virtualization Management: assign VQ resources to secondary controller k
3. Virtualization Management: assign VI resources to secondary controller k
4. Enable VFs at the PCIe level (sriov_numvfs = N)          // VF config spaces appear
5. Virtualization Management: set secondary controller k Online
6. Attach namespace(s) to controller k (Namespace Attachment)
7. Pass VF to VM; guest NVMe driver enables controller (CC.EN=1) normally
🏭 Implementation-dependent

Whether steps 2–5 must happen before or after VF Enable, whether resources can be changed while a VF is enabled, whether a device supports private (fixed) resources only, and how bandwidth/IOPS are partitioned among VFs, all vary by product. Some devices pre-assign resources and need no Virtualization Management at all.

💡 Senior insight

Draw two boundaries on every SR-IOV whiteboard: the PCIe boundary (config space, RIDs, BARs, MSI-X tables, IOMMU) and the NVMe boundary (controller IDs, queues, namespaces, resources). Most customer escalations are on the line between them: the PCIe side says “VF exists”, the NVMe side says “controller offline”. Live migration of such controllers is exactly what the 2026 “PCIe Exported NVM Subsystem Migration” topic sits next to.

🧪 Lab 56.1 (Extended Lab 47) — Conceptual PF/VF topology SAFE

Objective: build a paper model of an SR-IOV NVMe SSD and classify each property as specification-defined (PCIe or NVMe) or implementation-specific. Prerequisites: this chapter. Setup: PF at 3b:00.0, First VF Offset = 1, VF Stride = 1, NumVFs = 4, VF BAR0 size 16 KiB, flexible VQ total 64, VI total 32.

  1. Identity: compute each VF’s BDF.
  2. Resources: split VQ/VI so VF1 gets twice the queues of the others; remember each controller needs an admin queue pair.
  3. Isolation: list what isolates VF1 from VF2 (RID-based IOMMU, separate BAR slices, separate controllers) and what does not (NAND, link bandwidth).
  4. Queues and interrupts: how many I/O queue pairs can VF1’s guest create? How many MSI-X vectors?
  5. Virtualization: what changes if NumVFs becomes 8 with the same BAR?

Observations: identity and address isolation are PCIe-defined; queue/interrupt resources are NVMe-defined; performance isolation is implementation-specific.

Solution

BDFs 3b:00.1–3b:00.4. VF BAR0 region = 4 × 16 KiB = 64 KiB carved contiguously. A split such as VF1 = 24 VQ, VF2–4 = 13/13/14 VQ (total 64), VI 12/7/7/6 (total 32) — exact granularity per Primary Controller Capabilities. Whether VQ counts include the admin queue is defined in the Base spec’s virtualization section — check it; this is a classic off-by-one. With NumVFs = 8, First VF Offset/Stride may change (they are allowed to depend on NumVFs) and BAR slices double in count; check System Page Size alignment.

Extension (intermediate): on a real lab SSD, read primary-ctrl-caps and list-secondary and fill your model with real values. Advanced: design a test that measures noisy-neighbour impact. Senior forensic: given a guest log showing controller not ready, enumerate the evidence needed from the host to locate the fault.

Quiz

  1. What is VF 3’s RID if PF = 3b:00.0, offset 4, stride 2?

    Answer

    RID offset = 4 + 2×2 = 8 ⇒ function 8, which requires ARI ⇒ with ARI the RID is bus 3Bh, function number 8 (displayed as 3b:01.0 in non-ARI notation).

  2. Which NVMe command assigns flexible resources?

    Answer

    Virtualization Management (admin opcode 1Ch).

  3. Does SR-IOV guarantee performance isolation?

    Answer

    No; it defines functional separation. Performance isolation is implementation-dependent.

Interview questions

  1. Beginner What is a VF?
    Model answerA lightweight PCIe function created by a PF via the SR-IOV capability, with its own RID, BAR slice and MSI-X, sharing the device’s hardware.
  2. Intermediate Why does a VF’s Vendor ID read FFFFh?
    Model answerThe SR-IOV design makes several VF config fields read-only or not implemented to save hardware; software identifies VFs through the PF’s SR-IOV capability.
  3. Advanced Primary vs secondary controller?
    Model answerThe primary controller (on the PF) manages flexible resources and secondary controller state; secondary controllers (on VFs) are ordinary NVMe controllers from the guest’s view once online.
  4. Senior How would you validate VF isolation?
    Model answerNegative tests: VF DMA to addresses outside its IOMMU domain must fault; namespace not attached must be invisible; reset of one VF must not affect another; performance tests with noisy neighbours; error injection on one VF and check others continue.
📌 Summary

PCIe SR-IOV creates functions; NVMe virtualization turns them into resourced, online controllers; namespace attachment gives them storage; performance isolation is up to the device.
