83 Failure Library III: NVMe Queues, Commands, Media and Firmware

NVMe-layer failures live in the contract between host memory structures (queues, PRPs, SGLs) and controller behavior. Your best tools are the Lab 3–8 decoders, the error log, and an analyzer that saw queue creation.

  • Locate the broken stage of the command chain.
  • Use CQE status, error log and Async Events as first-class evidence.
  • Separate host data-structure bugs from controller bugs from media problems.

F13 — Missing NVMe completion

SymptomsI/O ... timeout, aborts, resets; application hangs ~30 s
Likely layersAny stage: doorbell, fetch, controller, CQE posting, interrupt, host processing
Trace signatureChain stops at a stage (Lab 8 classification): no fetch / fetch without CplD / SQE without data / data without CQE / CQE without MSI-X
Linux evidenceTimeout line with QID and tag; "completion polled" variant indicates CQE existed
NVMe evidenceError log (often empty); CSTS (CFS?); Abort result
PCIe evidenceAER CmpltTO (fetch stage), UR (bad address)
First checkKernel message variant; AER around the doorbell time (≈ timeout − 30 s)
Disambiguating experimentAnalyzer with Lab 8 classification; or polled-queue experiment (lab: nvme.poll_queues) to bypass interrupts
Likely root causesController FW hang for a command type; lost interrupt (F24); CQ full due to host not updating head; SQE fetch completion lost (F9)
RemediationFix the owning stage
Regression testLong soak with mixed opcodes; Lab 8 detector on sampled captures; zero timeouts

F14 — Queue corruption

SymptomsRandom Invalid Opcode / Invalid Field errors; wrong data returned; controller fatal
Likely layersHost memory management (driver), DMA coherency, rarely controller
Trace signatureSQE CplD payload containing garbage (unexpected opcode, NSID, PRPs); CQE written to unexpected slot
Linux evidenceError completions with odd status; KASAN/memory corruption reports in debug kernels
NVMe evidenceError log with parameter error location pointing at corrupted fields
PCIe evidenceSQE payload in CplD
First checkDecode the fetched SQE: is it what the host intended to write (driver trace)?
Disambiguating experimentDriver-side logging of SQE contents at submission vs SQE as fetched; debug kernel (KASAN); IOMMU strict
Likely root causesMissing memory barrier before doorbell (SQE not visible when fetched); buffer reuse; non-coherent DMA mapping misuse
RemediationCorrect ordering (write SQE, barrier, then doorbell); lifetime fixes
Regression testStress on weakly-ordered architectures with SQE checksum validation in a test driver

F15 — Wrong doorbell

SymptomsNo I/O completes on some queues; Async Event errors; controller fatal on some devices
Likely layersHost driver/harness (doorbell offset computation)
Trace signatureDoorbell MWr to an address that is not the intended queue's register; no SQE fetch follows (TL-8)
Linux evidenceTimeouts; for in-kernel driver rare (bug would be universal)
NVMe evidenceAsynchronous Event: error status (invalid doorbell register / write value) impl
PCIe evidenceDoorbell address vs 1000h + (2y [+1]) × (4 << CAP.DSTRD)
First checkRead CAP.DSTRD (nvme show-regs) and recompute doorbell offsets
Disambiguating experimentRun harness on devices with different DSTRD
Likely root causesHard-coded stride; queue ID mix-up (SQ vs CQ)
RemediationCompute from CAP
Regression testEmulated devices with DSTRD 0/1/2

F16 — Wrong queue pointer (tail/head)

SymptomsCommands executed twice or never; stale CQEs consumed; Invalid Doorbell Write Value events
Likely layersHost driver queue accounting
Trace signatureDoorbell value beyond queue size; tail moving backwards; SQE fetch of slots never written; CQ head doorbell ahead of posted CQEs
Linux evidenceDuplicate completions, "invalid id" style driver warnings version
NVMe evidenceAsync Event error; CQE SQHD inconsistent with host view
PCIe evidenceDoorbell payloads sequence; SQ fetch addresses
First checkPlot doorbell values over time per queue: monotonic modulo size?
Disambiguating experimentVary queue size (e.g. 2, 3, 64, 1024 entries) to expose wrap bugs; check the "one slot empty" full-queue rule
Likely root causesOff-by-one on wrap; 0-based QSIZE confusion; missing phase flip on wrap
RemediationFix accounting
Regression testQueue-size sweep with millions of wraps; Lab 7 correlator must report zero anomalies

F17 — Invalid PRP

SymptomsInvalid PRP Offset / Invalid Field / Data Transfer Error statuses; or silent corruption
Likely layersHost driver PRP construction; IOMMU
Trace signaturePRP entries with non-zero offsets beyond PRP1; list pointer to unmapped memory; data MWr to unexpected pages
Linux evidenceI/O errors; IOMMU faults
NVMe evidenceCQE status; error log parameter location (PRP field)
PCIe evidencePRP list CplD payload; UR completions
First checkDecode SQE PRPs and list contents with Lab 5
Disambiguating experimentUnaligned-buffer I/O tests (O_DIRECT with various offsets); transfer sizes around page and list boundaries
Likely root causesOffset arithmetic bug; list chaining bug at 512-entry boundary; buffer not page-aligned when assumed
RemediationFix builder; validate PRPs in debug builds
Regression testSize/offset sweep (4 KiB × n ± 512 B, list-chaining sizes) with data verification

F18 — Invalid SGL

SymptomsSGL-related error statuses (e.g. SGL descriptor type invalid, data SGL length invalid, invalid number of SGL descriptors); Invalid Field when SGLs unsupported
Likely layersHost SGL construction; controller SGL support
Trace signatureSQE PSDT ≠ 00b; SGL segment fetch MRds; descriptor contents inconsistent with transfer length
Linux evidenceI/O errors; driver choosing SGL vs PRP depends on size thresholds and device support version
NVMe evidenceIdentify Controller SGLS field (support); CQE status
PCIe evidenceSGL segment CplD payloads
First checkDoes the controller support SGLs for this command set (SGLS)?
Disambiguating experimentForce PRP path (driver parameter, lab) — errors disappear?
Likely root causesUsing SGLs on a controller that lacks support; descriptor length sum ≠ transfer length; wrong descriptor type/subtype
RemediationHonor SGLS; fix descriptor builder
Regression testSGL descriptor matrix (data block, segment, last segment, bit bucket if supported)

F19 — Controller fatal (CSTS.CFS)

SymptomsAll I/O stops; driver resets controller; may recover or loop
Likely layersController firmware/hardware; host register misuse (TL-9)
Trace signatureMMIO read of CSTS returns CFS=1; I/O activity ceases; sometimes preceded by host writes violating init order
Linux evidencecontroller is down; will reset: CSTS=0x3-style messages (bit 1 = CFS); note CSTS=0xffffffff means device not responding (different!)
NVMe evidenceTelemetry log (controller-initiated) if supported; vendor logs
PCIe evidenceLink healthy (distinguishes from surprise down)
First checkCSTS value: CFS vs all-ones
Disambiguating experimentReproduce with captured host register sequence; FW A/B
Likely root causesFirmware assert; internal hardware error; illegal host programming
RemediationFW fix; host init-order fix
Regression testStress + reset-injection suite; telemetry collection automated

F20 — Media error

SymptomsRead I/O errors on specific LBAs; long-latency reads (successful after retries)
Likely layersMedia (NAND), controller ECC/error recovery
Trace signatureNormal link traffic; CQE with SCT 2h (Media and Data Integrity), e.g. Unrecovered Read Error; or long SQE→data gap (Lab 80.1)
Linux evidenceI/O error, dev nvme0n1, sector …; critical medium error messages
NVMe evidenceSMART media_errors increment; error log entry with LBA; critical_warning bits
PCIe evidenceNone abnormal
First checkError log LBA and status; SMART deltas
Disambiguating experimentLab copy only: re-read the LBA; rewrite and re-read; check whether the error is persistent
Likely root causesAged/worn NAND, retention loss, read disturb, defect
RemediationRestore data from redundancy; rewrite; replace drive if spare/critical warnings
Regression testNot a code regression — monitoring: SMART thresholds, scrub schedule
⚠️ Data safety

Never "test" a media error by writing to the LBA on a production drive — rewriting destroys the evidence and possibly the only copy of data. Work on lab drives or on images.

F21 — Namespace error

SymptomsInvalid Namespace or Format; Namespace Not Ready; namespace missing after management operations; write-protected namespace errors
Likely layersNVMe namespace management, host configuration, multipath
Trace signatureSQE with NSID not attached to this controller; CQE generic error status
Linux evidenceMissing nvme0nX; rescan messages; I/O errors
NVMe evidenceIdentify active namespace list (CNS 02h), namespace attachment state, Changed Namespace List log (04h)
PCIe evidenceNone
First checknvme list-ns / id-ns for the NSID; was a namespace operation performed?
Disambiguating experimentRescan; compare active NS list across controllers of the subsystem
Likely root causesNamespace detached/deleted; format in progress; host using stale NSID; write protection state
RemediationCorrect attachment; wait for readiness; refresh host view
Regression testNamespace create/attach/detach cycles with I/O running (lab drives only)

F22 — Firmware issue

SymptomsNew behavior after FW update: timeouts, latency shifts, CFS, feature changes; activation failures
Likely layersController firmware; update process
Trace signatureSame host traffic, different device timing or responses compared with golden trace on old FW
Linux evidenceCorrelates with fw update date; fw-log active slot change
NVMe evidencefw-log, Identify FR, Firmware Commit status (e.g. activation requiring reset)
PCIe evidenceUsually none; link-level FW changes possible
First checkGolden trace diff old vs new FW with identical host
Disambiguating experimentA/B FW on same hardware, same host, same workload; bisect FW versions if available
Likely root causesFW regression; incompatible feature default change; interrupted activation
RemediationVendor fix; roll back (if permitted by FW slot/rollback policy)
Regression testQualification suite with golden-trace comparison per FW release
⚠️ Firmware changes

Firmware download/commit is state-changing and can render a drive unusable if interrupted or if the image is wrong. Lab-only, vendor-approved images, verified power, and a recovery plan.

84 Failure Library IV: Interrupts, Performance, Power and Reset

System-level failures are where layers interact: interrupts cross PCIe, the platform's interrupt remapping and the OS; performance depends on everything; power management and reset touch the link, the controller and the driver at once.

  • Diagnose interrupt-path failures with MSI-X table/PBA evidence.
  • Separate performance limits by resource (link, controller, media, CPU, queueing).
  • Debug power-state and reset/resume sequences.

F23 — MSI-X problem (configuration)

SymptomsAll I/O completions slow or only via polling; fewer queues than expected; interrupts land on one CPU
Likely layersHost interrupt allocation, MSI-X capability, platform interrupt remapping
Trace signatureMSI-X MWr to unexpected address/data; no MSI-X MWr at all with legacy INTx Assert/Deassert messages instead
Linux evidencelspci -vv MSI-X Enable-/Count; /proc/interrupts; driver log "x/y/z default/read/poll queues"
NVMe evidenceGet Features Number of Queues (07h); Interrupt Vector Configuration (09h)
PCIe evidenceMSI-X capability, table contents via host debug interfaces
First checkMSI-X enabled and vectors allocated = queues
Disambiguating experimentBoot with different nvme queue parameters; check platform interrupt-remapping logs
Likely root causesVector exhaustion; remapping failure; virtualization config
RemediationKernel/platform configuration
Regression testBoot-time checks on vector counts; per-queue interrupt delta test

F24 — Interrupt loss

SymptomsExact io_timeout stalls with "completion polled"; per-queue hangs
Likely layersHost interrupt management (mask/unmask, affinity), platform, rarely device
Trace signatureCQE MWr not followed by MSI-X MWr (masked vector or device omission) — TL-6
Linux evidenceTimeout + polled message; affinity changes at the time
NVMe evidenceInterrupt Coalescing feature (rule it out)
PCIe evidenceMSI-X Vector Control mask bits; PBA pending bits
First checkIs the CQE present when the timeout fires?
Disambiguating experimentPin IRQ affinity (stop irqbalance) — stalls vanish? PBA read after stall
Likely root causesMask without unmask in affinity path; interrupt remapping race; device not sending for unmasked vector
RemediationFix host path or device FW
Regression testAffinity-churn stress (TL-6)

F25 — High latency

Symptomsp99/p99.9 far above expectation; average may look fine
Likely layersHost queueing, CPU scheduling, controller (GC, read retry), power states, link recovery
Trace signatureLong phases in Lab 6 timeline: SQE→data (device), CQE→head doorbell (host)
Linux evidenceblktrace Q2D vs D2C; fio clat percentiles; CPU stats
NVMe evidenceTemperature, controller busy time, APST states
PCIe evidenceRecovery/ASPM exit events at spike times
First checkSplit host vs device time (blktrace D2C)
Disambiguating experimentDisable APST/ASPM (lab), precondition drive, isolate CPUs, compare distributions
Likely root causesQueue depth too high (queueing), background device work, power-state exit latency, CPU contention
RemediationTune QD, power policy, CPU isolation; vendor FW
Regression testLatency SLO test with percentiles and repeatability (Chapter 88)

F26 — Low throughput

SymptomsBandwidth below expectation
Likely layersLink (speed/width/MPS), controller/NAND limits, host CPU, insufficient concurrency, NUMA
Trace signatureGaps between data TLPs (credit starvation or device pacing); small payloads (MPS); few outstanding reads (writes)
Linux evidenceLnkSta, MPS, fio CPU usage, numa_node, iostat util
NVMe evidenceThermal throttling counters, MDTS
PCIe evidenceAnalyzer bandwidth statistics; UpdateFC cadence
First checkCompute the ceiling (Chapter 90) and required concurrency (Little's law)
Disambiguating experimentIncrease QD/jobs; move to local NUMA node; check for CPU-bound jobs
Likely root causesDowngraded link; insufficient QD; single-thread CPU limit; device steady-state write limit
RemediationFix link; tune workload; accept device limit
Regression testThroughput matrix (bs × QD × jobs) with tolerance bands

F27 — Queue-depth instability

SymptomsIOPS oscillates; latency grows superlinearly with QD; throughput collapses at high QD
Likely layersController scheduling, host block layer (tag exhaustion), workload generator
Trace signatureBursty doorbells; outstanding commands at device plateau then latency climbs
Linux evidencenr_requests, blk-mq tags; fio iodepth histogram
NVMe evidenceNumber of queues; MQES (max queue entries)
PCIe evidenceOutstanding MRd counts for writes (tags)
First checkPlot IOPS and latency vs QD (Little's law consistency)
Disambiguating experimentRepeat with preconditioned steady state; vary numjobs vs iodepth at constant total outstanding
Likely root causesDevice saturation (more QD only adds queueing delay); host tag limits; GC interference
RemediationOperate at the knee of the curve
Regression testQD sweep with knee detection

F28 — Power-management issue

SymptomsLatency spikes after idle; timeouts after idle; device disappears after idle (some platforms)
Likely layersNVMe power states (APST), PCIe link states (ASPM L1, L1 substates), device D-states
Trace signatureElectrical idle / L1 entry, then exit via Recovery when traffic resumes; first command after idle slow
Linux evidenceAPST settings (nvme get-feature -f 0x0c), ASPM policy (/sys/module/pcie_aspm/parameters/policy), LnkCtl ASPM
NVMe evidencePower state table entry/exit latencies; current power state (Feature 02h)
PCIe evidenceL1 PM Substates capability and control; LTR values
First checkDo problems correlate with idle periods?
Disambiguating experimentLab: disable APST (nvme_core.default_ps_max_latency_us=0) and/or ASPM (pcie_aspm=off) — one at a time
Likely root causesExit latency larger than advertised; platform/device incompatibility in L1.2; firmware bug in deep power state
RemediationQuirk/policy limit; FW fix
Regression testIdle/active cycling test with latency histogram on first I/O after idle

F29 — Reset loop

SymptomsRepeated "resetting controller" messages; eventually removal
Likely layersController (does not become ready), host init sequence, link
Trace signatureCC.EN 1→0, CSTS.RDY polling, CC.EN=1, RDY never 1 (or CFS=1); repeated
Linux evidenceDevice not ready; aborting reset, CSTS=…; Removing after probe failure
NVMe evidenceCAP.TO; CSTS values; telemetry
PCIe evidenceLink up and stable (else see F1/F2)
First checkCSTS value during the loop; link state
Disambiguating experimentPower-cycle vs controller reset vs function-level reset — which recovers? Capture host register sequence (TL-9)
Likely root causesFirmware stuck; host enabling before configuring admin queues; device needs longer than CAP.TO
RemediationFW fix; host ordering fix; quirk
Regression testReset-injection loop: 10,000 controller resets with I/O

F30 — Resume failure

SymptomsAfter suspend/resume: device missing, timeouts, or reset loop; intermittent
Likely layersPlatform power sequencing, link retraining, driver resume path, controller re-init
Trace signatureLink retraining at resume (Detect…L0), config restore CfgWr, NVMe register restore; deviation at the first wrong step (TL-9)
Linux evidenceResume timeline in kernel log; previous-boot journal if the system crashed
NVMe evidenceCSTS after resume; unsafe_shutdowns increment (power lost without notification?)
PCIe evidenceLnkSta after resume; AER Surprise Down
First checkWhich power state did the device actually reach (D3hot vs D3cold)?
Disambiguating experimentForce each path (platform settings) and compare failure rates
Likely root causesDriver assumes preserved state; device FW slow to boot after power loss; link training issue at resume
RemediationFull re-init path; quirk for delays; platform fix
Regression testThousands of suspend/resume cycles per power path with data verification

Quiz

  1. CSTS=0x3 vs CSTS=0xffffffff — which library entries?

    Answer

    0x3 = RDY+CFS → F19 (controller fatal). All-ones → device not responding on the link → F1/F2/F30 territory.

  2. Exactly 30 s stall with "completion polled": which entry?

    Answer

    F24 interrupt loss (CQE existed; interrupt did not lead to processing).

  3. Why is "rewrite the LBA" not a valid first experiment for F20 on production?

    Answer

    It destroys data and evidence; use lab drives or images.

Interview questions

  1. Senior Pick any three failures from the library and explain how you'd separate them with one experiment each.
    Model answer

    E.g. F13 vs F24: polled queues (lab) — if stalls vanish, the interrupt path is guilty. F2 vs F25: force a lower link speed — if tail latency persists, the link was not the cause. F26 link vs CPU: run more jobs on other cores — if throughput scales, CPU-bound.
