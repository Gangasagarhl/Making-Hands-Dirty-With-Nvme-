PART LIII

Things Engineers Commonly Get Wrong

Forty-two misconceptions about NVMe and PCIe, each with the reality, why it matters, and — most importantly — how to prove the reality on a real system or in a trace. This part also contains the analogy-safety rules, the mastery loop, counterexample training and layer-confusion training: the habits that stop misconceptions forming in the first place.

R3 Things Engineers Commonly Get Wrong About NVMe and PCIe

R3.1 Why this chapter exists

Misconceptions are not random ignorance; they are stable wrong models that survive because they usually predict the right answer. They fail exactly in the corner cases where bugs live. This chapter collects the most common ones encountered in validation, driver and firmware teams, and gives each a concrete disproof.

  • Recognise 42 common misconceptions in your own and others' reasoning.
  • State the correct model in one or two sentences each.
  • Design an experiment or trace check that demonstrates the correct model.
  • Explain the engineering consequence of each misconception.

Prerequisites: R1, the NVMe architecture (Part IX) and PCIe transaction layer (Part V).

🧒 Kid analogy

Many people think the Great Wall of China is visible from the Moon with the naked eye. It sounds right and gets repeated, but it's false. Engineering has its own "Great Wall" myths — they sound right, get repeated, and someone has to check.

🧩 Where the analogy breaks

A trivia myth costs nothing. An engineering myth costs weeks: a team that believes "AER tells you the root cause" will replace the wrong component.

R3.2 Layer and identity misconceptions

#MisconceptionRealityWhy it mattersHow to prove
M1NVMe is the same thing as PCIe.NVMe is a storage interface/command architecture; PCIe is one transport (others: RDMA, TCP, Fibre Channel). verifiedErrors must be assigned to the right layer: a PCIe Completion Timeout is not an NVMe command timeout.nvme list -v on an NVMe/TCP host shows NVMe controllers with no PCIe device; lspci shows PCIe devices that are not NVMe.
M2M.2 means NVMe.M.2 is a form factor/connector; M.2 cards may be SATA or PCIe (NVMe or, historically, AHCI). verifiedBuying or debugging the wrong thing; a SATA M.2 never shows in nvme list.Check lsblk -o NAME,TRAN (sata vs nvme) and the keying (B/M) of the module.
M3PCIe is the NVMe protocol.PCIe carries memory reads/writes; NVMe meaning (SQE, CQE, doorbell) is assigned by addresses and data structures in memory.An analyzer's "NVMe decode" is an inference; if it misses the queue setup, it mislabels traffic.Start a capture after queues are created and observe the analyzer showing only raw MRd/MWr.
M4The NVMe command set is the same as the transport.Since NVMe 2.0, command sets (NVM, ZNS, KV, ...) and transports (PCIe, RDMA, TCP) are separate specifications. versionReading only the base spec leaves out Read/Write details (NVM CS) and doorbell mapping (PCIe transport).Open the specification index at nvmexpress.org and list the documents.
M5The controller is the namespace.A controller is the interface that processes commands; a namespace is a quantity of non-volatile storage. One controller can have many namespaces; a namespace can be shared by controllers.Namespace-level errors (format, capacity) vs controller-level (CSTS.CFS) need different recovery.nvme list-ns /dev/nvme0 and nvme list-subsys.
M6A queue is the same as a doorbell.A queue is a ring in memory; a doorbell is a register holding one index for it."Queue is broken" may mean memory corruption or doorbell misaddressing — different fixes.Dump SQ memory (debugfs/driver instrumentation in a lab) and compare to doorbell writes in a trace.
M7The doorbell write contains the command.It contains only the new tail index (or CQ head). The command is fetched by the controller via DMA.Looking for command fields in a 4-byte MWr wastes hours.In a trace, decode the doorbell payload: a small integer < queue size.
M8DMA is a CPU copy.The device masters the bus and moves the data; the CPU does not touch payload bytes.CPU utilisation is not proportional to bytes moved; cache effects differ.Compare perf CPU cycles for large direct I/O vs memcpy of the same size.
M9A TLP is the same as an NVMe command.One command produces several TLPs; the SQE bytes travel inside a CplD.Counting TLPs ≠ counting commands; throughput analysis goes wrong.Count TLPs per command in a synthetic or real capture of a single 4 KiB read.
M10A Completion TLP is an NVMe Completion Queue Entry.A PCIe completion answers a non-posted request; a CQE is a 16-byte structure written by a posted MWr.Misreading "completion timeout" as "command timed out".Find CQE writes: they are upstream MWr into the CQ address range, not Cpl/CplD.
M11PCIe completion and NVMe completion mean the same.Different layers, different matching keys (Requester ID+Tag vs SQID+CID).Wrong layer = wrong fix.Show both in one trace: CplD for SQE fetch, MWr for CQE.
M12PCIe generation is the NVMe revision."Gen4" is a PCIe link speed; "NVMe 2.0" is a spec revision. They are independent.A Gen5 drive can implement an older NVMe revision and vice versa.lspci -vvv LnkSta vs nvme id-ctrl VER field.
M13SSD latency is PCIe latency.Link/transaction latency is a small part (sub-µs to a few µs derived); media access and firmware dominate (tens of µs for NAND reads impl).Upgrading the link does not fix media-bound latency.Measure QD1 4 KiB latency on the same SSD at Gen3 vs Gen4 link: small change.
M14AER identifies the root cause.AER reports what a port detected; the cause may be the link partner, the channel, the firmware or software.Replacing a "reporting" component wastes time.Correlate AER header log with a trace; often the first error is elsewhere.

R3.3 Queue, command and data misconceptions

#MisconceptionRealityWhy it mattersHow to prove
M15CQEs come back in submission order.The controller may complete commands in any order.Drivers that assume order corrupt state.Mix 4 KiB and 1 MiB reads at QD>1; log CIDs in completion order.
M16NLB is the number of blocks.NLB is zero-based: NLB=0 means one block.Off-by-one data corruption or "LBA Out of Range".Decode CDW12 of a 4 KiB read on 512 B format: NLB=7.
M17An LBA is 512 bytes.LBA size is set by the namespace's active LBA format (commonly 512 B or 4 KiB, optionally with metadata).Byte offsets computed with the wrong size.nvme id-ns /dev/nvme0n1 → flbas, lbaf entries ("in use").
M18Queue size N holds N commands.Full when head == tail+1 (mod N): at most N−1 entries outstanding.Overrun corrupts the ring.Ring arithmetic exercise with N=4.
M19The host writes both head and tail for every queue.Host writes SQ tail and CQ head; the controller reports SQ head inside CQEs (SQHD) and owns CQ tail.Misplaced writes cause invalid-doorbell errors.Check doorbell offsets in a trace: only SQyTDBL and CQyHDBL.
M20The phase tag is a status bit.It marks newness; status is in bits 31:17 of DW3.Misinterpreting P=0 as failure.Decode the second pass of a CQ: P=0, status 0 = success.
M21Submission queues live on the SSD.Normally in host memory; optionally in the CMB.Explains why SQE fetch is a device MRd.Trace shows MRd from the device to SQ base.
M22CID is globally unique.Unique per SQ among outstanding commands.Correlating by CID alone across queues merges different commands.Find two in-flight commands with the same CID on different SQs.
M23PRP entries can point anywhere at byte granularity.Only PRP1 may have an offset; others must be page-aligned (except the first entry's offset rule).Invalid-field errors or silent corruption.Construct a misaligned PRP2 in a simulator; observe status.
M24SGLs are always supported.Optional for I/O commands over PCIe; check Identify Controller SGLS.Driver must fall back to PRPs.nvme id-ctrl /dev/nvme0 | grep -i sgls.
M25Completion means data is on NAND.Only with FUA, a non-volatile/absent write cache, or after Flush.Data loss on power failure.nvme get-feature /dev/nvme0 -f 0x06 (Volatile Write Cache) and Identify VWC.
M26Deallocate (TRIM) erases data immediately.It marks LBAs as deallocated; read-back behaviour is reported in DLFEAT; physical erase happens later.Not a security erase.Compare DSM deallocate with Sanitize semantics.
M27nvme format is a harmless refresh.It destroys data in the namespace (optionally with secure erase).Irreversible.Read the command description; never run it on a disk with data.
M28More queues always means more performance.Beyond one per CPU (or per core group) gains vanish; resource cost rises.Over-allocation wastes memory/vectors.Vary nr_poll_queues/io queues in a lab; plot IOPS.
M29Higher queue depth is always better.Past saturation, more QD only adds latency (Little's law).Tail latency SLOs violated.fio QD sweep: IOPS plateaus, latency rises linearly.

R3.4 Link, error, reset and performance misconceptions

#MisconceptionRealityWhy it mattersHow to prove
M30A posted write is confirmed delivered.No end-to-end acknowledgement. Ack DLLPs confirm only receipt by the next link partner.Flush-by-read patterns exist because of this.Trace: Ack DLLP for a doorbell comes from the switch, not the endpoint, when a switch is present.
M31An Ack DLLP means the command completed.Ack is Data Link Layer acknowledgement of TLP sequence numbers.Layer confusion in trace review.Ack precedes any controller activity.
M32"x4 Gen4" gives 8 GB/s of user data.16 GT/s × 4 × 128/130 ≈ 7.88 GB/s raw after encoding; TLP/DLLP overhead reduces it further (~85–92% derived).Unrealistic performance targets.Formula in R12; sequential read fio test.
M33If lspci shows Gen4 x4 capability, the link runs at Gen4 x4.LnkCap is capability; LnkSta is current. Links can down-train or be in low power.Hidden half-bandwidth links.sudo lspci -vvv -s <bdf> | grep -E 'LnkCap|LnkSta'.
M34Correctable errors are harmless.They are corrected, but rising rates indicate a marginal channel and precede uncorrectable errors or down-training.Early warning ignored.Track AER correctable counters in sysfs (aer_dev_correctable) over time.
M35Completion Timeout means the SSD is dead.It means a non-posted request got no completion in time: could be the requester's view of a hung completer, a lost TLP, a surprise down, or a misconfigured timeout.Premature RMA.Check which side logged it (requester), then the link state and the partner's logs.
M36A reset is a reset.Conventional (cold/warm), Hot Reset, FLR, NVM Subsystem Reset, Controller Reset (CC.EN 1→0) have different scopes.Choosing too small a reset leaves state; too big a reset loses others' I/O.Reset scope table in Part XVI; observe what lspci config survives.
M37MSI-X interrupt delivers the completion.The interrupt says "look at CQ"; the CQE is already in memory.Debugging interrupts when CQEs are wrong (or vice versa).Polling mode (io_uring with hipri) completes I/O with no interrupts.
M38Interrupt coalescing is free throughput.Fewer interrupts, but added completion latency.QD1 latency regressions.Set Features 08h in a lab and measure QD1 latency.
M39A Gen5 SSD is always faster than Gen4 for applications.Only if the workload is link-bound (large sequential at high QD).Wasted upgrade budget.Compare random 4 KiB QD1 on both.
M40A healthy SMART log means a healthy link.SMART reports device/media health; link errors appear in AER and PCIe status registers.Link issues missed.Compare nvme smart-log with AER counters.
M41An SR-IOV VF is an independent physical device.VFs share the physical link, controller hardware and media; resources are assigned by the PF.Noisy-neighbour effects and reset scope.Load one VF and measure another VF's latency.
M42An analyzer decode is ground truth.The decode is the analyzer's interpretation; the raw symbols/TLPs are the evidence, and probe placement matters.Mis-decodes treated as device bugs.Check the raw header bytes behind every decoded field you rely on.

R3.5 Deep dive: why M10/M11 matter so much

In a typical 4 KiB read at least three TLPs could be called "completion": the CplD that returns the SQE bytes to the controller, the MWr that writes the CQE, and the MSI-X MWr that "signals completion". Only the second is the NVMe completion. If a status report says "completion missing", ask: missing at which layer? A missing CplD (PCIe) produces a Completion Timeout logged by the device (the requester of the SQE fetch); a missing CQE (NVMe) produces an I/O timeout in the host driver (Linux logs a timeout and typically aborts/resets); a missing MSI-X with a present CQE produces a stalled queue that a poll would rescue.

R3.6 Common mistakes when correcting misconceptions

  • Replacing one absolute with another ("AER is useless") — AER is valuable evidence of where something was detected.
  • Correcting the words but not the experiment — learners only abandon a misconception when they see the disproof.
🐞 Debugging connection

At the start of a debugging session, scan this table against the team's current hypothesis. If the hypothesis depends on any misconception here, stop and run the "How to prove" check first.

💡 Senior insight

When a misconception keeps recurring on a team, it is usually built into a tool, a dashboard label, or a document — e.g. a log column called "completion" that mixes PCIe and NVMe events. Fix the artefact, not just the people.

🧪 Lab R3.1 — Disprove five misconceptions on your machine SAFE

Objective: gather first-hand evidence against M2, M12, M17, M24 and M33.

lsblk -o NAME,TRAN,MODEL                       # M2: transport per block device
sudo nvme id-ctrl /dev/nvme0 | grep -E '^ver|^sgls|^mdts'   # M12, M24
sudo nvme id-ns /dev/nvme0n1 | grep -E 'flbas|lbaf'         # M17
BDF=$(basename "$(readlink -f /sys/class/nvme/nvme0/device)")
sudo lspci -vvv -s "$BDF" | grep -E 'LnkCap:|LnkSta:'        # M33

Observations: record VER (e.g. 0x20000 = 2.0), SGLS bits, active LBA format, LnkCap vs LnkSta.

Questions: Is your link running at capability? Does VER correlate with the PCIe generation?

Solution

VER is an NVMe revision encoding (MJR in bits 31:16, MNR 15:8, TER 7:0) and has no relationship with the PCIe link speed reported in LnkSta. A mismatch between LnkCap and LnkSta may indicate a slot limit, down-training or power management; confirm by checking the upstream port's LnkCap as well.

Extension: record AER correctable counters before and after a 10-minute sequential read.

Quiz

  1. A CQE has P=0 and status 0. Did the command fail?

    Answer

    No. P only distinguishes passes through the ring; status 0 is success.

  2. Who logs a PCIe Completion Timeout for an SQE fetch?

    Answer

    The requester of the MRd — the SSD's function — not the host.

  3. What is the maximum number of outstanding entries in a 64-entry SQ?

    Answer

    63.

Interview questions

  1. Intermediate "Our Gen5 upgrade didn't improve database latency." Explain.
    Model answer

    Database random reads at low QD are media/firmware latency bound; link transfer time for 4 KiB at Gen4 x4 is ~0.5 µs versus tens of µs NAND access. Gen5 halves only the transfer component.

  2. Senior A colleague says "AER shows the SSD's port logged Unsupported Request, so the SSD is broken." Respond.
    Model answer

    UR logged at the SSD means the SSD received a request it doesn't support — e.g. host MMIO to an unclaimed address, or a config access to a non-existent function. The suspect is the requester (often host software). Inspect the header log to see the offending TLP.

R4 Analogy Safety and the Mastery Loop

R4.1 Why this chapter exists

The previous chapters used analogies freely and catalogued misconceptions. This chapter turns both into method: rules for using analogies safely, and a twelve-step loop (plus three supporting tests) that every concept in the book should pass through before you claim to know it.

  • Apply the analogy-boundary rule: what maps, what does not, what is hidden.
  • Run any concept through the 12-step mastery loop.
  • Explain any concept at three levels that remain mutually recognisable.
  • Pass the five-question depth test and the trace-based mastery test for a mechanism.

Prerequisites: R2, R3.

R4.2 Child analogy safety — the analogy boundary

Analogies are for intuition, not normative truth. After every analogy write an Analogy boundary block with three parts:

  1. Maps well — the relationships that genuinely correspond.
  2. Does not map — properties of the analogy that are false for the engineering object.
  3. Hidden detail — the engineering fact the analogy conceals and which you must learn directly.
🧒 Kid analogy

The doorbell: the teacher rings a bell to tell the librarian new request slips are in the box.

🧩 Analogy boundary

Maps well: notification is separate from content; one ring can announce several slips. Does not map: it is not a physical bell, not a sound, not a "ring now"; it is a number — the new tail index. Hidden detail: the real operation is a host MMIO write (a posted PCIe Memory Write TLP) to a controller register at BAR0 + 1000h + (2y × (4 << CAP.DSTRD)); it must be ordered after the SQE store, and the controller then fetches SQEs by DMA.

R4.3 The twelve-step mastery loop

Every concept must be learned through: intuition, terminology, structure, mechanism, example, counterexample, trace, lab, failure, recovery, explanation by the learner, and assessment. Here is the loop applied fully to the Completion Queue phase tag.

StepPhase tag worked through the loop
1 IntuitionThe answer cards change colour every lap of the box, so yesterday's cards can't be mistaken for today's.
2 TerminologyPhase Tag (P), DW3 bit 16 of the CQE; "expected phase" kept by the host.
3 StructureCQ memory initialised to zero; controller writes P=1 on the first pass, P=0 on the second, and so on.
4 MechanismHost reads the CQE at head; if P == expected, it is new; on head wrap to 0, the host inverts expected.
5 ExampleCQ of 4 entries: pass 1 writes P=1 into slots 0–3; pass 2 writes P=0 into slot 0 — host expected phase is now 0, so it is new.
6 Counterexample"P=1 means a new entry" is false on the second pass. A driver that hard-codes P=1 hangs after the first wrap.
7 TraceSuccessive CQE MWrs to slot 0 a lap apart show DW3 bit 16 alternating.
8 LabIn a queue simulator (pseudocode below), run 10 laps and assert alternation.
9 FailureDriver forgets to zero the CQ before Create I/O CQ: stale P=1 values from a previous use look "new" → phantom completions.
10 RecoveryController reset, reinitialise CQ memory to zero, recreate queues; abort/requeue in-flight commands.
11 ExplainLearner teaches it in 60 seconds using a two-lap whiteboard sketch.
12 AssessGiven a CQ dump and the head index, learner identifies which entries are new.
// Phase-tag simulator (language-neutral pseudocode)
N = 4; cq = [ {p:0} ] * N; ctrl_tail = 0; ctrl_phase = 1
host_head = 0; host_phase = 1
function controller_post(cid):
    cq[ctrl_tail] = {cid: cid, p: ctrl_phase}
    ctrl_tail = (ctrl_tail + 1) % N
    if ctrl_tail == 0: ctrl_phase ^= 1          // phase inverts on wrap
function host_poll():
    while cq[host_head].p == host_phase:
        consume(cq[host_head].cid)
        host_head = (host_head + 1) % N
        if host_head == 0: host_phase ^= 1
    write_cq_head_doorbell(host_head)
// Assert: for 10 laps every posted cid is consumed exactly once.

R4.4 Three-level explanation requirement

The same concept must be recognisable across all three levels. Example: Completion Timeout.

LevelExplanation
1 — ChildYou sent a letter asking for something and promised to wait. If no answer comes after a long time, you give up and tell a grown-up.
2 — Junior engineerA requester that sends a non-posted request (MRd, config, I/O) starts a timer. If no completion with the matching Requester ID and Tag arrives within the configured Completion Timeout range, it logs an uncorrectable error (AER Completion Timeout status bit) and treats the request as failed.
3 — Senior engineerTimeout ranges are programmed in Device Control 2 (with supported ranges advertised in Device Capabilities 2) verified. The error is typically non-fatal by default severity impl; its consequence depends on what the request was: a timed-out SQE fetch in the SSD may lead to a controller fatal status, while a timed-out host MMIO read returns all-ones to software. Root cause candidates: completer hang, lost TLP after unrecovered link error, surprise down, ACS/routing misconfiguration, or a completer whose own downstream access is stalled. Prove with a trace showing the request, absence of completion, and link state.

Check: the child's "letter", the junior's "non-posted request" and the senior's "MRd with tag" are the same thing — recognisable at all three levels.

R4.5 The five-question depth test

After every major concept ask: What? Why? How? What happens if it fails? How would you prove what happened? Worked for MSI-X:

QuestionModel answer (MSI-X)
What?An interrupt delivered as a PCIe memory write to an address/data pair taken from a per-vector table in device BAR space.
Why?To give each queue its own vector (per-CPU locality), avoid shared level-triggered pins, and order interrupts behind data writes.
How?Driver programs table entries, enables MSI-X in the capability's Message Control; NVMe binds CQs to vectors at Create I/O CQ; the controller writes Message Data to Message Address after posting a CQE.
Failure?Masked vector → pending bit set, no interrupt → I/O timeouts despite CQEs present. Wrong address → IOMMU interrupt-remapping fault or interrupt to wrong CPU.
Prove?Read /proc/interrupts counts for the nvme vectors; a trace showing CQE MWr without subsequent MSI-X MWr; read the PBA in a lab with care (read-only).

🧪 Lab R4.1 — Run the full loop on Get Log Page SAFE

Objective: take Get Log Page (02h) through all twelve steps plus the three tests.

sudo nvme smart-log /dev/nvme0          # Log Identifier 02h
sudo nvme error-log /dev/nvme0 -e 4     # Log Identifier 01h, first 4 entries
sudo nvme get-log /dev/nvme0 --log-id=0x02 --log-len=512 | head

Steps: write the loop table; predict the TLP sequence for a 512-byte log; identify one failure (e.g. log length exceeding what the controller supports) and its status code.

Solution

Packet prediction: doorbell MWr ↓, SQE MRd ↑/CplD ↓, data MWr ↑ totalling 512 B (e.g. 2 × 256 B), CQE MWr ↑, MSI-X ↑. Failure: requesting an unsupported Log Identifier returns Invalid Log Page (command-specific status) or Invalid Field in Command — check the base spec for the exact code in your revision version.

Extension: compare numd dword arithmetic: NUMD = (bytes / 4) − 1 (zero-based).

  1. Senior Explain FLR at three levels in under three minutes.
    Model answer

    Child: "turn one appliance off and on without unplugging the house". R5 Counterexample Training

R5.1 Why this chapter exists

A rule you have never seen fail is a rule you do not understand. For every important concept this chapter gives a naive interpretation that sounds right, a concrete situation where it is wrong, and the evidence that exposes it.

  • Recognise 20 naive interpretations that fail in practice.
  • Construct a counterexample for a new rule on demand.
  • Use counterexamples as test cases in validation plans.

Prerequisites: R4.

🌍 Analogy

"All swans are white" was a perfectly good rule in Europe until black swans were observed in Australia. One observation is enough to falsify a universal rule.

🧩 Where the analogy breaks

In engineering, many "rules" are true for your device and false in general (implementation-dependent). The counterexample may not exist on your bench yet — it exists in the specification's permission space.

R5.2 The counterexample catalogue

C5Link Up means the device is usable.Link in L0 but controller CSTS.RDY=0 or CSTS.CFS=1.Read CSTS; nvme driver logs.
C6A successful CQE means the data is correct.End-to-end protection disabled + silent DMA to wrong IOVA = success with wrong data.Application checksum; enable protection information if supported.
C7No AER errors means the link is clean.AER may be disabled, not reported to OS (firmware-first), or masked.Check AER capability presence, mask registers, and platform firmware policy.
C8A bigger MPS is always better.Large TLPs increase latency for other traffic and require larger buffers; MPS is limited by the smallest in the path.DevCtl MaxPayload across hierarchy; latency of small reads under load.
C9MRRS = transfer size.Device may issue smaller requests than MRRS; completer may split into RCB-aligned completions.Trace MRd lengths and CplD Byte Count/Lower Address sequences.
C10Tags are unique per transaction for all time.Tags are reused immediately after completion.Same tag used twice within microseconds for different addresses.
C11If the CQE says success, PCIe had no errors.Correctable errors with replay happened silently; the command succeeded.AER correctable status; Replay counters if exposed.
C12Abort command cancels the command.Abort is best-effort; the target may complete normally; Abort's own CQE DW0 bit 0 indicates whether it was not aborted.Both CQEs: aborted command status (Command Abort Requested) or normal; Abort DW0.
C13Writing CC.EN=0 resets everything.Does not reset PCIe config state or the link; doesn't affect other functions.Config space unchanged; LnkSta unchanged.
C14Deallocated LBAs read back as zero.Read behaviour is reported by DLFEAT; may be unspecified/vendor.Identify Namespace DLFEAT.
C15QD1 latency = device latency.Includes software stack, interrupt delivery, scheduler wakeups.Compare interrupt vs polled completion latency.
C16A switch is transparent to timing.Adds store-and-forward or cut-through latency and its own Ack/Nak and flow control per link.Analyzer on both sides of the switch.
C17If nvme list shows the drive, MSI-X works.Admin commands may complete by polling during early init in some drivers impl; failures show later under I/O./proc/interrupts counters per nvme queue.
C18Poisoned TLP means the link corrupted the data.EP=1 is set by the source to forward known-bad data (e.g. uncorrectable memory error); the link CRC passed.LCRC fine, EP bit set in header; source error logs.

C20Sequential host writes are sequential on NAND.FTL may interleave across dies; other writes and GC intervene.Not visible from host; vendor tools/telemetry only impl.

R5.3 Worked counterexample in depth (C1)

Naive claim: "In the capture I see a Completion with Data right after the doorbell, so the command finished in 600 ns." Disproof: the doorbell is downstream MWr; the controller then requests the SQE with MRd; the CplD 600 ns later is the root complex returning the 64-byte SQE to the controller. The command has only just started. Evidence: the CplD's Requester ID is the SSD's BDF (it is a completion to the SSD), its Tag matches the SSD's MRd, Byte Count is 64, and its payload decodes as an SQE whose CID will later appear in a CQE.

🎯 Exercise — Build your own counterexamples

For each rule, construct a counterexample: (a) "The controller always fetches exactly one SQE per doorbell." (b) "A Read command always generates at least one MWr." (c) "The CQ head doorbell is written once per CQE."

Answer

(a) Controllers may fetch multiple SQEs in one MRd (e.g. 128 or 256 bytes) when tail advanced by several entries impl; also zero fetches if the tail equals the already-fetched head. (b) A Read that fails before data transfer (LBA Out of Range) produces a CQE MWr but no data MWr; and a Read with a CMB destination may keep data inside the device BAR impl. (c) Drivers batch: Linux processes several CQEs then writes the head once.

Quiz

  1. Give a counterexample to "a poisoned TLP means bad link".

    Answer

    Source forwarded data it knew was corrupt (e.g. memory ECC uncorrectable) — LCRC was valid.

  2. Why does C12 matter in timeout handling?

    Answer

    Because the original command may still complete; the driver must handle both CQEs and not reuse the CID/buffer until both resolve.

Interview questions

  1. Senior Give a counterexample to "doorbells are always 4-byte writes".
    Model answer

    Doorbell registers are 32-bit, but a host might (incorrectly or via a write-combining mapping) emit a merged write covering several doorbells; behaviour for such accesses is a spec question — check what the transport spec says about register access widths and treat anything beyond as implementation-dependent.

💡 Senior insight

Turn every counterexample into a regression test: a validation suite that encodes the black swans is worth more than one that re-confirms white ones.

R6 Layer-Confusion Training

R6.1 Why this chapter exists

The single most expensive class of reasoning error in NVMe/PCIe work is putting an observation in the wrong layer. These drills deliberately pair look-alike concepts from different layers until telling them apart becomes automatic.

  • Distinguish nine canonical pairs of confusable concepts.
  • Classify mixed statements by layer: application, block, driver, NVMe, PCIe Transaction, Data Link, Physical, media.
  • Rewrite ambiguous bug reports to be layer-explicit.

Prerequisites: R3; the PCIe layer model (Part IV).

🧒 Kid analogy

"I got a letter" could mean the envelope arrived, or you read what's inside, or you did what it asked. Envelope, message and action are different things.

🧩 Where the analogy breaks

In PCIe/NVMe there are more than three nested "envelopes" (Physical framing, DLL sequence/LCRC, TLP header, NVMe structure), and the same word ("completion", "reset", "queue") names different things at different layers.

R6.3 Drill set A — classify the statement

For each statement, name the layer(s) and, if it mixes layers incorrectly, rewrite it.

  1. "The read completed with a UR."
  2. "The SSD NAKed our doorbell."
  3. "Namespace 2 went into fatal status."
  4. "The link reset cleared the CQ."
  5. "Gen5 adds support for ZNS."
  6. "The interrupt had status Invalid Field."
  7. "Our 1 MiB write was a single TLP."
  8. "After FLR the namespace data was lost."
Answers
  1. Mixed. If "read" means a PCIe MRd: "the MRd received a Completion with status UR" (PCIe TL). If it means the NVMe Read command: NVMe commands don't complete with UR; perhaps a device MRd during it got UR → the controller reports a data transfer error status in the CQE.
  2. Mixed. NAK is a DLLP indicating a TLP with bad LCRC/sequence (DLL); it is not a rejection of the doorbell's meaning. Rewrite: "the link partner NAKed the TLP carrying the doorbell; replay succeeded/failed."
  3. Wrong entity. CSTS.CFS (Controller Fatal Status) belongs to a controller, not a namespace.
  4. Partly right but imprecise. A link-level reset (Hot Reset, conventional) resets the function, so the NVMe controller loses queue state; the CQ memory in host RAM is not "cleared" — it is abandoned and must be reinitialised by the driver.
  5. Wrong. ZNS is an NVMe command set; PCIe generation is irrelevant.
  6. Wrong. MSI-X carries only message data; status is in the CQE.
  7. Impossible. Max TLP payload is MPS (≤ 4096 bytes per the spec maximum verified); a 1 MiB write is many TLPs (and many MRd/CplD pairs).
  8. Wrong layer for "lost": FLR resets the controller; non-volatile namespace data persists. Data in a volatile write cache not yet flushed may be lost impl.

R6.5 Drill set C — rewrite the bug report

Original: "Drive times out on completion after reset, interrupts look broken, Gen4 issue?"

Layer-explicit rewrite

"After a Controller Reset (CC.EN 1→0→1) initiated by the Linux nvme driver's timeout handler, the first I/O command on qid 3 produced no CQE within the block-layer timeout (30 s default impl). PCIe: link stayed in L0 at 16 GT/s x4 (LnkSta), no AER errors logged at the root port or endpoint. NVMe: CSTS.RDY=1, CSTS.CFS=0. Interrupts: /proc/interrupts count for the qid-3 vector did not increase. Unknown: whether a CQE was written (no trace). Next step: poll the CQ memory via a debug build or capture the link to see whether the controller fetched the SQE." — Notice "Gen4 issue" is removed: there is no evidence linking link speed to the symptom.

Quiz

  1. Which reset preserves the PCIe link and config space but loses NVMe queues?

    Answer

    Controller Reset (CC.EN 1→0).

  2. Is "DMA" a layer?

    Answer

    No — it is a device behaviour expressed as PCIe memory transactions.

Interview questions

  1. Intermediate "Is an Ack DLLP sent for an MSI-X write?"
    Model answer

    Yes — every TLP, including the MSI-X MWr, is acknowledged by the link partner's Data Link Layer; that says nothing about the interrupt being serviced.
