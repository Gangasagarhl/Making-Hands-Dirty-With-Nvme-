PART XVII

Advanced PCIe

You already know what a Transaction Layer Packet (TLP) is, how a link trains, and how an NVMe command turns into memory reads and writes. This part opens the hood on the rules that make that traffic correct under stress: who may overtake whom (ordering), how answers to reads come back (completion rules), how a sender knows the receiver has room (flow-control credits), how a 32 GT/s or 64 GT/s link makes its electrical eye open (equalization), how errors are logged and contained (AER and DPC), and how one physical SSD pretends to be many (SR-IOV). Every chapter ends with the same question a senior engineer always asks: what would this look like in a trace, and what would I suspect when it breaks?

51 PCIe Ordering — Who May Overtake Whom

📘 Specification baseline

51.1 Why this chapter exists

An NVMe SSD finishes a 4 KiB read by doing three things on the wire, all of them posted Memory Write (MWr) TLPs going upstream: it writes the data into the host buffer, it writes a 16-byte Completion Queue Entry (CQE) into the host Completion Queue (CQ), and it writes an MSI-X (Message Signaled Interrupt – Extended) message. Software trusts that when it sees the CQE’s phase tag flip, the data is already in memory. Nothing in NVMe itself enforces that. PCIe ordering rules do. If you do not understand ordering you cannot explain the most frightening class of storage bug: the one where the completion arrives, the checksum fails, and five seconds later the same buffer is correct.

  • Beginner: name the three ordering classes (Posted, Non-Posted, Completion) and say which TLPs belong to each.
  • Intermediate: state the producer/consumer guarantee and show why “data write, then CQE write, then MSI-X write” is safe by default.
  • Advanced: explain Relaxed Ordering (Attr[1]), ID-Based Ordering (Attr[2]) and No Snoop (Attr[0]) and which NVMe writes may safely use them.
  • Senior: reason about deadlock avoidance (why posted writes must be able to pass non-posted requests) and about ordering across switches and the Root Complex.
  • Trace analysis: given a synthetic trace, identify whether a CQE could have become visible before its data.
  • Debugging / validation: design an experiment that distinguishes an ordering violation from a host-side cache or driver bug.

Prerequisites. TLP types and headers (MRd, MWr, CplD — see glossary TLP, MWr, MRd, CplD); the NVMe completion path (CQE, phase tag, MSI-X). Flow control is covered next door in Chapter 53; you need it to understand why ordering and deadlock are linked.

51.2 Story and analogy

🧒 Kid analogy

Imagine a one-lane mountain road from the library (the SSD) to the school (the host). The librarian sends a truck full of books (the data), then a postcard saying “your books arrived” (the CQE), then rings the school bell (the interrupt). Because the road is one lane and nobody overtakes, by the time the postcard arrives the books are already on the teacher’s desk. Now imagine the road gets a passing lane, and the postcard truck is small and fast. If it is allowed to overtake, the teacher reads “your books arrived”, looks at the desk, and finds… nothing. Ordering rules are the traffic law that says which trucks may use the passing lane.

🧩 Where the analogy breaks

Real PCIe has several independent “lanes” per direction in the logical sense (separate buffers for Posted, Non-Posted and Completion traffic, per Virtual Channel), the rules differ by pair of packet classes, and some overtaking is mandatory (to avoid deadlock), not merely permitted. Also, “arrived” really means “became visible to a reader of that memory”, which involves the Root Complex and CPU cache coherency, not just the wire.

51.4 Engineering view — the rules that matter

The ordering table in the PCIe Base Specification is a grid of “row = later TLP, column = earlier TLP, may the later one pass the earlier one?”. Each cell says No (must not pass), Yes (must be allowed to pass — required for deadlock freedom) or Y/N (permitted, not required). You do not need to memorise every cell. You need the five rules that drive real bugs:

  1. Posted must not pass Posted (default, Relaxed Ordering clear). A later MWr may not overtake an earlier MWr in the same direction. verified This is what makes “data, then CQE, then MSI-X” safe.
  2. Posted must be able to pass Non-Posted. A write must never get stuck behind a read that cannot complete. verified This is the deadlock-avoidance rule: if a read’s completion depends on a write getting through (for example, through a bridge), blocking writes behind reads could lock the fabric.
  3. Non-Posted must not pass Posted (default). A read issued after a write must not overtake it, so a read “flushes” earlier writes in the same direction. verified Drivers rely on this: a read of a device register after an MMIO write guarantees the write has reached the device (the classic “posted write flush” pattern).
  4. Completion must not pass Posted (default). A read completion travelling in the same direction as earlier writes may not overtake them. verified This is the producer/consumer guarantee for “write data, then let the consumer read a flag”.
  5. Completions for the same request stay in address order. When a read is answered by several CplD TLPs (split at Read Completion Boundaries), they return in increasing address order. verified (Details in Chapter 52.)

51.6 Hardware view

🔧 Hardware

Inside the SSD controller, the DMA engine that streams read data and the completion engine that posts CQEs are often separate blocks. A correct design either funnels both into a single in-order posted queue toward the PCIe core, or tags the data writes with RO and keeps the CQE strictly ordered behind them. Inside the Root Complex, writes may be committed to memory through multiple paths (different memory controllers, different coherency agents). The Root Complex must still honour PCIe ordering for what a consumer can observe. impl How it does that (write-combining buffers, coherency fences) is not visible in a PCIe trace.

The wire order of TLPs 4–21 still looks perfect: the CQE was transmitted after the data. That is the trap. Ordering is about what the Root Complex is allowed to do after receipt. 51.9 Worked example — is this design safe?

A firmware engineer proposes: “To speed up completions, the CQE write engine will run on a separate PCIe virtual channel (VC1) from the data engine (VC0).” Analysis: ordering rules apply within a Virtual Channel (and traffic class mapping); there is no ordering between VCs. verified So the CQE on VC1 may become visible before data on VC0. The design is unsafe unless the device explicitly waits for data to be committed — which a posted write cannot report. derived The engineer would have to issue a zero-length or ordinary read after the data writes (a read completion cannot pass the writes) before sending the CQE, which costs latency. Most NVMe devices simply use one VC. impl

51.10 Common mistakes

  • Believing wire order equals visibility order. It does only for the default (strong) ordering case.
  • Assuming an MMIO write has taken effect when it returns to the CPU. Posted writes return immediately; use a read-back to flush.
  • Assuming ordering holds across different Requester IDs when IDO is enabled.
  • Blaming the SSD for a stale buffer when the driver forgot a DMA sync / memory barrier on a non-coherent platform.
  • Forgetting that peer-to-peer traffic through a switch follows the same rules but different paths.

💡 Senior insight

Ordering bugs are statistical. They hide at low queue depth and appear under exactly the conditions that make the Root Complex reorder: many outstanding writes, multiple memory channels, remote NUMA memory. When you see “rare, load-dependent, self-healing corruption”, put ordering on the suspect list before media errors, and prove or disprove it with Attr bits in the trace.

Quiz

  1. Why must Posted requests be able to pass Non-Posted requests?

    Answer

    To avoid deadlock: if a read cannot complete until some write gets through, blocking writes behind reads could lock the fabric permanently.

  2. Which NVMe write is it safe to mark Relaxed Ordering?

    Answer

    Data writes into host buffers (they may reorder among themselves). Not the CQE and not the MSI-X write that follows it.

  3. Why does reading CSTS after writing CC “flush” the CC write?

    Answer

    Non-Posted requests must not pass Posted requests in the same direction, so the read reaches the device after the write. The completion therefore proves the write arrived (not that its effect finished).

  4. Does an analyzer on the SSD link prove that the host observed data before the CQE?

    Answer

    No. It proves transmit order and attribute bits. Visibility inside the Root Complex and memory system is not observable on that link.

📌 Summary

Posted writes in one VC stay in order unless RO says otherwise; reads and completions do not overtake earlier writes; writes must be able to overtake reads. NVMe’s “data → CQE → interrupt” correctness rests entirely on these rules. A trace shows permission to reorder, not reordering itself.

52 Completion Rules — How Answers Come Back

📘 Specification baseline

DOCUMENT: PCI Express Base Specification — Completion rules, Completion Timeout mechanism, Read Completion Boundary (RCB), Device Control / Device Control 2 registers. STATUS: normative. VERSION NOTES: Configuration Request Retry Status (CRS) was renamed Request Retry Status (RRS) in later revisions, which also allow it for some non-configuration cases version; 10-bit tags are optional from 4.0, and 14-bit tags appear with FLIT mode in 6.0 version.

52.1 Why this chapter exists

Every time an NVMe controller fetches a Submission Queue Entry (SQE), a PRP list, or the data of a write command, it issues a Memory Read (MRd) and waits for a Completion with Data (CplD). Every time the CPU reads a controller register, the controller must answer with a CplD. If completions are split, late, mis-tagged or carry an error status, the NVMe layer sees stalls, timeouts or controller fatal status — and the root cause is invisible unless you can read completion headers. This chapter teaches you to read them.

  • Decode Completer ID, Requester ID, Tag, Completion Status, Byte Count and Lower Address.
  • Explain the Read Completion Boundary and predict how a read will be split.
  • Explain Completion Timeout ranges and what happens when one fires.
  • Distinguish UR, CA, CRS/RRS and Successful Completion and attribute each to a layer.
  • Recognise Unexpected Completions and tag aliasing in a trace.

Prerequisites: Chapter 51 (ordering), TLP header basics, MRRS and MPS.

🧒 Kid analogy — the library request desk

You hand the librarian a request slip with a ticket number (the Tag) and your name (the Requester ID). The librarian may bring the books back in several trips, but always with your ticket number and always in page order. If the book does not exist, you get a slip saying “no such book” (Unsupported Request). If the librarian is broken, you get “I can’t do this” (Completer Abort). If the library is still opening, you get “come back later” (Retry Status). If nobody comes back at all, after a while you give up (Completion Timeout).

🧩 Where the analogy breaks

In PCIe the requester must have pre-reserved buffer space for the answer — there is no “I’ll wait at the desk” without room for the books. And “giving up” (timeout) is a hardware mechanism with programmable ranges, not patience.

52.3 Splitting: Read Completion Boundary (RCB)

A completer may return a read in several CplD TLPs. Each must not exceed the Max Payload Size of the path, and split points (other than the first and last) must fall on naturally aligned RCB boundaries. Root Complexes have an RCB of 64 or 128 bytes (reported in the Link Control register’s RCB bit for the root port); endpoints mirror the setting. verified

N_cpl ≥ ⌈ (A_start mod RCB + L) / min(MPS, chosen chunk) ⌉   (lower bound; completer may split at any RCB multiple)
  • N_cpl — number of completion TLPs
  • A_start — starting byte address of the read
  • RCB — Read Completion Boundary (64 or 128 B)
  • L — requested length in bytes (≤ MRRS)
  • MPS — Max Payload Size programmed on the path

Worked example

The SSD reads a 512-byte PRP list at host address 0x1_2340_0FC0 with MRRS = 512 and MPS = 256, RCB = 64. The Root Complex may answer: CplD #1 covers 0FC0–0FFF (64 bytes, ends at a 64-byte boundary, Byte Count 512, Lower Address 40h), CplD #2 covers 1000–10FF (256 bytes, Byte Count 448, Lower Address 00h), CplD #3 covers 1100–11BF (192 bytes, Byte Count 192, Lower Address 00h). synthetic Another legal answer uses more, smaller completions — the choice is implementation-dependent impl; the constraints (address order, RCB-aligned splits, ≤ MPS, Byte Count arithmetic) are not.

52.4 Completion Timeout

The requester runs a timer per outstanding non-posted request. If no completion (or not all completions) arrives in time, it logs a Completion Timeout — an uncorrectable error, by default non-fatal — and frees the tag. Device Control 2 lets software choose a range; Device Capabilities 2 reports which ranges are supported (Ranges A–D) and whether timeout disable is supported. The default range is 50 µs to 50 ms. verified

🏭 Implementation-dependent

What the NVMe controller does after a Completion Timeout on an SQE fetch or on write-data fetch is not defined by PCIe. Many controllers set CSTS.CFS (Controller Fatal Status); some retry; some complete the affected command with an internal error status. Your controller’s datasheet decides.

🧪 Lab 52.1 — Predict the completion split SAFE

Objective: compute legal completion sequences. Setup: RCB = 64 B, MPS = 128 B. Steps: for reads of (a) 256 B at 0x...000, (b) 200 B at 0x...0F0, (c) 4096 B at 0x...F80 with MRRS = 4096, list one legal sequence with Byte Count and Lower Address per completion. Questions: what is the minimum number of completions for (c)?

Solution

(a) Two completions of 128 B: first BC 256 / LA 00h, second BC 128 / LA 80h (low 7 bits of 0x…080). (b) 0F0–0FF (16 B, BC 200, LA 70h), 100–17F (128 B, BC 184, LA 00h), 180–1B7 (56 B, BC 56, LA 00h). (c) F80–FFF (128 B, BC 0 meaning 4096, LA 00h because 0xF80 has its low 7 bits clear), then 31 further 128-byte completions; minimum 32 completions because each is capped at MPS = 128 B. Lower Address is always the low 7 bits of that completion’s starting byte address.

Quiz

  1. Who generates the Completion Status field?

    Answer

    The completer (the function that serviced the request), or an intermediate element that terminated the request (e.g. a bridge returning UR).

  2. What does Byte Count 0 mean in a CplD?

    Answer

    4096 bytes remaining (the 12-bit field encodes 4096 as 0).

  3. Is a Completion Timeout correctable?

    Answer

    No, it is an uncorrectable error (default severity non-fatal, programmable in AER).

Interview questions

  1. Beginner Which TLPs require completions?
    Model answerNon-posted: memory reads, I/O and config requests, AtomicOps.
  2. Intermediate Why may a 4 KiB read return as many TLPs?
    Model answerEach completion is capped by MPS and splits are allowed at RCB boundaries; the completer chooses.
  3. Advanced How would you detect tag aliasing with 10-bit tags enabled on only one side?
    Model answerCheck Device Control 2 10-bit Tag Requester Enable and the completer’s 10-bit Tag Completer Supported; look for completions whose upper tag bits differ from the request; correlate with Unexpected Completion logs.
  4. Senior The controller sets CFS after a UR. Is the controller wrong?
    Model answerNot necessarily; PCIe does not dictate NVMe recovery. Determine why the host returned UR (IOMMU, BME cleared by error recovery, bad PRP). The NVMe behaviour is implementation-dependent; the root cause is upstream.
📌 Summary

Completions carry Requester ID + Tag for matching, Completion Status for error attribution, Byte Count and Lower Address for split reassembly. Splits respect MPS and RCB and stay in address order. Timeouts are requester-side, programmable, and their NVMe-level consequence is implementation-dependent.

53 Flow Control and Credits

📘 Specification baseline

DOCUMENT: PCI Express Base Specification — Flow Control (Transaction Layer), Data Link Layer InitFC/UpdateFC DLLPs. STATUS: normative. VERSION NOTES: Scaled Flow Control (larger credit fields with a scale factor) was introduced to support higher bandwidth-delay products version; FLIT mode in 6.0 adds shared credit pools alongside dedicated credits version. The counter rules below are for the classic (non-FLIT, unscaled) case.

53.1 Why this chapter exists

PCIe never drops a TLP because a buffer is full. Instead, the receiver advertises how much buffer space it has, in credits, and the transmitter is forbidden to send a TLP unless enough credits are available. When credits run dry, the link goes quiet even though both sides are healthy. Most “mysteriously low NVMe throughput” investigations that end at the PCIe layer end here.

  • List the six credit types and what each counts.
  • Explain InitFC1/InitFC2 and UpdateFC DLLPs.
  • Apply the credit gating rule and compute credit-limited throughput.
  • Recognise credit starvation in a trace and distinguish it from a slow device.

Prerequisites: ordering classes, DLLPs (DLLP, FC), Ack/Nak.

🧒 Kid analogy — parking tickets

The school car park gives the library six kinds of parking tickets: big-truck tickets and small-car tickets, for three different car parks (deliveries, requests, answers). The library may only send a vehicle if it holds a ticket for that car park. When the school empties a space, it mails a ticket back (UpdateFC). If the school is slow to mail tickets back, the library’s trucks wait at the gate even though the road is empty.

🧩 Where the analogy breaks

Tickets are not individual objects; they are running counters that wrap around. The receiver does not “mail back tickets”; it periodically advertises the total it has ever freed, and the sender computes the difference. And a sender may be told “infinite credits” (advertised as 0), meaning no tickets are needed at all for that type.

53.3 Initialisation and update

During Data Link Layer initialisation (link reaches DL_Active), each side sends InitFC1 then InitFC2 DLLPs for P, NP and Cpl, per VC0 (other VCs when enabled). After that, the receiver sends UpdateFC DLLPs as it frees buffer space. verified

Send allowed ⇔ (CREDIT_LIMIT − (CREDITS_CONSUMED + CUMULATIVE_CREDITS_REQUIRED)) mod 2FieldSize ≤ 2FieldSize / 2
  • CREDIT_LIMIT — most recent value advertised by the receiver (from InitFC/UpdateFC)
  • CREDITS_CONSUMED — credits consumed by TLPs sent since init (modular)
  • CUMULATIVE_CREDITS_REQUIRED — credits this TLP needs (1 header, ⌈payload/16⌉ data)
  • FieldSize — 8 for headers, 12 for data (unscaled)

verified (form of the gating rule from the specification’s flow-control model; confirm FieldSize when Scaled Flow Control is enabled).

53.4 Credit-limited throughput

BW_max ≈ (Credits_D × 16 B) / RTT_FC
  • BW_max — sustainable payload bandwidth for one credit type
  • Credits_D — data credits advertised (buffer size / 16)
  • RTT_FC — round-trip time from sending a TLP until the UpdateFC that returns its credits is processed (wire, receiver processing, UpdateFC scheduling)

Worked example

A Gen4 x4 link carries ≈ 7.9 GB/s raw after 128b/130b encoding (16 GT/s × 4 lanes × 128/130 ÷ 8). derived Suppose a switch port advertises 128 PD credits (2 KiB) and the credit loop RTT is 600 ns. BW_max ≈ 2048 B / 600 ns ≈ 3.4 GB/s. The NVMe SSD streaming reads (posted writes upstream) would be capped well below link speed. synthetic numbers chosen for teaching. Doubling the buffer or halving the RTT doubles the ceiling. This is why Scaled Flow Control and larger receive buffers appear as speeds rise.

53.5 Hardware view

🔧 Hardware

Credit buffers are SRAM inside the Transaction Layer of each port. Switches have a set per port per VC. Root ports often advertise generous posted credits because host writes from devices are the bulk direction. The SSD itself must reserve completion buffer space for every MRd it has outstanding; this, together with the number of tags, bounds how much write data it can prefetch from host memory. impl

💡 Senior insight

Bandwidth-delay product is the single most useful mental model in PCIe performance. Credits, tags, MRRS and NVMe queue depth are all the same idea at different layers: “how much can be in flight before I must wait for an acknowledgement?” If any one of them is smaller than bandwidth × latency, it becomes the bottleneck.

🧪 Lab 53.1 — Credit counter simulation SAFE

Objective: simulate the gating rule. Setup: Python 3.

FIELD = 12                      # data credit field width (unscaled)
MOD = 1 << FIELD
limit, consumed = 256, 0         # InitFC advertised 256 PD credits (4 KiB)
def can_send(payload):
    need = -(-payload // 16)     # ceil(payload/16)
    return ((limit - (consumed + need)) % MOD) <= MOD // 2
sent = 0
while can_send(256):
    consumed = (consumed + 16) % MOD
    sent += 1
print("TLPs sent before gating:", sent)   # expect 16
limit = (limit + 64) % MOD                 # UpdateFC returns 64 credits
print("after update can send:", can_send(256))

Questions: why does modular arithmetic handle wrap-around? What happens if the receiver advertises 0? Extension: add RTT and compute throughput.

Solution

Counters wrap; comparing the modular difference against half the range distinguishes “ahead” from “behind”. An advertised 0 means infinite — the real implementation skips gating for that type; this toy code would mis-handle it, which is exactly the bug class to watch for.

Quiz

  1. How many PD credits does a 256-byte MWr consume?

    Answer

    16 (256 / 16) plus 1 PH credit.

  2. Which DLLPs carry credit information?

    Answer

    InitFC1, InitFC2 (initialisation) and UpdateFC (runtime), each per class (P, NP, Cpl) and per VC.

  3. What does an advertised credit value of 0 mean?

    Answer

    Infinite credits for that type.

Interview questions

  1. Intermediate Why does PCIe use credits instead of retransmitting on overflow?
    Model answerCredits guarantee the receiver always has space, so the Data Link Layer replay mechanism only handles bit errors, not congestion; this keeps latency deterministic and avoids loss.
  2. Senior Throughput is 60% of link rate behind a switch but 95% direct. Walk me through it.
    Model answerCompare posted credits advertised by the switch upstream port vs root port, measure UpdateFC latency, check MPS on all hops, check switch egress contention from other devices, compute bandwidth-delay product.
📌 Summary

Six credit types, per VC, initialised by InitFC and replenished by UpdateFC; a TLP may only be sent if its header and data credits are available. Credit-limited bandwidth ≈ buffer / round-trip time. Gaps in a trace mean starvation only if counter reconstruction says so.
