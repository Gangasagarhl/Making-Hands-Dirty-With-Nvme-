31.1 Why this chapter exists

The NVM command set is the block-storage personality of NVMe: logical blocks addressed by LBA (Logical Block Address). Ninety-nine percent of the commands a production SSD sees are Read and Write; the remaining few — Flush, Write Zeroes, Dataset Management, Compare, Verify, Copy, reservations — carry outsized importance for correctness (durability, trim, clustering). This chapter gives you the opcode table and the shared Read/Write field layout used by most of them.

31.2 Learning objectives

  • Recall the NVM opcode table and each command's data direction.
  • Encode Read/Write CDW10–15 (SLBA, 0-based NLB, LR, FUA, PRINFO, DTYPE, DSM, DSPEC, PI tags).
  • Explain Write Zeroes, Compare, Verify, Write Uncorrectable and Copy and when to use them.
  • Explain reservations conceptually (register, acquire, release, report) and the Reservation Conflict status.
  • Check controller support (ONCS) before using optional commands.

Prerequisites: Ch 29, Ch 30 (Identify Namespace: LBA format).

🧒 Kid analogy — the numbered lockers

A namespace is a corridor of numbered lockers, each exactly the same size (the LBA size). "Read" means "bring me the contents of lockers 4096 to 4127"; "Write" means "put these things in those lockers"; "Write Zeroes" means "empty those lockers without me carrying anything"; "Compare" means "check those lockers contain exactly this"; "Flush" means "make sure everything you've been told to put in lockers is really locked in, not still in your hands".

🧩 Where the analogy breaks

Lockers on an SSD are virtual: an LBA has no fixed physical location. The FTL (Flash Translation Layer) remaps every write to a fresh NAND page, so "empty a locker" may only update a table.

31.5 The other NVM commands

  • Write Zeroes (08h): same SLBA/NLB layout, no data pointer. Makes the range read as zeros. CDW12 bit 25 DEAC (deallocate) lets the controller deallocate instead of writing, if DLFEAT says deallocated blocks read as zero verified. Linux uses it for BLKZEROOUT / REQ_OP_WRITE_ZEROES.
  • Compare (05h): host supplies data; controller reads media and compares; mismatch → 2/85h Compare Failure. Used fused with Write (§29.8).
  • Verify (0Ch): controller reads and checks integrity (ECC, PI) without transferring data; error statuses as for Read. Useful for scrubbing without PCIe bandwidth.
  • Write Uncorrectable (04h): marks blocks so subsequent reads return Unrecovered Read Error until rewritten — for testing error paths. CAUTION: destroys data in range.
  • Copy (19h): copies one or more source ranges (in a descriptor list, formats selected by a field) to a destination SLBA inside the namespace, without host data transfer version (introduced around 2.0; formats extended later). Limits in Identify Namespace (MSSRL, MCL, MSRC).
  • Reservations: Register (a host registers a reservation key), Acquire (take a reservation of a given type — Write Exclusive, Exclusive Access, and their Registrants-Only / All-Registrants variants — or preempt), Release, Report (list holders). Other hosts' conflicting commands fail with 0/83h Reservation Conflict. Used by clustered/shared storage (SCSI-PR-like) verified.

31.6 Capability discovery before use

📌 Remember

Before using an optional command or field: check Identify Controller ONCS (optional NVM commands), FUSES, VWC, SGLS; Identify Namespace DLFEAT, DPC/DPS, RESCAP, NOWS/NPWG (preferred write granularity); and the Commands Supported and Effects log. A controller is allowed to return 0/01h Invalid Command Opcode for any optional command it does not implement.

🧪 Lab 31.1 — Encode NVM commands SAFE LAB

Objective: encode CDW10–13 for given requests (namespace with 4096-byte LBAs). (1) Read 64 KiB at byte offset 1 GiB with FUA. (2) Write 8 KiB at LBA 0x1_0000_0000 with LR. (3) Write Zeroes 1 MiB at LBA 0 with DEAC.

Solution

(1) LBA = 2^30/4096 = 0x40000; NLB = 16−1 = 15 → CDW10 = 0x00040000, CDW11 = 0, CDW12 = 0x4000000F (FUA bit 30). (2) CDW10 = 0x00000000, CDW11 = 0x00000001, CDW12 = 0x80000001 (LR bit 31, NLB 1). (3) 256 blocks → NLB 255; CDW12 = 0x020000FF (DEAC bit 25).

Extension: feed the encoded commands into the Ch 29 decoder.

Quiz

  1. NLB = 0x00FF with 512-byte LBAs. Transfer size?

    Answer

    256 × 512 = 128 KiB.

  2. What does FUA mean on a Write?

    Answer

    The data must be on non-volatile media before the completion is posted (no reliance on a volatile cache).

  3. Which command checks data integrity without a data transfer?

    Answer

    Verify (0Ch).

Interview questions

  1. Beginner List the mandatory NVM commands.
    Model answerFlush, Write, Read.
  2. Intermediate Why is NLB 0-based?
    Model answerA zero-length transfer is meaningless, so the 16-bit field covers 1–65536 blocks.
  3. Advanced Write Zeroes vs DSM deallocate?
    Model answerWrite Zeroes guarantees subsequent reads return zeros (and may deallocate if DEAC and DLFEAT allow); DSM deallocate is advisory and reads of deallocated blocks return what DLFEAT says (possibly unspecified).
  4. Senior When would you set LR?
    Model answerIn redundant systems (RAID/erasure coding/replicas) where failing fast and reconstructing elsewhere beats waiting seconds for deep error recovery.

32 READ — End to End

32.1 Why this chapter exists

A single 16 KiB read touches about a dozen software and hardware layers and produces around 70 PCIe TLPs. When a read is slow or wrong, the bug can be in any of them. This chapter walks one read from pread() to wake-up and gives every layer its evidence, so you can bisect a latency or correctness problem instead of guessing.

32.2 Learning objectives

  • Name each layer in the read path and what it produces for the next.
  • Build the exact SQE for a 16 KiB read at LBA 0x1000 and predict every TLP.
  • Compute TLP counts from Max_Payload_Size and explain completion ordering.
  • Build a latency budget and identify which layer owns each microsecond.

Prerequisites: Ch 28, Ch 31; PRP basics (forward reference: Ch 36).

🧒 Kid analogy

You ask your teacher for a book. The teacher writes a request slip, drops it in the librarian's box and rings the bell. The librarian reads the slip, finds which shelf in the giant warehouse holds the book (the map), fetches it, and — instead of handing it to the teacher — walks straight to your desk and puts the pages there (DMA). Then she drops an "all done" note in the answer box and taps the teacher on the shoulder (interrupt).

🧩 Where the analogy breaks

The "pages on your desk" are spread across several desks (physical pages are not contiguous) and the librarian delivers them in small parcels (TLPs ≤ Max_Payload_Size) that may arrive in any order relative to each other only if Relaxed Ordering is used; with default ordering they arrive in order.

32.4 Worked example — 16 KiB at LBA 0x1000 with 4 KiB pages

Assumptions synthetic: namespace 1, 512-byte LBA format, MPS = 4 KiB (CC.MPS = 0), I/O queue 1 (DSTRD 0), CID 0x0042, the application buffer occupies four non-contiguous physical pages: 0x1_1234_0000, 0x1_1234_5000, 0x1_2000_0000, 0x1_0F00_3000. The driver allocates the PRP list from its own DMA pool, in a separate page at 0x1_7F00_0000 — a PRP list must never share memory with the data it describes (a read would overwrite the list while the controller may still be walking it).

  1. Size: 16384 / 512 = 32 blocks → NLB = 31 = 0x1F. (4 KiB LBA format: 4 blocks → NLB = 3.)
  2. Pages touched: buffer starts at offset 0 within the page → ceil((0 + 16384)/4096) = 4 pages.
  3. PRP1 = 0x1_1234_0000 (first page). Since more than 2 pages are touched, PRP2 = list pointer = 0x1_7F00_0000.
  4. PRP list (3 entries, 8 bytes each): [0] 0x1_1234_5000, [1] 0x1_2000_0000, [2] 0x1_0F00_3000.
SQE (little-endian bytes):
00: 02 00 42 00  01 00 00 00  00 00 00 00  00 00 00 00   CDW0 opc=02 CID=0042, NSID=1
10: 00 00 00 00  00 00 00 00  00 00 34 12  01 00 00 00   MPTR=0, PRP1=0x1_1234_0000
20: 00 00 00 7f  01 00 00 00  00 10 00 00  00 00 00 00   PRP2=0x1_7F00_0000, CDW10=SLBA lo=0x1000
30: 1f 00 00 00  00 00 00 00  00 00 00 00  00 00 00 00   CDW12 NLB=0x1F, FUA=0 LR=0 PRINFO=0

The same command drawn as a map: the left half of the SQE (SLBA, NLB) selects which blocks on the namespace; the PRP fields select which host pages the bytes go to. Block-to-page order is simple: the first 4 KiB of the transfer go to the page in PRP1, the next 4 KiB to PRP list entry [0], and so on. For the full doorbell → fetch → DMA → completion sequence, see Figure 39.0 (Read) and Figure 40.0 (Write); a Write uses exactly the same fields, only the data moves the other way.

🧪 Lab 32.1 — Follow one read through Linux CAUTION LAB

Objective: correlate a user read to an NVMe command. Setup: test system; root; nvme tracepoints. Procedure: (1) enable nvme_setup_cmd tracing; (2) run dd if=/dev/nvme0n1 of=/dev/null bs=16k count=1 skip=256 iflag=direct (reads byte offset 4 MiB); (3) find the Read command in the trace.

⚠️ Safety

if= must be the device and of=/dev/null. Swapping them destroys data. Double-check before pressing Enter.

Questions: what SLBA and NLB do you expect? Which QID? Why?

Solution

Offset 4 MiB = 8192 × 512 → SLBA 0x2000 with 512-byte LBAs (NLB 31) or 0x400 with 4 KiB LBAs (NLB 3). QID = the hardware queue mapped to the CPU dd ran on.

Extension: run with bs=1M and observe splitting at MDTS / max_sectors_kb.

🧪 Lab 32.2 — Senior forensic: count the TLPs SAFE LAB

Given: 128 KiB read, buffer offset 0x800, MPS(PCIe) = 512 B, NVMe MPS = 4 KiB, SQE fetched singly. Compute pages touched, PRP list entries, data TLPs, total TLPs.

Solution

Pages = ceil((2048 + 131072)/4096) = 33 → PRP1 + 32 list entries (256 B list). Data TLPs: the first page carries 2048 B → 4 TLPs; 31 full pages × 8 = 248; the last page carries 2048 B → 4; total 256. Plus doorbell, SQE MRd/CplD, PRP list MRd/CplD (CplD may be split at RCB), CQE, MSI-X, CQ doorbell ≈ 264.

Quiz

  1. For a read, who issues the data TLPs and of what type?

    Answer

    The controller issues MWr TLPs into host memory.

  2. Why can't a data TLP cross a 4 KiB address boundary?

    Answer

    PCIe forbids a memory request from crossing a 4 KiB boundary; so per-page splitting is natural.

  3. Why can a read complete "successfully" with garbage data?

    Answer

    Data MWrs are posted; if the IOMMU drops them the device is not told, so it reports success.

33 WRITE — End to End

33.1 Why this chapter exists

Writes reverse the data direction and add the hardest question in storage: when is data safe? A Write completion may mean "data is in a volatile cache" or "data is on NAND", depending on the write cache, FUA and power-loss protection. Durability bugs (lost writes after power loss) and write-latency spikes (garbage collection) both live here.

33.2 Learning objectives

  • Trace a Write: buffer → PRP/SGL → controller MRd → CplD → buffer in controller → NAND program → completion.
  • Count MRd requests from Max_Read_Request_Size and CplD from Read Completion Boundary.
  • Explain the volatile write cache, FUA and Flush, and what completion means in each configuration.
  • Explain NAND programming constraints (page program, block erase, write amplification) and their latency effects.

Prerequisites: Ch 32; MRRS (MRRS) and MPS (MPS).

🧒 Kid analogy

You want to store a box of drawings. The librarian walks to your desk and picks the drawings up herself (the device reads your memory). She may put them on her desk "to file later" (write cache) and tell you "done!" — fine, unless the lights go out before she files them. If you say "file it in the cabinet before telling me" (FUA) she does that first, which is slower.

🧩 Where the analogy breaks

Many enterprise SSDs have capacitors (power-loss protection) so "on her desk" is already safe; and the cabinet (NAND) can only be written in whole pages and erased in whole blocks, so filing even one drawing may cause a big re-shuffle (garbage collection).

33.3.1 Worked TLP count — 16 KiB write, MRRS 512 B, MPS 256 B, RCB 64 B

Data reads: 16384 / 512 = 32 MRd requests (each within one 4 KiB page). Each 512 B request is answered by CplDs no larger than MPS = 256 B and split on RCB-aligned boundaries; for aligned addresses that is typically 2 CplD per MRd → 64 CplD derived (completer may split further impl). The controller needs enough outstanding tags (8-bit, or 10-bit if enabled) to keep the link busy: at 1 µs round trip and 7 GB/s, ~7 KB must be in flight ≈ 14 outstanding 512 B reads. derived

outstanding_reads ≥ (bandwidth × round_trip_latency) / MRRS
  • bandwidth — target bytes/s on the link.
  • round_trip_latency — MRd issue to last CplD (s).
  • MRRS — Max_Read_Request_Size in bytes.

Linux reads VWC and sets the block queue's write-cache mode (/sys/block/nvme0n1/queue/write_cache: "write back" or "write through"); with write back, filesystems issue preflush/FUA (→ NVMe Flush and FUA bit) at journal commits. verified (behaviour of Linux block layer)

33.5 Flash programming in one paragraph

NAND is programmed in pages (e.g. 16 KiB) and erased in blocks (hundreds of pages); a page cannot be rewritten without erasing its whole block. So the FTL writes new data to a fresh page and marks the old one invalid; garbage collection later copies valid pages out of mostly-invalid blocks and erases them. The ratio NAND bytes written / host bytes written is write amplification (WA). Program times are hundreds of µs to ms for TLC/QLC; a controller hides them with parallelism across dies and with SLC caching. When the SLC cache fills or GC runs, write latency rises sharply. All figures impl.

WA = NAND_bytes_written / host_bytes_written
  • Host bytes: SMART "Data Units Written" × 512,000. NAND bytes: vendor-specific log only impl.

Quiz

  1. In a Write, which side sends MRd TLPs?

    Answer

    The controller reads host memory.

  2. Does a Write completion guarantee durability?

    Answer

    Only if there is no volatile write cache (or it is disabled/protected) or FUA=1; otherwise a Flush is needed.

  3. Why can write failures on DMA be reported but read DMA failures not?

    Answer

    Write data is fetched with non-posted MRd (gets a completion status); read data is delivered with posted MWr (no completion).
